# 主动欺骗与网络隔离：验收标准（待实现后逐条取证）

每条都必须给出可核验的证据（命令输出、日志片段、截图），不接受"应该没问题"。

## A. 业务无损（最高优先级）

- [ ] A1 引流开启前后各跑一次真实点击验收（`frontend/scripts/verify-security-trace-live.cjs`），两次都 9/9。
- [ ] A2 真实路径全绿：`/healthz`、`/readyz`、管理员登录、审查任务详情、对话、溯源三接口。
- [ ] A3 管理员自身来源在整个回归过程中**从未**进入 `prism-decoy-*`（断言集合成员为 0）。
- [ ] A4 保护来源回归用例覆盖引流路径（沿用 `deploy/tests/test_prism_security_trace.py` 风格）。

## B. 诱捕有效性

- [ ] B1 模拟扫描器连续命中 3 个诱饵路径，在 `decoy_min_hits` 个不同路径内被引流。
- [ ] B2 引流后真 backend 日志对应该来源的记录数**为 0**（证明请求没到真业务）。
- [ ] B3 诱饵响应与真站响应在状态码、头部集合、页面模板上不可区分（人工比对 + 差异清单）。

## C. 不可穿透

- [ ] C1 诱捕容器内 `curl https://www.lijiadong.cn`（或任意外部地址）**失败**（internal 网络无网关）。
- [ ] C2 无法通过诱捕层的任何路径读到真实数据（尝试 `/.env`、`/api/v1/internal/debug` 等，全部为虚构内容）。
- [ ] C3 诱捕容器根文件系统只读：容器内写 `/` 必须失败；`/tmp` 为 tmpfs。

## D. 不放大、不影响水位

- [ ] D1 单 IP 20 并发触发时，诱捕层出口带宽不超过 `decoy_max_bandwidth`。
- [ ] D2 同一时刻宿主机 `cr_backend` / `cr_frontend` 的 CPU 与内存水位波动在正常范围（对比基线）。
- [ ] D3 诱捕容器内存不超过 128M，超限被 Docker 限制而不是拖垮宿主。

## E. 可回滚

- [ ] E1 面板一键关闭 → `ipset flush prism-decoy-*` + 移除链引用，10 秒内 `healthz` 正常。
- [ ] E2 关闭后原封禁行为完全恢复（`PRISM-SEC-IN` / `PRISM-SEC-DK` 行为不变）。
- [ ] E3 `.releases/previous.env` 保留上一版本，可按既有 `rollback.sh` 回退。

## F. 可取证

- [ ] F1 导出证据包含：源 IP、国家/地区/组织、ASN、命中路径序列、UA/工具指纹、首末时间、引流次数。
- [ ] F2 证据包不含任何真实业务数据、不含请求正文、不含真实凭据。

## G. 链序 fail-closed

- [ ] G1 故意把 `PRISM-DECOY-IN` 放到 DROP 规则之后，启用必须**拒绝**并报明确错误。
- [ ] G2 恢复正确链序后再次启用成功，且业务无损（复跑 A1）。

## H. 出网分离（若批准 D3a）

- [ ] H1 情报查询确实从新出口发出（对端看到的源 IP 变更），且溯源归因仍成功。
- [ ] H2 模型 API 与通知渠道调用成功率与迁移前一致（迁移前后各 10 次真实调用对比）。
- [ ] H3 业务入口 IP 上不再出现情报/证书/更新的出站记录。
