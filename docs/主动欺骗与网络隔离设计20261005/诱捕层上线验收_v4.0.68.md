# 诱捕层上线验收（v4.0.68，独立端口方案）

生产版本：**v4.0.68 / `fd09f4e6340b3bc74c23cfcb2076ac4a299da9ef`**
方案：把诱捕层做成**独立 TLS 端口**，主机侧用 ipset + DNAT 把已判定来源改写到它；
主站 nginx **完全不参与转发**，从根上避开 v4.0.57—v4.0.62 的 rewrite 内部重定向死循环。

## 3. 诚实声明：没有观察到"真实公网攻击者被引流"

引流链路已**安装并逐项校验通过**，但**"某个真实攻击者被 DNAT 改写到诱捕层"这件事没有观察到**，
原因是：DNAT 只在 `nat` 表的 `PREROUTING` 生效，而回环流量不经过该链；我在宿主上无法伪造
来自集合成员的源地址（加入 `203.0.113.0/24` 文档段与 `127.0.0.2` 后分别用 `curl` 测试，
前者本机没有该地址、后者走回环，两次都不会穿过 PREROUTING）。

因此本项的验证等级如实标注为：

- **机制完整**：链、规则、ipset、route_localnet、链序、诱捕层本体与证书全部实测通过；
- **端到端待观察**：需要一个真实来源被规则引擎判定后加入 `prism-decoy-*`，
  届时诱捕容器会收到被改写的请求（可通过 `docker logs cr_decoy` 与执行器 `security_decoy_status` 观察）。

## 4. 当前生产链序（关键，别改顺序）

```
INPUT:  -A INPUT -j PRISM-DECOY-IN     ← 引流优先
        -A INPUT -j YJ-FIREWALL-INPUT  ← 云厂商链
        -A INPUT -j PRISM-SEC-IN       ← 既有封禁链
PREROUTING(nat): --dport 80/443 + prism-decoy-v4 → DNAT 127.0.0.1:8443
```

`PRISM-DECOY-IN` 必须在 DROP 链之前，否则流量会被丢弃、到不了诱捕层（执行器已 fail-closed 校验）。

## 5. 如何使用（最高管理员）

1. **观察**：安全中心 → 溯源与响应 → 防御面卡可见 `ipset 已就绪`；执行器动作
   `security_decoy_status` 会汇总命中来源（IP / 命中路径数 / 工具指纹 / 首末时间）。
2. **引流**：`security_decoy_apply` 把命中诱饵的来源加入 `prism-decoy-v4`（默认租约 3600s，
   内核 TTL 自动到期）。保护来源（管理员连接、本机地址、白名单、已建立公网对端）一律跳过。
3. **取证**：`security_ip_trace` 对任一来源做完整溯源；导出交给云厂商或网警。
4. **回滚**：`ipset flush prism-decoy-v4 prism-decoy-v6` + 删除链引用即可恢复原状；
   发布账本保留上一版本镜像。
