## 2. 面板能看到什么

| 区块 | 内容 |
| --- | --- |
| 状态卡 | 诱捕容器（运行中/未运行）、诱饵命中总次数与来源数、已引流来源数与集合/端口、引流链序（正确/异常） |
| 引流入口 | 「引流原因」输入 + 「把命中来源加入引流」；原因为空时不发请求；结果如实回报"已引流 N 个 / 跳过 M 个" |
| 幽灵访客表 | 来源 IP、命中次数、不同路径数、工具指纹（UA）、最近命中时间，每行「溯源」一键跳到溯源分区并自动查询 |
| 明细折叠 | IPv4 / IPv6 已引流来源明细 |
| 保护来源说明 | 明示管理员连接、本机地址、白名单、已建立公网对端一律跳过；租约由内核 TTL 自动到期 |
| 失败态 | `available !== true` 时清空数据 + 错误条 + 重试按钮，不显示任何默认数值 |

## 5. 仍然存在的边界

1. **没有观察到真实攻击者被引流**：DNAT 只在 `nat` 表的 `PREROUTING` 生效，回环流量不经过该链，
   宿主无法伪造集合成员源地址。机制已逐项校验（链、规则、ipset、route_localnet、链序、诱捕层本体与证书），
   端到端等真实来源被规则引擎判定后才会有生产证据。
2. 诱捕容器 `access_log off`，端到端观察当前依赖内核集合与执行器状态。
3. P4 出网分离、P5 表面迷惑、P6 第二个 EIP 未做。
