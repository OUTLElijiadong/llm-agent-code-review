# 主动欺骗与网络隔离：前提与现状核对

核对时间：2026-10-05 23:40 CST（设计评审前，全部只读实测）

## 1. 已具备的能力（可直接复用）

| 能力 | 现状 | 复用点 |
| --- | --- | --- |
| root 白名单执行器 + Unix socket + 请求账本 | `/run/prism-ops/agent.sock`，`OpsExecution` 审计 | D2 的 ipset/链操作走同一入口 |
| 定时巡检 | `prism-security-block.timer` 每分钟 | 新增 `security_decoy_*` 动作后无需新定时器 |
| 内核封禁链 | `PRISM-SEC-IN`（INPUT）、`PRISM-SEC-DK`（DOCKER-USER），ipset 原生 TTL | D2 新增 `PRISM-DECOY-IN` 可照此模式 |
| 溯源取证 | `security_ip_trace` / `security_surface_audit` / `security_traffic_summary` | D4 面板与证据包直接复用 |
| 保护来源 | 管理员连接、本机地址、近一小时 SSH 成功来源、白名单、已建立公网对端 | D2 的引流必须同样排除这些来源 |
| 安全中心分区框架 | 四分区（概览/事件/策略/溯源与响应） | D4 加第 5 分区 |

## 2. 需要新增的基础设施（本设计的成本项）

| 项 | 说明 | 影响面 |
| --- | --- | --- |
| 诱捕容器 `cr_decoy` | 静态应答服务，internal 网络、只读根、无出网、128M | 新增一个容器，不触碰现有容器 |
| ipset `prism-decoy-v4/v6` + 链 `PRISM-DECOY-IN` | 引流入口 | 只改我们自己的链，云厂商链保持只读 |
| 独立出网（D3a） | 高风险查询走第二个出口 | 需第二个 EIP 或代理容器；影响 `THREAT_INTEL_BASE_URL` 与证书/更新流量 |

## 3. 现状里的三个硬约束

1. **业务 IP = 出网 IP = `81.70.251.90`**：对手反向拉黑会同时打掉业务；D3 就是解这个。
2. **Nginx 是容器内的唯一入口**（`server_name ${APP_DOMAIN} ${APP_DOMAIN_ALIASES} ${SERVER_IP}`），
   所以 D1 的诱捕路由只能加在这份模板里，改完必须走完整发布流程并做真页面验收。
3. **云厂商链 `YJ-GLOBAL-INBLOCK/OUTBLOCK` 只读**：D2 不得依赖也不得修改它们。

## 4. 与既有约定的冲突检查

| 既有约定 | 本设计是否冲突 | 说明 |
| --- | --- | --- |
| 「授权门在最前，未过授权不得主动探测」 | 不冲突 | 本设计无任何对外动作 |
| 「模型不能指定处置目标」 | 不冲突 | 引流目标由宿主机规则引擎判定，模型只看到脱敏候选 |
| 「隐私禁写：不写凭据与第三方隐私」 | 需注意 | 诱捕层只提供**虚构**凭据，绝不返回真实配置；面板不记录请求正文 |
| 「SRC 只读红线：只查不改」 | 不冲突 | 诱捕层不接触任何真实业务数据 |
| 「生产渗透必须双人授权」 | 不冲突 | 本设计不涉及渗透执行 |
