## 连接测试与现有向量服务补漏

父代理真实 UI 发现 API 配置测试会发送实际 `chat/completions` ping，但原来无平台日志；同时完整检索定位已有 `/embeddings` 远端服务。沿现有服务边界复用统一 `record_usage_attempt`，没有新增表或本地模型监控框架：

- 个人 `/api/api-config/test` 与管理员 `/api/admin/llm/test` 均从真实鉴权用户传入数据库与 owner。每次 POST ping、重试、超时、非 200、200 坏结构均恰记一次，真实 usage 缺失保持 NULL；`GET /models`、预检拒绝、未发请求不记。日志失败原样传播，不能再次请求。前端说明已改为不保存 API 配置或 API Key，但记录实际调用用量；Key 显隐按钮名称由权限子代理独立补齐。
- 远端 embedding 每 32 条文本发送一批，实际 HTTP 每批单独记账。先读取可能存在的 usage，再处理非 200/解析异常；保持既有上游失败哈希降级。`UsageAccountingError` 在 `embed_texts` 和重嵌三次重试两层都单独传播，不会因日志故障再次发送模型请求。
- 个人入库/检索、Agent 入库/联合检索、能力及已发布 Agent 搜索、人工知识抓取、管理员重建向量均传递已鉴权用户。定时全局抓取没有可证明 owner 时保存 NULL；有当前受信作用域时保留 root/run/tool 等来源，未从文档文本/模型载荷/文档所有人猜测操作者。
- embedding 只写上游报告的 usage（缺 completion 保持 NULL）、模型、状态、耗时与异常类型；输入文本、向量、原始响应、URL、Key 均不入账。响应 model 中控制字符删除并遮盖该调用的 Key。未配置、空列表、本地哈希均零 HTTP、零模型日志。
