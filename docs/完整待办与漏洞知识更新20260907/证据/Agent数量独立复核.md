# Agent 数量口径独立复核

独立阅读实现、接口入口、事件过滤、注册表和测试。实际构建的内置注册表为 17；另两项自定义目录是隔离测试中明示的合成数据，不能将 19 当作生产实测数量。本账号有调用记录的可见集合、管理员全平台目录、MetaGPT 内置适配器三个范围有明确定义。

普通账号所有三个计数入口均由真实认证用户 ID 限定，列表与分类/态势共用过滤后的集合；自定义调用权限影响三个计数且真实零保留。管理员与超级管理员显式使用全平台范围。后台事件过滤限定本人，前端也不把他人及无归属系统事件认作本人正在执行；近期事件不是在线心跳证明，文案已明确。原 SSE 系统事件传递合同未扩宽。

独立重新执行 6 项后端真实注册表/隔离数据库测试与 5 项真实 Vue/Pinia/Element Plus 挂载测试均通过，证据为 `Agent数量独立复核.xml` 和 `Agent数量前端独立复核.xml`。5/19/17 的测试模型、自定义权限变化、账号事件隔离和历史日志不变都得到覆盖；未访问生产目录、未触发模型调用。

随后增加与本轮真实模型入口的交叉检查，发现明确 `agent_label=api_connection_test/embedding` 的日志仍在原统计 helper 中被回退成 `code_reviewer`。这会把仅调用连接测试/向量模型的账号误显示为运行过代码审查员。独立新增测试 2 项均先失败，证据为 `Agent非目录来源独立红灯.xml`；打回作者后，聚合逻辑与热点统一，仅在没有明确标签时兼容旧模型名。明确非目录来源不再虚构运行过的 Agent。

修复后的独立复跑为后端 11 项通过（原 6 项、作者追加的 3 项非目录/旧兼容回归、独立新增的 2 个交叉反例），前端仍为 5 项通过。`Agent数量独立复核.xml` 已更新为这 11 项，源码指纹同步刷新。未发现本次冻结改动仍有阻断问题。
