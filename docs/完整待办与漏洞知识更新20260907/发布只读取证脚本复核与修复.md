# 发布只读取证脚本复核与修复

发布后补记：本文保留采集器的发布前复核过程。生产collector已执行成功，运行态、42外键和前端资源均有真实结果及独立重算，见`证据/生产发布运行态与048核验.json`和`证据/新版生产数据独立复核.md`。

日期：2026-09-07。范围仅 `证据/collect_release_readonly.py` 及其本地附加测试，不改业务实现、不执行生产取证。

## 独审发现

原脚本要求前后端容器同时具有 APP_RELEASE/APP_VERSION 环境变量，正常前端会失败：Compose 只向 nginx final stage 注入域名/IP，VITE_APP_VERSION/VITE_APP_RELEASE_SHA 仅用于 builder。既有 `deploy/lib/common.sh` 也只核 backend 运行 Env。另有三处证据不足：只核可变镜像 tag、没有将运行 image_id 与发布账本求等；VERSION/知识哈希对可变工作区而非指定提交；42 外键未核引用数据库和单列可空约束。

## 完成修复

1. 只解析 `deploy/.releases/current.env` 必要发布字段，不 source/eval 环境文件。绑定其 RELEASE_SHA/APP_VERSION/组件 tag/image_id，实际容器 Image 必须等于账本 ID 和当前 tag 解析 ID；检查健康、运行与可选镜像标签冲突。仅 backend 核实际 APP_RELEASE/APP_VERSION，前端明确以绑定镜像和账本作为版本依据。
2. 用 `git show <sha>:VERSION` 及提交内文件字节校验，避免工作区改动冒充已提交版本。容器实读 5 文件 SHA：安全 catalog、官方公告记录、known_cves、统一用量 helper、sandbox_report_summary。不会读取历史报告正文。
3. 检查运行源码被 bind mount 覆盖或容器可写层改动。前端 assets 的已有命名卷合法保留，但镜像 `/opt/prism-dist` 全部文件须在实际服务目录逐一同 hash；额外旧 hash 资产可保留兼容，不能替代当前 index/资源。
4. SQL 为 REPEATABLE READ + READ ONLY 一致性快照，显式查询当前数据库与 transaction_read_only，读取 revision/42FK 后 ROLLBACK。必须是准确的 7表×6列、当前数据库引用、目标 id、SET NULL、nullable BIGINT、单列外键。
5. 结束再次核对账本字节、Git HEAD、容器 ID/image_id/启动时间与健康，防止取证过程中拼接不同部署。断言改为显式 require，Python 优化模式不会移除验证。命令失败/超时或未知错误只返回固定错误码/异常类型和非零退出，不回显 stdout/stderr、Env 或异常原文。

该脚本只执行 git show/rev-parse、docker inspect/image inspect/diff、容器内文件 hash 与只读 MySQL SELECT，不运行镜像 entrypoint、不创建临时容器、不导入应用模块、不变更状态。成功证据只输出白名单版本/ID/hash/DDL 元数据；敏感 Env 只在内存提取白名单后使用，未输出。
