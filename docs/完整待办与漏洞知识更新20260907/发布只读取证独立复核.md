# 发布只读取证独立复核

结论：未发现阻止本次只读生产采集的问题。独立完整阅读采集器、17 项测试、前后端 Dockerfile、前端资源保留 entrypoint 和生产 compose，并重新执行全部 17 项测试，0 失败、0 错误、0 跳过。冻结 SHA 与作者提供值一致，完整指纹和结果见 `证据/发布只读取证独立复核.json`。

前端 final nginx 没有 APP_RELEASE 环境变量符合实际构建方式。脚本以指定 Git 提交、发布账本、镜像标签解析出的镜像 ID、实际容器 Image 共同绑定版本；后端另验证真实 APP_RELEASE/APP_VERSION。不存在的镜像标签元数据没有被当作已存在证据，已存在却冲突则拒绝。

后端五个运行文件逐一与指定提交的 git show 内容比较。前端镜像内 dist 与实际服务目录逐文件计算 SHA，允许资源保留机制留下旧 assets，但本次构建的每个文件必须匹配。源码挂载或受保护目录可写层变更会拒绝；后端镜像设置 PYTHONDONTWRITEBYTECODE，正常运行不会以 pyc 写入触发误拒。前端资源保留入口允许 assets 命名卷，不修改当前 index。

数据库查询只有只读一致性事务、SELECT 和 ROLLBACK；检查目标 schema、048 版本和 7 表 × 6 字段共 42 个外键，逐一核对目标表、id、SET NULL、bigint、可空及单列约束。取证结束再次核验账本、Git HEAD 和容器 ID/Image/StartedAt，避免采集期间切换版本而混合证据。

命令使用参数数组；两个哈希目录和 MySQL shell 命令固定，不混入用户输入。环境配置仅用于内存核验，不进入报告；异常仅输出固定错误码与类型，测试中的敏感哨兵未泄露。

以上 17 项为独立本地命令输出注入测试，证据为 `证据/发布只读取证独立复跑.xml`。本独审没有执行生产 Docker 命令或数据库查询，不把脚本可执行性审查表述为生产取证完成。它是 3922 项应用全量之后追加的验收工具检查，不伪称重跑应用全量。
