# 生产 HTTP 验收脚本说明

脚本：`backend/scripts/verify_permission_acceptance_https.py`。脚本编写阶段没有向生产发送请求。6 项隔离回归通过，其中一项使用真实 FastAPI、真实密码登录/JWT、真实 RBAC 与 SQLite 执行 600 余个请求；只替换传输到本地 TestClient 和数据库，不替换认证或业务服务。两项目、两文件、成员关系、534 格负向矩阵均通过，ReviewTask/AiCallLog 行数仍为 0。证据为 `证据/生产验收脚本隔离回归.xml` 和 `.log`。

## 分阶段执行

- `--phase fixtures`：4 个专用账号真实登录并核对 ID、用户名、普通角色；有权限账号严格等于 20 个预定权限，无权限账号角色/权限均为空。创建 A/B 两个标记项目和两个普通源码文件，添加 A 的 reviewer，验证读取正向、跨项目 404、同项目 reviewer 写 403及拒绝后内容保持。随后 owner 真正修改/重命名文件，验证两个版本，撤权后 404，再恢复 reviewer 并重新登录验证数据/权限持久性。保留这些专用资源供浏览器验收，不创建报告、审查记录或模型执行。
- `--phase matrix`：执行全部已证明有前置门禁的负向接口，不创建项目或文件。必须提供 `--plan` 和与当前服务版本一致的 `--source-root`；发布前旧代码不能配新版计划。默认参数形式为 `--phase all`，先矩阵再 fixtures。
- 不传 `--execute` 时，不发送 HTTP。生成计划使用 `--build-plan --plan 新路径`；只读取实际注册 APIRoute 和依赖树，不启动 app lifespan、TestClient 或调度器。计划文件、凭据文件均要求当前系统账号拥有、权限 0600、非符号链接。

生产专用凭据由主任务创建并保存在服务器 `/root/prism-acceptance-20260907/credentials.json`，账号 ID 为 owner_a=103、member_a=104、owner_b=105、no_permission=106，自定义角色 ID=6。这些 ID 来自主任务本轮创建回执；执行脚本会通过真实登录再次核对，不以这份文档替代动态核验。凭据不随代码或文档提交。

主机执行 fixtures 需要指定：`--phase fixtures --credentials /root/prism-acceptance-20260907/credentials.json --base-url 既有生产HTTPS站点 --output /root/prism-acceptance-20260907/fixtures.json --execute`。脚本只接受 HTTPS 根站点，启用默认系统 CA 和主机名核验，禁用代理继承和 HTTP 重定向。

## 负向请求的前置拒绝依据

本轮实际路由有 313 个方法/路径组合。依赖图包含数据库会话、当前用户、两个来源的 admin guard、super_admin guard、require_permission 闭包以及报告格式 guard。逐个读过这些函数及其 RBAC/唯一超管辅助函数：数据库依赖仅开启/关闭 session；身份校验只读用户，权限查询只读角色/权限；缺失 JWT 在 get_current_user 中先抛出，空权限账号在对应 guard 中先抛出。FastAPI 完成这些依赖后才调用业务端点。

中间件仅 CORS 和请求上下文；后者产生正常访问日志及进程内计数，不写业务状态。计划保存依赖求值顺序、路由源位置及完整源码 SHA，执行前逐文件核验 SHA。未知依赖、未知中间件或没有相应门禁的格子列为 blocked，不尝试调用。

本轮依赖图计划为 299 个匿名 401 请求、235 个无权限 403 请求，合计 534。原始计划有 14 格没有 get_current_user 依赖，后续逐项读取后确认其中 8 个在 handler/service 内手动鉴权，不能称它们为公开接口。独立补充脚本 `backend/scripts/verify_manual_auth_https.py` 专门验证这 8 个无凭据 401，合计认证接口为 307；剩余 6 个为验证码、注册、登录及健康/指标接口。

235 项是显式 RBAC 权限门禁，其余接口按各自的仅登录、资源归属或专用 token 契约分类。“不适用通用 403”不等于“权限未测”，也不能强制所有接口返回 403。原始计划的 blocked 是生成器保守停止标记，不是最终业务契约分类。补充脚本不接收任何用户 JWT、Cookie 或 API Key；8 项本地契约测试同时放置 DB、事件订阅、worker代理、上游请求、存储的禁止调用断言，必须在这些操作前拒绝。

所有通用负向请求使用空 JSON，路径参数替换为 -1，避免指定现有业务 ID。对管理/执行/删除路由也只会在门禁证据有效时发送。任何状态不符合预期立即停止；不把 422/429/404 当成预期 401/403，不绕过限流、不重试写请求。独立本地测试已逐项实际验证这些请求先返回身份/权限错误。

## 证据与失败恢复

输出文件使用 O_EXCL 首次创建，已有路径拒绝覆盖。每次请求前记录账号标签、路径、方法、用途、预期、请求 ID；返回后记录实际状态、响应字节数/SHA、服务请求 ID、耗时。密码、令牌、响应正文均不落盘。资源创建后立即保存返回 ID，事实检查单独记录通过/失败。

网络失败或非预期响应会保留已创建资源与请求意图，不自动重放 POST，也不自动删除可能需要核账的记录。若中途失败，应根据已记录专用资源 ID 定向复核并继续；直接重新运行 fixtures 可能因标记项目已存在而停止，这是防止重复造数据。新输出文件和新登录只代表新的验收轮次，不抹掉旧失败记录。

重新登录会撤销该专用账号的旧 JWT。执行期间不要并行用同账号浏览器登录；fixtures 完成后再登录浏览器。HTTP 重登持久性不等同于生产进程重启验收，全部按钮仍须浏览器按账号/页面/动作补证。
