## 实现结论

- 登录路由仍在密码校验之前取得原子准入；本次只增加具体等待秒数文案。未放宽 5 次失败、后续请求拒绝的既有规则，冷却中的正确密码同样不会进入校验。
- 服务端统一错误处理同时返回原有 `Retry-After` 头与新增 `retry_after_seconds`。这来自本次服务器限流结果，不固定猜测 60 秒。
- 客户端支持秒数与 HTTP 日期形式，日期优先使用服务器 Date；代理 HTML 429 也能形成可读提示，无剩余值则不伪造倒计时。登录请求的 401 由表单处理，不触发普通业务会话失效流程；其他请求的 401 仍清令牌、发会话失效事件并跳登录。
- 登录页以绝对截止时间计算剩余秒数，按钮和直接 submit handler 均阻止冷却期请求。计时结束只恢复手动操作，没有自动重放密码；卸载清理计时器，重新挂载保留同一截止时间。sessionStorage 只保存截止时间，不保存账号、密码或令牌。
