内置敏感信息规则 20 条、静态语义规则 27 条；规则检测逻辑未虚增，只将实际 CWE 对应的类别改为官方 2025 映射。证书校验 CWE-295 归 A07、凭据保护 CWE-522 归 A06、硬编码凭据 CWE-798 统一归 A07，均非简单替换年份。

## 漏洞参考库

原 known_cves.md 是本地 PHP 生态速查资料，不是 NVD 同步数据库。本次将原有编号逐个核对 CVE 官方记录，并增补 PHP 官方 2026 年变更日志的全部 18 个 CVE 编号及 Laravel 2024—2026 公告，形成 41 条具有来源及哈希的参考记录，含 20 条 2026 编号。最新纳入的 CVE 官方记录公布于 2026-09-04。

38 条采用 CVE CNA 官方 JSON；CVE-2026-48041、CVE-2026-12184 和 CVE-2026-9672 的 JSON 端点抓取失败后分别使用维护者公告和 PHP 官方变更日志。来源类型分别标明，未伪造成 CNA JSON。第三条公告未给完整 libgd 影响版本，保留“以实际依赖和上游补丁为准”的边界。

旧库把 CVE-2021-21381 归为 Symfony 调试 RCE，官方记录实际属于 Flatpak，已从 PHP 活动参考集移除。Guzzle 三条 CVE 使用官方的跨域 Cookie/Authorization 泄漏说明；不能把这些公告直接当作所有 Guzzle 版本 SSRF 的证据。没有经验证 CVE 编号/版本范围的旧模式不再作为已确认组件漏洞。

实际模型读取链为 `security_sentinel_agent._knowledge_context` → `audit_knowledge_loader.build_prompt_context` → `l2_for_role(recon)` → `_read(known_cves)` → `app/ai/audit_knowledge/known_cves.md`。读取路径直接使用文件并有两层进程级 lru_cache，不涉及 SQL/嵌入接口。生产发布重启后会读取本次新文件，无需重建数据库知识索引。`seed_agent_playbooks.py` 的六个来源不含安全分类/known_cves，不应为本任务重跑其删除重建步骤。

`证据/安全知识/官方原始快照20260907.zip` 保存 55 个文件（54 个官方原始下载和 1 个本地派生的 verified_advisories.json），大小 2,442,386 字节；逐文件 URL、长度和 SHA256 见 `来源哈希清单.json`。MITRE XML ZIP 原始 SHA256 为 `3976f599e5e5200219a3108bb896d06e2a88fbb293369e1883cb423a5e9d7d50`。

解包后运行 `backend/.venv/bin/python backend/scripts/build_security_catalog.py --source-dir /绝对路径/解包目录`，会离线生成后端定义库、前端分类快照、CVE 结构化参考和模型速查 Markdown。需要刷新时先完整下载并核验新官方来源，再生成并测试，不由生产 GET 请求自动联网或写库。

回滚采用上一版完整 Git bundle 恢复代码、数据文件并重启后端；本任务没有知识 SQL 写入，不需要恢复用户知识表。统一发布前后应再次运行 `backend/scripts/audit_security_knowledge_storage.py` 留存计数、匹配 ID 与哈希，确认未触碰用户资料。
