## 实现与纠正

完整阅读新纯解析 helper、发布路径、审查列表/详情、报告来源统计、相关 schema/types，以及页面修改和生成报告的原始 prompt。原协议规定问题清单包含位置/代码/POC/修复建议，未规定字段只能使用列表行，因此字段小标题必须保持属于上层发现。

独立构造并实际运行发现 3 个边界反例：字段小标题含序号时把 1 条计成 2 条、字段小标题带值时同样计成 2 条、空清单未声明“无发现”却计成 0。作者按证据修正后，原 3 个反例和精确字段名对照全部通过；反例原文件保留，没有覆盖旧失败数据。代码围栏中的伪标题与列表不计入发现，下一个同级章节结束当前问题清单，未知结构保留未知。

审查列表、详情、报告列表、报告详情、领域 JSON 导出和仪表盘复用同一沙箱摘要。读取时只修改返回对象，不修改历史 ORM 记录；新发布或用户原有重新发布流程才按当前报告写入摘要。普通代码审查继续使用结构化 ReviewIssue 契约，没有从沙箱 Markdown 推断普通审查问题。
