# 用量归因验收

## 需求与边界

补齐 Agent 根任务与模型用量的精确外键归因。复用既有 Responses 运行、工具账本、团队、子任务和不可变领取事件，不建立另一套运行框架。历史 task11/team5、task35/team12、历史孤儿及 executing 工具账本不改状态，不按时间、trace、名称或数量猜测归因。

相关上下文为 20260906 续接修复验收、TODO、架构审视与 20260905 生产修复记录。本子任务检查了模型入口、来源传播、后台恢复、日志展示、迁移及相关测试；独立代理补充全应用模型调用点枚举与实链复核，清单保存在 `证据/用量独立复核/模型调用点清单.json`。本子任务没有执行 commit、push 或生产发布，生产验收由主任务另记。

## 精确来源与持久化

七张表使用六个可空外键：`ai_call_log`、`agent_response_run`、`agent_team`、`review_task`、`agent_mesh_message`、`pentest_engagement`、`sandbox_environment`。日志保存实际来源，其余表保存跨线程、重启和下一次执行所需的持久快照。

| 字段 | 引用 | 含义 |
| --- | --- | --- |
| root_agent_run_id | agent_response_run.id | 最初 Responses 根运行 |
| agent_run_id | agent_response_run.id | 触发该调用的当前运行 |
| tool_execution_id | agent_tool_execution.id | 持久占位成功后执行的工具账本 |
| agent_team_id | agent_team.id | 当前执行团队；新团队来源快照中可表示父团队 |
| agent_team_task_id | agent_team_task.id | 实际执行的团队子任务 |
| agent_execution_event_id | agent_team_event.id | 本次 task.claimed 事件，每次重新领取不同 |

根 Responses 行自身可以不自引用，实际日志以根行主键关联；嵌套运行保存祖先根 ID。独立创建的团队通过真实团队、子任务与领取事件关联，不虚构 Responses 根任务。既有 `task_id` 保持审查任务含义。

来源顺序为：原调用显式快照 → 当前同用户执行作用域（明确为空同样有效）→ 无执行作用域时已验证归属的 ReviewTask 持久来源。新根 B 分析历史任务 A 时，日志归 B，A 的历史字段不变。延迟写入只使用原调用快照，不串到后来执行的另一个根或账号。

调用链覆盖：

1. Responses 每个模型轮次按运行键和用户精确查询运行行；工具实际执行前已提交工具占位与来源父行。
2. 团队创建保存发起来源；领取产生 `task.claimed` 事件，执行器和 Mesh 请求继承该事件主键，结果沿原请求回投。
3. Mesh 消费者从所属用户的持久消息恢复来源；转入新 Responses 会话时继续保存。
4. Review、Pentest、圆桌、Sandbox 的创建、后台线程、恢复和报告发布继承持久来源；线程池与 executor 显式复制上下文。
5. 普通请求的 Orchestrator 给所有 BaseAgent 绑定可信用户与 Engine 工厂，覆盖语言识别、目录分析、普通聊天及嵌套安全扫描；不再仅绑定操作类 Agent。
6. Agent 内部 ASGI 再入由独立代理补齐受信来源传播，并通过真实鉴权、同步端点、真实 BaseAgent HTTP 与数据库日志的测试。

## 每次模型请求的账本

BaseAgent、DeepSeek raw/chat、ChatAssistant 多轮历史 HTTP、Responses 轮次统一记录实际尝试。每次网络重试是一条独立记录；原请求失败但返回了 usage 时保留真实值。没有返回 usage 时写 NULL，真实 0 保留；负值、布尔、字符串、浮点数不伪装成精确 token。没有按文本长度估算模型消耗。

用量写入使用明确绑定的数据库 Engine 创建独立 Session 并提交，不与业务事务共享 Session。复制的上下文只携带来源值与 Engine 工厂，不把请求 Session 跨线程传递。没有可信数据库时不隐式连接生产 `SessionLocal`；明确提供数据库的系统任务允许 `user_id=NULL`，不会伪造用户。

成功记账返回实际日志 ID。既有顺序和并行补录接口按这些 ID 与用户查询同一行，仅补充经过校验的 task/file/chunk 及业务失败信息，不重复增加成本行，不改原根来源。记账提交失败抛出专门异常，不能被 HTTP 重试或模型回退逻辑当作供应商失败而再发一次请求。

`http_attempts=0` 明确表示 Base/Chat 预检或预算拒绝、根本没有发送 HTTP，上层 `_log_call` 和 `log_deferred` 不造日志。正数表示实际尝试；旧兼容结果的 `None` 表示没有声明该证据，保留旧补录兼容路径，不能用这类人工结果宣称完成真实 HTTP 验收。应用中的新实际调用入口均使用受信绑定或作用域。

Responses 失败、非 200、无终止帧、收到 usage 后断流、终止帧缺 output、事件回传期间取消都保留已观察模型/用量。`CancelledError` 在记账后原样传播，不转为自动续跑。账本描述模型请求及返回；业务结构解析仍按原流程决定任务是否成功。

连接测试 ping 和远端 embedding 的额外真实 HTTP 入口由独立代理补齐，本代理只读重审并独立运行 34 项通过，证据见 `证据/用量独立复核/连接测试与向量调用独立复核.md`；模型列表 GET、本地哈希 embedding、MetaGPT 仅预览或发布配置不虚造模型用量。供应商 HTTP 在本地验收中使用 MockTransport，未为测试向真实模型收费请求。

## 接口与兼容迁移

`GET /api/ai-logs` 和详情在原管理员权限内增量返回六个 ID、`root_agent_run_key`、`usage_state`（unknown/partial/reported）。列表新增根运行、团队、团队任务、工具执行 ID 过滤，未放宽组织或账号权限。

迁移为 `048_ai_usage_attribution`，前置 `047_review_input_snapshot`：

- 七张表各六字段、索引与外键，共 **42 外键、42 索引**；已有行新字段全部 NULL。
- 全部外键 `ON DELETE SET NULL`，删除来源后日志和旧工具账本仍保留。
- 没有 UPDATE 历史来源、任务状态、事件或工具账本；旧工具字符串 run_id 不加新约束，历史孤儿不阻塞升级。
- 降级按“先外键、再索引、最后列”执行，避免 MySQL 1553。

主代理在独立真实 MySQL 库完成升级、42 外键与索引、历史全字段不变、未知来源拒绝、删父 SET NULL、降级再升级，并清理临时库。还验证独立日志提交 7 tokens（含真实 0）后业务回滚：日志保留、待提交业务用户不存在。此处直接测试日志事务，没有调用真实上游 HTTP。证据为 `证据/MySQL迁移核验.json`。

## 复现、测试与独立复核

原始红灯证据为 `usage-attribution-red.xml`：缺少根运行外键、缺 usage 被转为 0。MySQL 第一次降级因先删索引触发 1553，修复后通过真实复跑；原始证据保留。独立审查随后复现安全扫描、普通 BaseAgent、raw 失败及 Responses 失败轮次原先无账，已据此实现集中记账，而不是仅增加外键字段。

早期 355/356/357 与中间 450/451 项记录属于阶段证据，不能代替最终封版。中间 450 项唯一失败是新增聊天测试假调度器缺少 `list_agents()`；修正夹具后对应真实调用测试通过，不是生产逻辑缺陷。

本地实现已完成，历史归因与状态没有回填。主任务继续执行全量集成检查、Git bundle 发布和生产验收；最终生产结果由主任务交付文档记录。
