# 三角色闭环共识

沿用棱镜现有紫色、浅色卡片、中文排版及可爱菱形小菱，不整站换视觉语言。复用现有论坛与反馈API和组件。

论坛三角色均需有可见入口、查看/发帖/回复；作者和管理员编辑权限按后端契约执行，普通用户不得获得他人帖子的管理能力。管理员还需能从管理后台进入论坛与支持中心。渗透测试入口也需恢复到有权限的用户/审查员导航组。

反馈每个角色均有提交入口和本人进度；管理员另有全局列表、已读和回复能力。只有标记“已回复”时回复正文必须非空；单独标记已读、待查看或关闭可不写回复。打开处理表单保留原状态，编辑非空回复会按规则转为已回复，管理员显式选择状态则保留。用户回到页面或页面活跃时可读到最新回复和状态。当前产品没有通知中心，不承诺站外/即时推送。

实际发布版本更新公告，以当前代码和已验事实写内容，不承诺未测效果、不披露服务器细节/防御内部配置/账号凭据。正式发布后保存帖子链接，三个角色真实打开并刷新确认。发现当前业务约束与界面矛盾先记录，再按已有权限契约修复。

完成条件：保留矩阵和权限矩阵、全部已确认缺陷修复、适当回归、生产发布身份和真实复测、数据/截图独立复核、知识库闭环。

## v4.0.74 补充验收共识

审批来源提示必须与服务端核验状态一致。已核验事项可明确说明当前管理员账号下的原会话关联，并提供返回入口；未核验事项不得说成“已绑定”或要求返回某个会话，且不得提供跳转。生产审批记录只读核验；本次不审批、不驳回、不执行，也不清理历史记录。

## v4.0.75 首次异步数字值显示共识

共享数字滚动组件的首个异步值必须直接呈现接口值，避免页面已标记读取完成而数字仍处于计数动画中间帧；后续刷新或数据变化保留既有平滑动画。不得由 UI 动画现象推断后端统计正确或错误；统计 API 原始值未取得时，数据层波动仍标为未核实。

## v4.0.75 沙箱压缩与资源回收验收共识

生产首轮任务已证实现有源码上下文硬停在 32 个完整分片；此阈值不得继续充当整份源码的压缩上限。修复需对所有分片执行有界多层压缩，分层保留并核验原始 source ID、顺序、SHA-256、覆盖 ID、可回引证据及受保护的权限/否定/更正约束；源证据不全、模型截断、调用/时间预算耗尽或摘要超过目标预算时必须显式失败，不得丢弃尾部继续给决策模型。

百万级压力回归使用本地合成语料和可控假模型，不调用真实模型并标明分词代理口径；另以真实“公务通”生产源码快照验证相同业务入口，避免把合成夹具结论冒充线上语义验收。Worker 响应正文应限长、脱敏后保存诊断。停止操作对已接受任务必须取得终态清理回执；未接受任务可以在明确状态后收敛，状态缺失、路由不兼容或超时均不得假报 `stopped`。并发提交期间收到停止请求必须可被 Worker 识别，且不得因 404 丢失终止竞态。

验收顺序：先红测复现 33/40 片与提交/停止竞态，再实现和通过定向回归；确认生产旧任务的真实资源状态后，用原项目与设置重跑白盒且核对来源覆盖、阶段、工件、终态和清理；再串行运行仅回环、无远程目标的黑盒任务。白盒完成前不以 Worker `/health` 代替实测，不并发叠加同项目任务。

## v4.0.76 Worker 契约与压缩复测补充共识

Worker 的严格 execute 白名单保持不变。Backend 在网络调用前必须投影成 Worker 明确允许的字段；源码版本、修复版本和 repair round 留在持久化后台审计账本，不能因为业务元数据扩展 Worker 的输入面。

受保护事实改为按来源 ID 单独保存，不要求模型把完整事实重复塞入 600 字摘要。该事实侧账本与摘要、来源 ID 一起纳入最终上下文预算，超限时仍明确拒绝，不得丢弃、采样或声称已完整理解。压缩失败只允许有次数/时间上限的纠正重试；模型 `length` 终态只有在配置允许更高输出额度时才用更高额度重试。动态测试一轮任务只做一次压缩，所有生成反馈轮复用已验摘要。测试代码输出遇到 length 后只允许一次缩小范围重试；再次截断时明确标记动态用例未完成，不得降级标记为 AI 白盒通过。

自动回归后必须以用户已选的审查员账号，在同一现存项目与白盒设置下真实重跑，核查来源覆盖和哈希、Worker 执行回执、实际测试结果、工件及资源清理回执；未确认清理前禁止再开并发任务。白盒闭环后串行做一个仅访问本机回环地址的黑盒任务。一次生产小项目或本地百万代理单元都不构成“真实模型完整理解超过 100 万 token”证据；该项只有拿到供应商真实 usage/tokenizer 口径、模型响应完整终态和首/中/尾及受保护事实核验后才能标通过。
