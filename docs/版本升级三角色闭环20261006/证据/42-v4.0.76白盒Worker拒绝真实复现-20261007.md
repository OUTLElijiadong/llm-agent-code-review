# v4.0.76 白盒 Worker 请求契约失败真实复现（2026-10-07）

## 证据范围

- 生产只读健康接口 `https://lijiadong.cn/healthz`、`/readyz` 均返回 HTTP 200；healthz 为 `version=4.0.76`、release `069babf61ce8f5b93a3dfc2356ec81fd665b221c`，readyz 为 `status=ready` 且同一版本和 SHA。
- 普通 Safari 的已登录审查员会话直接打开生产 `/sandboxes`，左栏页脚显示 v4.0.76；只读查看已有沙箱记录，没有创建、重试、取消或删除任务。
- 线上已有白盒任务 `sbx_5c65ce4e3d2e447d9e856338`，项目 `V4验收样本20260920`，Python、白盒测试。记录显示任务 2026-10-06 22:55:22 开始，22:56:21 整体失败。

## 复现结果

生产页面事件顺序显示：源码上下文摘要为空/超长、引文核验失败、模型输出 `finish_reason=length`、关键事实超过摘要预算；动态测试生成多轮未通过执行前契约校验后回退到确定性白盒检查。随后 Worker 执行失败，原始错误为 HTTP 400，拒绝字段 `repair_round`、`source_revision_id`、`source_revision_sha256`。任务结果明确记录 `Sandbox worker /execute 返回 HTTP 400`，所以此项是实际可见业务失败，不是推断的风险。

## 候选修复及本地复现

- Backend 保存源码修订、repair round 等审计字段于后端持久请求信封，并在发 `/execute` 前通过 `_worker_execute_payload` 投影为 Worker 的固定白名单字段；Worker 白名单没有放宽。
- 契约回归将后端首轮与 PHP 修复轮的实际投影 payload 交给 Worker `_validate_execute`；两者均被接受，且 revision/repair 元数据没有进入 Worker 请求体。未知危险字段仍被 Worker 拒绝。
- 修复前新增的 `target_status=failed/blocked` + Worker `succeeded` + exit code `0` 红测复现总结果误判通过。候选修复要求成功状态与退出码同时有效，并要求黑盒/组合执行具备完整通过的黑盒回执、动态测试具备完整执行回执、远程目标具备通过回执。
- 项目详情的最近沙箱任务此前原样返回 `coverage`，项目列表已有权限过滤。通过成员 API 回归断言复现该数据差异后，详情按 `REPORT_VIEW` 权限统一隐藏 coverage。
- 报告列表此前将带 partial coverage 的失败任务都显示红色“未通过”。现改成 partial 显示黄色“验证未完成”、unknown 显示“结果未知”，确定性失败仍显示“未通过”。

## 运行环境与边界

- 此证据记录的是现行生产 v4.0.76 的旧失败和候选源码修复。检查当时没有写生产业务数据；旧失败记录保留。
- 候选代码的全量本地回归与版本提交尚待本轮最终记录。即使候选本地回归通过，也不等于生产 Worker 已接收修复或真实模型生成/压缩成功。
- 修复版本发布后，必须在同一生产项目、Python、白盒设置下新建一项串行白盒任务，核对 source hash、Worker request/receipt、实际测试结果、工件、终态和资源清理回执；白盒通过且清理确认后才运行无远程目标的回环黑盒。未完成此前，不得写“生产黑白盒已修复”或“真实业务不会失败”。
