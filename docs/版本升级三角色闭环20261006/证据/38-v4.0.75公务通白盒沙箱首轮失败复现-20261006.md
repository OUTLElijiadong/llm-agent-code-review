## 源码核对与证据边界

- 当前候选 HEAD `d0ae493180e02abdbd9f036ed23247f8248b970a` 以当前生产提交 `0bbe8c84038c8f59da3c91e08ce21d2e37493347` 为祖先。源码 `backend/app/agents/source_context.py` 将 `MAX_SOURCE_CHUNKS` 固定为 32，`compact_source_context()` 对更多分片直接抛出 `SourceContextError`；`backend/app/services/sandbox_service.py::_source_summary_for_agent_tests()` 也在清单/源码分片超过 32 时标记覆盖不完整。与页面错误文本相符，证明当前实现无法把该源码规模交给这条 Agent 压缩路径。
- Worker 执行请求 400 的响应正文未呈现在页面结果；`_call_worker()` 当前调用 `raise_for_status()`，没有将结构化响应正文带入任务结论。本次因此不能归因 400 的具体校验字段或运行时原因。

- `stopping` 是当前保护行为：平台未取得 Worker 终止回执，所以没有把未知资源状态谎报为 `stopped`。同时任务仍未闭环，不能将该行为描述为回收成功。
- 这是 v4.0.75 的一次真实生产失败复现，不代表所有白盒/黑盒模式都失败，也不代表 Worker 容器仍一定存活。最终资源状态尚未得到回执。
