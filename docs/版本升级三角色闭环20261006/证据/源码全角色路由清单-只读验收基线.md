# Prism v4.0.72 全角色路由清单（源码只读验收基线）

## 范围与使用方法

- 基线来源：当前候选 worktree 的 `frontend/src/router/index.ts`、`guards.ts`、`components/layout/AppSidebar.vue`、`components/admin/AdminLayout.vue`、`views/admin/AdminUnifiedCenter.vue`、`utils/adminUnifiedNavigation.ts` 和路由守卫测试。核对版本为 `4.0.72`，提交 `717d9476008303ce52b2efafbb65f6ea7f0eaac1`。
- 这里是**源码可访问页面和预期路由行为**，不是生产页面访问证据。生产验收仍须在普通 Safari 中登录真实角色后核对实际菜单、页面状态和 API 结果；本清单的生成没有访问生产。
- 71 条路由记录包含布局父路由、业务路由、旧入口重定向和兜底，不等于 71 个独立页面。旧管理入口应按重定向进入 4 个管理中心的对应分区。
- 所有表中的路径除显式注明外均需登录。匿名访问私有路径预期跳转 `/login?redirect=<原完整路径>`；已登录但角色/权限不符时，只有最终实际匹配路由上的守卫约束才会生效。带 `redirect` 的兼容路径需同时核对目标路由，不能仅依据源记录的 `meta` 推断。
- 权限列使用 `A 或 B` 表示路由守卫按**任一权限满足**放行；`管理员`表示应用层 `isAdmin()` 绕过普通角色/权限校验。标有“唯一超管”的入口先检查超级管理员身份，普通管理员不能绕过。
- 主站侧栏的数据项虽带 `roles` 字段，但当前显示逻辑没有按这个静态字段过滤，而是逐项调用路由权限判定。因此生产里应以当前账号实际菜单与 `router meta` / RBAC 返回值为准，不要单凭源码数组中的 `roles` 名单推断隐藏或放行。

## 管理员端

侧栏主入口：`/admin/governance`、`/admin/operations`、`/admin/access`、`/admin/platform`；超级管理员另有 `/admin/security-center`。`/forum`、`/support` 是管理员侧栏中的社区与支持入口。普通 admin 应看不到安全中心侧栏入口；直接访问 `/admin/security-center` 预期 `/403`。LLM/RAG/MCP 旧路径的行为见下方“管理旧入口与目标”，不要把源路由上的 `superAdmin` 元数据当作重定向后的拒绝证据。

| 可验页面/分区 | 规范路径 | 默认/分区内容 | 只读验收边界 |
|---|---|---|---|
| Agent 治理 | `/admin/governance?section=...` | `agents` Agent 目录、`studio` 创建与测试、`approvals` 审批中心、`evolution` 自进化、`knowledge` 知识与记忆、`skills` Skill | 只查看清单、状态、详情；不创建/测试/发布 Agent，不批准或驳回，不变更记忆、Skill |
| 运行与审计 | `/admin/operations?section=...` | `overview` 运行总览（默认）、`policies` 策略、`tools` 工具权限、`jobs` 任务调度、`observability` 监控告警、`logs` 日志与审计、`rewards` 奖惩趋势、`rollback` 版本回退 | 仅看数据与历史；不改策略/工具权限/调度，不执行任务、版本回退或处置 |
| 用户与权限 | `/admin/access?section=...` | `users` 用户管理（默认）、`roles` 角色管理、`permissions` 权限点 | 只查看账号、角色、权限；不改状态、角色或授权 |
| 平台配置 | `/admin/platform?section=...` | `beta-codes` 内测码（默认）、`report-templates` 报告模板；唯一超管专属 `llm` 大模型、`embedding` RAG 嵌入、`mcp-workers` MCP 与沙箱节点 | 仅查看配置；不生成/撤销注册码、不保存模板或全局配置、不连接/重启/变更节点 |
| 安全中心 | `/admin/security-center` | 独立页面含概览、事件、策略、溯源/流量/防御面/诱捕层等分区 | 仅查看自动读取的数据和历史。禁止点“运行监控”、保存策略、标记告警处理、提交诱捕应用、执行封禁/防火墙/主机动作或其他处置 |
| 论坛、支持 | `/forum`、`/support?section=maintenance\|feedback` | 全角色社区与反馈/工单页面 | 仅浏览；不发帖/回复、不置顶/编辑/删除、不提交工单/反馈、不标记已读、不回复/受理/关闭 |

管理旧入口与目标：

| 旧路径 | 规范目标 |
|---|---|
| `/admin`、`/admin/overview` | `/admin/operations?section=overview` |
| `/admin/agents`、`/admin/approvals`、`/admin/agent-releases`、`/admin/knowledge`、`/admin/evolution`、`/admin/skills` | `/admin/governance`，对应 `agents`、`approvals`、`approvals`、`knowledge`、`evolution`、`skills`；`agent-releases` 的 `releases` 别名由页面解析为 `approvals` |
| `/admin/policies`、`/admin/tools`、`/admin/jobs`、`/admin/observability`、`/admin/rewards`、`/admin/rollback`、`/admin/ai-logs`、`/admin/audit` | `/admin/operations` 对应分区；`ai-logs` 和 `audit` 均折叠到 `logs` |
| `/admin/users`、`/admin/rbac/users`、`/admin/rbac/roles`、`/admin/rbac/permissions` | `/admin/access` 对应 `users`、`users`、`roles`、`permissions` |
| `/admin/beta-codes`、`/admin/report-templates`、`/admin/llm`、`/admin/embedding`、`/admin/mcp-workers` | `/admin/platform` 对应同名分区；后三者设计为唯一超管专属，但旧入口的实际重定向会绕过源路由 `superAdmin` 检查，见下文 |

`/admin/agent-releases`、`/admin/audit` 等路径是兼容重定向，不应作为独立页面重复计数。注意：`/admin/llm`、`/admin/embedding`、`/admin/mcp-workers` 源路由声明了 `superAdmin: true`，但它们重定向到仅要求 admin 的 `/admin/platform?section=...`；普通管理员实际进入平台中心后，超管 Tab 被隐藏，选中项回落到第一个可见 Tab（通常为“内测码”），URL 中原 `section` 查询值保留。此行为与“普通 admin 直达应 403”的元数据意图不一致，是待修复/生产验证的权限差异；清单不将它写成已拒绝。

未知分区会让内容选中该中心当前可见分区的默认项，但 URL 中原 `section` 查询值会保留；需要验收特定内容时显式带 `section`，并同时核对 URL 与实际选中 Tab。

## 审查员端

审查员登录后默认 `/dashboard`。主导航项目按其账号当前 RBAC 权限动态显示；至少逐项核对下表中“审查员角色要求/权限”满足的页面。缺权页面预期拒绝，不应把菜单缺失自动记录成故障。

| 页面/路径 | 审查员所需条件 | 动态参数/注意点 |
|---|---|---|
| 工作台 `/dashboard` | 登录 | 只读概览 |
| 项目 `/projects`、`/projects/:id` | `project:view` | `:id` 换成现有可读项目 ID；只读详情 |
| 代码中心 `/code`、`/code/:projectId`、`/code/:projectId/file/:fileId`、`/code/:projectId/file/:fileId/versions` | `file:view` | 参数必须来自可访问项目和文件；编辑器只看，不编辑/保存/回退 |
| 审查任务 `/reviews`、`/reviews/:id`、发起页 `/reviews/start` | 列表/详情 `review:view`；发起 `review:start` | `:id` 使用现有可读任务；发起页只查看表单，不提交审查任务 |
| 渗透任务 `/pentests`、`/pentests/:publicId`、发起页 `/pentests/start` | 列表/详情 `pentest:view`；发起 `pentest:start` | 详情使用已有 engagement；发起页加载目标/规则属于读取，勿创建委托草稿或提交授权申请。源码说明提交授权后仍等待审查员/管理员批准，批准前不会启动测试 |
| 安全与规则 `/security`（旧 `/rules` 重定向） | `security:view` **或** `rule:view` | 查看，不保存策略 |
| 问题追踪 `/issues` | `issue:view` | 不改状态/指派/关闭 |
| 报告 `/reports`、`/reports/:id`、模板 `/report/templates` | `report:view`；模板 `report:template_manage` | `:id` 用现有可读报告；模板管理只读 |
| 操作审计 `/audit` | 审查员角色且 `audit:view` | 已合并审计员身份；普通 user 不因单有权限而放行 |
| Agent 工作台 `/agents`、兼容入口 `/agent-studio` | `/agents` 路由允许 `agent:view` **或** `agent_asset:create`；`/agent-studio` 源路由声明 reviewer/admin 与 `agent_asset:create`，但重定向后目标守卫只检查 `/agents` | 工坊实际组件以 `agent_asset:create` 或 admin 决定能否进入创建区，没有 reviewer 角色判断。因此普通用户若持有该权限，可能经 `/agent-studio` 或 `/agents?section=studio` 进入；这是源路由意图与实际重定向/组件权限不一致，必须在生产核对真实 RBAC，不能宣称角色隔离已验证。只读 Agent/团队，勿创建、测试、运行、发布 |
| 代码沙箱 `/sandboxes` | 登录（路由未声明额外权限） | 可能连接或分配运行环境；只查看状态，不启动/执行命令/上传源码 |
| 论坛 `/forum`、`/forum/new`、`/forum/:id`、`/forum/:id/edit` | 登录 | 详情首次读取会增加浏览计数；编辑路由由页面再检查作者/管理员，审查员不得编辑他人内容；不发帖/回复/删除 |
| 知识、支持、个人页 `/knowledge`、`/support`、`/profile`、`/profile/personalization`、`/profile/password`、`/profile/api-config` | 登录 | 支持分区通过 `?section=maintenance\|feedback`；勿改密码、API 配置、测试连接或提交支持内容 |

## 普通用户端

普通用户默认 `/dashboard`。大部分菜单同样由实时权限过滤；其可访问页面条件和审查员共用上一表中的路由权限，但以下差异需要明确核验：

- `/audit` 明确要求 `reviewer`，普通用户预期 `/403`，即使给该账号残留 `audit:view` 也不应放行。
- `/agent-studio` 的源路由写有 `reviewer`/`admin`，但重定向目标 `/agents` 有任一 Agent 权限即可通过，组件再按 `agent_asset:create` 展示工坊；因此普通用户若有残留该权限，不能据当前实现断言会 `/403`。须作为权限差异单独验收/修复。
- 用户应能进入 `/forum` 并看到发布入口；验收只读地确认入口和权限呈现，不提交内容。论坛详情首次访问会增加浏览计数（见副作用说明）。
- `/sandboxes`、`/knowledge`、`/support`、`/profile*` 在前端路由中没有额外角色/权限元数据，表现为登录即放行；这只描述前端守卫，不证明服务端数据范围。

## 匿名与无权预期

| 会话/身份 | 预期行为 |
|---|---|
| 匿名访问任一非公开业务页，包括 `/admin/*` | 登录页，并保留目标完整路径为 `redirect` |
| 已登录访问 `/login` 或 `/register` | profile 成功读取后跳至角色首页：管理员 `/admin/operations?section=overview`，审查员/普通用户 `/dashboard` |
| 普通用户或审查员访问 `/admin/*` | `/403` |
| 普通 admin 访问唯一超管页面 `/admin/security-center` | `/403` |
| 普通 admin 访问旧入口 `/admin/llm`、`/admin/embedding`、`/admin/mcp-workers` | 当前实现重定向到平台中心，超管 Tab 隐藏并回落到第一个可见 Tab；不是 `/403`。这是源路由约束未延续到目标路由的待修复权限差异 |
| 登录用户缺失业务权限，或 reviewer/user 与 `meta.roles` 不符 | `/403` |
| `/403` | 公开错误页面，可匿名查看 |
| 任意未知 URL | 公开 404 兜底页；不应误跳登录 |

## 有副作用的页面与控件

这些地址可用于核对页面和权限，但只读验收只加载或查看，不触发下列动作：

| 路径/页面 | 首次加载/操作风险 | 真实浏览器限制 |
|---|---|---|
| `/forum/:id` | 详情组件首次调用 `getPost(..., {recordView:true})`；后端服务递增 `view_count`。 | 这不是严格无写入的 GET 页面。打开前应把浏览计数变化列为已知低影响副作用；如果“只读”要求零写入，就只测论坛列表/详情权限静态入口，不打开帖子详情。 |
| `/register` | 提交注册表单会创建新账号。 | 只核对表单，不提交注册。 |
| `/projects`、`/projects/:id` | 列表/详情提供创建、编辑、删除、源码上传/导入、项目成员和安全审计等入口。 | 只看列表/已有详情；不新建、编辑、删项目/成员、导入/上传源码，也不运行安全审计。 |
| `/reviews/start` | 提交会创建审查任务并触发 AI/Agent 工作。 | 只核对表单与项目读取状态，不点发起/批量审查/重试。 |
| `/reviews/:id` | 详情可打开安全扫描/AI 修复辅助、查看待复核问题，并操作人工复核状态。 | 只读任务状态、报告和问题；不启动扫描/AI、提交复核结论或变更问题状态。 |
| `/pentests/start` | 提交目标范围会创建 engagement 草稿；下一步提交授权会创建授权申请，批准前按页面说明不会启动测试。 | 只检查授权说明和已有选项读取，不创建草稿、不提交授权申请或测试。 |
| `/code/:projectId/file/:fileId` | 编辑器提供保存源码操作。 | 只读展示，不输入、不保存、不回退。 |
| `/agents`、`/agent-studio` | Agent 工坊提供新建、修订、测试、提交审批、撤回等操作；工作台可发起 Agent/团队任务。 | 不发送提示词、不创建/修订/测试/运行/发布/撤回 Agent。 |
| `/sandboxes` | 页面自动读取并轮询现有环境；任务配置可调用测试/部署 Agent；已有环境可打开预览、续期或关闭。 | 仅看已有记录，不提交任务，不部署，不打开动态预览，不续期或关闭，不上传源码/运行命令。 |
| `/forum/new`、`/forum/:id/edit` | “发布/保存”写帖子；“AI 发帖助手”会产生模型调用。 | 只查看空表单/只读原文，不填入后提交、不用 AI 助手。帖子详情回到原文也可能产生一次浏览数写入。 |
| `/support` | 提交反馈/工单，管理员可回复、标记已读、受理或关闭；反馈组件活跃时会自动刷新列表。 | 自动刷新为读取；不得点提交、标记已读、回复、保存、受理、关闭。 |
| `/profile/password`、`/profile/api-config` | 修改密码、保存/删除凭据；“测试连接”会发起模型供应商调用。 | 仅读当前状态；不改值、保存、重置、删除或测试连接。 |
| `/profile/personalization`、`/knowledge` | 可保存/重新学习个人画像；知识库页面可入库、删除或同步内容。 | 只读取现状，不保存/重新学习、不入库/删除/同步。 |
| `/admin/security-center` | 挂载时自动拉取概览/最近事件/服务器摘要；控件中有监控触发、策略保存、告警处理、诱捕应用等操作。 | 页面只读查看；刷新/查询类按钮也应按服务行为先判断是否会留日志或触发采集；不点任何触发、保存、处理、封禁类控件。 |
| `/admin/governance|operations|access|platform` | 区域 Tab 载入各类资源；页面提供审批、Agent 发布、权限变更、任务调度、策略、回退、LLM/MCP 配置等写操作。 | 只展开/浏览 Tab，不点击批准、拒绝、保存、创建、停用、执行或回退。 |

## 源码定位与覆盖边界

- 路由及权限声明：`frontend/src/router/index.ts:4-430`；匿名、角色、权限、超管守卫：`frontend/src/router/guards.ts:42-103`。
- 主站静态菜单、动态权限过滤和分组：`frontend/src/components/layout/AppSidebar.vue:60-153`；管理员菜单：`frontend/src/components/admin/AdminLayout.vue:34-48`。
- 管理中心四域和所有 query 分区：`frontend/src/views/admin/AdminUnifiedCenter.vue:10-111`；旧分区 alias：`frontend/src/utils/adminUnifiedNavigation.ts:1-14`。
- 路由矩阵测试筛选 `record.name && !record.meta.public`，覆盖 64 条具名私有路由记录；它将解析路由直接交给守卫，未覆盖真实重定向后的路由行为、3 条无名路由记录或生产 HTTP/API 权限。因此不应表述为“所有非公开路由均已通过”。自动化路由测试也不是生产真实 HTTP 授权结果。
- 页面列表来自注册路由，不包括菜单项内部二级功能/弹窗中使用的所有 API、动态数据记录和后端权限；生产逐页验收应把“入口不可见”“直达 `/403`”“服务端拒绝”和“页面空状态”分开记证据。
