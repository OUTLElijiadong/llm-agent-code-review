## 阶段实际副作用

| 阶段 | 实际行为与写入 |
| --- | --- |
| `--build-plan` | 读取已加载应用的路由、依赖、锁及源码SHA；独占写入一个0600计划文件。无HTTP、无调度/应用启动生命周期。 |
| `--phase matrix` 不带execute | 核验计划与源码、重新发现完整路由图。无HTTP；不读取凭据。 |
| `--phase fixtures` 不带execute | 只输出fixtures_ready，不做完整路由计划验证，也不读取凭据。它不是生产夹具已可执行的证明。 |
| `--phase matrix --execute` | 四QA正常密码登录、各读取自身角色和权限；登录会更新登录时间/IP、会话版本/旧JWT有效性、认证审计及限流/会话状态。再发311个无JWT 401请求和243个空权限403请求。正常情况下不创建项目/文件/审查/报告/模型任务；访问日志和进程计数仍会变化。另写0600意图/结果日志。合计应为554个负向+12个登录/角色/权限请求=566个HTTP请求。 |
| `--phase fixtures --execute` | 同样登录四QA，然后创建A/B两项目、两源码文件及版本1，添加A reviewer；实际读写隔离测试后修改A项目描述、创建文件版本2、重命名文件、撤销再恢复A reviewer，并再次登录member_a测试旧JWT失效。保存这些资源，不自动清理。失败保留部分已创建内容与请求意图。 |
| 默认 `--phase all` | 先matrix再fixtures，会产生上述全部副作用。本次复用既有QA时不要使用默认all。 |

夹具循环首先按标记查询同名项目，并要求 total=0；历史项目尚存时会拒绝继续，不能删除旧资源或改marker/身份来绕过。另要求三个有权账号可见项目总数精确为1，新增业务归属也会使夹具断言失败。当前任务适用matrix阶段；真实资源跨项目/成员读写复验应复用既有资源单独安排，不冒充matrix已完成这些检查。

## 拒绝不安全请求的保护

1. 每条负向请求必须具备已复核、只读的前置身份/RBAC/工坊角色依赖；未知依赖、中间件变化、未知路由节点、未支持Mount、重复或遗漏路由均停止/列blocked。执行前再次核完整路由和源码SHA，不能把并行编辑导致的指纹变化忽略。
2. 匿名格必须在get_current_user拒绝；无权格必须在已复核guard拒绝。所有负向路径参数替换为-1，请求体为空JSON；没有通用前置门禁的路由不发送请求。422/404/429不替代预期401/403，任一异常立即失败，不重试写请求。
3. HTTPS只接受无路径/凭据/查询的根站点，系统CA及主机名校验启用；不继承代理，不跟重定向。网络超时20秒，请求间隔0.15秒。
4. 凭据和计划使用当前OS账号的0600普通文件，拒绝符号链接。首次结果文件独占创建，已有文件不覆盖。发请求前保存意图，返回后保存HTTP状态/字节/SHA/请求编号/耗时，不落密码、令牌或响应正文。
5. 325×2中96格因契约不同而blocked，不等于权限缺陷，也不等于已测。手动鉴权端点、WebSocket、真实资源隔离、全部按钮以及重启持久性需要独立验收。四个QA在执行期间不能被浏览器或其它脚本并行登录；matrix完成后浏览器应重新正常登录。
