# 生产图片历史与消息时间修复

日期：2026年9月13日。触发：主代理真实生产合成蓝色圆形问答成功，运行中用户消息有缩略图，终态服务器同步后变为文字“[图片]”；台北00:33显示成16:33，第二轮后全部历史时间又变16:34。此次子任务不发布、不修改历史检查点；真实生产证据由主代理保全。

## 已复现原因

1. 后端 `_public_transcript_messages` 把持久化 `input_image` 引用转换为单纯“[图片]”；前端终态恢复整体替换消息，只复制 role/content，没有图片资产信息，因此缩略图丢失。
2. 后端 naive UTC 的 run.update_time 直接 isoformat 不带时区，前端按本地时间解析；同时它用同一个 run.updated_at 给整段历史每条消息赋时间，下一轮完成后全部时间被改写。

## 修复边界

- session 回放仅返回本人、同 surface、同 session 的 input 资产编号／MIME／SHA256，二进制仍在原资产表，检查点不新增 base64、不改旧数据。
- 当前轮按显式 prism-asset 引用恢复图片；后续纯文字轮可从同会话旧图片轮补回缩略图，必须逐条验证相同位置之前的公开历史前缀。最多查询100个有图片运行；公开消息达到100条截断窗口时不推测旧图片位置，仅保留当前检查点显式资产引用。不能证明位置时保留文字降级，不拿相似问题猜图片。
- `AuthenticatedChatImage` 通过现有认证下载方法读取 `/agent-responses/assets/{id}/image`，使用内存 Blob 地址展示；不携 token URL，不向模型发送历史资产地址。404／网络失败常驻“图片暂时无法显示”与重试。账号变化、会话切换组件卸载及过时请求都丢弃旧结果并回收对象地址。
- 历史图片元数据与实时提交的 images 字段分开，下一条纯文字请求不携旧图片。服务端原“仅本人”资产下载权限保持。
- run.updated_at 明确序列化 UTC 偏移。检查点没有逐条发送时间，因此恢复消息不再展示虚构的时间，欢迎语也不附本次同步时间；实时发送期间仍可显示本地真实发送时刻。无数据不能补造逐条时间。
