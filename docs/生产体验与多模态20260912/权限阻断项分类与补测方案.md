# 权限阻断项分类与补测方案

## 重算结论

本轮从实际应用重新生成 325 个方法路径：650 个“匿名/无权限 × 方法路径”格中，554 格已具备原 runner 的前置拒绝证明，96 格被保守阻断。**96 格涉及 82 个方法路径，不是 96 个独立端点**：匿名 14 格、无权限 82 格。当前分析没有生产登录或 HTTP 请求。

| 实际合同 | 匿名 blocked | 无权限 blocked | 结论 |
|---|---:|---:|---|
| 公开端点：验证码、注册、登录、healthz、readyz、metrics | 6 | 6 | 统一期待401/403不适用；公开功能、限流及部署暴露范围另验 |
| 预览代理：GET/HEAD/POST | 3 | 3 | Cookie鉴权；匿名缺Cookie应401；普通JWT/RBAC无权限格不适用 |
| Agent事件SSE | 1 | 1 | 缺JWT应401；已登录零权限用户可订阅本人/系统事件，403不适用 |
| 独立上游Responses协议：POST/GET/DELETE/input_items | 4 | 4 | 缺Bearer应401；使用上游API凭据隔离，与平台JWT/RBAC不是一个合同 |
| 服务内固定门禁：Word/PDF导出、帖子置顶 | 0 | 3 | 真正未测的403，可用合法参数最小补测 |
| 本人/他人分支：4个RBAC本人服务、头像读取 | 0 | 5 | 本人允许；读取他人应403，需要分别测试 |
| 登录及资源能力服务 | 0 | 60 | 不要求统一RBAC权限，403矩阵不适用；功能、所属资源、正向写入仍未由该矩阵证明 |
| 合计 | 14 | 82 | 96格 |

完整逐格路径、源文件/行号、合同和当前源码指纹见 `证据/96项阻断精确分类.json`。60 格分别来自：认证本人3、工作台6、AI聊天4、提示词4、沙箱8、个人API配置4、维护4、反馈3、论坛8、画像4、头像写入3、个人知识库6、多模态资产2、讨论启动1。

“不适用”仅指统一拒绝预期，不代表功能通过。例如零权限用户允许读本人工作台/偏好、发反馈、个人知识库；对应写入、数据隔离和故障恢复仍须单独验收。多模态资产列表对他人 run 返回空列表，图片按资产与本人归属查找，越权返回404；只有真实存在的对应资源和本人正向读取配对，才能认定隔离，不能用随机不存在的ID冒充越权验收。

## 可执行最小补测合同

`证据/阻断项最小补测契约.json` 已逐条列出方法、路径、合法请求体、精确期望状态与源码门禁依据。它是待执行契约，不会自行联网。

1. **补8格手动匿名鉴权**：预览3、SSE1、Responses4。明确不带 Authorization/Cookie；Responses POST 使用合法 `{}`，应在上游HTTP/存储操作前401。不能用坏JSON400冒充鉴权。不得向 `/v1/responses` 发送 QA 登录 JWT：该接口会将合法格式的 Bearer 作为上游凭据转发。
2. **补3格服务内403**：无权限账号GET旧Word/PDF导出 `task_id=-1`；PUT帖子 `post_id=-1` 的置顶请求体 `{"pinned":false}`。权限/角色门禁在资源查询前，预期403；若退化成404就是门禁失败。帖子使用不存在的负数ID，即使管理员门禁退化也不会修改真实帖子；不得改用有效帖子ID。请求体是合法schema，不能以422代替403。
3. **补5格他人分支403**：QA110读取QA107的roles、permissions、menus、data-scope及avatar/image，均应先于资源查询403。自身RBAC四项分别应200，roles/permissions为空、data-scope默认project_own，menus按无权限菜单规则校验，不能硬断言空。自身未上传头像404仅说明无图片。
4. **额外补15个普通用户工坊合同**：它们已在原计划ready范围，**不计入96格**。以107或108登录，对15个工坊路径验证403；router级 `require_studio_role` 先于请求体验证和端点写入。108仅是项目内reviewer，基础user+QA角色不等于系统/RBAC reviewer。生产拒绝不能单独证明审查者正向可用，仍需真实系统审查者账号的独立验收；不增加权限或改账号来凑结果。

执行必须绑定最终发布源码并重新验证原plan，额外绑定本次复核的服务源码；仅调用明确列出的 `Runner.request`，**不得调用默认 `Runner.run()`**，以免误跑fixtures或全矩阵。沿用安全凭据读取、0600日志、不记录响应正文/密码/令牌、无代理/重定向、遇到非预期状态立即失败。现有Runner会完整读取body，因此仅用于SSE匿名的非流式401；已鉴权SSE须另用限时流式客户端，读连接事件后关闭，不能无限等待。

## WebSocket及有副作用的GET

WebSocket `/api/ws/discuss/{session_id}` 在HTTP计划外单列未测，不属于96格。代码在accept前校验：缺失/无效token关闭4001；不存在会话4004；真实他人会话4003，并且授权前不消耗pending。由于accept前关闭，真实握手客户端可能只看到HTTP403，不能把它误记成应用已返回4003。要证明owner隔离，需配对真实会话和owner正向连接；但owner连接pending会立即启动讨论/模型调用，当前只读范围不能创建或消费会话。不得用随机不存在会话的拒绝结果替代真实跨owner测试。token应走 `Sec-WebSocket-Protocol: prism-auth, <token>`，不放URL或日志。

不要批量扫全部GET：`/api/discuss/start` 会创建内存会话和pending，后续WS启动模型；预览代理即使GET也会转发到worker并commit；SSE会建立订阅；验证码会写入限流/验证状态。沙箱启停/续期、论坛写入、注册/改密码、个人配置/头像/画像、知识库嵌入和模型调用均不能由只读补测冒充完成。

## 精确白名单执行器

已实现 `证据/execute_blocked_contracts_https.py`。31用例及10个额外服务源码SHA内嵌，运行时不能传任意路径/用例；所有请求严格匹配固定顺序、账号、方法、body和预期状态，禁止token override。默认dry-run重建校验最终plan与服务指纹，**不读取凭据、0请求**。`--execute` 才登录所需的QA107与QA110，不登录108/109；**6个正常登录/角色/权限前置 + 31个补测 = 完整37请求**。

真实Runner搭配内存假HTTP客户端的4项离线自检通过。故障注入红证据：第7请求把应有401替成404，结果立即failed，实际仅7请求（6passed/1failed），无重试；绿证据完整37请求通过。日志验证无密码、令牌、错误正文，权限0600。正式Python3.11环境以不存在credentials路径执行dry-run，仍通过325路由计划验证，证明未读取凭据。以上没有生产HTTP。
