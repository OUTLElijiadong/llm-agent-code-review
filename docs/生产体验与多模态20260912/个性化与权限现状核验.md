## 已确认缺口与故障路径

### 头像

- `backend/app/api/v1/avatars.py` 上传只检查魔数，读取使用无界 `await file.read()`；`MAX_AVATAR_DIMENSION = 4096` 未被使用。抽取原函数执行确认：仅 8 字节 PNG 文件头、3 字节 JPEG 头、6 字节 GIF 头均被识别为有效对应 MIME。路由随后可将不可解码文件存库，界面无法显示；现有测试只覆盖错误魔数，未覆盖截断图片/像素上限。
- 内置头像服务端接受任意字母数字 key，和前端 12 个清单不一致；无效 key 会保存成功而回退文字，属于虚假成功反馈。
- 重复上传时，`ProfileCenter.vue` 撤销缓存并仍设置相同 `avatar='upload'`，`UserAvatar.vue` 只监听 avatar/userId，无更新版本。新图片不会触发重新拉取；旧 URL 被撤销仍留在子组件状态，可能继续旧图或显示不出。
- `UserAvatar.vue` 异步请求没有请求代次校验。切换账号/头像后，旧请求可能写入新状态，且 `setCachedAvatarUrl` 以请求完成时 props.userId 为缓存键，存在错归属风险。
- 上传入口是隐藏 input + 无 tabindex/键盘处理的 span role=button，键盘不可正常触发。所有头像变更未统一 busy 防重，连续选择响应乱序可能使 UI 与服务端最终值不一致。
- 头像读取接口只要求登录、不检查跨主体可见性。需明确产品范围后与现有人员可见策略一致；目前不能宣称头像跨组织隔离已验收。

### 偏好与新手引导

- `XiaolingPreferenceDialog.vue` 从不读取已有偏好；打开时表单为空。再次保存技术栈/爱好会把未选择的既有字段清空，已有自由文本也无法正常编辑。
- 保存分成 PUT 画像与 POST 标记两次请求。前者成功后后者失败会导致部分完成，当前无分段反馈；跳过失败则直接关闭，永久跳过没有成功却没有明确本地状态说明。
- 弹窗默认允许遮罩/Escape 关闭，但结算事件只在按钮触发。引导 pending 可残留；偏好稍后标志也未记录，重新挂载可能重复打扰。
- 新手第二页仅提供“去上传项目”，没有继续下一步按钮；点击立即完成整个引导，后续审查与报告步骤无法沿“下一步”到达。跳转未按当前权限过滤。
- Greeter 仅按 legacy role 排除管理员，未使用已有 `userStore.isAdmin()`；仅检查 `preference_prompted`，不检查已经存在的显式资料与长期使用情况，不能证明“已有画像不弹”“常用用户不弹”。
- `PersonalizationCenter.vue` 的加载无持久失败块与重试；`profile_service.to_dict` 对损坏 derived_stats JSON 不容错，可能使整个偏好读取报错。
- `ProfileCenter.vue` 仍使用没有用户 ID 的 `prism:user-prefs`。全前端检索仅该页读写，默认审查类型/完成通知没有实际消费者；保存成功并不代表审查行为改变，同浏览器账号也会共用。

### 长期学习与知识闭环

- `refresh_implicit` 在整个应用中仍仅由手动 `/me/profile/relearn` 调用，没有长期使用触发、冷却/去重或任务调度。弹窗注释中“持续沉淀”不是已实现能力。
- `update_profile` 不更新 derived_summary，而聊天注入只读取 derived_summary。新填技术栈/爱好等不保证立即影响小菱，尤其 hobbies 不参与 `_build_summary`；保存成功提示“已记住”夸大当前链路。
- 没有将用户偏好作为可追溯、本人隔离来源写入 knowledge_doc/chunk 的机制；现有 RAG 可复用但需增来源、幂等更新与失败保留。
- GET 画像使用 get_or_create 会提交新记录；不宜把每次首页探测变成数据库写入。长期学习不得通过 GET 无条件触发写库/外呼。
- 显式用户事实与统计推断需标记来源并分开展示；不能把“忽略问题”直接等同用户兴趣事实。现有 auto_learn 可复用，提供关闭、查看与清除学习结果。

### Agent 工坊

- 049 只撤销名为 user 的默认角色权限；自定义角色仍可能授予创作权限。API 仅 require_permission，服务 `_assert_reviewer` 判断“legacy reviewer 或拥有 create 权限”，因此普通身份只要重新获权限仍可使用。需统一严格身份门禁与操作权限两层检查，管理员保留管理路径。
- list/read API 没有统一角色检查；应覆盖所有工坊 15 条操作路由，不能只修创建。
- `AgentStudio.vue` 创建 Agent 成功但详情读取失败时 currentVersion 仍为空，重试会再次创建同编码并冲突；创建 Skill 成功后立即写 createdSkillVersionId，若绑定失败，重试跳过绑定并可能测试没有 Skill 的版本。
- resume 不复位 createdSkillVersionId/skillForm，跨草稿继续可能携带上一草稿临时状态。测试不是实际沙箱执行：调用上传固定 sample_output 的结构验证，文案“沙箱试跑”应与实际能力一致。
- loadAssets Promise.all 任何一个失败会丢失本次另一路可用结果；提交取消没有 catch，多个请求失败依赖 toast、缺少页面可重试状态。
