# 取消终态反馈复核

根任务生产真实复现：停止请求发出前任务已完成，数据库 status/checkpoint 均 completed、有最终输出且无取消原因；界面却提示“已停止任务”。本子未修改该历史运行。

源码根因是共享 `cancelAgentResponseRun` 只判断 HTTP 200，完全没有读取该接口返回的 SSE。SSE 的 HTTP 200 仅代表流已建立，后续仍可能 completed、cancelled、failed 或错误。普通端和管理员端都忽略实际结果并强制本地 cancelled。

修复复用现有 `streamResponses` 解析器，返回本次 run 的明确终态及输出/错误。流无终态、只有其他 run 终态、认证过期或执行错误均不确认取消。两端以该返回值更新状态：completed 提示已完成、保留服务端结果，failed/incomplete 给失败/未完成反馈，仅 cancelled 提示已停止。关闭本地订阅引起 AbortError 时，已完成/已失败结果不再被包装为取消卡片。未收到 run id 时不能声称停止成功。

取消确认等待期间重复点击只发一个请求；绑定请求时的账号、会话、run，并检查组件轮询停止标记，避免迟到结果落入新会话或已卸载组件。未改后端取消语义、历史状态、密钥或生产配置。

验证：新增红测 9 项失败；当前共享 API、普通 Drawer、管理员 Copilot 三文件合计 81 项通过，六文件 ESLint 通过。覆盖 completed/cancelled/failed/incomplete、HTTP200提前断流、运行错误、错误run、重复点击和会话切换。专项之后仅补两端 `sessionPollStopped` 卸载保护和注释，未改状态行为；由于根任务正恢复 node_modules，最终类型/全量/build由根任务统一执行，此处不冒称最终构建通过。

## 类型门禁和判重补充

根任务类型检查发现管理员消息对象使用 `payload.content`，原新增判重误写为 `entry.content`。新增已有真实助手 delta 的测试先复现结果重复，再改成 `role === 'assistant'` 且 `payload.content` 匹配。独立审查又发现普通侧需排除同文用户消息，新增“用户原话等于最终输出”红测后修复。最新 API、普通端、管理端三个完整文件合计 **84 项通过**，六文件 ESLint 通过；最终类型/构建仍由根任务统一执行。最后结果以根任务最终门禁为准，未把早期81项专项冒称最终构建。
