# 代理调用时间时区复核

根任务在生产 Agent 中心观察到本次刚调用的小菱显示“最近8小时前”。后端 `agent_service.py` 的旧版使用统计与运行目录聚合两处直接对数据库 naive UTC 时间调用 `isoformat()`，没有时区；前端 dayjs 按浏览器本地时区解释，UTC+8 用户因此多算8小时。

修复仅两处最近调用字段序列化，复用本文件既有 `_parse_event_timestamp`：naive 时间按数据库既有 UTC 约定附时区，带 offset 时间先转 UTC，再比较并输出明确 `+00:00`。无新依赖、未改变调用次数、模型归因或前端全站格式化。不解析的异常时间不冒充最近调用，但调用计数保持。

红测2项失败，修复后 Agent 服务与运行目录2个完整文件 **15项通过**，Ruff通过。用真实隔离SQLite持久化 `2026-09-12 16:30 UTC`，验证旧版Schema与新版聚合输出都保持时区，东八区 `2026-09-13 00:32 +08:00` 与其仅差120秒；另验证混合offset输入按实际时间选最近一次而非按字符串错选。未修改生产记录。生产重新发布后真实显示由根任务验收。
