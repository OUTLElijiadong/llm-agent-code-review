# 模型能力现状核验

核验日期：2026-09-12。生产基线由主代理只读确认：`bc207b273441e2f01f988122d28e2f2acb17f4c5`，版本 3.9.0。本报告对应从该提交建立的隔离工作区，以下修复在发布前只属于本地候选代码。

## 官方事实与协议

DeepSeek 于 2026-09-10 正式发布 V4.1 Flash，当前模型标识为 `deepseek-flash`。旧 `deepseek-v4-flash` 与 `deepseek-v4-flash-vision-exp` 对应模型已退役，请求暂时兼容路由至新的 Flash。V4 Pro 在 2026-09-14 后继续提供服务；不能使用非官方“即将转路由”的传言修改生产配置。[官方变更日志](https://api-docs.deepseek.com/updates/)

当前官方能力表明确：`deepseek-flash` 支持视觉输入，`deepseek-v4-pro` 不支持；两者均支持工具调用和 Responses 接口。[官方模型能力表](https://api-docs.deepseek.com/quick_start/pricing/)

图片通过 Chat Completions 的 `image_url` 内容块，或 Responses 的 `input_image` 内容块提交。支持 PNG、JPEG、GIF、WebP；本项目继续收紧为每轮最多 4 张、单张 1.5 MB。Chat 图像仅支持用户消息；Responses 也接受 developer 消息及工具输出图像，但本应用公开接口仅接受最后一条用户消息的本轮附件。[官方视觉指南](https://api-docs.deepseek.com/guides/vision/)

`GET /models` 只返回模型标识及所有者等基础资料，不提供可靠的视觉能力字段。因此不能因模型名称包含 vision、claude 等词就宣称可看图。实现使用已核验的官方映射，未知模型由管理员确认；能力来源与模型列表来源分开。[官方模型列表接口](https://api-docs.deepseek.com/api/list-models/)

DeepSeek Responses 是无状态接口，`previous_response_id`、`conversation`、`store` 等不承担服务端会话存储。应用必须自行保存并重放完整工具上下文；`store=false` 不能代替项目自己的输入输出留档。[官方 Responses 指南](https://api-docs.deepseek.com/guides/responses_api/)

Chat Completions 思考模式携带 tools 时，后续请求需要保留 `reasoning_content`，否则可能返回 400。此次图片功能沿用既有 Responses 工具循环，没有另建会丢失工具关联的新聊天链路。[官方思考模式指南](https://api-docs.deepseek.com/guides/thinking_mode/)

## 已复现的缺口与修复

| 发现 | 基线证据 | 本轮候选修复 |
| --- | --- | --- |
| 小菱/总调度模型分配保存后不生效 | 运行时未读取 chat / orchestrator 两个角色 | 新增统一模型解析，SSE 元数据与实际请求共用 |
| 子 Agent 只改 `_model` 仍会被显式 `api_config` 覆盖 | BaseAgent.call 和普通审查另建客户端 | 请求级子模型绑定；普通审查使用新配置副本，保留用户自有配置优先 |
| 新 Flash 被误标为不支持视觉，未知名称被误判 | 隔离复现 JSON 与红测 | 官方映射与能力来源，未知模型不猜测；旧拉取条目可按官方能力刷新 |
| 非视觉模型可分配到视觉角色 | 后端仅校验模型在列表中 | 保存分配时校验视觉能力；移除在用模型或关闭正在使用的视觉能力会返回明确错误 |
| 同步失败仍写入手填 fallback 模型 | 两项红测（success=false、success=true+fallback=true） | 只有真正拉取成功才合并，失败完整保留注册表与编辑 |
| 草稿端点拉取结果可能被分配给另一个已保存端点 | 配置与注册表无单独密钥绑定 | 注册表同步只使用已生效端点及凭据，修改后需先保存；普通模型列表草稿预览仍保留 |
| 图片暂停、重试后发出无效 `prism-asset://` | 隔离复现首轮 data、恢复轮 prism-asset | 按用户、界面、会话和运行归属重载原始图片；缺失时停止并明确要求重新上传 |
| 恢复图片任务可能回退到不支持图片的模型 | 恢复时未带视觉标志 | 运行时依据真实图片内容禁止非视觉降级，包含失败重试轮 |
| 超出 4 图静默丢弃；历史/助手消息可携图 | 原测试把静默截断当正确结果 | 超量或错误位置明确拒绝，图片只绑定当前最后一条用户消息 |
| 图片或模型配置损坏可能阻碍取消 | 取消也初始化模型与图片 | 取消只操作隔离的检查点，不依赖上游或图片 |
| 失败的模型分配返回成功码和空 data | 捕获 ValidationError 后返回 Resp(code=0) | 异常走统一 HTTP 400 处理，界面保留编辑并显示常驻错误 |

图片魔数伪造问题已交个性化子代理统一修复 `image_utils.py`，避免头像与小菱使用两套校验。

## 模型优先级与恢复边界

1. 普通文字：用户自己启用的 API 配置优先；否则读取管理员分配的 chat（小菱）、orchestrator（管理端）。子 Agent 优先读取 agent:<注册名> 独立覆盖，再继承 subagent 默认；未分配时保留系统原有默认层级。角色名单复用运行时注册中心，普通审查对应 code_reviewer；失效的历史覆盖在管理界面显示并允许清除。
2. 图片：使用管理员管理的平台视觉配置及其对应端点/凭据，不把平台模型名发送到用户自有端点。一次任务的全部工具轮、追问、审批与重试保持该图片模型和原始图片上下文。
3. 本轮完成、失败或取消都不会修改全局模型设置。同会话下一次纯文字任务重新解析默认配置。图片任务的历史文字结论继续保留；新文字轮不重复发送旧图片。
4. 资产读取按用户隔离，恢复额外校验 surface、session_key；取消保留审计记录。图片缺失或摘要不符时，不伪装已经看过图片，不静默降成纯文字成功。
5. 输入图片保存在资产表，输入文字、输出文字和工具 I/O 保存在检查点，以 run_id 关联。DeepSeek 当前视觉能力是图片理解，本次不宣称具备图片生成输出。

## 冻结后独立复核补充（2026-09-12）

独立复核发现先前测试没有覆盖所有独立执行入口，已重新打开实现范围，不能沿用此前“全部分配生效”的推断。

- 图片上下文压缩：先有文本历史、当前图片位于后续用户消息、经过 12 轮工具调用时，旧压缩算法会把图片消息改为文字摘要。两项红测复现漏图与预算超限未拒绝。现在图片消息纳入必保集合，预算无法容纳时抛 ContextBudgetError，保持检查点和原图资产；不把漏图请求发送上游。压缩策略标识升级为 `agent-transcript-v2-images`。
- 圆桌：请求开始用独立短数据库会话读取用户/平台 API 配置；通用、可靠性、性能、可维护性使用 `agent:code_reviewer`，安全角色使用 `agent:security_sentinel`，主持总结/问题抽取使用审查客户端。映射沿用现有注册角色，不创建虚拟 persona 键。
- 独立运维诊断：`OperationsAgent.diagnose` 消费 `agent:operations` → `subagent` → 平台默认。
- 沙箱四条实际入口：测试用例生成、部署协调、测试报告、语法修复都在 API Key 缺失判断前通过 `configure_subagent` 注入配置，管理员只配置数据库而 .env 未配置时也能执行。四种实现类未加入注册中心，因此继承现有 `subagent` 默认，不创建虚构注册名分配项。
- 独立进化：EvolutionAgent 请求实例通过统一 helper 注入 `agent:evolution` / 子 Agent 默认，再执行现有业务逻辑。
- 已发布工坊 Agent：动态发布版本继承 `subagent`；保持精确版本解析、权限和审计。
- 渗透 LLM：使用已存在安全哨兵角色 `agent:security_sentinel` / 子 Agent 默认，保留 8192 输出预算和 JSON 校验。
- 论坛辅助建议继承子 Agent 默认；黄金集评测使用审查者角色；旧管理员副驾驶规划消费 orchestrator，委派按真实注册名消费子 Agent 分配。
- 个人 API 配置始终优先于平台角色分配，独立实例注入不更改原 ApiConfig 或其它请求实例。timeout/retries/temperature 仅在有效配置明确提供时覆盖实例值。

新增 `test_model_independent_paths.py` 20 项：压缩保图/预算失败，运维命名分配，圆桌全局与个人配置，5 种独立实例×2来源，真实部署服务先注入配置再判断可用性，以及工坊/渗透真实服务入口×2来源。相关旧状态机/缓存测试仅修正隔离 fixture，未删除原断言。该文件及权限/生命周期组合 60 项全通过，另含各失败回退功能的 177 项相关回归全通过。生产真实模型、图片续跑与 UI 分配仍须主代理发布后核验。
