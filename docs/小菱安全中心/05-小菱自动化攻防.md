# 小菱自动化攻防（SecOps）

> 目标：让管理小菱能**自己**完成「感知 → 研判 → 处置 → 验证」的攻防闭环，
> 而不是把一堆扫描器塞给她。所有动作复用平台已有的运维执行器与渗透流水线，
> 安全中心只做编排、约束与留痕。

## 1. 五个环节各自落在哪

| 环节 | 实现 | 数据来源 |
| --- | --- | --- |
| 感知 | `ops_service.execute` 的固定白名单动作 | `ssh_login_events`、`nginx_attack_events`、`flytrap_attack_events`、`db_threat_signals`、`certificate_status`、`security_surface_audit`、`security_traffic_summary` |
| 研判 | `secops_service.threat_digest` | 按来源 IP 聚合：命中次数、命中传感器数、攻击类型、地理归属，输出 `critical/high/medium/low` 与 `block/watch` 建议 |
| 处置 | `secops_service.apply_block` / `release_block` | 走 `security_block_configure` + `security_block_apply_anomalies` / `security_block_release` |
| 验证 | `secops_service.baseline_check` | 文档暴露、安全响应头、TLS 版本与证书、攻击面、备份审计 |
| 授权攻 | `secops_service.start_authorized_pentest` | 只驱动**已授权且在时间窗内**的渗透委托 |

研判严重度口径：**≥3 个传感器同时命中，或窗口内 ≥20 次命中 → critical**；
2 个传感器且 ≥4 次 → high；≥3 次 → medium；其余 low。这样"一个来源被 Nginx、SSH、
蜜罐同时记录"才会被抓成 critical，避免单源噪音触发封禁。

## 2. 小菱能自己调用的工具

登记在 `admin_capability_registry`（8 条），并通过小菱安全策略字段 `security_ops_tools`
穿过"禁止改生产配置 / 禁止外带"的一刀切——但仍受**停机开关**与**单轮/每小时预算**约束：

| 工具 | 风险 | 说明 |
| --- | --- | --- |
| `secops.threat_digest` | read | 多源攻击研判 |
| `secops.surface_audit` | read | 自身暴露面盘点 |
| `secops.block_candidates` | read | 自动封禁候选 |
| `secops.baseline_check` | read | 自身安全基线 |
| `secops.patrol_status` | read | 巡检状态 |
| `secops.block_apply` | critical | 封禁（超管 + confirm）|
| `secops.block_release` | critical | 解封 |
| `secops.pentest_start` | critical | 启动已授权渗透 |

默认 `security_ops_tools` **只含 5 个只读工具**：封禁/解封/启动渗透属于状态变更，
要放行必须管理员显式把它们加进策略——这是"自动化"和"无人把关"之间的分界线。

## 3. 无人值守巡检

`secops_patrol_enabled`（默认开）：挂在 JARVIS 巡逻循环上，每轮跑一次
`threat_digest + block_candidates`，有异常就写 `secops.patrol` 审计 + 生成 `secops.patrol` 告警；
没有告警条目时也照常跑（不依赖 JARVIS 的 brief）。

`secops_auto_block_enabled`（默认**关**）：打开后也只处理「critical 且不在 IP 白名单」的来源，
每轮最多 5 个，封禁 1 小时，全部留痕。打开方式：

```bash
# deploy/.env
SECOPS_AUTO_BLOCK_ENABLED=true
```

## 4. 配置项

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `SECOPS_PATROL_ENABLED` | `true` | 定时巡检开关 |
| `SECOPS_AUTO_BLOCK_ENABLED` | `false` | 自动封禁开关（每轮最多 5 个） |
| `SECOPS_PUBLIC_BASE_URL` | 空 | 基线核查探测的自有地址，如 `https://lijiadong.cn`；空则跳过网络探测 |
| `SECOPS_ASSET_HOSTS` | `[]` | 允许作为渗透目标的**自有**主机名；为空时拒绝任何指向外部地址的委托 |

## 5. 安全边界（红线写在代码里）

1. **不实现攻击载荷**：本模块不含扫描器、exploit、字典；"攻"只驱动既有渗透流水线。
2. **目标受限**：`start_authorized_pentest` 要求委托状态 ∈ `authorized/running`、时间窗有效、
   且目标主机在 `SECOPS_ASSET_HOSTS` 内，否则 `40344/40345` 拒绝。
3. **处置要人**：`apply_block` / `release_block` 只允许唯一超管 + `confirm=true`；
   拒绝封禁回环/未指定/组播地址，也拒绝封禁小菱安全中心 IP 白名单里的地址（防止封掉自家出口）。
4. **宿主机动作单一路径**：全部经 `ops_service.execute(source="security_center")`，
   沿用既有的动作白名单与超级管理员校验，应用进程不直连主机。
5. **全量留痕**：每个动作写 `secops.*` 审计（脱敏后落库），巡检另写告警。

## 6. 上线后怎么用

```bash
# 研判（小菱也能自己调）
curl -s -H "Authorization: Bearer $TOKEN" https://lijiadong.cn/api/admin/secops/digest?hours=24 | jq '.data.totals'
# 自身基线
curl -s -H "Authorization: Bearer $TOKEN" https://lijiadong.cn/api/admin/secops/baseline | jq '.data.failed'
# 封禁（需超管）
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"ip":"45.135.228.155","reason":"暴力破解","confirm":true}' \
  https://lijiadong.cn/api/admin/secops/block
```

管理台位置：**运行与审计中心 → 小菱安全 → 安全运营（自动化攻防）**
（攻击源研判表、Top 来源、基线整改、封禁按钮、巡检状态、授权攻说明）。

## 7. 生产上线与实测（2026-11-17）

发布链路：4.1.61（能力上线）→ 4.1.62（守卫表述修正）→ 4.1.63（巡检来源修正）→
4.1.64（传感器真实形态解析）→ 4.1.65（别把自己的登录当攻击源）。
生产现役 `VERSION=4.1.65`，`release=3c7b74e8dbd3eea3b3eb74ad423f67c0226a98e9`。

### 7.1 上线过程抓到并修掉的三个"自动化陷阱"

| 版本 | 症状（生产日志/接口实测） | 根因 | 修法 |
| --- | --- | --- | --- |
| 4.1.63 | 巡检日志：`db_threat_signals 失败: 无交互调度只允许运维只读动作`、`security_block_candidates 失败: 自动封禁只能由固定安全巡检或高级管理员安全中心调用` | 来源标识写死 `security_center`；执行器对调度身份要求 `scheduler` | 按身份选来源：`actor=None → scheduler` |
| 4.1.64 | 研判 `totals.sources = 0`，而同期 SSH 失败 13 次 | 传感器返回的是聚合形态（`failed_by_ip/by_ip/peers`），解析器只找 `events` 列表 | 新增 `_unwrap_payload` + `_extract_events`，按每种传感器的真实形状解析，并补 `security_traffic_summary` |
| 4.1.65 | `183.6.24.15`（管理员自己的广州出口，在白名单里）被判 `critical → block` | ① 把 `accepted_by_ip`（成功登录）算成攻击命中；② 没排除白名单来源 | 只统计失败尝试；白名单来源标 `allowlisted=true`、降级、不给封禁建议 |

这三条都不是"写错一行"，而是**只有真跑起来才会暴露**的自动化风险：第一条让巡检静默降级、
第二条让攻防看不见、第三条会让自动封禁把自己锁在门外。
