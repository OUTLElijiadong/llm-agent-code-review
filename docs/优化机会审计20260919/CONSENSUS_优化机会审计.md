# Prism 继续优化机会审计共识

## 1. 优先级结论

| 优先级 | 优化项 | 结论 | 依据 |
| --- | --- | --- | --- |
| P0 | 会话事实源与 GET 副作用 | 必须先治理 | 管理端旧会话表仍被写入；Agent 列表 GET 会归档并提交；两套事实源会造成历史不一致 |
| P0 | 10 条上限与归档历史 | 必须先定合同 | 当前只限制活跃列表，运行中会话受保护；归档数据没有用户可检索入口 |
| P1 | `/support` 能力注册收敛 | 必须收敛 | `/support/maintenance` 与 `/support/feedback` 仍是两组能力和页面指南条目 |
| P1 | RBAC 判定集中化 | 必须治理 | Mesh、Responses 和其他服务各自兼容旧 role 字段与 RBAC，异常处理口径不一致 |
| P1 | 输入边界统一矩阵 | 必须补齐 | 部分模型没有 `extra=forbid`、统一控制字符策略或嵌套负载大小上限 |
| P1 | 自定义 Agent 范围 | 必须确认并测试 | 发布 Agent 查询按全局 published 返回，是否应按项目/所有者隔离未形成合同 |
| P1 | 初始化 SQL/ORM 漂移 | 必须修正 | ORM 密码为 `String(60)`，MySQL 初始化 SQL 仍为 `VARCHAR(255)` |
| P2 | DeepSeek 1m 真实性与续跑 | 独立依赖 | 1m 只是配置上限，仍需供应商能力探测、token 预算、分片续跑和成本/失败账本 |
| P2 | 运行态性能与可观测性 | 持续优化 | Agent 列表逐会话查运行状态，确认锁为进程内锁，缺少跨 worker 的统一指标闭环 |
| P2 | 外部安全能力 | 独立里程碑 | 平台上传项目 CodeQL worker、Codex Security 深度扫描不能由仓库 CI 或单次静态检查替代 |

## 2. 统一决策

- 以 Agent Responses/Mesh 的账号、会话面、会话键和运行账本作为新会话主事实源；旧管理员会话表只能作为迁移兼容源，不能继续产生第二套历史。
- GET/列表接口必须只读。归档、标题更新、清理等写操作放到创建/心跳/后台任务或显式 POST，并可观测。
- “最多 10 条”按用户确认解释为**同一账号跨 user/admin surface 合计最多 10 条活动会话**。超限只归档最旧的空闲会话，不物理删除消息、运行或审计账本；10 条都处于运行中、待审批或待输入时，第 11 条创建必须返回 409。
- 归档历史必须提供账号隔离的分页/检索和显式恢复入口；恢复同样执行 10 条硬上限并优先归档最旧空闲会话。
- `/support` 是唯一导航、搜索和能力描述入口；旧反馈/维修地址只保留兼容跳转或内部适配，不再作为第二个页面事实源。
- 使用一个集中授权判定服务，RBAC 查询异常 fail-closed 并写入可观测日志；不通过进程内锁承担跨 worker 幂等。
- 已发布自定义 Agent 的正式语义为“管理员审批后的平台级目录”；列表、搜索、派发和团队组装必须复用同一发布谓词，普通调用者不返回内部 `owner_id`。
- 输入防线采用“结构化字段严格 Schema + 文本字段统一规范化/控制字符策略 + 动态攻击字典”三层，不对所有文本做盲目 HTML 清洗。
- DeepSeek 的上下文参数必须由启动探测和真实请求回执证明；遇到截断要续跑并保留部分结果，不能用“1m 配置存在”作为完成凭证。

## 3. 范围限制

本文件不授权删除测试账号、历史消息、项目或审计数据；也不授权在缺少备份、回滚和生产验收证据时直接改生产参数。CodeQL 上传项目扫描和 DeepSeek 真实 1m 能力仍以外部许可、额度和真实回执为完成门槛，不能用本地代码或配置替代。
