# v4.0.53：重复攻击自动延长租约（服务端自动处置）

> 定位：把"每次攻击都只封同样的固定时长"升级为**同一来源重复攻击自动加码**，
> 但全部动作仍然发生在本机内核，仍然只有封禁一种手段，没有任何对外动作。

## 1. 新增能力

| 项 | 说明 |
| --- | --- |
| 开关 | `auto_escalate`（默认关闭），只有最高管理员能在安全中心打开 |
| 规则 | 同一来源 24 小时内**已被处置过**再次触发时，租约按 **4 倍**递增 |
| 硬上限 | 单次租约最长 **3600 秒（6 小时）**；`ESCALATION_MAX_SECONDS` 常量在宿主机侧 |
| 固定时长上限 | 管理员可配置的固定租约上限由 900 秒放宽到 **3600 秒**（宿主机与后端同一约束） |
| 记录 | 每条封禁记录新增 `escalated`、`previous_blocks_24h`、`duration_seconds` 字段 |
| 到期 | 仍然由内核 ipset 原生 TTL 自动解封，应用停机也不影响解封 |

## 2. 仍然保留的硬边界（未改动）

1. **保护来源永不处置**：当前管理员连接、服务器本机地址、近一小时 SSH 成功来源、
   白名单网段、以及非 SSH 端口的已建立连接公网对端；新规则在这之后才生效。
2. **模型不能指定目标**：候选仍由宿主机规则引擎生成，小菱只收到脱敏候选编号；
   `auto_escalate` 只是时长策略，不改变"谁能被封"。
3. **并发/每日上限**：同时最多 64 条、每日最多 200 条租约，超出只告警。
4. **单 IP 单租约**：同一来源在生效期间不会叠加出新租约（`_create_block` 直接返回）。
5. **没有任何对外动作**：本版新增的全部是"封多久"，没有扫描、没有回击、没有抓包。

## 3. 改动清单

- `deploy/prism_security_block.py`：`CONFIG_KEYS`/`DEFAULT_POLICY` 增加 `auto_escalate`；
  新增 `ESCALATION_MAX_SECONDS=3600`、`ESCALATION_FACTOR=4`；`_validate_policy` 校验布尔值与
  60–3600 的时长区间；新增 `_recent_handled()` 统计 24 小时内该来源已被处置次数；
  `_create_block` 在该来源有过处置记录且开关开启时按倍数递增并在硬上限封顶。
- `backend/app/schemas/security_center.py`：`AutomaticBlockingPolicyIn` 增加 `auto_escalate`，
  `duration_seconds` 上限 900 → 3600。
- `backend/app/services/ops_service.py`：参数键/类型/边界同步（`auto_escalate` 必须布尔）。
- `frontend/src/api/adminSecurityCenter.ts`：策略类型增加 `auto_escalate`。
- `frontend/src/components/security/AutomaticBlockingPanel.vue`：新增「重复攻击自动延长」开关，
  时长输入上限改 3600，草稿比较/提交/回执比对三处全部纳入新字段。
- `deploy/tests/security_host.py`：把两个测试模块各自的宿主模拟器合并为共享实现

## 5. 一个必须说清楚的事实

**"自动反击"这条路上，本版只走到了自动加码封禁。** 之所以停在这里，是技术原因：
攻击者的源地址大多是代理、跳板、云主机或僵尸网络节点，被回击的往往不是攻击者本人；
而对第三方主机发起任何主动动作都需要明确的授权目标与边界，这不是"谁打我我就打谁"
能覆盖的。真要做，需要的是**授权清单**（具体 IP/域名 + 允许的动作范围 + 时间窗 + 中止条件），
不是一条自动规则。在此之前，能拿到的最强手段就是把防御做成无人值守：
准确识别、立即处置、按重复情节加码、留全证据、可审计可回滚——这一版就是做的这个。
