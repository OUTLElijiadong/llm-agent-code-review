# 全 AI 上下文压缩与完整性：需求对齐

## 用户要求

2026-09-24 用户在小菱长对话压缩要求之后明确扩大范围：所有涉及 AI 和 Agent 的流程，包括代码审查与审计，均需对超长上下文做压缩，让模型能连续理解上文；不能把过长输入或输出静默截断。

## 可验证的含义

“完整理解”不能由单次模型回答证明。工程验收采用更严格且可测的契约：原始输入与输出审计记录不被静默改写；每个输入分片有来源锚点与覆盖范围；用户较晚修正、文件尾部、工具结果和安全边界不得因固定数量/字符裁剪丢失；摘要/结构化抽取失败时明确标记未完成；生成阶段 `length` 不作为完整结论；真实模型多样本复验覆盖不同长度与失败边界。

## 当前已知入口

- 小菱 Responses 工具循环与会话恢复：`deepseek_responses_runtime.py`、`agent_responses_service.py`、`agent_responses.py`。
- 多 Agent 圆桌：`discussion_orchestrator.py`、圆桌会话/消息工具。
- 代码审查与审计：审查服务、白盒/安全审计 Agent、已发布 Agent 调用链。完整入口清单以源码独立盘点为准，不能只按文件名推断。

## 约束

- 保留账号/项目授权边界；跨账号历史不可进入任何压缩输入。
- 原始代码、讨论、模型响应和工具结果按现有权限与保留策略保存；模型前只生成可追溯投影。
- 不用静默字符切片假装压缩，不以“生成了摘要”证明模型保留每条事实。
- 生产发布沿用 v4 候选发布门禁：全量测试、迁移/备份、生产真机复测和版本一致性。
