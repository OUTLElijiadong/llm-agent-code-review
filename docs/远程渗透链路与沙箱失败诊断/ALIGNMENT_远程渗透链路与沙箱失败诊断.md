# 对齐：远程渗透链路与沙箱失败诊断

## 原始需求

- 核验黑盒/白盒任务失败和报告不可见的原因；先复现，再修复并重复原场景、增加样本。
- 项目沙箱与远程网站采用清晰分开的任务、授权和报告链路。
- 远程网站不要求选择本地项目，仍呈现完整七阶段进度。
- 不削弱报告账号隔离；异常需显示已保存的真实失败原因。

## 项目现状与已证实事实

- 现有 `PentestEngagement`、阶段、发现和 `ReviewTask` 均绑定 `project_id`，不能安全地把该字段改为可空或伪造项目。
- 现有项目流程中的远程 URL 只记录为范围说明；探测器仍指向项目沙箱。
- 授权队列按全局 `pentest:authorize` 展示，但批准服务额外要求批准人有目标项目执行角色，造成可见操作返回 403/404 的权限错配。
- 截图中普通账号访问其他账号的报告被拒绝，符合当前报告 ACL；不得为解决显示问题而放宽到跨账号读取。
- 已固定的黑盒失败样本为 404 根路径、无业务路由；这应报告为路由覆盖失败，而不能宣称漏洞验证成功。

## 范围边界

- 修复项目沙箱授权队列权限一致性、失败证据持久化/展示和前端流程提示。
- 设计并实现独立远程任务、独立授权快照、阶段记录和报告 ACL。
- 远程链路仅允许固定的 HTTPS 公网主机、少量只读请求与安全配置检查；漏洞利用和后渗透仅作证据复核/桌面推演，不发送利用载荷、不写入目标。
- 不访问真实外部目标进行测试，不更改生产数据或生产配置。
- 生产 Safari 真实点击验收受当前 Computer Use 域名策略阻止；只能在本地自动化和 API 层验收，不能宣称已完成生产点击验收。

## 验收标准

1. 全局授权人无需成为项目成员即可批准申请；仅有项目角色而没有全局授权权限仍被拒绝。
2. 报告发起人可查看自己的报告；非发起普通账号看不到正文、评分、发现统计；管理员按既有规则可查看。
3. 黑盒 404、模型截断、报告保存错误均显示可追溯原因，并保留真实执行范围，不伪报完成。
4. 远程站点有独立的七阶段任务进度、独立报告记录与独立账号隔离；创建远程任务无需项目 ID。
5. 远程任务的授权内容绑定规范化目标与范围摘要，审批人不同于申请人；启动时再次校验范围、授权时间窗和开关。
6. 自动化测试只使用本地 HTTP fixture/mock，不向公网发送探测请求。

## 未覆盖项

- 生产 Safari 点击、真实生产远程目标探测与浏览器截图无法由当前工具完成；均不得记作已验收。
