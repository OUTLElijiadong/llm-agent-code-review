# 共识：远程渗透链路与沙箱失败诊断

## 明确需求

项目沙箱渗透保持原有项目/沙箱执行边界。远程网站作为独立业务对象，不要求选择本地项目；必须有自己的任务、审批、七阶段进度和报告记录。远程测试不可使用伪造 `project_id`，也不可复用项目报告 ACL 的宽松替代。

## 七阶段及覆盖语义

| 阶段 | 远程链路执行方式 |
|---|---|
| 前期交互 | 资产归属依据、规范化目标、检测范围、排除项、规则版本和授权时间窗入快照；独立审批 |
| 情报收集 | 固定已解析的公网 IP 与 HTTPS SNI，仅对已授权根路径发出一次只读 GET，记录状态码和响应头；不读取响应正文 |
| 威胁建模 | 根据已观察的响应配置形成有限假设，不调用模型、不推断未观察事实 |
| 漏洞探测 | 只检查安全响应头是否存在；不进行凭据尝试、注入载荷、路径枚举或压力测试 |
| 受控验证 | 最多再发出一次相同的只读 GET，复核配置观察；不属于漏洞利用验证 |
| 后渗透推演 | 离线桌面推演，不访问目标、不执行命令、不持久化 |
| 报告输出 | 单独保存远程报告，披露方法、请求上限、覆盖边界与证据链 |

“七阶段完整”表示七个阶段均有状态、输入/输出摘要和终态；不等同于全面主动利用测试。页面与报告必须说明此范围。根路径返回 404、重定向或其他非 2xx 时，报告覆盖状态为“部分”，不能把错误页响应头推广为业务应用结论。

## 技术约束

- 新增独立远程任务、阶段、发现、报告模型和迁移；既有项目表不改空值语义。
- 外网请求必须 HTTPS、限制 443、拒绝凭据/私网/回环/链路本地地址，DNS 解析后固定首轮公网 IP；第二次请求若解析 IP 不一致则在发 HTTP 前失败关闭。禁用重定向、代理环境变量、Cookie 和认证头。响应正文不读不存，超时和请求次数均设硬上限。
- 独立审批只需要 `pentest:authorize`；不会授予项目成员权限、代码读取权限或远程报告读取权限。
- 远程报告和七阶段明细/证据只对任务发起账号和管理员开放。仅有授权权限的审批人只访问申请范围和任务状态；前端不得把 API 未提供的阶段默认渲染为“待执行”。
- 授权时间窗长度纳入审批快照；审批时展示目标、申请人声明、补充范围、规则版本和时长，并要求二次确认。申请人的授权声明不等于平台核验。
- 现有项目链路 `pentest:authorize` 不再叠加项目执行角色；实际启动仍由发起人的项目执行授权二次校验。
- 公网网络请求可由配置关闭；测试以本地 mock 证明输入拒绝、固定 IP 与上限，禁止单测访问真实域名。

## 异常策略

- 目标解析、TLS、响应超时或校验失败：阶段失败并记录安全错误类别，不保存敏感响应正文。
- 授权摘要变化、审批人自批、授权过期、权限撤销或任务取消：拒绝启动/立即停止后续阶段。
- 模型或报告持久化失败：任务标失败并显示服务端保存的失败码；不得显示旧报告或把空报告当成功。

## 验收

按 ALIGNMENT 的 6 项验收标准执行。代码、迁移、本地回归均通过后再判断是否可进入生产发布门；当前工具禁止对生产站点进行真实浏览器点击，因此生产浏览器项必须保留为未验收。
