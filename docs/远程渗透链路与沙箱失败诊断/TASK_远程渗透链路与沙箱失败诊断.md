# 任务：远程渗透链路与沙箱失败诊断

## 输入契约

- 已确认远程网站要独立完整七阶段链路，不需要项目 ID。
- 当前项目 Pentest 权限、报告权限、沙箱执行器、远程 URL 探测器和数据库迁移链可用。
- 测试仅使用本地 SQLite、mock HTTP，不访问生产或真实外部目标。

## 子任务

1. **复现与诊断**：重放报告中 404 根路由/覆盖不足；复现报告失败原因未保存、授权审批按钮权限错配和报告账号隔离。
2. **项目链路修复**：区分全局授权审批与项目执行权限；完善 404、截断和报告保存失败的证据与 UI 显示。
3. **远程独立域**：添加独立模型/迁移、固定安全 URL 校验、授权状态机、七阶段记录、owner/admin 报告 ACL。
4. **前端**：独立远程任务创建、队列、详情、报告页面；项目沙箱入口明确远程 URL 不会由该流程探测。
5. **验证**：单元/API/前端测试；目标校验和账号隔离负向测试；阶段间取消/权限撤销、重启恢复、重复启动/审批、DNS 混合解析及首轮与复核 IP 变化、404 覆盖样本。
6. **交付文档**：更新 ACCEPTANCE、FINAL、TODO；生产浏览器与发布状态需有独立证据，不能从本地测试推断。

## 原子验收

- 审批人仅凭全局 `pentest:authorize` 可核准他人 pending 项目申请；无该全局权限时即使是项目成员也失败。
- 报告成功/失败/保存异常均有区分状态与稳定原因；跨账号报告指标被隐藏。
- 远程创建不接受 project_id；批准前不能启动；启动前拒绝 scope digest 变更/过期授权。
- 审批快照包括授权时间窗；重复审批和重复启动只有一个请求能成功认领。
- URL 解析绕过、私网 DNS、重定向、HTTP、非标准端口、URL 认证信息均被拒绝。
- 两次远程请求间 DNS 解析到不同公网 IP 时，第二次请求在网络连接前被拒绝并留下部分报告。
- 审批账号不能看到“0/7 待执行”伪进度，且不读取报告或阶段证据。
- 测试无公网流量；七阶段有独立阶段行和报告行。
- 非 2xx（特别是根路径 404）只生成部分覆盖报告，不把错误页响应头标成完整应用审计。
- 前端测试通过，构建通过；生产浏览器点击或部署需要单独具备的验收环境与证据。
