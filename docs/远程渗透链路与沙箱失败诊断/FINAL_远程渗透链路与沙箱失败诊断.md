# 最终交付：远程渗透链路与沙箱失败诊断

## 交付结果

项目沙箱与远程网站现在使用分开的任务、授权、阶段和报告链路。项目沙箱保留项目权限；全局渗透授权人审批项目申请时不再被额外的项目成员条件挡住，真正启动仍需要申请人具备项目执行权限。黑盒失败与报告持久化失败现在保留可追踪状态，404 等非成功响应不会伪装成完整覆盖。

远程网站模式无需本地项目，拥有独立申请、独立授权快照、七阶段记录、列表、详情和报告。报告仍只对任务所有者和管理员开放；授权人只查看任务状态与授权范围。安全探测固定为 HTTPS 公网目标的最多两次根路径只读 GET，不跟随重定向、不读取响应正文；解析地址发生变化会在连接前拒绝。七阶段是工作流完整，不表示全面漏洞利用覆盖。

## 主要改动

- 新增远程任务模型、schema、服务、API、迁移及远程任务前端页面。
- 修正项目授权审批与项目执行权限耦合导致的审批失败。
- 修正并行检测任务的排队计时，使超时从工作实际开始时计算。
- 把黑盒覆盖、执行失败、报告保存失败分开记录并在有权详情中展示真实原因。
- 保持项目与远程报告 ACL；无权账号不获得报告正文、评分或问题统计。
- 增加授权快照、DNS 固定解析复核、取消/权限/有效期检查及失败关闭处理。
