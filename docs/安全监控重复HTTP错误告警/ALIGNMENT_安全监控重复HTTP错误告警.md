# 安全监控重复 HTTP 错误告警需求对齐

## 原始需求

用户表示已使用临时注册码创建普通账号用于自有环境的安全验证，并明确要求“只要监听”，同时监听小菱；继续核查、检查和优化系统。

## 项目与任务特性

- 系统已有每 5 分钟运行的 `security_monitor`，由运维执行器只读收集 Nginx、SSH、备份与状态信息。
- 生产部署在独立服务器；运行状态必须以真实容器、当前 release、探针及公网只读响应为准。
- 本任务的对象是已记录的应用入口访问日志；400/403/444 只表示 HTTP 响应状态，不足以证明越权成功或漏洞可利用。

## 任务边界

本任务只读取已有日志并新增重复 HTTP 错误的被动告警，不主动发起请求，不封禁、不反击、不对来源 IP 做外部溯源，不更改账号或生产数据。发现的样本应区分用户授权验证流量与无法归因的真实异常；IP/账号标识不进入公开仓库证据。

## 复现结论

生产过去一小时出现同一来源 39 条 Nginx HTTP 400/403 记录。旧逻辑只评估 `recent` 中的代理 CONNECT 与 TLS 乱码，没有重复 HTTP 错误规则；因此该样本未生成 Nginx 告警。SSH 失败数命中 SSH 白名单而跳过 SSH 爆破告警，这是独立规则，不应豁免该来源的 HTTP 行为。

## 验收边界

1. 同 IP 在 1 小时内聚合 HTTP 400/403/444；默认阈值 20，可配置。
2. 聚合使用完整采集窗口，而非最多 300 条的展示用 `recent`。
3. SSH 白名单不影响 Nginx 告警；重复告警按来源去重。
4. 达阈值产生 `scanner` warning 和管理员提示，不执行阻断、反制或外部 IP 查询。
5. 如执行器达到 30,000 行采集上限，告警必须标明计数为下界。
6. 代码、运维执行器、生产运行 SHA 与公网 buildInfo 对齐后，才能记录为已发布。

## 待核事项

执行器每轮最多读取 30,000 行；达到上限时只可报告观察下界，不得宣称完整窗口。账号主体与来源 IP 的绑定无法单凭日志独立证明。生产新告警效果须以部署后的下一轮调度数据复核。
