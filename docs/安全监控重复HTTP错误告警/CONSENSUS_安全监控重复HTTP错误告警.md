# 安全监控重复 HTTP 错误告警需求共识

## 明确需求

为现有被动安全监控补齐同一来源反复触发 Nginx HTTP 400、403、444 的窗口聚合告警，使“采集任务成功”不再掩盖规则覆盖缺口。

## 实现约束

- 窗口沿用安全监控的 `since_hours`，默认调度窗口 1 小时；阈值设置 `security_nginx_failure_threshold`，默认 20，限制 1–5000。
- 运维执行器从完整的采集输出聚合符合阈值的来源；`recent` 继续只承担页面/诊断样本展示。
- `scanner` warning 不进入需要第三方情报服务的归因类别。
- 不自动防火墙封禁，不反向连接来源，不触碰注册用户内容。
- 采集器有 30,000 行上限；达到上限时通过 `source_truncated` 标记，并在告警中明确计数是下界。

## 验收标准

阈值下方无告警；等于阈值触发；混合状态码正确累计；近期样本不完整不影响聚合；达到采集行上限需标出下界；白名单来源仍可触发 Nginx 告警；重跑去重且刷新 `last_seen`；正常数据源失败/降级语义不回归；生产运行 SHA、后台构建信息和 HTTPS 健康响应一致。
