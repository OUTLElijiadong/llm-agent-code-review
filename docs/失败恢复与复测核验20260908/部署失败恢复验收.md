# 部署失败恢复验收

## 实际缺陷与修复

备份命令替换中的 ERR 继承会让子 Shell 和主 Shell重复处理故障并提前解锁；显式fatal原本也可能绕过ERR。现在由主事务处理一次，EXIT覆盖显式退出，锁仅释放一次。独立代理进一步真实注入复现了第二次rmdir可移除下一持有者锁、assets退出码43被改成1、回滚成功后末尾ps失败被误报回滚失败，均已修正。

发布失败记录阶段、原始退出码和迁移是否已尝试。切换前停止保留旧应用；切换后按上一镜像完整回滚；回滚失败明确失败与人工核查，保留pending。应用回滚不自动降级或恢复数据库。已成功写账本后的容器列表读取失败仅警告，不再次回滚。

运维内存/磁盘采集失败曾显示“-1%达到临界阈值”；现明确采集失败、检查权限与重试。门禁仍关闭，未将无法采集当作正常容量。

## 测试范围

`deploy/tests/deploy_failure_cases.sh`用真实deploy.sh、rollback.sh和common.sh执行13个隔离场景；Docker、curl、Git等外部依赖由命令替身控制，不做生产故障注入。覆盖备份、备份验证、后端构建、迁移、后端切换/健康/冒烟、前端构建/切换/assets/健康、HTTPS、回滚失败。断言每个精确退出码、当前/上一/pending状态、锁释放、恢复后完整旧镜像，禁止数据库恢复或降级命令。

完整部署/运维隔离套件通过，含新增采集失败门禁。macOS沙箱曾阻止sysctl读取，使旧ops_consistent测试采集值为-1而失败；允许本地只读系统统计后通过，未改变容量阈值使测试通过。

独立子代理另有3项准确旧版反例、6项修复后边界测试；包括新锁持有者保护、显式fatal、迁移验证失败、发布/回滚账本提交后ps失败。证据与实现指纹见证据目录。

这些隔离回滚证据不能替代生产发布后的实际版本、健康、备份和应用数据验收。
