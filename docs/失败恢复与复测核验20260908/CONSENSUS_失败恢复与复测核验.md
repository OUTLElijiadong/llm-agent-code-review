# 失败恢复与复测核验：验收约定

1. 缺失、软删除、跨主体不可见的审查任务统一任务级404反馈，不泄露是否存在；401/403和服务异常保持原契约。
2. 读取失败保留可继续使用的已有数据，并明确失败和重试；跨实体或失去权限时清除旧实体数据。
3. 创建请求进行中禁止重复提交；辅助分析失败保留用户输入；读取结果按最新请求生效。
4. Agent部分读取失败可降级，不能失败后报成功，也不能把加载失败显示为没有数据。
5. 登录限流保留5次/60秒策略；修正剩余亚秒显示与窗口延长问题，覆盖同窗正确密码、跨窗和并发。
6. 部署故障按切换前停止、切换后应用回滚、回滚失败分别反馈，保留真实退出码和数据库边界。
7. 每项保留修前复现、修后回归与独立复核；源码函数注入、隔离HTTP、生产API、浏览器点击分别计数。原未测矩阵不能自动转通过。

8. 新复现的Redis故障冷实例绕过：仅配置Redis的登录准入故障关闭，返回503和有界重试时间，5秒后探测恢复；无Redis开发模式及普通业务GET保持原行为。认证已提交会话版本而结算失败时不返回JWT，不逆向写回会话版本，并明确审计失败。
