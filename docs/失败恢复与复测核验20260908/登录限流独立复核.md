本地隔离 Redis 的 39 项后端回归全部通过，包含 5 项真实 Lua；登录组件与 HTTP 拦截器 32 项全部通过，无跳过。首次默认沙箱运行因 Docker socket 不可访问产生 5 个 setup error、其余 34 通过；获本地 Docker 准入后重新执行才得到 39 项通过。原始失败文件保留，没有把环境错误算成应用缺陷或隐去。

独立确认的行为：

- Redis PTTL 只剩亚秒时返回至少 1 秒，准入与失败结算不会将原窗口重置为 60 秒；只有存在但无过期时间的 key 才补原窗口。
- 配置 Redis 后，客户端初始化、Lua 执行、结果解析与 reset 故障都关闭登录准入；没有从冷实例空内存重新取得名额。每实例锁串行化探测，5 秒退避结束后读取原共享桶。
- 准入前故障不会调用密码认证。认证已提交后结算故障不返回 JWT；原单设备会话版本已递增，审计明确这一结果，不把事务说成已回滚。
- Login 503 原因保留，倒计时只恢复手动提交按钮，不自动重发密码。原认证会话读取不依赖此次登录故障保护；连接日志不含 Redis URL 或原始连接异常。

此结论只覆盖本轮限流修改。真实 Lua 来自本地无网络容器和随机测试 key，未调用生产登录或写生产 Redis；不能据此推断用户所述生产现象唯一由 Redis 故障造成。固定窗口跨过期点后恢复，与仍在同一窗口内绕过限流是不同情况，现有测试已分别验证。
