# 临时定义与运行时独立复核

日期：2026-09-20。复核者：前端子代理，未修改被审后端源码。阶段：本地交叉复核，不能替代真实模型与生产验收。

完整阅读 temporary_agent_runtime.py、TemporaryAgentDefinition/成员 schema、agent_team_service 的创建与 resolve_temporary_member/require_active_task_lease，以及 dispatcher 临时分支，并阅读相关定向用例。独立重跑两组测试得到 49 passed、0 failed，退出码 0；唯一警告为现有 passlib crypt 弃用提示。证据：[JUnit XML](证据/前端/临时运行时独立复验.xml)。

## 核对结果

1. 定义确实由本次工具/API 输入 purpose、instructions 生成，严格禁止额外字段、模型端点或权限覆盖。temporary 地址必须匹配 member_key，不能绑定永久模板。创建时只写团队成员审计快照与校验和，没有写永久 Agent/工坊资产。
2. 执行只从数据库冻结定义取值，不信任消息携带的定义覆盖；需要 owner_user_id、团队任务归属、成员 ID/地址、非终态团队、running 任务以及未过期有效租约。普通 mesh 投递不能直接执行 temporary 成员。管理员也受当前账号团队归属限制。
3. 每次实例化独立 BaseAgent 并配置当前账号模型，实际进入 call_json，不是把文本角色名当执行结果。没有工具执行器、网络或写入能力；正式报告仍由内置审查链负责。只读输入复用现有项目/文件权限服务。
4. file_ids 明确限定 1—5 个、正整数、不重复且同项目。二进制先用元数据拒绝；项目默认只取最多5文件、单文件12000字符、总上下文60000字符，coverage 和 limitations 披露省略。模型输出必须满足结构、有效来源 ID、文件/行号边界，失败不能冒充已完成。
5. 模型返回后结束旧只读事务并重新读取账号/权限/项目/已纳入文件归属。账号停用、聊天权限撤销、项目或文件访问撤销时不回传分析结果。用量仍保留当前账号审计；账本写入失败不能自动重复调用。
6. 前端以 kind=temporary 展示“本任务临时”，没有提供永久创建或编辑入口，与后端 team_only 和终态仅留审计的语义一致。

结论：本次阅读和49项独立测试未发现上述契约的阻断项。测试模型是替身，真实模型是否生成合规临时定义、真实并行运行与生产隔离必须由主控的端到端验收另行证明；不能将本页替代该证据。
