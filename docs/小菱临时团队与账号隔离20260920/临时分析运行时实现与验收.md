# 临时分析运行时实现与验收

## 已确认边界

临时成员由当前团队的职责定义创建独立分析实例，使用当前账号的既有模型配置和调用记账内核。定义仅当前账号、当前团队有效租约内可执行；定义、校验和与结果保留用于审计，不创建永久 Agent、版本或正式审查任务。主控负责团队归属和租约校验，本执行器负责模型输入、资料权限、输出证据与分析范围。

## 实现

- 复用 `BaseAgent`、`configure_subagent`、独立事务用量账本和现有项目/文件读取服务，无新增工具执行、网络浏览、数据库写入或审批旁路。
- 支持一般文本、单 `file_id`、1 至 5 个不重复的 `file_ids`，或项目中最多 5 个文件。`file_id` 与 `file_ids` 互斥；文件必须属于同一项目且当前账号有权读取。
- 每文件最多 12000 字符，传给模型的结构化用户上下文最多 60000 字符；任务输入最多 16000 字符、依赖最多 20 项且每项最多 12000 字符。超范围或省略均如实反映，不将有界分析称为正式全量审查。
- `coverage` 包含总文件数、纳入文件 ID 与数量、纳入字符数、省略文件数、跳过文件 ID、限额、截断与完整标记。完整标记只描述本次有界输入；结果始终同时返回 `execution_mode=analysis_only` 和 `formal_review=false`。
- 模型必须返回严格结构化结论、证据引用、事实/推断类型与局限。拒绝未知来源、未提供文件、片段外行号以及没有对应源码引用的文件发现。模型不能返回伪造的正式任务/报告字段。
- 模型调用结束后结束旧只读事务，重新加载账号、当前聊天/项目/文件权限与文件当前项目访问权。停用账号、撤权、文件移出原项目或删除时丢弃模型结论，不回传资料。
- 调用本身由原 BaseAgent 精确记账。HTTP 成功但结构合同无效时，更新原账本条目为失败，不添加重复调用；账本落地失败时禁止自动重发模型。

## 本地回归

初始运行时红测为 14 项中 7 失败、7 通过。新增运行期间撤权、引用和账本合同用例后，准确复现 9 失败、15 通过；实现修复后通过。最终运行时 37 项加独立团队/审计权限 9 项，共 46 通过、0 失败、0 跳过，Ruff 检查通过。另有真实调用内核返回非 JSON 的 1 失败、2 通过红测，确认原 HTTP 成功账本在解析失败后必须更新为失败，已回归通过。

证据：`证据/临时运行时回归摘要.json` 及对应 XML。单元测试中的 HTTP MockTransport 仅证明实际调用内核与账本集成，不冒充真实外部模型；真实模型结果另行保存。

## 二〇二六年九月二十三日最终模型验收

最新源码定向验证为运行时 38 项及独立团队权限边界 9 项，共 47 项通过、0 失败、0 跳过，Ruff 检查通过。新增长期保留的回归用例确认：没有文件定位的一般发现只能通过顶层 `findings` 单一出口汇总，不能因同时放入证据区而计数翻倍。

独立容器使用既有依赖镜像、只读当前源码与本轮独立 SQLite，没有连接生产数据库。输入仅合成源码及一般产品需求，真实外部模型未替换或模拟。两个不同职责的临时成员先并发分析，再由既有报告成员汇总，最终 19 项检查全部通过：

- 两次真实 HTTP 调用重叠 5.760290 秒，对应两条成功用量账本，账号、团队与任务归属一致。
- 源码分析返回 3 条发现，一般需求分析返回 2 条，报告成员最终精确汇总 5 条。
- 永久 Agent、永久版本、正式审查任务与正式报告，执行前后均为 0，新增量为 0。
- 临时定义与校验和留存，两项输出都标明只读分析及非正式审查，文件覆盖数量分别为 1 和 0。
- 330 个业务 Python 文件的运行前指纹与本轮本地冻结源码一致。临时运行时 SHA-256 为 `f56072b27728a07429d97e04b52e24969195f98f91631ed85d8cb63765d00ac7`。
- 临时模型配置文件已删除，隔离执行容器已移除。失败的第一次资源打包记录保留：缺少静态 JSON 资源导致导入失败，当时尚未发起模型请求；补齐既有资源后验收成功。

原始时序、账本、前后计数、结果及独立重算在本地 `证据/真实临时模型最终0923/`。这些证据证明有界临时分析和混合团队的真实执行；完整正式代码审查、生产自然语言入口与界面验收由各自的验收记录证明，不能由本次隔离结果替代。

生产只读核验脚本也已复查：字段与当前模型一致，事务明确设为只读；终态复用检查仅调用租约解析，跨账号检查只对本次合成团队执行读取。脚本不执行模型或调度、不写团队状态、不修改权限，且独立重算临时发现的单一出口及汇总数。
