# 依赖审计与修补

本次发布前对生产锁文件重新审计，发现 AnyIO 4.14.1 存在三项已知漏洞：TLS 主机名 IDNA 处理、进程池标准错误输出死锁，以及子进程附加组参数处理。依照项目官方公告，将生产与开发锁文件中的 AnyIO 最小升级至 4.14.2，两个发布制品的 SHA-256 均来自官方 PyPI 元数据，其余包不变。

- [TLS 公告](https://github.com/agronholm/anyio/security/advisories/GHSA-82r6-8w77-94w6)
- [进程池公告](https://github.com/agronholm/anyio/security/advisories/GHSA-5p39-cfhj-2xmp)
- [附加组公告](https://github.com/agronholm/anyio/security/advisories/GHSA-3w57-8xmc-8v26)

修补后 `pip-audit -r backend/requirements.lock --disable-pip --no-deps` 对生产锁依赖的检查未发现已知漏洞。前端通过官方 npm registry 的生产依赖审计，结果同样为零已知漏洞。这是指定时间、指定依赖集合的数据库审计结果，不代表软件不存在其他漏洞。

原本地后端虚拟环境与生产锁文件有 26 项版本差异，因此另建隔离虚拟环境，使用两份锁文件和 `--require-hashes` 安装；93 项精确版本逐项匹配，`pip check` 通过。最终全量结果以该环境的验收报告为准，不以旧环境的通过结果替代。
