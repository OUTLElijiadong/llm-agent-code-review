# 后端账号隔离复核

## 需求与边界

本轮以用户最新要求为准：小菱可编组既有和临时成员；账号只能使用本人已有业务权限，私人聊天及其派生内容严格按账号隔离。管理员的项目管理权限不等于读取其他账号私人对话的权限。本报告负责聊天与内容归属，临时成员创建及执行由本任务另外两位代理实现和独立复核。

已读取私人聊天入口、持久化会话与检查点、工具执行缓存、图片资产、事件总线、追问、圆桌、团队、会话目录和 AI 日志链路。检查点/工具缓存和 Responses 会话主查询已有所属账号约束，保留原实现，并补同名会话键的两账号回归。未把随机或难猜 ID 视为授权。

## 准确复现及修复

| 入口 | 修复前可复现行为 | 修复后边界 |
|---|---|---|
| 私人 SSE | 管理员接收其他账号事件；无 owner 事件发送给所有账号 | 仅明确正整数 owner 与当前账号相同才发送；无归属事件留在内部 |
| 追问回填 | 管理员可代填他人追问；缺失 owner 可被消费 | 同账号才可预留、消费和执行；拒绝不产生副作用 |
| 圆桌 WebSocket 和工具 | 管理员可读或控制他人圆桌；工具对空 owner 转整数报错 | 本人正向访问保留；其他账号及无归属会话拒绝，管理员同样适用 |
| 审计进度中继 | 仅按阶段过滤全局总线，其他账号及同账号别的运行进度可进入当前聊天 | 同时匹配 user_id 与当前 run_id；结束时释放中继订阅 |
| 目录与管理面图片 | 普通账号省略 surface 可列出自己的旧管理员会话；降权后仍能读旧管理员图片 | 普通账号只读 user 面；管理员仍可读本人两个面 |
| 图片下载与权限撤销 | 私人图片响应可缓存一小时；撤销聊天权限仍能通过图片 GET | 图片 no-store；列表和下载都检查当前 AGENT_CHAT，保留原 owner 约束 |
| AI 日志详情 | 管理员可绕过聊天接口，通过模型日志读到他人 prompt、response 和 error_message | 对私人聊天及带 run/tool/team 归属的派生调用，跨账号原文置空并明确 content_redacted；保留既有用量、归因元数据和正常业务审查管理权限 |
| 全局操作审计历史 | 旧团队目标、取消/归档理由进入 detail；即使隐藏返回文本也可用关键词命中总数推断 | 读取时按动作和目标类型识别私人记录，跨账号 detail 置空；SQL 搜索同步只匹配可见 detail，不修改历史行；本人、动作及操作者元数据仍可见 |
| 审批及知识操作审计历史 | 旧审批标题和知识标题包含聊天衍生内容，其他管理员可读及搜索 | `approval` 与 `agent_knowledge_doc` 的 detail 保守限定操作者本人，动作/状态等运营元数据保留 |
| 治理策略/工具调用日志 | 私人 context/reason/input/output/error/resource 经全局治理列表暴露；上下文自报 owner 也不可靠 | 根据持久执行/运行/运维请求账本证明 owner；跨账号和归属失联的私人原文按 `content_redacted` 隐藏；普通业务日志保持原可见性 |

团队列表/详情的管理员 owner 豁免由主代理同步修复，本测试包含普通、管理员、超级管理员的跨账号拒绝验证。日志修复不能仅按固定 Agent 名判断：正式画像、定制画像和带正式 task_id 的聊天派生调用均在测试内。没有正式任务归属的历史未知调用也按私人内容处理。

图片权限门禁使无权限拒绝验收从 249 条增至 251 条，三个固定基线已同步，并对两条图片 GET 显式断言 `agent:chat`。计划使用既有 `verify_permission_acceptance_https.py --build-plan` 入口生成，记录 332 条路由、318 条匿名拒绝与 251 条无权限拒绝，未执行生产请求。超级管理员自己的圆桌仍先走审批再控制，异主圆桌即使审批也不产生控制副作用。

主代理同步将团队新写入的全局操作日志改为固定动作标签；读侧投影专门覆盖发布前已经存储的旧文本，不能仅靠新写入修复来宣称旧数据隔离。最终再次全量需覆盖本次追加的审计读取业务和知识旁路修复，当前尚未开始。五项跳过均为原有 Redis Lua 环境项，本轮限流实现未修改。

红测数是参数化用例失败数，不能相加称为漏洞数；各回归范围有交集，不能相加宣称独立用例总数。更早试跑中出现过测试夹具参数、预期状态、时间字段错误，均已校正，未作为业务失败证据。一次针对性命令路径拼错没有收集到测试，也不计入有效验证。Ruff 对本代理修改的业务文件与测试检查通过。
