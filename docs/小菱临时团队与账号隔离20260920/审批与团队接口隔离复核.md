# 审批与团队接口隔离复核

本轮针对用户明确要求的账号隔离，修复了管理员和超级管理员通过私人审批旁路读取、拒绝或批准其他账号请求的问题。Responses 审批必须有有效同账号 owner；旧聊天知识审批必须通过原运行归属校验，孤儿或损坏记录不可处理。本人审批和共享业务审批保持可用，服务器权限要求保持有效。

新审批审计不复制私人标题，团队创建、取消、归档审计不复制 objective 或原因；修复重试接口 return 后的不可达审计，使真实重试保留固定动作记录。旧日志另由统一审计读取服务按账号隐藏原文。

- 先建立新的 12 项审批隔离测试。首轮夹具名称错误已单独保留，不计为产品缺陷复现。
- 使用 HEAD 原审批服务在独立 Python 模块中执行同一测试：10 失败、2 通过；后者受已修复的知识服务下游防护影响，没有宣称 12 项全红。
- 修复后与既有治理、团队 API 回归合计 **50 通过，0 失败**，JUnit 为本目录本地证据。团队重试使用真实的明确改道策略，没有取消业务门禁。
- Ruff 检查通过。最终全集和生产部署证据另见总验收文档，以上结果不等同于发布完成。
