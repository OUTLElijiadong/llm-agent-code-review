# 稳定部署与生产验收对齐

## 原始需求

“为什么一直改变部署，不用管 GitHub 上传失败就算了，我要能完整部署生成，所有功能正常使用即可。”

## 项目与运行现状

- 正式项目是 Prism，生产主机 `/opt/code-review` 可经 SSH 访问；本地发布候选使用独立受管 worktree。
- 生产主机当前检出的源码版本为 `4.1.0`；本地待发布候选版本为 `4.1.6`。本任务固定使用候选既有版本，不再次修改 `VERSION`。
- 项目要求使用 `deploy/deploy.sh all --revision <完整 SHA>` 完成带备份、隔离恢复、迁移、构建、健康检查、HTTPS 冒烟及应用回滚能力的正式发布事务。
- 用户明确要求 GitHub 上传失败不阻塞部署。拟通过本地 Git bundle 传送已提交的精确 SHA，再在生产工作树运行正式部署脚本；不以 GitHub 操作代替生产发布。
- 已发现圆桌停止按钮依赖 WebSocket，WebSocket 断开时停止命令可能未送达；远程评估审批人列表可能包含自己无权读取的他人已完成任务卡片。

## 需求边界

本任务覆盖：

1. 锁定现有候选版本，修复停止、取消终态与远程评估报告卡片可见性问题。
2. 提交单一可审查 SHA，正式发布前后端同一版本。
3. 发布后以生产健康检查、真实页面和已有任务/报告数据检查版本、权限、报告详情与格式。
4. 按实际证据区分已测、未测与受外部条件阻塞项目。

本任务不覆盖：

- 不递增或改写版本号，不要求 GitHub 上传成功。
- 不触发无关或重复的模型任务，不为获得“绿色”结果伪造报告。
- 未取得官方数据授权或数据文件前，不声称 CNVD/CNNVD 全量同步或逐条匹配已经完成。
- 不改变生产目标范围、账号权限、真实用户数据或数据库记录以迁就测试。

## 验收口径

- 固定候选版本仍为 `4.1.6`，正式部署只执行一次精确 SHA 的 `all` 事务。
- 发布脚本完成备份与恢复验证、迁移、前后端构建和切换、HTTPS/健康冒烟；失败时按原脚本回滚。
- 停止请求经已鉴权 REST 到达服务端后，圆桌进入持久取消终态，不因重连或迟到快照恢复为活动状态；已发出的上游请求可能自然结束需明确告知。
- 审批人列表只显示自己拥有的任务与待审批申请，不显示无权查看的他人已完成报告卡片；分页总数与过滤后的列表一致。
- 生产可访问页面的身份边界、报告详情/导出与管理员用量图以真实账号和真实回执验证；未验证的账号或报告类型明确标为未验收。
