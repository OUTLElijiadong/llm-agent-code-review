# 稳定部署与生产验收共识

## 需求

用户要求停止版本号来回变化，以一份可审查的稳定候选完成生产部署；GitHub 上传失败不是部署阻断条件。部署后需确认报告和管理功能在账号权限范围内可用，不能把“有任务卡但无报告权限”显示成正常报告，也不能把未实测说成通过。

## 固定决策

- 版本号固定为候选 `4.1.6`，不再调整 `VERSION`。
- 生产发布采用单一完整 Git SHA，打包为本地 bundle 传至生产主机；生产仓库精确检出该 SHA 后运行仓库正式 `deploy/deploy.sh all`。
- 不绕过正式脚本，不跳过发布备份、恢复验证、迁移与健康门禁。
- 只修复并验证已证实的停止可靠性与远程评估列表可见性问题；候选内已有的报告格式/权限修复按生产验收单核对。
- 对 CNVD/CNNVD 仅在存在授权官方数据、精确组件/版本命中及官方记录凭据时声明权威匹配；否则使用明确标注的 OWASP 兜底并将缺失接入条件列为待办。

## 验收标准

1. 候选源代码和版本号固定、提交干净、SHA 可在生产仓库解析。
2. 正式部署事务成功，版本与前后端 release SHA 一致，服务健康、HTTPS 冒烟、迁移与备份恢复通过。
3. 圆桌停止接口具备所有者检查、服务端持久终态和迟到事件保护；针对性回归通过。
4. 远程评估列表的授权过滤先于分页计数；审批人只看到待审批请求和本人任务，普通账号只看到本人任务，管理员范围按既有授权保留。
5. 真实生产账号的报告详情、列表卡片与导出遵循同一账号权限；没有实际证据的报告类型不宣称已通过。
6. 生产页面滚动检查与 Token 每日用量图核验留存操作证据；版本、时间、账号、任务 ID 与数据口径可追溯。

## 约束与边界

- 不要求 GitHub 上传成功，不从未提交或脏源码构建。
- 不运行重复或无必要的模型调用；在账号权限、授权范围或模型额度不明确处先使用已有真实任务与报告。
- 取消会阻止应用启动后续 Agent 阶段，但无法撤回已发至供应商的在途请求或承诺停止其计费。
- 正式渗透、外部目标访问和其他高风险写操作必须走现有用户确认、授权与审批机制。
