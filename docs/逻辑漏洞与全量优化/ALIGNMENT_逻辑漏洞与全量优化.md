# ALIGNMENT_逻辑漏洞与全量优化

## 原始需求

用户要求检查项目还有哪些优化点，重点检查逻辑漏洞，并完成优化。用户已确认“给你最高权限，全部做”，执行范围覆盖业务逻辑、安全权限、性能稳定性、前端交互体验、测试和文档同步。

## 项目上下文

- 项目为前后端分离的智能代码审查平台：后端 FastAPI + SQLAlchemy + MySQL，前端 Vue 3 + TypeScript + Vite + Element Plus。
- 核心业务对象包括用户、项目、代码文件、审查任务、审查问题、审查规则、AI 调用日志、用户 API 配置和多 Agent 圆桌讨论。
- 生产入口既有约束为 HTTPS-only：公网 API 应统一通过 Caddy `443` 网关进入，后端 `8000` 与 MySQL `3307` 仅本地绑定。
- 当前工作区已有未提交改动，涉及 HTTPS 文档、`frontend/Caddyfile`、注册页和 `说明文档.md`；本次修改必须保留并兼容已有进展，不能回滚无关用户改动。

## 审计范围

- 后端认证与对象级授权：项目、文件、任务、问题、规则、讨论 WebSocket、Agent Clarify。
- 用户自定义大模型 API 配置与外部 HTTP 调用链路。
- 生产入口配置：Caddy、Docker Compose、公开端口与 HTTPS 策略。
- 前端高风险交互：登录重定向、外链、Markdown 渲染、token 使用。
- 测试与文档：新增回归测试，更新 `说明文档.md` 与 6A 文档。

## 已确认问题

1. 讨论审预检接口 `/api/discuss/start` 只校验项目和文件存在，没有校验项目归属，普通用户可用猜测 ID 启动他人代码讨论审。
2. 讨论 WebSocket 只验证 token 有效，没有校验 token 用户是否拥有对应讨论会话。
3. 审查任务问题接口 `/api/review/tasks/{task_id}/issues` 缺少任务归属校验，普通用户可枚举他人任务问题。
4. 问题详情接口 `/api/issues/{issue_id}` 缺少对象归属校验。
5. 审查规则 `toggle/update/delete` 仅按 `rule_id` 操作，缺少规则所有者校验，可能修改他人自定义规则或全局内置规则。
6. 用户自定义 API `base_url` 会被后端直接访问，存在 SSRF 风险，并且实际 AI 审查链路会复用该配置。
7. 当前 `frontend/Caddyfile` 工作区状态提供 HTTP 明文回退并关闭 HSTS，与项目 HTTPS-only 约束和当前文档不一致。
8. 前端登录 redirect 只判断 `startsWith("/")`，应拒绝协议相对路径；部分外链缺少 `rel="noopener noreferrer"`。

## 边界确认

- 本次不处理腾讯云/DNSPod 控制台备案或域名管控问题，因为它不在仓库代码内，且当前没有腾讯云 CLI/浏览器控制台授权。
- 本次不改变认证形态为 HttpOnly Cookie，避免引入大范围 CSRF 与会话迁移工作；先修复当前 Bearer token 模式下的对象级授权。
- 本次不删除用户 API 配置能力，但会增加 URL 安全校验，默认阻止私有/本机/链路本地地址；如后续确需内网模型服务，可通过显式环境开关放行。

## 关键假设

- 管理员可查看和管理全平台资源，但普通用户只能访问自己创建的项目、任务、问题、规则和讨论会话。
- 内置规则属于全局治理资产，普通用户不能切换或修改；管理员可以启停内置规则，但仍不能编辑/删除内置规则正文。
- HTTPS-only 是生产安全基线，HTTP 只能做到 HTTPS 域名的永久跳转，不能直接提供应用页面或 API。
