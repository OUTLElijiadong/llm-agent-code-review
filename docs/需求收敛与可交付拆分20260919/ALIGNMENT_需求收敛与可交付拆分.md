# Prism 需求收敛与可交付拆分对齐

## 一、原始需求的可执行解释

用户要求把 v3.9.2/v3.9.4 遗留问题、侧边栏重复功能、小菱会话、角色与渗透授权、输入注入、DeepSeek 完整审查、CodeQL、知识库回填和生产发布全部做完。这个集合不能作为一个无边界任务验收：其中既有已经在 3.9.9 发布的能力，也有需要付费模型额度、外部扫描权限、生产浏览器账号和数据归属确认的独立工作。

本次将需求改成“可完成、可验收、可发布”的合同，原则如下：

1. 已发布能力不重复开发，只补缺失证据或修复真实回归。
2. 相同功能只在业务目标、事实源、权限语义和数据生命周期都相同时合并；仅因页面相似、角色不同或展示字段不同，不强行合并。
3. 认证、授权、账号隔离、数据完整性和发布回滚属于发布硬门禁；模型失败、非关键扫描失败必须保留部分结果并明确失败原因。
4. 外部依赖未满足时记录为独立阻塞项，不用本地测试或静态检查冒充生产完成。

## 二、当前已知事实

- 生产当前为 3.9.9，前后端绑定提交 `77cc1fa952a96ea572bf78beece0606085312722`，健康检查、数据库备份和全量自动化测试已有记录。
- 已合并的入口包括管理端四个业务中心、用户端 Agent 工作台、安全与审查规则、支持中心；旧地址只做兼容跳转。
- 小菱会话已按账号、会话面和会话键隔离；收到首条消息后生成内容标题；每账号每会话面最多 10 条活跃会话，超出后归档最旧且未运行的会话，消息与审计记录不物理删除。
- v3.9.4 复核中确认的三类可分配角色为普通用户、评审与审计合并角色、管理员；最高管理员为独立且不可分配的 `super_admin`。内部代码标识沿用现有角色枚举，改名或重建枚举不属于本轮需求收敛。
- 当前仍缺三角色生产逐页证据、动态输入攻击字典、平台上传项目 CodeQL 执行器、测试/演示数据归属治理和受管 Codex Security 扫描收尾。

## 三、边界确认

### 本次发布闭环范围

- 以 3.9.9 现有合并入口为唯一导航事实源，补齐三角色的页面、标签、权限、旧路径、空态、失败反馈和响应式生产证据。
- 把登录、注册、项目、聊天、反馈、论坛、规则配置等文本输入纳入统一动态安全字典；至少覆盖 SQL 注入、XSS、模板注入、超长、Unicode、控制字符和特殊字符。
- 验证小菱同账号重登历史、跨账号隔离、浮窗恢复、10 条活跃上限和归档可追溯性。
- 验证普通用户、评审与审计合并角色、管理员和最高管理员的正向能力、负向 403、危险写操作和重启持久性。
- 通过版本、迁移、备份、health/ready、自动化测试、生产浏览器证据和回滚点后才允许发布。

### 独立依赖里程碑

- 平台上传项目的 CodeQL worker、CLI、SARIF 入库、去重和报告合并。
- Codex Security 标准/深度扫描；前提是工具提供受管且只读的文件系统权限。
- DeepSeek 有预算的全项目真实回归，以及上下文窗口参数的实际供应商验证。

### 需要人工确认后处理

- 测试账号、演示账号、项目、任务和会话的归属清单；在归属确认前只允许导出清单和软停用，不允许按名称批量硬删除。
- 是否把现有内部角色代码改成新的中文/英文枚举。默认不改代码枚举，只合并审查与审计的业务权限。

## 四、图片证据的处理方式

用户提供的三张角色/权限页面截图和后续小菱历史截图是问题证据，反映重复功能、测试角色残留和“新对话”展示问题。截图中的账号、时间、外部标签和浏览器页签不作为新的生产事实；生产事实必须以当前版本接口、数据库和浏览器复核为准。

## 五、完成定义

“完成”不是代码已提交，而是每个范围项都具备：实现或明确的现状、正向证据、负向证据、失败路径证据、数据隔离证据、回滚点和对应文档。每项只能标记为 `通过`、`不通过` 或 `阻塞`，禁止用“部分测试通过”替代未完成项。
