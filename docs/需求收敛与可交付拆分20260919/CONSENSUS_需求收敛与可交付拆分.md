# Prism 需求收敛与可交付拆分共识

## 1. 业务目标

将 Prism 从“功能很多但验收边界不清”调整为“一个事实源、少量业务中心、可追溯权限、可证明发布”。本共识覆盖当前用户提出的合并、授权、会话、注入、扫描、DeepSeek 和生产发布要求，不新增未提出的产品线。

## 2. 唯一业务入口

| 业务域 | 唯一入口 | 合并规则 |
| --- | --- | --- |
| Agent 与创建测试 | `/agents`；管理端归入 `Agent 治理` | 目录、创建、测试、发布审批共享能力注册表；不同权限只显示不同标签 |
| 安全与审查规则 | `/security`；管理端归入 `运行与审计` | 安全态势、规则选择、扫描历史和报告跳转统一；`/rules` 只兼容跳转 |
| 意见反馈与申请维修 | `/support` | 使用同一工单事实源，页内用“反馈/维修”类型切换，不再维护两套列表和提交接口 |
| 用户与角色 | 管理端 `用户与权限` | 用户资料、角色分配、权限点在一个中心内完成；角色管理不再重复提供独立分配流程 |
| 小菱历史 | 当前账号的“我的对话” | 历史按 `user_id + surface + session_key` 查询；不读取无主旧缓存，不跨账号合并 |

## 3. 角色合同

- `super_admin`：唯一最高管理员，不作为普通可分配角色。
- `admin`：管理员，管理平台配置、用户与权限和运营审计，但不能越过服务端授权边界。
- `reviewer`：审查与审计合并角色，可自定义 Agent、提交/处理审查，并在被授予 `pentest:authorize` 后批准渗透授权。
- `user`：普通用户，只能访问本人或被授权的项目、Agent、会话和支持工单。
- 渗透授权必须是申请人提交、另一名有权限的评审员/管理员批准；申请人自批必须返回 403，批准/取消/删除写入审计账本。
- 角色页面不得展示测试账号、过期权限行或已停用自定义角色作为可分配选项；历史关联保留用于审计，但不产生有效权限。

## 4. 小菱会话合同

- 每次成功登录后首次打开小菱进入新的空白会话；已有对话通过“我的对话”显式选择，不自动把旧对话内容拼进新对话。
- 首条用户消息成功落库后生成稳定内容标题；空会话统一显示“新对话”，不能用“内容总结”冒充标题。
- 历史查询必须带服务端当前用户身份、会话面和会话键；前端缓存按账号分区，无法证明归属的缓存丢弃。
- 每个账号、每个会话面最多 10 条活跃会话。第 11 条创建后，只归档最旧且未运行的活跃会话；消息、模型运行、文件和审计记录保留，可按归档状态查询。
- 浮窗显示状态和位置按账号持久化，重新登录或刷新后等待真实面板尺寸再定位，不能出现不显示或出视口。

## 5. 发布分层

### A 类：本次必须闭环

角色和导航生产补证、动态输入字典、会话隔离与保留回归、支持中心唯一入口、发布回滚与文档证据。

### B 类：独立里程碑

平台上传项目 CodeQL 执行器、受管 Codex Security 扫描、真实 DeepSeek 全项目回归和上下文窗口供应商验证。B 类未完成不能宣称“平台已具备完整 CodeQL/深度扫描/全项目真实审查”。

### C 类：确认后执行

测试/演示数据的归属确认、软停用或归档。没有归属清单不执行批量删除。

## 6. 发布硬门禁

A 类任何一项为“不通过”时不发布；B/C 类只能作为独立待办，不阻塞 A 类代码验收但必须在发布报告中显式列为未完成。认证、授权、跨账号隔离、数据损坏风险和回滚失败均为阻断问题。
