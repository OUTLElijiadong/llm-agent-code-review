# 管理员小菱平台计费作用域共识

## 验收要求

1. 有效平台管理员可在管理端使用受支持的模型，不再因缺少个人/企业付款主体而失败。
2. 每次托管模型调用先预占平台模型成本上界；可信 usage 到达后结算，usage 缺失、超界或网络结果未知时保持待核，不自动重放。
3. 平台成本记录独立于积分账本；管理员调用不创建/扣减个人钱包或企业钱包，不增加任何企业用量。
4. 非管理员无法构造管理员计费作用域；权限撤销在每次预占和发送前重验。
5. 普通用户个人计费、企业账本、用户自有 Key、未计量调用默认关闭与未定价工具门禁均保持现状。
6. 默认 V4 Pro 与当前 Flash 可用的托管模型按官方 DeepSeek 峰时、缓存未命中价格记平台成本上界；不因此开放用户购买 V4 Pro。
7. 价格快照记录定价版本、来源地址和核对日期；更新价格时新增费率版本，不改写历史调用成本。

## 实现方案

- 新建独立平台模型成本流水表及迁移 122，保存管理员、运行、模型、供应商身份、费率快照、上界、可信用量和状态。
- 为管理员 Responses 和管理员子 Agent 建立服务端受权的 `platform` scope；接入通用预占/结算/未知结果生命周期。
- 在后台恢复及管理员 Agent 团队工作线程恢复同一授权和计量语义。
- 使用 DeepSeek 官方人民币峰时/缓存未命中费率作为成本上界，整数微元运算，不使用个人零售费率推断平台成本。官方页面当前列示 Flash 输入/输出 ¥2/¥8、V4 Pro ¥9/¥27 每百万 Token；旧 Flash 名称按官方规则映射到现行 Flash 价格。

## 技术约束

- 新迁移唯一父版本必须是生产 head `121_billing_model_evidence`。
- 不能修改 `BILLING_ALLOW_UNMETERED_EXTERNAL_CALLS` 为 true，也不能扩展个人商业模型白名单来解决平台归属问题。
- 所有模型外呼依旧经过共享计量门；服务端 Search/Fetch、MCP、第三方端点等未定价成本继续默认拒绝。
- 运行和助手 UI 的现有 Token 统计仍由 `AiCallLog` 提供；平台成本行不进入个人/企业积分流水。

## UX、DX、AX 决策

- UX：管理员仍从原有小菱入口对话；修复不要求管理员选择付款方。供应商结果不确定时显示待核对并禁止自动重发。
- DX：入口统一调用一个服务端计费作用域；价格、授权、预占、结算和未知状态集中实现，避免 API、团队与恢复路径分别处理。
- AX：付款方由服务端依据 `admin` surface、当前 RBAC 和托管凭据绑定；Agent 不能通过提示词、工具参数或页面上下文指定平台成本归属。
