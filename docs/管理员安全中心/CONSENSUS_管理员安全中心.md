# 管理员安全中心共识

## 需求与边界

交付一个仅最高管理员可用的独立安全中心。其数据源是当前系统已持久化的 AgentAlert、AgentJobRun、OpsExecution、AuditLog 与既有服务器运行时采集。页面明确标记“报告主张”“系统记录”“已独立验证”的证据状态，不导入未经核实的报告内容为生产事件。

当前实现定位为被动监控。用户请求的“主动防御”在本次落地为可审计的检测阈值调节和告警灵敏度；不提供伪装成可用的攻击反击/自动封禁开关。安全策略更新只能让监控更敏感，不能关闭数据源、抬高阈值或提高弹窗门槛。

## 技术方案

- 新增后端安全中心路由与服务，读取并聚合安全告警、巡检运行、白名单安全采集动作和策略变更；各事件只返回经过字段白名单处理的摘要。
- 时间线纳入已有登录审计及角色/权限、用户和全局模型配置变更审计；普通管理员不能通过旧通用告警接口绕过安全中心的数据边界，Agent 能力目录与执行侧都隐藏/拒绝超管专属安全能力。
- 旧告警迁移中的 `source` 可空，权限边界不只依赖该字段：同时识别 `security.*` 类型，以及来源为空且类别属于安全监控类别的告警；SQL 列表筛选与对象级读写使用同一小写及 ASCII 空白归一化规则。通用列表、分页、未读、已读、处置、安全中心计数与时间线共用该分类。
- 使用 `SystemConfig` 保存 SSH/Nginx 阈值、观察窗口及修订元数据；用 `AuditLog` 同事务记录操作者、前后阈值和更新时间。最低弹窗严重度只读沿用环境配置，不在页面提供修改入口。
- 扩展监控服务从该安全策略读取阈值；环境 Settings 是默认基线。安全中心不能写环境变量、密钥或防火墙配置。
- 手动巡检和安全状态读取以真实超级管理员作为运维采集主体；操作来源从同一请求 ID 关联的审计记录读取，定时任务仍显示为系统调度。
- 巡检周期按数据库持久化任务的实际 schedule 展示，不以环境变量推断；Nginx 观察窗口使用独立配置，不复用已退役 FlyTrap 参数。
- Admin Copilot 的安全中心、手动巡检和安全状态能力只向超级管理员展示并允许调用；普通管理员不能仅凭通用权限描述调用后再撞上 API 403。
- 处置告警时保留原始证据，在 `detail_json` 中追加处置子字段。
- 该时间线仅呈现已有持久化审计和被动数据源；平台没有对所有成功只读管理 API 逐请求持久化审计。未进入已接入数据源的操作可能不可见，页面不得把无记录描述成没有访问或没有攻击。
- 前端新增 admin 路由、侧栏入口、盾牌主题页面；复用既有状态、告警与资源 API/设计令牌。

## 验收标准

1. 无凭据 401、普通/审查员/普通管理员 403、唯一超级管理员成功；前后端及旧告警接口权限一致。
2. 时间线对告警、巡检、只读采集、策略更改显示有事实依据的类型/状态/时间、操作者和可追溯来源，且不会输出原始参数、完整命令输出或秘密。
3. 策略输入范围和“只增强”约束服务端校验，审计日志与实际有效配置一致。
4. 告警关闭保留原 evidence，并记录处置说明和处理者。
5. 新增或修改测试覆盖有效、无效、边界、去重、授权与脱敏场景；前端测试和生产构建通过。
6. 发布仍需符合项目生产发布门：SHA/包完整性、备份/迁移、运行版本、健康检查和真实 HTTPS 核验。

## 明确不做

本次不执行附件 PoC，不重放攻击，不对外发请求追踪或反击，不封禁来源 IP，不轮换生产秘密，不宣称完成全面渗透测试。
