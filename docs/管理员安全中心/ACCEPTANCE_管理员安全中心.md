## 缺陷复现和修复

1. 历史迁移记录的 `source` 可为空。修复前回归复现显示，`source=NULL` 的旧安全告警能进入普通管理员通用告警列表，读取端点也曾接受该行。该证据是本地回归，不是生产账号越权测试结果。
2. 带制表符/换行的旧告警字段在 SQL 列表过滤与 Python 读取判定间不一致。新增测试先失败，再统一两侧 ASCII 空白规范化；最终覆盖 NULL 来源、空白字段、普通治理告警可见/可读、安全告警读取/处置返回 404 且不改写记录。
3. v4.0.42 修复 Nginx 安全监控采集器未传入必需阈值参数导致采集失败的问题。生产安全中心显示最近运行的 6 个来源成功；运行 `149086` 的持久化执行结果为完成 6 项、失败 0、降级 0。
4. v4.0.42 生产复核时，真实 `ops-check.sh` 复现了备份误报：`.env` 配置了 `/opt/prism-backups` 且备份文件存在，但未导出 shell 环境变量时检查仍报“没有备份”。原因是运维脚本只读进程环境变量，没有读取部署 dotenv。
5. v4.0.43 增加 `configured_backup_dir()`：进程环境变量优先，其次读取 `DEPLOY_ENV_FILE` 指向的 dotenv，最后才使用默认目录。备份、备份校验、运维巡检和部署容量检查统一使用该函数。新回归测试先在修复前因 helper 缺失失败，修复后通过；并通过未导出 `BACKUP_DIR` 的候选巡检及生产巡检复测。
