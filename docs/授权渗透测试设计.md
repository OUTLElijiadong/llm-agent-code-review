# 授权渗透测试设计(七阶段多 Agent 流水线)

> 版本:v1(2026-08-29)· 代码基线:生产 `eccab68` + 本分支
> 关联代码:`backend/app/services/pentest_service.py`、`backend/app/api/v1/pentest.py`、`backend/app/models/pentest.py`、迁移 `044_pentest_domain`、前端 `src/views/pentest/`

## 1. 定位与边界

平台新增"黑盒测试·授权渗透"分支:在**用户显式授权 + 时间窗**约束内,由小菱编排多个 Agent 按(并行或排队)推演线执行渗透测试并产出报告。

**能力矩阵(诚实分级,不虚标)**:

| 目标类型 | 档位 | 说明 |
| --- | --- | --- |
| Web 应用渗透 | `dynamic` 可动态探测 | SQL注入/XSS/文件上传/越权/CSRF/命令执行/逻辑漏洞 |
| API 接口渗透 | `dynamic` | 未授权访问/参数篡改/越权/业务逻辑漏洞 |
| 主机/系统渗透 | `dynamic` | 弱口令/配置错误/组件过期/提权路径(以沙箱容器为面) |
| 移动 APP 渗透 | `static` 静态分析 | 密钥硬编码/本地存储/证书绕过/接口越权(工件静态) |
| IoT 物联网渗透 | `static` | 固件静态分析(APK/JAR 反编译复用沙箱既有 jadx 计划) |
| 内网渗透 | `tabletop` 纯推演 | 横向移动/域攻击仅做沙盘推演,**不主动探测** |
| 无线渗透 | `tabletop` 纯推演 | WiFi/蓝牙风险仅做威胁建模与检查清单推演 |

主动探测只发生在**平台沙箱隔离网络**(容器 `network=none`,仅回环可达);对第三方公网目标沿用既有 `remote_target_authorized`(40340)+固定公网 IP 浏览器黑盒链路,本流水线不新增任何出口。

## 2. 七阶段流程

```
前期交互(授权门) → 情报收集 → 威胁建模 → 漏洞探测(多线并行)
                  → 漏洞利用(受控验证) → 后渗透(纯推演) → 报告输出
```

| 阶段 | phase_key | 实现 | 产物 |
| --- | --- | --- | --- |
| 前期交互 | (engagement 状态机) | 创建 draft → 用户签署规则(`rules_ack=1`)+时间窗 | `pentest_engagement` |
| 情报收集 | `recon` | 项目静态盘点 + 沙箱环境 recon 事实 + LLM 攻击面提炼 | 资产/技术栈/入口清单 |
| 威胁建模 | `threat_model` | STRIDE×目标类型检查清单 → 攻击假设(≤`pentest_max_hypotheses`) | `hypotheses[]` |
| 漏洞探测 | `detect` | 动态档位先跑一次受控黑盒沙箱探测(purpose=test/test_mode=blackbox,复用固定协议);随后**每假设一条推演线**并行分析 | 候选发现(指纹去重) |
| 漏洞利用 | `exploit` | 候选按严重度**分批判定**(≤12 条/批) confirmed/refuted/inconclusive + CVSS3.1 向量(经 `ai/cvss.py` 校验计分), confirmed 受证据门禁(按能力档位分层);**不生成破坏性 payload、不删改数据** | 验证结论 |
| 后渗透 | `post_exploit` | 攻击链/影响面/持久化风险**沙盘推演**,不执行任何真实动作 | 推演报告段 |
| 报告输出 | `report` | 中文报告(统计/发现/复现/修复建议)入库报告中心:直建 `ReviewTask(review_type='pentest')`+`ReviewReport`(沿用 `sandbox_test` 先例) | 报告+评分 |

评分:`score_version=pentest-v1`,按**已确认**严重度扣分(严重40/高25/中12/低5/提示0),底 0。

## 3. 授权门(硬性前置)

1. `draft → authorized` 必须用户在前端显式勾选规则(`ack_rules=true`),后端记录 `rules_version`+`authorized_at`+时间窗;
2. 流水线每个阶段前复核 `_pipeline_alive`:取消→停;超窗→`expired` 自动停;
3. 小菱工具 `create_pentest_engagement` **只能创建草稿**,授权必须人到前端完成;`start_pentest_engagement` 只接受已授权委托且加入 `_WRITE_TOOLS`(聊天内还需二次确认);
4. 规则文本 v2(`PENTEST_RULES_TEXT`)八条:自有/授权目标、只读验证禁破坏禁删改、探测仅沙箱回环、超窗即停、结果仅本人与管理员可见、排除范围(未声明资产与登记远程地址不主动测)、紧急中止、数据留存与删除权。

## 4. 上下文隔离(无论什么任务什么情况下)

红线:**每条推演线的输入只允许 [上游阶段结构化产物 + 本线假设]**。

- `_build_line_context()` 是唯一输入构造入口,产出带 sha256 指纹的输入快照,写入 `pentest_line_run.context_digest` 作隔离审计证据;
- 线工作线程不持共享 DB 会话/共享可变状态,结果由流水线主线程统一落库;
- LLM 调用无跨线历史(每次独立 `DeepSeekAgent.chat`);
- 并发上限 `pentest_max_parallel_lines`(默认 4,≤4);沙箱探测天然受执行器单槽串行约束;
- 回归证明:`tests/unit/test_pentest_service.py::test_concurrent_line_prompts_do_not_cross_contaminate`(并发双线+金丝雀断言)。
- 全平台既有隔离机制梳理见 [Agent上下文隔离保证.md](./Agent上下文隔离保证.md)。

## 6. API 与小菱工具

REST(`/api/pentest`):`GET /rules`、`POST /engagements`、`POST /engagements/{id}/authorize|start|cancel`、`GET /engagements[/{id}]`(详情支持 `?slim=true` 轮询瘦身;`scope=all` 需 `pentest:manage`)、`DELETE /engagements/{id}`(终态级联删除+报告软删)。

小菱固定工具:`create_pentest_engagement`(创建草稿,返回授权入口)、`start_pentest_engagement`(已授权才可启动,写工具需确认)、`get_pentest_status`(阶段/推演线/发现摘要)。

## 7. 与行业标准的对照

七阶段流程与 **PTES(Penetration Testing Execution Standard)** 的七个环节一一对应:Pre-engagement Interactions(前期交互)、Intelligence Gathering(情报收集)、Threat Modeling(威胁建模)、Vulnerability Analysis(漏洞探测)、Exploitation(受控验证)、Post-Exploitation(后渗透推演)、Reporting(报告输出)。Web/API 类目标的检查清单覆盖 **OWASP WSTG v4.2** 的核心类目:信息收集、身份/认证/授权/会话管理、输入校验(注入)、业务逻辑、API 测试;内网/无线按纯推演档位只做威胁建模,不执行主动探测——这是对授权边界的收敛而非标准缺失。

## 8. 接口数据闭环审计(入口↔出口)

| 接口/链路 | 数据入口 | 数据出口 | 闭环结论 |
| --- | --- | --- | --- |
| GET /pentest/rules | 平台规则常量(政策文本非用户数据) | 前端授权步骤展示 | ✓ |
| POST /pentest/engagements | 表单(项目/类型/说明) | `pentest_engagement` 行 | ✓ 写入即有详情/列表出口 |
| POST …/authorize | 规则签署+时间窗 | 行字段(rules_version/ack/window) | ✓ 详情页与启动校验都读它 |
| POST …/start | 委托 ID | 线程→`pentest_phase_run`/`pentest_line_run`/`pentest_finding`→`ReviewTask`+`ReviewReport`→`summary_json`/`report_task_id` 回填 | ✓ 全链路落库,详情页阶段时间线/发现/报告入口逐级可读 |
| POST …/cancel | 委托 ID | 行状态+未完阶段 skipped | ✓ 详情页状态即出口 |
| GET /pentest/engagements[/{id}] | DB 真实行 | 列表/详情序列化 | ✓ 无任何演示数据 |
| 报告查看 | `report_task_id` → 既有 /reports/{id}(owner/admin 可读) | ReportDetail 渲染 | ✓ 复用报告中心出口 |
| 小菱工具 create/start/get_status | 聊天参数 | 与 REST 同一 service 函数、同一批表 | ✓ 与页面数据同源 |
| 工作状态事件 | 运行/工具/阶段生命周期 → AgentEventBus(user_id 隔离) | /api/agents/events SSE → Agent 中心工位卡;统计另读 AiCallLog(真实调用日志) | ✓ 状态信号+持久统计双出口 |
| 虚拟鼠标导航 | 助手回复中的 PRISM_NAVIGATE 指令(站内路由白名单+守卫) | VirtualCursor 定位真实元素→动画→真实点击/路由跳转;降级=「前往页面」按钮 | ✓ 交互闭环 |

前端所有渗透页面数据均来自上述接口返回(真实库行);`PENTEST_PHASE_DISPLAY` 仅提供展示标签骨架,每阶段状态/摘要/推演线全部来自 `pentest_phase_run`/`pentest_line_run` 真实数据行。

## 9. Agent 工作状态与虚拟鼠标联动

- 小菱自身运行(对话/工具循环)与渗透阶段均向全局 AgentEventBus 广播(`agent=chat_assistant`,user_id 隔离):运行开始 dispatch、每工具 progress、结束 complete/failed;Agent 中心工位卡经 `/api/agents/events` SSE 实时显示「小菱正在工作」。
- 回复正常结束后,回复中的导航指令**自动执行**:VirtualCursor 虚拟鼠标按目标路由定位真实页面元素(侧边导航/页面按钮),滑入→点击涟漪→触发真实点击跳转;`prefers-reduced-motion` 时降级,「前往页面」按钮始终保留为手动入口;失败/取消的回复不自动跳转。

## 10. 已知边界与 2026-08-29 审计整改

### 已知边界(v1)
- mobile/iot 静态档当前为文件名级盘点+LLM 推理(沙箱 jadx 反编译未接入, 完成后升级);
- internal/wireless 为纯推演档(不执行任何主动探测), 报告明标"未经执行验证";
- 漏洞数据库/厂商通告比对未接入(CWE 编号为模型自报, 未对照目录校验)。

### 审计整改(2026-08-29 第二轮, 对照 PTES/NIST SP 800-115/WSTG v4.2/CVSS 3.1/ISO 27002 8.10)
1. **报告字节截断**: summary 按 UTF-8 字节(60000)截断, 此前按字符截断在 15+ 条中文发现时必炸 MySQL TEXT;
2. **exploit 分批判定**: 候选按严重度分批(≤12 条/批多次调用), 模型漏评显式置存疑并计数, 不再静默;
3. **证据门禁(分层)**: confirmed 须证据背书——动态档仅 probe/static, 静态档仅 static, 推演档允许推理但报告标注"未经执行验证"; verified_evidence 持久化进 evidence_json;
4. **报告九节结构**: 执行摘要/范围授权/方法与边界(探测降级强制披露)/情报/统计(已排除单列+CVSS 对照)/发现(证据来源标签)/后渗透/修复汇总/附录(阶段时间线+推演线统计+复测建议);
5. **健壮性**: 启动 reaper 收割重启遗留 running 委托; 失败阶段落 failed+error_message(不再误标已跳过); detect 可中断等待(取消/超窗立即停止, 线级 420s 超时); 取消同步跳过推演线;
6. **性能**: 探测死线 660s→480s 可配置; detect 并行度默认 4; 推演线逐条增量落库+事件(不再整段静默); 详情轮询 slim 模式(体积降约 90%); 列表项目名批量查询(消 N+1); recon 授权范围字段永不截断;
7. **治理**: 授权规则升 v2(排除范围/紧急中止/数据留存); DELETE /pentest/engagements/{id} 级联删除+报告软删; 报告中心删报告联动清 report_task_id; 小菱工具路径补审计留痕(与 REST 同源);
8. **清单补齐(WSTG v4.2)**: web 补认证/安全配置/加密传输三类, api 补 BOLA/BFLA/SSRF/批量赋值/错误暴露, mobile 补 MASVS-CODE/RESILIENCE 与 WebView/IPC, iot 补硬编码密钥/安全更新机制; owasp 字段放开 WSTG/API-Top10 对照。
