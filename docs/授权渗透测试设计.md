# 授权渗透测试设计(七阶段多 Agent 流水线)

> 版本:v1(2026-08-29)· 代码基线:生产 `eccab68` + 本分支
> 关联代码:`backend/app/services/pentest_service.py`、`backend/app/api/v1/pentest.py`、`backend/app/models/pentest.py`、迁移 `044_pentest_domain`、前端 `src/views/pentest/`

## 1. 定位与边界

平台新增"黑盒测试·授权渗透"分支:在**用户显式授权 + 时间窗**约束内,由小菱编排多个 Agent 按(并行或排队)推演线执行渗透测试并产出报告。

**能力矩阵(诚实分级,不虚标)**:

| 目标类型 | 档位 | 说明 |
| --- | --- | --- |
| Web 应用渗透 | `dynamic` 可动态探测 | SQL注入/XSS/文件上传/越权/CSRF/命令执行/逻辑漏洞 |
| API 接口渗透 | `dynamic` | 未授权访问/参数篡改/越权/业务逻辑漏洞 |
| 主机/系统渗透 | `dynamic` | 弱口令/配置错误/组件过期/提权路径(以沙箱容器为面) |
| 移动 APP 渗透 | `static` 静态分析 | 密钥硬编码/本地存储/证书绕过/接口越权(工件静态) |
| IoT 物联网渗透 | `static` | 固件静态分析(APK/JAR 反编译复用沙箱既有 jadx 计划) |
| 内网渗透 | `tabletop` 纯推演 | 横向移动/域攻击仅做沙盘推演,**不主动探测** |
| 无线渗透 | `tabletop` 纯推演 | WiFi/蓝牙风险仅做威胁建模与检查清单推演 |

主动探测只发生在**平台沙箱隔离网络**(容器 `network=none`,仅回环可达);对第三方公网目标沿用既有 `remote_target_authorized`(40340)+固定公网 IP 浏览器黑盒链路,本流水线不新增任何出口。

## 2. 七阶段流程

```
前期交互(授权门) → 情报收集 → 威胁建模 → 漏洞探测(多线并行)
                  → 漏洞利用(受控验证) → 后渗透(纯推演) → 报告输出
```

| 阶段 | phase_key | 实现 | 产物 |
| --- | --- | --- | --- |
| 前期交互 | (engagement 状态机) | 创建 draft → 用户签署规则(`rules_ack=1`)+时间窗 | `pentest_engagement` |
| 情报收集 | `recon` | 项目静态盘点 + 沙箱环境 recon 事实 + LLM 攻击面提炼 | 资产/技术栈/入口清单 |
| 威胁建模 | `threat_model` | STRIDE×目标类型检查清单 → 攻击假设(≤`pentest_max_hypotheses`) | `hypotheses[]` |
| 漏洞探测 | `detect` | 动态档位先跑一次受控黑盒沙箱探测(purpose=test/test_mode=blackbox,复用固定协议);随后**每假设一条推演线**并行分析 | 候选发现(指纹去重) |
| 漏洞利用 | `exploit` | 逐条候选做证据判定 confirmed/refuted/inconclusive + CVSS3.1 向量(经 `ai/cvss.py` 校验计分);**不生成破坏性 payload、不删改数据** | 验证结论 |
| 后渗透 | `post_exploit` | 攻击链/影响面/持久化风险**沙盘推演**,不执行任何真实动作 | 推演报告段 |
| 报告输出 | `report` | 中文报告(统计/发现/复现/修复建议)入库报告中心:直建 `ReviewTask(review_type='pentest')`+`ReviewReport`(沿用 `sandbox_test` 先例) | 报告+评分 |

评分:`score_version=pentest-v1`,按**已确认**严重度扣分(严重40/高25/中12/低5/提示0),底 0。

## 3. 授权门(硬性前置)

1. `draft → authorized` 必须用户在前端显式勾选规则(`ack_rules=true`),后端记录 `rules_version`+`authorized_at`+时间窗;
2. 流水线每个阶段前复核 `_pipeline_alive`:取消→停;超窗→`expired` 自动停;
3. 小菱工具 `create_pentest_engagement` **只能创建草稿**,授权必须人到前端完成;`start_pentest_engagement` 只接受已授权委托且加入 `_WRITE_TOOLS`(聊天内还需二次确认);
4. 规则文本 v1(`PENTEST_RULES_TEXT`)五条:自有/授权目标、只读验证禁破坏禁删改、探测仅沙箱回环、超窗即停、结果仅本人与管理员可见。

## 4. 上下文隔离(无论什么任务什么情况下)

红线:**每条推演线的输入只允许 [上游阶段结构化产物 + 本线假设]**。

- `_build_line_context()` 是唯一输入构造入口,产出带 sha256 指纹的输入快照,写入 `pentest_line_run.context_digest` 作隔离审计证据;
- 线工作线程不持共享 DB 会话/共享可变状态,结果由流水线主线程统一落库;
- LLM 调用无跨线历史(每次独立 `DeepSeekAgent.chat`);
- 并发上限 `pentest_max_parallel_lines`(默认 2,≤4);沙箱探测天然受执行器单槽串行约束;
- 回归证明:`tests/unit/test_pentest_service.py::test_concurrent_line_prompts_do_not_cross_contaminate`(并发双线+金丝雀断言)。
- 全平台既有隔离机制梳理见 [Agent上下文隔离保证.md](./Agent上下文隔离保证.md)。

## 6. API 与小菱工具

REST(`/api/pentest`):`GET /rules`、`POST /engagements`、`POST /engagements/{id}/authorize|start|cancel`、`GET /engagements[/{id}]`(`scope=all` 需 `pentest:manage`)。

小菱固定工具:`create_pentest_engagement`(创建草稿,返回授权入口)、`start_pentest_engagement`(已授权才可启动,写工具需确认)、`get_pentest_status`(阶段/推演线/发现摘要)。

## 7. 已知边界(v1)

- detect 动态探测为**单轮**黑盒沙箱任务;项目存在活动沙箱环境/语言不支持时自动降级为纯分析并在产物中注明;反向同理:探测运行期间会占用该项目唯一的测试沙箱槽(单 worker 语义),期间该项目不能并发发起其他测试;
- exploit 阶段为证据判定 + LLM 推理验证(与 fullchain `_llm_verify` 同型),不再追加破坏性 PoC;
- 后渗透为纯推演;移动/IoT 为静态档位;内网/无线为 tabletop 档位;
- 流水线为进程内守护线程(与 review_service 同型),后端重启时运行中委托停摆,可从详情页重新启动(阶段全量重跑);
- 报告正文写入 TEXT 列前按 60K 字符截断,完整数据始终在结构化表。
