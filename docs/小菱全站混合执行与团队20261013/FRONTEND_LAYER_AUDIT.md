# 前端图层与站点浏览器桥接专项复核

日期：2026-10-13

复核范围：候选工作树的全局弹层顺序、圆桌列表、虚拟光标、站点 DOM 执行桥接、聊天 SSE 事件与 pending 恢复。
证据边界：下述自动化均运行于本地候选代码，Playwright 把 `/api/**` 响应替换为测试桩；它们不访问生产数据库、真实账号或模型。生产 v4.0.98 的 Safari 截图只用于问题基线，不视为修复后的生产证据。

## 复现根因与修复

用户截图中的圆桌菜单是页头按钮的绝对定位子级。页头使用 `backdrop-filter` 并处于独立层叠上下文，子级的高 `z-index` 不能越过祖先层叠上下文；菜单因此被页面卡片和筛选控件压住。现将页头触发器留在页头槽位，把选择菜单传送至 `body`，再按按钮矩形计算视口坐标并限制左右边距与最大高度。Escape、外部点击、路由变化和圆桌选择仍各自走原有关闭/打开流程。

虚拟鼠标此前只在两次 `requestAnimationFrame` 定位到目标后才读取目标祖先层级，首帧仍使用默认 `2700`，可能被 Element Plus 弹层基数 `4000` 压住。现在收到已定位的 DOM 目标事件时先同步提升光标层级，再开始显示和移动；目标被遮挡时仍停止，不把装饰光标指向后台控件。光标容器保持 `pointer-events: none`，不会拦截用户的真实鼠标命中。

独立复核新增的 E2E 断言首次复现了首帧层级问题：375px 和 768px 得到光标 `2700`、圆桌菜单 `4000`；1280px 因渲染时序不同曾偶然通过。修复后重新跑了三种视口，断言包括目标层级、`pointer-events`、中心命中和光标最终中心与控件中心偏差小于 3px。进一步补验发现，捕获阶段的圆桌 Escape 监听原先无条件关闭菜单并恢复低层触发器焦点；现在会先比较菜单和可见业务对话框的有效图层，仅在没有更高模态时消费 Escape。高层模态打开时事件继续传递，圆桌不抢键、不夺焦点。

## 层级表与残余值

| 用途 | 当前值 | 说明 |
|---|---:|---|
| 页头 | 100 | 固定页面导航 |
| 移动端侧栏遮罩 / 侧栏 | 1900 / 1910 | 遮罩低于侧栏 |
| 页面引导 / Agent 活动状态 | 2400 / 2410 | 活动边框自身 `pointer-events: none` |
| 小菱聊天 | 2500 | 用户与管理员聊天浮层共用 |
| Agent 团队窗口 | 2600 | 高于聊天、低于全局模态 |
| 虚拟光标默认值 | 2700 | 有已知目标时按祖先最大 `z-index + 1` 动态提高 |
| 自定义模态 / 嵌套确认 | 3000 / 3100 | 业务模态层级 |
| Element Plus 弹层起始值 | 4000 | 由全局配置递增器分配；嵌套弹层继续递增 |

全站 `z-index` 静态扫描中，跨组件交互层已使用 `--layer-*` 语义令牌或 Element Plus 递增器。剩下的字面数值位于组件内部层级：聊天/管理聊天的拖拽遮罩 `19/20`、会话菜单 `20`、圆桌对话内滚动按钮 `5`、空状态/时间线/卡片内部装饰 `0/1/2/3/6`。这些数值不参与跨组件弹层排序。`variables.scss` 仍保留一组旧 `--z-index-*` 兼容令牌（1000–1070、2000、3000）；本次源码检索仅发现加载遮罩引用 `--z-index-loading: 2000`，其他旧变量目前没有仓库内引用，未删除以避免破坏未检索的外部覆盖。

## 站点浏览器桥接复核

- 控件观察仅从可见业务 `main` 或按有效祖先 `z-index` 与 DOM 顺序选择的最高业务对话框收集；不会把“最后插入 DOM”误当成“最上层”。小菱自身聊天窗、Monaco 编辑器和明确排除区域不进入控件列表。Teleport 弹层只在可见触发器声明 `aria-controls`/`aria-owns` 时加入观察范围。
- 每个控件使用随机 handle，服务端要求事件携带 handle、路由和快照；执行前还核对快照 TTL、账号 ID、登录 token、会话、运行、界面、路由、控件签名和禁用状态。执行后重新观察并回传回执，不接受 CSS 选择器或任意 DOM 路径作为目标。
- 密码/密钥等敏感输入、文件输入和文件上传触发器只要求本人处理；表单填充不会读取或回传控件值，观察文本不读取剪贴板或本机文件路径。外部链接、未授权站内路由、旧快照和被遮挡目标均拒绝或暂停；未知目标不会猜测页面主按钮。
- API 客户端把 claim、ack、pending 分别绑定当前 session/surface/run。前端先 claim 才能执行；事件队列串行执行，同页有 `sessionStorage` 去重，重连恢复只重放待执行事件并跳过服务端已经 executing 的条目。单测以 API mock 验证；跨标签页互斥由服务端 claim 保证，本次未用真实 API 或生产账号验证。
- 两个聊天入口（用户 `AgentChatDrawer`、管理员 `AdminCopilot`）都先过滤当前 scope，再将 `response.browser.required` 交给同一桥接器。SSE parser 将此事件作为非终态事件传递；pending 恢复按运行状态轮询并复用同一队列。相关前端测试通过，但这不能证明服务端权限/租约/审批闭环，也不替代模型实际请求。

## 自动化验证

### 几何和交互 E2E

命令：`cd frontend && npm run test:e2e -- e2e/overlay-layers.spec.ts`

每个视口均重复打开/关闭圆桌菜单三轮，并检查边界位置、卡片覆盖顺序、聊天浮窗、Element Plus“近 30 天”下拉和无写入的退出确认取消。另在每个视口把虚拟光标指向圆桌项，核对光标层级高于弹层、容器仍为 `pointer-events: none`、`elementFromPoint` 命中原按钮，且动画落点与目标中心相差小于 3px。复跑中确认持久壳层可能还有更高的引导/聊天对话框；高层模态存在时菜单 Escape 正确不再抢键，E2E 用触发按钮关闭菜单，单测独立验证没有高层模态时 Escape 关闭菜单。最终完整运行结果：375px、768px、1280px 三项全部通过，每项圆桌交互三轮。

Playwright 截图与这份文档同目录的 `evidence/`：三种视口圆桌菜单，以及 1280px 的圆桌菜单加虚拟光标。查看截图可见菜单浮在统计卡片前，虚拟光标覆盖实际第一项；没有因光标层制造新的点击拦截。
