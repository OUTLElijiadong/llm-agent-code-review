# 小菱唯一主控与 Agent 团队原子任务

| 编号 | 输入与实现范围 | 输出与验收 | 依赖 |
|---|---|---|---|
| A1 根身份统一 | 用户面、管理面 Responses persona 和可见 Agent 目录 | 两个 surface 均为小菱；manager/orchestrator 不可成为子目标；session 权限不变 | 无 |
| A2 唯一团队入口 | Mesh task.request、Team REST 创建、内部 Orchestrator 工具 | 公开接口拒绝；小菱内部工具可以创建；审计记录落账 | A1 |
| A3 目标授权闭合 | 用户/管理 surface 的 monitor、operations 和其他 Agent 目标 | 发送与认领都重新校验；不允许隐藏目标、伪造来源或过期会话 | A2 |
| A4 发布审批分离 | 自定义 Agent owner、ApprovalItem、发布端点 | 作者不能审批自己包；类型、owner、资源、编码、版本必须一致 | 无 |
| A5 反幻觉路由与结果提示 | 小菱、专业内置 Agent、固定 Agent 与临时 Agent 运行链路 | 明确职责路由；固定 Agent 的证据须逐字来自当前代码分片且对应行号；临时 Agent 的证据须逐字对应输入来源，压缩分片的摘录先由服务端核验；不确定则省略/标未覆盖 | A1 |
| A6 固定 Agent 治理 | 当前审查员账号真实创建草稿并提交 | 六个专业 review Agent 的精确编码/职责/权限和静态测试记录 | A4、A5 |
| A7 管理员真实审批与发布 | 超级管理员真实 UI 操作 | 新版本/新 Agent release 与目录可见；记录审批人、作者、版本、成本 | A6 |
| A8 真实模型与团队验收 | 现有生产项目代码和小菱真实对话 | 至少一个自定义 Agent 真实调用、一个团队多 Agent 执行及可核对事件/账本 | A7 |
| A9 全面回归与交付 | 后端、前端、构建、部署/健康状态、知识闭环 | 全量证据矩阵、6A 最终报告和清楚 TODO | A1-A8 |
| A10 黑白盒与修复后复测 | 小菱、只读修复 Agent、`sandbox_deployer`、`test_verifier`、沙箱快照 | 只读补丁建议；用户批准后的小菱源码编辑；固定新 SHA-256 的白盒+黑盒复跑与新增样本；团队运行终态与审计证据 | A1-A5 |
| A11 远程黑盒与正式渗透授权 | 外部 HTTPS 目标、当前调用审批、渗透委托与独立审批 | 每个外部目标绑定当前批准参数；正式渗透目标/范围/时间窗需独立授权；无有效授权不得发请求；smoke 与渗透结果分开 | A2、A3、A10 |

并行无依赖工作由小菱团队机制本身提供；此工程执行阶段按依赖顺序，不能以模拟模型输出替代生产真实调用验收。
