# 小菱唯一主控与 Agent 团队架构需求对齐

## 原始需求

- 全项目只保留小菱一个主 Agent，其余 Agent 都由小菱按权限和任务调用。
- 支持调用已有 Agent、生成当前任务/账号内的临时 Agent，并组成真正并行、可追踪的 Agent 团队。
- 由审查员创建可长期复用的专业 Agent，经管理员审批后发布；更新现有子 Agent。
- 为项目代码审查、审计、管理端运维等任务提供清晰路由。
- 通过证据约束、权限复核、结果校验和失败闭合降低模型幻觉与越权风险。
- 生产创建和发布需分别记录真实浏览器操作、审批、发布和真实调用证据。
- 小菱及其子 Agent 的任务计划、工具动作和结果需要有一个只读监督子 Agent 持续核验；低/中风险按策略自动通过，高风险回到当前账号询问。
- 小菱需要编排子 Agent 搭建隔离测试环境、在源码修订副本上修复后复测，并按授权执行白盒、黑盒和正式渗透工作流。

## 现状理解

- 用户面与管理面可继续作为权限和会话隔离面，但两面都应显示同一个主控身份 `chat_assistant / 小菱`。
- `manager` 是旧权限策略兼容编码，`orchestrator` 是内部调度实现；不得作为第二个可对话主控或可递归调用的子 Agent。
- 旧 `/api/admin/copilot/chat`、`/history` 固定返回 410；仍保留的 `/api/ai/chat` 调用同一 `chat_assistant` 代码身份，但它不是生产前端小菱工作台的团队协作入口。
- `create_agent_team` 已支持已发布 Agent 与临时 Agent 混编；临时定义在团队内持久化用于任务和审计，不加入永久 Agent 目录。
- Agent Studio 只允许声明式代码审查 Agent，测试按钮只校验结构、权限和工作流，不运行真实模型。
- `agent:operations` 是现有管理端只读运维子 Agent，限定唯一超级管理员的管理会话；有副作用的动作由小菱使用既有审批链执行。
- 固定 Agent 的真实发布会把已审批代码审查提示词应用到全站目录，并对每个源码分片增加模型调用。
- 已有 `approval`、`policy` 治理 Agent 画像和 `policy_engine`/`tool_gateway`，但不等于它们已统一监督 Responses、小菱、团队节点和结果；本轮已复现“未知动作默认低风险 allow”及“高风险 allow 规则仍放行”各自问题，3 个回归全部按预期失败。
- Agent Team 的 `test_verifier` 可将 `combined` 与指定 `source_revision_id` 路由到隔离沙箱；远程 REST 沙箱已用服务端一次性票据，而获批团队参数仍沿内部布尔授权路径，票据语义尚未统一。正式渗透委托目前由小菱主控走独立授权与审批，未找到子 Agent 实际启动该委托的 handler。

## 范围与边界

- 本任务优化主控身份、团队创建入口、跨账号/跨界面授权、审批分离、路由提示和证据要求。
- 固定 Agent 只提交到现有 Agent 工坊审批链，不新增替代发布接口。
- 不承诺消灭模型幻觉；验收目标是无证据不作为已确认事实输出，权限和团队边界由服务端强制，失败不伪装成成功。
- 不把“所有任务都强制组队”作为目标；只有用户明确要求并行或存在两个以上相互独立工作时组队。
- 生产管理员发布属于安全敏感的访问扩张，最终点击前单独展示准确清单、调用成本和生效范围并取得当时确认。
- 用户于 2026-09-28 明确确认风险路由：低风险与中风险自动通过，高风险向当前账号询问。实现时由服务端按固定能力清单分类：低风险限只读查询/分析；中风险限可逆项目元数据变更和当前项目隔离沙箱操作；生产写入、破坏性/权限动作、Agent 发布、外部 MCP/扫描/渗透及真实凭据属于高风险；未知分类、审计持久化失败或监督规则异常均 fail-closed。此处是服务端具体分类，不依赖模型自报风险等级。

## 验收口径

- 两个 surface 的消息、运行记录和可见主控身份均指向小菱；管理权限仍按当前账户和 surface 服务端校验。
- 普通用户不能直接发子 Agent 任务或创建团队；只能经小菱工具链创建，且服务端重新校验当前会话和目标 Agent。
- 临时 Agent 只在当前账号、当前团队和有效租约中执行；任务完成后保留审计记录但不进入永久 Agent 库。
- Agent 选择只接受目录中可执行的精确编码；权限不足、目录不可见、目标失效或模型结果无证据时明确阻断/未覆盖。
- 管理端治理界面、策略说明与运行时元数据不得再把 `manager` 或 `orchestrator` 表示为独立主控；仅保留清楚标注的兼容/内部实现名称。
- 代码审查员作者不能审批自己的发布包；管理员审批须精确匹配申请人、包、版本和动作。
- 生产验收分别记录草稿结构校验、管理员审批、发布后目录、真实模型调用和团队真实执行，不混为一项通过。
- 监督 Agent 必须对小菱与团队成员的输入计划、待执行动作及输出结果留下当前账号、surface、会话/团队、目标、风险级别、决策理由和证据记录；它不得拥有写/越权工具，且不得覆盖服务端权限、正式渗透授权或高风险人工确认。
- 策略正常时低/中风险 allow 可自动执行；高/严重风险必须在当前账号确认；拒绝策略始终拒绝；未分类动作、监督器不可用/结果结构无效、策略异常均不能降级成自动 allow。
- 高风险确认只授权绑定到当前用户、运行、调用、工具、完整参数和团队计划摘要的单次动作；确认不能越过服务端 RBAC、显式 deny、项目范围或正式渗透授权。
