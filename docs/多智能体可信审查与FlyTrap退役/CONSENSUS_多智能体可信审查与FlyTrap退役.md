# Consensus：多智能体可信审查与 FlyTrap 退役

## 最终需求

在保持现有 API 和报告兼容的前提下，将多智能体审查从“模型自由汇总”改为“结构化主张、确定性聚合、可审计冲突和人工裁决”；为长文件建立跨分片符号上下文；把 FlyTrap 从生产依赖中非破坏性退役。

## 统一发现协议

协议版本为 `finding-aggregation-v1`，每条原始主张至少包含：

- `claim_id`：由来源身份、位置、规则/CWE、证据哈希生成的稳定标识。
- `agent_code/agent_name/source`：真实 Agent 与引擎来源，分片身份参与 `claim_id`，不接受模型自报确认数量。
- `issue_type`：兼容现有安全、可靠性、性能、可维护性和质量问题分类。
- 原始与归一化的严重度、置信度、位置、CWE、证据和结论。
- `evidence_quality`：`verified/direct/inferred/unsupported`。
- `stance`：保留 Agent 的主张或异议状态；未提供时为 `asserted`。

聚合记录包含：

- canonical 发现和真实来源列表。
- `risk_score` 与版本化计算明细。
- `conflict_status`、冲突原因和人工复核状态。
- `coverage`：输入 claim 到输出或丢弃项的完整映射。
- 可恢复解析诊断，不包含完整源码、隐藏提示词或凭据。

## 严重度与风险映射

- 归一化等级：`严重=100`、`高=75`、`中=50`、`低=25`。
- 兼容 `critical/P0/error`、`high/P1`、`medium/P2/warning`、`low/P3/P4/note/info` 等输入。
- 同一物理问题的风险分使用各来源“严重度分 × 校准置信度”的加权平均；展示严重度与置信度始终取自同一 canonical 主张，不由风险分反推新的合成等级。
- 有合法 CVSS 向量时保留 CVSS 自身结论；无向量时不得由四级严重度猜测 CVSS。
- 历史任务总分继续使用 `severity-deduction-v1`；新 `risk_score` 只说明单条聚合风险，避免历史口径漂移。

## 置信度与冲突

- 缺失置信度为未知，不再默认 0.8；兼容存储时使用保守值并明确 `confidence_method`。
- 模型自报置信度只作为一个输入；证据能在当前源码中定位时加权，缺证据或无位置时封顶。
- 独立来源一致只增加可审计确认数，不自动抬高置信度；严重度跨度、CWE 分歧和异议状态触发冲突。
- 严重度跨度至少两档、CWE 冲突、聚合置信度低于阈值、严重/高危仅模型推断且证据不足时，`conflict_status=unresolved`、`human_review_status=pending`、问题状态为 `pending_review`。
- 人工可接受、驳回或要求补证；独立保存裁决历史，并同步为 `unfixed/ignored/pending_review` 业务状态，记录人员、时间和备注。

## 上下文构建

- `chunk_code_with_context` 先构建文件级符号索引，再按现有边界分片。
- Python 通过 AST 提取模块导入、类及基类、函数和嵌套函数、参数、赋值定义、调用边、危险调用；语法错误时退回词法索引。
- JavaScript/TypeScript/Java/Go/C++ 使用有界词法索引，明确标识 `lexical`，不伪装为完整 AST。
- 每个分片携带：文件级索引模式与统计、当前分片相关符号、调用边、变量引用边、继承关系和上下文指纹。
- 上下文有严格字符预算，不把整个长文件重复塞入每个请求。
- 超过 60000 字符不再直接跳过；按有界分片逐段处理，单片失败继续其他片。

## FlyTrap 退役

- 新增 `security_flytrap_enabled=false` 默认配置。
- 后端禁用时不把 FlyTrap 加入安全巡检动作，也不将其计入全部数据源失败分母。
- 状态查询保留兼容字段，返回 `enabled=false/status=retired` 和空历史窗口，不触发降级。
- 运维执行器保留只读动作名以兼容旧调用，但默认立即返回 `retired`，不访问 systemd 或日志。
- 发布完成后对生产两个 systemd 服务和证书续签 timer 执行 `stop + disable`，先保存 unit 状态和回滚命令，不删除 unit、程序、证书或队列。
- 关闭现有 FlyTrap 上游降级告警，关闭原因明确记录为“集成已退役”，不是“上游已恢复”。

## 验收标准

- 新增协议、解析、聚合、上下文、FlyTrap 和人审测试全部通过。
- 既有后端全量测试、迁移测试、前端测试、类型检查和构建通过。
- 使用已知真值样本重复运行上下文/聚合基准，顺序和提示词生成保持稳定。
- 生产备份、迁移、发布、服务退役和公网 API 复验完成，失败时可回滚。
- 独立子代理重新读取代码、数据和生产结果，确认任务语义与数据一致。
