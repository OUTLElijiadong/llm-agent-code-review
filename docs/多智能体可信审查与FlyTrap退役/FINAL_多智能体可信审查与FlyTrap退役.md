# Final：多智能体可信审查与 FlyTrap 退役

## 交付结果

Prism 已从“多个模型自由输出后再次交给模型汇总”改为“关系上下文构建、严格结构解析、版本化确定性聚合、冲突留痕和人工裁决”。FlyTrap 已从应用配置、巡检执行、告警语义和生产 systemd 四个层面非破坏性退役。

生产当前运行 `3.8.1`，提交为 `c8a80228f48b949daabe4520c880a8994540c08b`，数据库处于 `046_finding_aggregation`，公网健康、就绪和页面验收通过。

## 核心改造

### 1. 可信聚合

- 统一严重度别名、置信度量纲、证据等级和真实来源身份。
- 每条输入主张拥有稳定 `claim_id`，输入必须进入 canonical 结果或带理由的丢弃账本。
- canonical 严重度与置信度绑定同一来源主张，避免产生无人真正提出的组合结论。
- 完全连接聚类保证输入排列变化不改变输出；聚合版本和风险算法版本可追溯。
- 风险加权与确认数都仅使用去重后的真实来源；同一 Agent/引擎重复声明无法抬高综合分。
- 严重度、CWE、证据或立场冲突不被多数票掩盖，自动进入人工复核。
- 聚合器自身失败时原始主张仍被保留并逐条待审，不堵死整次审查。

### 2. 稳定漏洞识别

- 模型调用温度统一为 0，提示词加入稳定的上下文契约和“证据不足即线索、不得伪装确认”的规则。
- 安全哨兵取消超大文件静默跳过，改用相同的上下文分片链路。
- 评测门禁对同一候选重复运行，比较确定性签名；任何一轮不稳定或失败均不能以“干净结果”放行。
- 静态结果和有效模型结果在部分失败时继续保留；全部模型失败会明确显示覆盖缺口。

### 3. 跨分片上下文

- Python 先对完整文件建立 AST 符号索引，再生成分片。
- 分片携带导入、定义、嵌套关系、参数、变量引用、调用边、危险调用、类继承和稳定指纹。
- 单个超长定义与单行超长内容继续按字符预算拆分，保证阈值和源码守恒。
- 语法错误或非 Python 语言使用带诊断的词法索引，系统继续工作但不会隐瞒降级。

### 4. 人工交互

- API 和页面展示单条发现的风险、证据质量、冲突、来源和聚合详情。
- 人可接受、驳回或要求补证；决议记录操作者、时间和备注，并同步业务状态。
- 提交失败保留当前上下文并提示重试，不因单次错误把用户堵在不可恢复状态。

### 5. FlyTrap 退役

- 默认配置与运维执行器均以 `retired` 为正常状态，不再访问已关停上游。
- 安全巡检不再执行 FlyTrap 动作，也不把它计入失败分母。
- 生产 Agent、同步服务和证书续签 timer 已停止并禁止自启。
- 旧降级告警按“退役”关闭，未伪装成“上游恢复”。
- 全部 unit、历史数据和恢复材料保留，可审计、可回滚。
