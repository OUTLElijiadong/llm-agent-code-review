# 报告排版与覆盖口径修复对齐

## 原始需求与本轮背景

用户要求生产部署后继续逐页检查，确保代码审查、审计、黑白盒和远程评估报告能正确生成、权限正确、内容与格式清楚；管理员每日 Token 用量图需可读，并避免版本号反复变化。用户已说明 GitHub 上传失败不应阻断生产部署，Safari 当前已登录审查员账号，超级管理员检查已在前序任务完成。

## 已核实的问题

- 初始基线 Prism 4.1.6（SHA `e9e02858342bc4cb33119b070c09cfeb502493e6`）之后，4.1.7 已部署；本轮复核以 4.1.7 的真实浏览器行为为基线。
- Safari 的审查员会话可访问报告 #198（历史白盒任务）。真实数据表明本次请求为白盒，确定性检查与 AI 动态用例通过，黑盒和远程黑盒均为 `not_required`；旧 UI 仍显示“记录范围内已完成/已记录范围内无遗漏”，容易被误读为全面验证。
- 真实报告证据表导致详情页横向溢出；PDF/Word 导出把 Markdown 表格当普通文本，不能清楚阅读。
- 管理员 Token 图表在非窗口尺寸变化、例如侧栏/卡片布局变化时没有容器级重排监听。
- 代码中仍有 4.1.6 的开发回退默认值；直接构建可能与根目录 `VERSION` 不一致。
- 4.1.7 部署后的审查员浏览器验收发现：渗透测试列表允许审查员看到他人委托，且仅凭 `report_task_id` 显示“报告”按钮；点入报告后服务端正确拒绝访问，形成“卡片有报告入口、报告无权限”的错误体验。
- 4.1.8 部署后的审查员真实浏览器验收 `/reports/180` 时发现：统计显示 6 条问题，但正文没有完整问题清单；页面只把具有可验证 CVSS 向量的问题放进 Top 10，未评分问题因此没有标题、说明、证据位置和建议。问题接口默认还过滤为未修复/待复查，不能代表报告所有记录状态。
- 同账号打开 `/reports/171` 得到“当前账号已无权查看此报告，已清除报告内容”，无权详情保持拒绝；报告列表服务端可见性门禁继续保留。

## 本轮范围

修正覆盖状态文字与验证项明细；让 Markdown 表格在网页、PDF、Word 中按表格语义排版；限制报告详情表格宽度并折行；给 Token 图增加 ResizeObserver 容器重排与清理；统一后端、Compose 与前端的回退版本值；以现存真实报告和已登录角色会话做发布后复验。对生产复验中发现的渗透报告入口权限错配，服务端按报告实际可读范围批量计算可见性、无权时不返回报告任务 ID，前端列表和详情只为 `can_view_report=true` 显示入口。

本轮在现有 `issue:view` 权限门禁内使用已有问题接口的 `status=all` 读取完整问题记录；将标题、严重度、状态、证据状态、复核状态、位置、说明和已保存的建议/修复内容逐条呈现，并复用现有 Markdown 消毒渲染器。本轮不重新生成 AI 报告、不创建额外扫描任务、不改生产报告数据、不把未登录的角色或无现存样本的报告类型宣称为已验收。

## 版本决策

4.1.7 发布后由权限入口错配触发 4.1.8；4.1.8 部署后，审查员报告实测又复现了“统计有 6 条、正文缺问题清单”的确定缺陷。为避免报告继续遗漏已记录的问题，本次仅对该可复现缺陷发布一个补丁版本 `4.1.9`，完成后冻结版本并执行整体验收；GitHub 上传失败不阻断已冻结提交通过正式 bundle/部署流程上线。

## 验收标准

1. 本次请求模式和每个验证阶段清楚显示；未要求的黑盒不得被显示为已执行或完整通过。
2. 报告详情在常见桌面浏览器宽度下无整页水平溢出，长证据可换行或在代码块内部滚动。
3. PDF/Word 对 GFM 表格保留列结构、可阅读中文与长内容；HTML 表格不会撑宽版面。
4. Token 图表在其容器变化尺寸时重绘，并在页面卸载时断开观察器。
5. 自动化测试、静态检查、生产构建通过；生产发布后版本/SHA/健康回执匹配，审查员可打开有权报告并导出；无法检查的身份/报告类型如实列为未测。
6. 审查员可继续看到其有权审查的委托，但列表与详情中的“报告”入口仅对当前账号真实可读、关联完整的报告显示；服务端列表响应对无权报告不返回报告任务 ID；委托发起人仍可读取其已生成报告。
7. 报告问题清单与统计一致，接口使用 `status=all` 分页读取，包含未修复、待复查、已修复和已忽略记录；每条展示已有的描述、位置、状态、证据/复核状态和存在的建议/修复代码，缺失字段明确标“未提供”，Markdown 标记不会裸露，未经消毒的 HTML 不得执行。
