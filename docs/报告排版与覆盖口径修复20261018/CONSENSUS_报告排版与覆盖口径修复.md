# 报告排版与覆盖口径修复共识

## 确认的实现

- 初始计划是基于生产 4.1.6 集中发布 4.1.7；生产真实验收先后确认 4.1.8 修复渗透报告入口权限错配，4.1.8 的审查员报告检查又复现“统计有问题、详情缺完整问题清单”。本次只为该已复现缺陷追加一个必要补丁 4.1.9，并在它之后冻结发布版本。GitHub 上传失败不影响 Git bundle 直接导入生产仓库。
- 生产发布只执行项目正式 `deploy/deploy.sh all --revision <完整 SHA>`，保留备份、隔离恢复、迁移、前后端同 SHA、健康检查和回滚门禁。
- 报告覆盖措辞准确反映本次请求模式；白盒报告明确标记黑盒/远程黑盒未纳入，而不是“无遗漏”。
- PDF/Word 生成原生表格，报告详情控制表格溢出并允许长证据折行。
- 管理员 Token 图表监听容器尺寸变化并在离开页面时释放观察器。
- 优先使用已有真实报告和当前审查员会话，不为验收发起新的耗费 Token 的模型任务。
- 渗透委托列表和详情必须使用服务端计算的 `can_view_report`；无权或报告快照关联不完整时，响应中隐藏 `report_task_id`，前端不显示报告入口；合法发起人及有权管理员继续可读。
- 4.1.7 的部署后真实浏览器验收暴露了上一条权限错配，因此把权限修复作为一次补丁发布并与既有报告修复收口，候选 4.1.8；不再为同一任务拆分版本。
- 4.1.8 的审查员报告 #180 统计 6 个问题，但没有呈现所有问题详情；未评分条目无法进入 CVSS Top 10。报告详情须显式读取 `status=all`，完整展示每条已保存的问题内容，并继续用 `report:view`、来源权限和 `issue:view` 控制数据访问。界面每页只渲染 20 条，支持翻页，完整集合仍全部加载、计数。候选 `4.1.9` 是本轮最后一次、由生产复现触发的必要修复。
- 4.1.9 部署后的审查员真实浏览器检查又复现一项独立显示缺陷：沙箱黑白盒历史报告 #199 的 HTML 执行日志附录包含超长连续字符串，滚动至该段时超出视口并被截断。仅对此已观察到的缺陷增加 4.1.10 补丁，限制执行日志块宽度并允许长串换行、完整保留原始日志。该补丁通过后冻结，不再基于假设继续调整版本。
- 不启动新的 AI 审查、黑白盒任务或远程扫描来验收，以免产生模型额度消耗或未经授权的网络动作；使用现存报告、已有权限回归和生产浏览器检查。

## 验收边界

- 本地自动化与构建只能证明实现层行为，不能替代生产浏览器和权限验收。
- 服务端决定报告对象权限；前端只消费 `can_view_report` 和脱敏后的 `report_task_id`，不得用“ID 存在”推断当前账号可读。
- 真实审查员可见报告及导出可以直接检查；超级管理员既有验收可引用前序生产记录，但本轮无管理员真实登录态时，不补造新的管理员页面操作证据。
- 没有现存真实报告的类型标记为未测；AI 内容质量不通过空白样例或新生成任务伪装成全面通过。
- 服务商侧请求计费及 CNVD/CNNVD 授权官方记录不属于这次版式修复可证明的范围。
