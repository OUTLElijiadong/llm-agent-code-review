# 全域 AI 上下文压缩：待办与边界

1. 发布前须跑最终后端全量回归和独立复核；发布后核对版本 SHA、前后端镜像、备份恢复、迁移、HTTPS、健康，并在 390px 真浏览器复测表格。
2. 生产真实调用按入口逐项记录：旧 `/ai/chat` 长历史、公开 `/v1/responses` 历史压缩、正式协同审查、安全哨兵 `full` 模式、全链审计、圆桌追问。每项标明真实模型成功/失败、来源覆盖、模型完成原因和账号/凭据边界；当前定向桩测试不等于生产模型结果。对超大来源超过调用上限的情形保留明确失败与覆盖缺口，不能写成完整审计。
3. `audit_knowledge_loader` 的静态知识文件仍按预算摘录。现在显示每个文件的来源指纹及已摘录/省略段数；若要求模型读取全部知识规则，需要另设多轮来源压缩和成本预算。
4. 公开 `/v1/responses` 是上游 Bearer 密钥命名空间，并不使用 Prism 登录账号 ID；小菱产品聊天另按 Prism 账号隔离。共用同一上游密钥的外部调用者须把该密钥视为同一身份。
5. 来源 ID 与短引文能检查来源覆盖和明显伪造，无法严格证明模型摘要没有语义遗漏。重要约束仍须通过端到端断言和用户可追溯原文复核。
6. “全域”是产品目标，本轮已覆盖旧聊天、公开 Responses、正式审查、安全哨兵、全链审计和圆桌主路径，并非所有模型调用入口都已证明具备同等压缩能力。后续逐项盘点 `personalization_service.py` 的论坛发帖助手、`pentest_service.py` 的多阶段调用、`sandbox_service.py` 的 Agent 测试生成、`tool_gateway.py` 的工具输出摘要，以及 `agent_team_summary.py` 的有界团队问题摘要；针对进入模型的长输入补来源覆盖与失败态回归。展示用预览和日志字段与模型上下文分别评估，不能把前者的缩略计为已压缩上下文。
