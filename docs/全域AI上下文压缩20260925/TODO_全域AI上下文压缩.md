# 全域 AI 上下文压缩：待办与边界

1. v4.0.15 已完成最终后端全量回归、独立备份恢复、版本 SHA/镜像/迁移/HTTPS/健康核对及 Safari 390px 真实重开。长表格的横向手势位移仍缺可确认的浏览器证据，需在真机补验。
2. 生产真实调用仍须按入口逐项补验：旧 `/ai/chat` 长历史、正式协同审查、安全哨兵 `full` 模式、全链审计和圆桌超限追问。公开 `/v1/responses` 的一组真实历史压缩已成功，另一组在调用者显式设置 1024/4096 输出上限时返回 `incomplete`；取消上限的复跑又遇到上游 HTTP 402，须待该外部状态恢复后复测，不能推断默认预算必然成功。调用者可增大预算或缩小回答任务，网关不得擅自违反接口参数。每项标明真实模型成功/失败、来源覆盖、模型完成原因和账号/凭据边界；当前定向桩测试不等于生产模型结果。对超大来源超过调用上限的情形保留明确失败与覆盖缺口，不能写成完整审计。
3. `audit_knowledge_loader` 的静态知识文件仍按预算摘录。现在显示每个文件的来源指纹及已摘录/省略段数；若要求模型读取全部知识规则，需要另设多轮来源压缩和成本预算。
4. 公开 `/v1/responses` 是上游 Bearer 密钥命名空间，并不使用 Prism 登录账号 ID；小菱产品聊天另按 Prism 账号隔离。共用同一上游密钥的外部调用者须把该密钥视为同一身份。
5. 来源 ID 与短引文能检查来源覆盖和明显伪造，无法严格证明模型摘要没有语义遗漏。重要约束仍须通过端到端断言和用户可追溯原文复核。
6. “全域”是产品目标，本轮已覆盖旧聊天、公开 Responses、正式审查、安全哨兵、全链审计、圆桌主路径，以及 v4.0.15 的论坛助手、渗透背景和团队依赖，并非所有模型调用入口都已证明具备同等压缩能力。v4.0.16 候选已修复 `pentest_service.py` 其余阶段、`declarative_agent_runtime.py` 的 Skill 只读结果、沙箱报告三条知识固定裁切与正式审查聚合覆盖口径；4847 项本地回归通过，生产发布尚未完成。沙箱报告知识压缩设单轮 12 次调用、单来源 24000 字上限，超限明确失败，不能称为完整处理。`sandbox_service.py` 的 Agent 测试生成已使用来源分片压缩，仍需对应生产实测。`tool_gateway.py` 的千字截取只用于日志预览，不是模型上下文压缩。`agent_team_summary.py` 是确定性汇总而非模型调用；v4.0.15 已改为用完整私有结果计入第 201 条问题，公开前 20 条仍是明确标记的预览。对真实模型输入补来源覆盖与失败态回归，展示预览和日志字段另行评估。
