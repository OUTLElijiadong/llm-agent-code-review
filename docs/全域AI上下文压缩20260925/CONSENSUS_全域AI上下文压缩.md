# 全域 AI 上下文压缩：实现共识

1. 模型输入先按配置的上下文窗口与当前输出预算估算；能够完整容纳时直接传送带顺序和来源的原文。
2. 超预算时只压缩可投影的历史、工具输出和非源码知识；当前用户请求、强制规则、源码范围与账号归属不得静默丢失。多来源先分片、再按来源 ID 校验摘要覆盖，完整账本仍持久保存。
3. 压缩、模型输出或来源验证失败时明确记录失败和覆盖缺口，不把部分审查标为完整成功，也不把原始 JSON 当成自然语言发言。
4. 圆桌正常完成后保留固定五分钟追问；已接收问题可在后台有序回答，超过截止时间禁言。手机端分别显示正式讨论进度和追问等待状态，长表格能阅读。
5. 生产验收至少核对版本、镜像、备份、迁移、健康和真实账号操作；一份真实文件的成功不能替代其他入口的验收。

范围：旧聊天兼容入口、公开 Responses 网关、论坛助手、渗透阶段、团队依赖与只读 Skill、沙箱报告知识引用、安全审计固定裁剪、正式协同审查非源码上下文与聚合完成口径，以及相关回归与文档。逐入口验收仍受上游 HTTP 402 的实际状态限制；未真实验证或仍未覆盖的模型入口必须在待办中明确列出，不能宣称全域完成。
