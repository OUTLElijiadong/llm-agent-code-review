# CONSENSUS：全服管理 Agent 与内测前检查

## 架构决策

1. 保留 Agent 编码 `operations`，升级名称、职责契约和工具描述，避免历史审计、调度任务和治理画像断链。
2. 后端继续通过 `admin_execute_operation` 调用宿主机执行器；扩充结构化动作，不新增平行 API。
3. Root 执行器仍只监听 `/run/prism-ops/agent.sock`，使用独立令牌鉴权，不开放 TCP 端口。
4. 增加整机只读动作：主机清单、目录清单、脱敏文本文件检查。
5. 增加整机写动作：systemd 单元、Docker 容器、原子文本配置、软件包、防火墙、系统账户和 SSH 公钥管理。
6. 不增加任意 Shell、任意 argv、任意 SQL或自定义脚本工具；执行器只用固定可执行文件与严格枚举参数组装命令。
7. 文本写入只接受 UTF-8、小体积普通文件，拒绝 `/proc`、`/sys`、`/dev`、`/run` 和敏感凭据路径；覆盖前校验可选 SHA-256，并在 Root 专用目录保留原文件副本。
8. 账户工具不接受明文密码；SSH 工具只接受合法公钥，不能读取或写入私钥。
9. 所有非只读动作走 Responses 持久化审批；critical 审批卡必须输入“确认执行”，不能单击直接执行。
10. 执行器在后端数据库审计之外再写宿主机 JSONL 证据，参数按动作脱敏，避免单一审计源。
11. 生产发布前先创建并隔离验证数据库备份，再部署，再执行管理员/普通用户端到端验收，最后独立复核。
12. 新增 `admin_execute_capability` 固定能力工具；模型只选择能力编码和类型化参数，HTTP 方法与路径由注册表硬绑定。
13. 参数契约从应用 OpenAPI/Pydantic 模型生成，执行时使用当前管理员身份调用应用自身 API，保留原路由的认证、权限、校验和业务服务。
14. 所有业务写入都经 Responses 持久化审批和幂等执行账本；删除、发布/回滚、用户/RBAC、密钥配置、内测码和进化决策归为 critical。
15. 契约测试直接扫描管理路由和管理侧栏，任何新页面未加入能力注册表时失败。

## 风险分级

| 等级 | 动作 | 执行规则 |
| --- | --- | --- |
| low | 平台状态、证书状态、整机清单、目录清单、非敏感文件读取 | 自动执行并审计 |
| medium | 无容易回退的业务写入 | 普通批准 |
| high | 创建/验证数据库备份、平台容器重启、证书续期、数据库维护、白名单配置修改 | 普通批准 |
| critical | 删除、发布/回滚、用户/RBAC、密钥配置、内测码、进化决策；systemd/Docker 整机处置、服务器文件写入、软件包/防火墙/账户/公钥变更、应用回滚、数据库恢复、生产清理 | 输入“确认执行”并批准 |

## 验收口径

- 普通用户不能看到或调用管理员 Agent 工具；伪造 `surface=admin` 必须被拒绝。
- 管理员可获得真实整机清单，至少包含 systemd、Docker、监听端口、磁盘和内存事实。
- Agent 可在临时目录完成“读取 -> 带 SHA-256 写入 -> 回滚副本 -> 再读取”闭环，不触碰正式配置。
- critical 动作未输入确认短语时前端不能提交；拒绝后不得执行；批准后同一请求最多执行一次。
- 生产代码审查平台、FlyTrap 和其他既有服务在部署前后状态一致，除明确批准的动作外不得重启。
- 最新数据库备份必须同时通过 gzip、SHA-256 和隔离恢复验证。
- 23 个 `/admin` 页面的每个真实 API 动作均有固定能力映射；普通用户不能获得该工具或绕过执行校验。
