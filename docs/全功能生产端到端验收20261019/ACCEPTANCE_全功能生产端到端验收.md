## 部署预检阻断

执行了正式事务命令：`DEPLOY_ENV_FILE=<受保护的主工作区部署环境文件> ./deploy/deploy.sh all --revision 3711e3115cfa618c351464eab4dbfe6c2c27fe77`。隔离 worktree 自身没有 `deploy/.env`；复用既有受保护部署环境路径后，脚本首先报告 `MYSQL_ROOT_PASSWORD 必须至少 32 个字符` 并返回非零；对最终候选 SHA `3711e3115cfa618c351464eab4dbfe6c2c27fe77` 的本次正式预检也在同一门禁退出。随后对受保护文件仅检查变量名和长度，没有输出或改动凭据，确认 `MYSQL_ROOT_PASSWORD` 与 `MYSQL_PASSWORD` 均短于 32 个字符。两项还必须各包含至少三类字符且互不相同。该配置未设置 `APP_DOMAIN`；部署脚本后续还会检查域名证书、ACME webroot 与 GeoLite 数据路径，因此仅修复数据库密码不足以证明预检可通过。

为诊断 Docker 可用性启动了本机 Docker Desktop。它使用本机 `desktop-linux` context；Docker 启动后配置了自动重启的容器被引擎启动，其中 Prism 命名的 MySQL 容器健康，但没有运行中的 Prism Backend 或 Frontend。项目指南要求在 Linux 发布主机 `/opt/code-review` 发布，因此本机 context 不能作为生产已部署的证据；未在本机继续启动或切换 Prism 服务。以上发布失败发生在备份、构建、迁移或服务切换之前，没有由发布脚本修改任何数据或服务，也没有修改生产密码。

为查找可用的 Linux 发布入口，只读检查了现有 SSH 配置和 Docker context。配置中的远程主机探测未得到任何授权会话：3 个目标连接超时，1 个目标拒绝现有公钥认证；Docker context 列表也只有本机 `default` 与 `desktop-linux`。这些目标均无法据此确认是 `/opt/code-review` 发布主机，故当前仍没有可执行的生产 SSH/Docker 发布通道。
