# 全功能生产端到端验收：共识与验收标准

## 需求共识

用户要求正式部署后验证代码审查、黑白盒审计和远程网站评估报告；报告需属于当前账号可见范围，状态、内容、格式准确易读；无权查看的报告不得以空卡片显示。用户明确要求产品版本使用不超过三段的版本号（本次候选 `4.1.11`），GitHub 上传失败不应阻止可用版本部署。

## 已确认的实现与发布方式

1. 复用现有报告生成、权限判断和导出接口，不新造报告 API。
2. 无可用评分或覆盖证据不足时显示“未评估”，文件行及所有导出也不得残留不匹配的旧分数。
3. 保持真实任务成功、失败、部分覆盖和未验证状态；AI 自报成功不能替代独立测试证据。
4. JSON、HTML、PDF、Word 复用同一份规范化报告内容，清理 Markdown 展示残留，保留代码内容和星号运算语义。
5. 无权访问的报告不展示在当前账号列表中；后端详情/导出继续由权限校验保护。
6. 使用既有 Linux 正式发布脚本发布单一 SHA，产品版本固定为 `4.1.11`；GitHub 上传不作为部署门槛。
7. 生产报告优先复用当前账号可见的样本，不以其他账号数据代替。用户明确授权后，可对指定 HTTPS 根地址发起一次受限只读评估；本平台仍要求另一账号具备“渗透测试授权”权限并独立审批，批准前不会探测。

## 验收边界

- 产品部署已完成，不因 GitHub 上传失败回滚或再次改版本。
- 不为了填补报告样本而擅自发起新代码审查、沙箱或远程扫描。
- 不改变用户角色、权限、密码或模型配置。
- “报告生成接口测试通过”不等价于“生产真实报告已导出”；无样本时分别记录。
- 页面抽样仅覆盖验收记录明确列出的路由，不扩展为全站结论。
