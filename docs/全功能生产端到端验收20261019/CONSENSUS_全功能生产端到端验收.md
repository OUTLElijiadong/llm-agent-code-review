# 全功能生产端到端验收：共识与验收标准

## 需求共识

在不反复改版本、不阻断于 GitHub 上传、不删除数据、不制造无谓模型成本的前提下，基于生产 `4.1.10` 对用户可见路由、已有报告展示/导出、角色隔离和报告页逐屏滚动做真实浏览器验收。已确认的模式来源、沙箱汇总计数和 Word 标题问题应修复并在生产复测。报告生成只能通过既有真实报告/领域数据验证；没有当前审查员可见的远程评估样本时，不启动新扫描，也不声称该类型已完成端到端验证。

## 技术方案

1. 从报告快照 `coverage.requested_mode` 或任务 `coverage.requested_mode` 中选择明确受支持的沙箱模式，写入报告列表 `source.test_mode`。
2. 前端将 `source.test_mode` 传给既有 `reviewTypeLabel`；只有白盒、黑盒、黑白盒组合三种明确模式改变卡片标签，缺失值仍保留“模式未记录”。
3. 沙箱报告汇总按真实 markdown 结构解析分组标题与显式问题编号；提示/待复核/未分级项保持未分级，不强行归为低危。
4. Word 报告标题使用居中 18pt 中文字体，保留标题原文并避免默认超大标题样式导致长任务 ID 多行溢出。
5. 报告权限由服务端对象归属/来源权限结果与前端显式 `can_view_report` 共同 fail-closed。生产用审查员账号检查卡片、详情、导出；无权限项不得以占位卡展示。
6. 保持版本号 `4.1.10`；将所有修正合并为一个精确候选 SHA，使用现有正式部署脚本与数据备份/健康门禁，仅部署一次；不执行 GitHub 上传。
7. 发布后在生产真实浏览器点击和滚动验证。自动化测试作为代码质量证据，不替代生产接受测试。

## 约束

- 不运行新渗透扫描、代码审查或沙箱任务，仅为验收复用已有报告。若发现所有已有报告均缺失而需要新建带模型调用的任务，应先报告具体 token 成本风险并暂停该操作。
- 不进行任何删除、用户角色修改、权限扩张、密钥/模型设置变更。
- CNVD 与 CNNVD 必须分别声明证据；除非两者明确返回无匹配，OWASP 只能作为单独标明的次级参考。没有授权数据不能模拟命中或伪称已接入。
- 页面抽样须记录路由、登录角色、可见内容、交互、滚动完整度、异常和观察时间；不把有限抽样扩大成未测路由全通过。

## 验收门槛

- 列表、详情、导出均保持报告任务与来源一致，失败/部分/未知状态不会变成成功。
- 代码报告、沙箱黑盒/白盒/组合报告和远程评估报告仅在当前账号可读时显示；当前账号无权访问时列表无卡片，详情和导出后端仍拒绝。
- 报告导出格式与来源匹配，HTML/PDF/Word/JSON 可读且章节、计数、证据一致；不出现无依据评分、空白报告或 Markdown 星号装饰符。
- 真实生产页面逐页滚动检查不发现隐藏溢出、截断或按钮不可达；不宣称未检查页面通过。
- 小菱停止行为需确认当前执行真实状态；停止后不能因自动监控无条件复活同一被停止任务。当前请求在途可结束的情形必须透明说明。
- 远程评估页面对审查员没有可读任务样本时，验收结论只能是权限列表无卡片、报告生成无法实测；启动远程测试必须有用户明确指定的 HTTPS 根域名和授权依据。
- 发布服务版本仍为 `4.1.10`，生产健康/就绪与实际代码 SHA 一致，发布失败则停止并按发布事务回滚。

## 状态

共识已形成。首个生产候选已部署为 `4.1.10`；生产复测发现汇总 parser 与 Word 标题的两个具体缺陷，正在以同一版本号修复并准备唯一纠正发布。其余生产验收边界记录在验收文档中，不用“全功能通过”掩盖无样本项目。
