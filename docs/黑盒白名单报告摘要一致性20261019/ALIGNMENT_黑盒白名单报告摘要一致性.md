# 黑盒白名单报告摘要一致性需求对齐

## 原始需求

用户要求先在产品中强制执行本机黑盒 HTTP 路径白名单，再用固定的 PHP 靶场在生产产品内运行一次并展示真实请求、测试结论和覆盖缺口。4.1.12 已包含并部署该白名单执行链；本轮已获用户授权运行一次。执行成功后发现报告摘要与实际证据不一致，需要修正。

## 项目理解

白名单黑盒执行证据由服务端保存的 `blackbox_execution` 请求回执提供，逐项包含请求目标、HTTP 状态码、响应字节数、耗时与断言状态；`agent_test_generation` 记录 AI 动态用例是否生成或跳过。`_sandbox_execution_disclosure()` 负责生成确定性报告中的覆盖摘要与白名单细节。

## 已复现的问题

生产任务 `sbx_7d1ffc7ba9cb40c1bca743d3` 已按三条精确 GET 白名单运行完成。报告下半部分列出了三条实际请求，报告上半部分却同时写“执行器未提供可核验的逐项范围”“执行器未报告未扫描项”“无已记录跳过项”。`agent_test_generation.status=skipped`，白名单外路径发现也明确未执行，因此这些摘要文字与同一份报告的证据段相矛盾。

## 范围边界

- 修正确定性报告从已有结构化证据推导“已测试范围、未扫描范围、跳过项”的逻辑。
- 保留旧任务没有逐项证据时的“未知”说明，不从空值推断覆盖完成。
- 保持白名单黑盒总体状态为“部分通过”，不把 HTTP 状态断言通过解释为漏洞验证或完整覆盖。
- 保留历史报告，不批量改写；不再次运行第三方靶场。
- 本次按用户既定生产验收偏好，不在本机运行产品测试；通过代码评审、静态检查与部署后现有生产报告链路核验。

## 待确认问题

无。实际请求范围、AI 跳过状态与未覆盖路径均已由生产报告和固定白名单给出。
