# 黑盒白名单报告摘要一致性需求共识

## 明确需求与验收标准

确定性报告的摘要必须与同一任务的执行证据一致：

1. 精确白名单回执含请求条目时，“已测试范围”列出实际请求目标；没有回执时才显示范围未知。
2. 精确白名单执行明确不做路由发现时，“未扫描范围”说明白名单外路径未扫描；只有明确确认不存在缺口时才能写无未扫描项。
3. AI 测试生成状态为 `skipped` 时，“跳过项”必须列出 AI 动态测试未执行及可用原因；其他任务没有跳过证据时保留未知/无已记录项的既有语义。
4. 本机黑盒每项状态断言仍按真实回执显示；整体验证门禁仍为部分通过，明确没有运行 AI 动态用例和白名单外路由发现。
5. 不保存响应正文，不批量改写历史报告，不重复运行此次靶场。
6. 对此次已确认矛盾的报告，创建者重复请求终态“停止”时，允许仅根据持久化执行结果重建确定性报告；该动作不得触发 Worker、HTTP 请求或模型调用。

## 技术方案

调整 `backend/app/services/sandbox_service.py` 的确定性报告摘要派生与终态报告刷新逻辑，并在已有 `test_sandbox_report_publish.py` 增加边界回归用例。优先使用显式 `coverage` 字段；精确白名单与 AI 跳过状态有可信证据但覆盖字段缺失时，再从结构化证据派生摘要。完全没有证据的旧任务继续报告未知。历史报告仅在已持久化的精确白名单回执非空且摘要包含已知矛盾文案时刷新。

## 质量门控

- 与精确 HTTP 明细段使用同一 `blackbox_execution.requests` 数据源，避免两段口径分叉。
- 缺失、损坏或终止中的证据不得被推断成通过或完整。
- 不新增接口、表结构或数据迁移。
- 静态审阅确认报告文案不存在同任务的“已列出范围”与“未提供范围”冲突。
- 部署后只用既有真实执行记录验证报告链路，不再次运行靶场。
