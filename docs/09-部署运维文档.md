## 3. 配置:`.env`

项目根目录放 `.env`(从 `.env.example` 复制),用于 docker-compose 与后端读取。

```ini
# ===== 通用 =====
APP_ENV=prod
LOG_LEVEL=INFO
OPENAPI_ENABLED=false

# ===== 数据库 =====
MYSQL_ROOT_PASSWORD=please_change_me_strong
MYSQL_DATABASE=code_review
MYSQL_USER=code_review
MYSQL_PASSWORD=please_change_me_too
DB_HOST=mysql
DB_PORT=3306
DB_USER=code_review
DB_PASSWORD=please_change_me_too
DB_NAME=code_review

# ===== JWT =====
JWT_SECRET=replace-with-32-bytes-random-string
JWT_EXPIRE_SECONDS=604800

# ===== DeepSeek =====
DEEPSEEK_API_KEY=sk-xxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT=60
DEEPSEEK_MAX_RETRIES=2
DEEPSEEK_CHUNK_THRESHOLD=6000

# ===== 上传 =====
MAX_UPLOAD_SIZE=204800

# ===== CORS =====
CORS_ORIGINS=["http://localhost"]
```

> `.env` **不入版本库**(.gitignore 中)。仓库只提交 `.env.example`。

## 4. docker-compose

### 4.1 完整版 `deploy/docker-compose.yml`

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: cr_mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --default-authentication-plugin=mysql_native_password
    volumes:
      - mysql_data:/var/lib/mysql
      - ./mysql/init.sql:/docker-entrypoint-initdb.d/01_init.sql
      - ./mysql/seed.sql:/docker-entrypoint-initdb.d/02_seed.sql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 10s
      timeout: 5s
      retries: 10
    ports:
      - "3306:3306"

  backend:
    build:
      context: ../backend
      dockerfile: Dockerfile
    container_name: cr_backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
    environment:
      APP_ENV: ${APP_ENV}
      LOG_LEVEL: ${LOG_LEVEL}
      OPENAPI_ENABLED: ${OPENAPI_ENABLED}
      JWT_SECRET: ${JWT_SECRET}
      JWT_EXPIRE_SECONDS: ${JWT_EXPIRE_SECONDS}
      DB_HOST: ${DB_HOST}
      DB_PORT: ${DB_PORT}
      DB_USER: ${DB_USER}
      DB_PASSWORD: ${DB_PASSWORD}
      DB_NAME: ${DB_NAME}
      DEEPSEEK_API_KEY: ${DEEPSEEK_API_KEY}
      DEEPSEEK_BASE_URL: ${DEEPSEEK_BASE_URL}
      DEEPSEEK_MODEL: ${DEEPSEEK_MODEL}
      DEEPSEEK_TIMEOUT: ${DEEPSEEK_TIMEOUT}
      DEEPSEEK_MAX_RETRIES: ${DEEPSEEK_MAX_RETRIES}
      DEEPSEEK_CHUNK_THRESHOLD: ${DEEPSEEK_CHUNK_THRESHOLD}
      MAX_UPLOAD_SIZE: ${MAX_UPLOAD_SIZE}
      CORS_ORIGINS: ${CORS_ORIGINS}
    command: >
      sh -c "alembic upgrade head &&
             uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2"
    volumes:
      - backend_logs:/app/logs
    ports:
      - "8000:8000"

  frontend:
    build:
      context: ../frontend
      dockerfile: Dockerfile
    container_name: cr_frontend
    restart: unless-stopped
    depends_on:
      - backend
    ports:
      - "80:80"

volumes:
  mysql_data:
  backend_logs:
```

## 5. nginx 配置(前端容器内)

`deploy/nginx.conf`:

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;
    client_max_body_size 5m;

    # SPA 兜底
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代到后端容器
    location /api/ {
        proxy_pass         http://cr_backend:8000;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 90s;
        proxy_send_timeout 90s;
    }

    # 健康检查
    location = /healthz {
        proxy_pass http://cr_backend:8000/healthz;
    }

    # 静态资源缓存
    location ~* \.(?:js|css|woff2?|ico|svg|png|jpg|jpeg|gif)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript application/xml image/svg+xml;
    gzip_min_length 1024;
}
```

## 6. 部署步骤

### 6.1 准备工作

```bash
# 1. 服务器装 Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2. 装 Docker Compose 插件(docker engine 24+ 已自带,如有需要)
docker compose version

# 3. 克隆代码
git clone <your-repo>
cd 基于大模型智能体的代码审查平台
```

### 6.2 配置环境

```bash
cp .env.example .env
vi .env                # 填入 DEEPSEEK_API_KEY、强密码等
```

需要修改:
- `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` 替换为强密码
- `JWT_SECRET` 用以下命令生成:`openssl rand -hex 32`
- `DEEPSEEK_API_KEY` 替换为你的真实 key
- `CORS_ORIGINS` 改成生产域名,例如 `["https://review.example.com"]`

### 6.3 启动

```bash
cd deploy
docker compose --env-file ../.env up -d
```

首次启动:
- `mysql` 初始化数据库,执行 `init.sql` + `seed.sql`
- `backend` 等待 mysql 健康,然后 `alembic upgrade head`,再启动 uvicorn
- `frontend` 启动 nginx

### 6.4 验证

```bash
# 容器状态
docker compose ps

# 后端健康
curl http://localhost:8000/healthz

# 前端
open http://localhost
```

默认管理员账号(由 `seed.sql` 创建):
- 用户名:`admin`
- 密码:`admin123`(首次登录后立即改)

## 7. 数据迁移(Alembic)

### 7.1 首次部署

`backend` 容器启动命令已经包含 `alembic upgrade head`,无需手动。

### 7.2 后续升级

代码更新后:

```bash
cd deploy
docker compose pull         # 若用了镜像仓库
docker compose build backend
docker compose up -d backend
```

migrations 在容器启动时自动跑。

### 7.3 手动迁移

```bash
docker compose exec backend alembic upgrade head
docker compose exec backend alembic current
docker compose exec backend alembic history
docker compose exec backend alembic downgrade -1   # 回滚一步(谨慎)
```

## 8. 日志

### 8.1 日志位置

- 后端日志:容器内 `/app/logs/*.log`,通过 `backend_logs` 命名卷持久化
- nginx 日志:容器内 `/var/log/nginx/`
- MySQL 慢查询:容器内 `/var/lib/mysql/*-slow.log`(可选开启)

### 8.2 查看

```bash
# 实时
docker compose logs -f backend
docker compose logs -f --tail=200 mysql
docker compose logs -f frontend

# 持久化日志文件
docker compose exec backend ls -lh /app/logs
docker compose exec backend tail -n 200 /app/logs/app.log
```

### 8.3 日志清理

```bash
# 限制容器日志大小,在 daemon.json 配置(/etc/docker/daemon.json)
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "5" }
}
```

## 9. 备份与恢复

### 9.1 数据库备份

```bash
# 每日备份脚本 /usr/local/bin/cr_backup.sh
#!/bin/bash
DATE=$(date +%F)
DIR=/var/backups/code-review
mkdir -p "$DIR"
docker compose -f /opt/code-review/deploy/docker-compose.yml exec -T mysql \
  mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" code_review > "$DIR/db_$DATE.sql"
# 保留 14 天
find "$DIR" -mtime +14 -name 'db_*.sql' -delete
```

crontab:

```
0 3 * * * /usr/local/bin/cr_backup.sh >> /var/log/cr_backup.log 2>&1
```

### 9.2 恢复

```bash
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" code_review < /path/to/db_2026-05-26.sql
```

### 9.3 卷备份

```bash
# 备份 backend logs 卷
docker run --rm -v code-review_backend_logs:/data -v $PWD:/backup alpine \
  tar czf /backup/backend_logs_$(date +%F).tar.gz -C / data
```

## 10. 监控与告警(可选)

毕设可选,但作为亮点可写一段。

可接入 Uptime Kuma 等开源监控,每分钟探测。

### 10.2 关键指标

| 指标 | 来源 | 阈值 |
| --- | --- | --- |
| 请求 5xx 数 | nginx access_log / FastAPI 日志 | >5/分钟 告警 |
| DeepSeek 失败率 | `ai_call_log.status` 聚合 | >20% 告警 |
| 审查任务排队时长 | `review_task.create_time` - `start_time` | >30s 告警 |
| 数据库连接数 | `SHOW STATUS LIKE 'Threads_connected'` | >50 告警 |

## 13. 常见问题(FAQ)

### Q1:启动后 backend 容器一直 restart

检查:`docker compose logs backend`。常见原因:
- MySQL 未就绪 → 等待 30 秒后自愈
- `.env` 缺字段 → 对照 `.env.example`
- migration 失败 → `docker compose exec backend alembic current` 看版本

### Q2:登录返回 502

`nginx` 反代到 `cr_backend:8000`,但后端没起。`docker compose ps` 看状态。

### Q3:DeepSeek 调用 401

`DEEPSEEK_API_KEY` 错误,或 base url 写错。`curl https://api.deepseek.com/chat/completions -H "Authorization: Bearer $KEY"` 验证。

### Q4:前端报 CORS

`CORS_ORIGINS` 未包含访问域名。改 `.env` 后 `docker compose restart backend`。

### Q5:上传文件 413

nginx `client_max_body_size` 默认 1m。配置文件已改 5m,如仍报错,扩大该值并 reload。

### Q6:容器跑一段时间内存涨

MySQL 默认 InnoDB buffer pool 128MB。在 `my.cnf` 中限制:

```ini
[mysqld]
innodb_buffer_pool_size = 256M
max_connections = 100
```

## 14. 一键启动脚本

`scripts/start.sh`:

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")/.."

if [ ! -f .env ]; then
  echo "未找到 .env, 从 .env.example 复制并填写后再运行"
  cp .env.example .env
  exit 1
fi

cd deploy
docker compose --env-file ../.env up -d
echo "===== 状态 ====="
docker compose ps
echo "前端: http://localhost"
echo "后端: http://localhost:8000"
```

`scripts/stop.sh`:

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")/../deploy"
docker compose down
```

`scripts/logs.sh`:

```bash
#!/usr/bin/env bash
cd "$(dirname "$0")/../deploy"
docker compose logs -f --tail=200 "${1:-}"
```

## 15. 升级流程(零停机简化版)

1. 拉新代码:`git pull`
2. 构建镜像:`docker compose build backend frontend`
3. 滚动重启:`docker compose up -d backend frontend`
4. 健康检查:`curl http://localhost:8000/healthz`
5. 失败回滚:`git checkout <last_tag> && docker compose build && docker compose up -d`

迁移谨慎:`alembic downgrade` 在生产慎用,优先前向修复。
