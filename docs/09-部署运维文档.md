## 4. docker-compose

### 4.1 完整版 `deploy/docker-compose.yml`

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: cr_mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    volumes:
      - mysql_data:/var/lib/mysql
      - ./mysql/init.sql:/docker-entrypoint-initdb.d/01-init.sql
      - ./mysql/seed.sql:/docker-entrypoint-initdb.d/02-seed.sql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5
    ports:
      - "3307:3306"

  backend:
    build: ../backend
    container_name: cr_backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
    env_file: .env
    environment:
      APP_ENV: prod
      DB_HOST: mysql
      DB_PORT: 3306
      DB_USER: ${MYSQL_USER}
      DB_PASSWORD: ${MYSQL_PASSWORD}
      DB_NAME: ${MYSQL_DATABASE}
    ports:
      - "8000:8000"

  frontend:
    build:
      context: ../frontend
      dockerfile: Dockerfile
    container_name: cr_frontend
    restart: unless-stopped
    depends_on:
      - backend
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - caddy_data:/data
      - caddy_config:/config

volumes:
  mysql_data:
  caddy_data:
  caddy_config:
```

### 4.2 本地开发只起 MySQL

当前仓库没有 `deploy/docker-compose.dev.yml`。本地开发直接复用完整版 Compose 的 mysql 服务:

```bash
docker compose --env-file .env -f deploy/docker-compose.yml up -d mysql
```

也可以直接运行根目录 `./dev.sh`,它会确保 `cr_mysql` 运行,并分别启动后端热重载与前端 HMR。

## 5. Caddy 配置(前端容器内)

`frontend/Caddyfile` 负责静态资源、API 反代、HTTP 跳转 HTTPS 和 Let’s Encrypt 自动证书。核心结构:

```caddyfile
lijiadong.cn {
    encode gzip zstd
    reverse_proxy /api/* backend:8000
    reverse_proxy /docs backend:8000
    reverse_proxy /openapi.json backend:8000
    root * /usr/share/caddy
    try_files {path} {path}/ /index.html
    file_server
}
```

## 6. 部署步骤

### 6.1 准备工作

```bash
# 1. 服务器装 Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2. 装 Docker Compose 插件(docker engine 24+ 已自带,如有需要)
docker compose version

# 3. 克隆代码
git clone <your-repo>
cd 基于大模型智能体的代码审查平台
```

### 6.2 配置环境

```bash
cd deploy
cp .env.example .env
vi .env                # 填入 DEEPSEEK_API_KEY、强密码等
```

需要修改:
- `MYSQL_ROOT_PASSWORD` / `MYSQL_PASSWORD` 替换为强密码
- `JWT_SECRET` 用以下命令生成:`openssl rand -hex 32`
- `DEEPSEEK_API_KEY` 替换为你的真实 key
- `CORS_ORIGINS` 改成生产域名,例如 `["https://review.example.com"]`

### 6.3 启动

```bash
cd deploy
docker compose --env-file .env up -d --build
```

首次启动:
- `mysql` 初始化数据库,执行 `init.sql` + `seed.sql`
- `backend` 等待 mysql 健康,然后启动 uvicorn
- `frontend` 启动 Caddy，对外暴露 `80/443`

### 6.4 验证

```bash
# 容器状态
docker compose ps

# 后端健康
curl http://localhost:8000/healthz

# 前端
open http://localhost
```

默认管理员账号(由 `seed.sql` 创建):
- 用户名:`admin`
- 密码:`admin123`(首次登录后立即改)

## 7. 数据结构同步

### 7.1 首次部署

当前仓库没有 Alembic 版本文件,全新数据库通过 `deploy/mysql/init.sql` 初始化 14 张业务表。

### 7.2 后续升级

代码更新后:

```bash
cd deploy
docker compose --env-file .env up -d --build
```

如果后续引入新的表/字段,需要同步更新 `deploy/mysql/init.sql` 和 Alembic 迁移文件;在当前状态下,已有库的结构变更需手动执行对应 SQL 或补建迁移后再部署。

### 7.3 手动迁移

```bash
# 当前没有 migrations 可跑。若后续新增迁移文件,再使用:
docker compose exec backend alembic upgrade head
```

## 8. 日志

### 8.1 日志位置

- 后端日志:容器内 `/app/logs/*.log`;当前 compose 未挂载日志卷,生产环境如需持久化需增加 volume
- Caddy 日志:`docker compose logs -f frontend`
- MySQL 慢查询:容器内 `/var/lib/mysql/*-slow.log`(可选开启)

### 8.2 查看

```bash
# 实时
docker compose logs -f backend
docker compose logs -f --tail=200 mysql
docker compose logs -f frontend

# 持久化日志文件
docker compose exec backend ls -lh /app/logs
docker compose exec backend tail -n 200 /app/logs/app.log
```

### 8.3 日志清理

```bash
# 限制容器日志大小,在 daemon.json 配置(/etc/docker/daemon.json)
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "5" }
}
```

## 9. 备份与恢复

### 9.1 数据库备份

```bash
# 每日备份脚本 /usr/local/bin/cr_backup.sh
#!/bin/bash
DATE=$(date +%F)
DIR=/var/backups/code-review
mkdir -p "$DIR"
docker compose -f /opt/code-review/deploy/docker-compose.yml exec -T mysql \
  mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" code_review > "$DIR/db_$DATE.sql"
# 保留 14 天
find "$DIR" -mtime +14 -name 'db_*.sql' -delete
```

crontab:

```
0 3 * * * /usr/local/bin/cr_backup.sh >> /var/log/cr_backup.log 2>&1
```

### 9.2 恢复

```bash
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" code_review < /path/to/db_2026-05-26.sql
```

### 9.3 卷备份

```bash
# 备份 backend logs 卷
docker run --rm -v code-review_backend_logs:/data -v $PWD:/backup alpine \
  tar czf /backup/backend_logs_$(date +%F).tar.gz -C / data
```

## 13. 常见问题(FAQ)

### Q1:启动后 backend 容器一直 restart

检查:`docker compose logs backend`。常见原因:
- MySQL 未就绪 → 等待 30 秒后自愈
- `.env` 缺字段 → 对照 `.env.example`
- migration 失败 → `docker compose exec backend alembic current` 看版本

### Q2:登录返回 502

前端网关反代到 `cr_backend:8000`,但后端没起。`docker compose ps` 看状态。

### Q3:DeepSeek 调用 401

`DEEPSEEK_API_KEY` 错误,或 base url 写错。`curl https://api.deepseek.com/chat/completions -H "Authorization: Bearer $KEY"` 验证。

### Q4:前端报 CORS

`CORS_ORIGINS` 未包含访问域名。改 `.env` 后 `docker compose restart backend`。

### Q5:上传文件 413

Caddy `request_body` 已配置 50MB。如仍报错,扩大 `frontend/Caddyfile` 中的 `max_size` 后重建前端容器。

### Q6:容器跑一段时间内存涨

MySQL 默认 InnoDB buffer pool 128MB。在 `my.cnf` 中限制:

```ini
[mysqld]
innodb_buffer_pool_size = 256M
max_connections = 100
```

### Q7:低内存服务器前端 Docker 构建 OOM

2GB 内存服务器在 `vue-tsc && vite build` 阶段可能触发 Node heap out of memory。当前 `frontend/Dockerfile` 已设置:

```dockerfile
ENV NODE_OPTIONS=--max-old-space-size=1536
```

如仍失败,先确认 swap:

```bash
free -h
swapon --show
```

腾讯云 2GB 规格建议至少保留 2GB 以上 swap 后再执行 `docker compose --env-file .env up -d --build`。

## 14. 一键启动脚本

`scripts/start.sh`:

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")/.."

if [ ! -f .env ]; then
  echo "未找到 .env, 从 .env.example 复制并填写后再运行"
  cp .env.example .env
  exit 1
fi

cd deploy
docker compose --env-file ../.env up -d
echo "===== 状态 ====="
docker compose ps
echo "前端: http://localhost"
echo "后端: http://localhost:8000"
```

`scripts/stop.sh`:

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")/../deploy"
docker compose down
```

`scripts/logs.sh`:

```bash
#!/usr/bin/env bash
cd "$(dirname "$0")/../deploy"
docker compose logs -f --tail=200 "${1:-}"
```

## 15. 升级流程(零停机简化版)

1. 拉新代码:`git pull`
2. 构建镜像:`docker compose build backend frontend`
3. 滚动重启:`docker compose up -d backend frontend`
4. 健康检查:`curl http://localhost:8000/healthz`
5. 失败回滚:`git checkout <last_tag> && docker compose build && docker compose up -d`

迁移谨慎:`alembic downgrade` 在生产慎用,优先前向修复。
