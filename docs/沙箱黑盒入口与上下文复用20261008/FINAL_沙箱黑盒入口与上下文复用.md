# 沙箱黑盒入口与上下文复用最终报告

## 当前结论

v4.0.92 已完成代码修复、后端测试、发布脚本故障注入与前端构建，但尚未发布到生产。阻断原因是生产根盘最新可用空间仅 `11,083,206,656` bytes（95%），低于部署脚本默认的 12 GiB 容量门槛。现有构建缓存回收未释放文件系统容量；项目清理预览列出 52 个 Backend 和 53 个 Frontend 保留范围外的旧镜像标签。执行前已向用户说明并等待确认，当前生产仍运行 v4.0.91。

## 已复现的生产原因

生产任务 `sbx_b0e1448463804dcea6a696f3` 对 bWAPP/PHP 黑盒源码执行 481 个分片、259 个文件的源码上下文压缩。压缩用了 153 次模型调用、约 1.27M tokens，耗时 `300,050 ms` 后超过共享时间预算；AI 动态用例生成 fail-closed 跳过。确定性黑盒测试独立通过：`/login.php` HTTP 200、runner exit 0，沙箱清理回执 `cleanup_confirmed=true`。最终摘要明确区分“确定性黑盒通过”和“AI 动态补充未执行”。

沙箱事件独立记录 153 次调用和 `300,050 ms` 压缩耗时。按管理员、Agent 标签和任务时间窗汇总到 153 条 AI 调用日志，合计约 1.27M tokens；其中 51 次 `finish_reason=length`（47 次耗尽 2,048 token、2 次耗尽 4,096 token），另有 4 次读超时。AI 日志的 `task_id`/`file_id` 为空，token 与错误分类只按时间窗关联，不能逐条建立任务外键；调用总数与沙箱事件一致。代码先用 2,048、失败后再升到 4,096，首轮预算造成了可避免的重试开销。

## 候选修复

v4.0.92 调整源码摘要压缩的首轮输出额度为 `min(4096, configured_output_tokens)`。来源 ID、源码哈希、逐来源引文、受保护事实、递归无损拆分、调用上限、共享期限和 fail-closed 校验均保留。部署包位于项目验收证据目录，版本源码 SHA 为 `0bda311bbb6fe4a40dc12d9292913e9d687a80b1`。
