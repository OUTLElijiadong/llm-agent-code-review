# 沙箱黑盒入口与上下文复用对齐

## 原始需求

用户要求继续完成 Prism 黑盒、白盒测试验收，复现实际失败、修复后重跑并完成部署；本轮最新请求为“帮我部署，你看看什么原因”。

## 当前确认的项目与生产基线

- 本轮继续部署前，生产应用为 v4.0.88，代码 SHA `f2a8fd91101abe414e2bec04fd9c99b89c0a23bb`；本次修复候选版本为 v4.0.89。部署前已通过 HTTPS `/healthz` 与 `/readyz` 再次核对该版本和 SHA。
- 候选工作树基于上述生产 SHA 创建。旧主工作区有未提交修改，不纳入本候选。
- 普通 Safari 真实生产任务 `sbx_149fd2ec2fe447b593d9671e` 对 bWAPP 项目执行了本机隔离 PHP 黑盒测试，任务失败；结果回执保留且 Worker 回执确认容器和 job 目录已清理。
- v4.0.88 上通过普通 Safari 创建的 bWAPP PHP 黑盒任务 `sbx_642c37d4a79d4255b4adff0f` 失败，任务记录、失败回执与 cleanup 证据均保留；本轮以该实际任务为修复前样本。

## 已复现问题与证据边界

1. 生产任务中的 bWAPP 源码快照包含 259 个文件、481 个源码片段；上下文压缩经历 34 次模型调用、约 214.8 秒后失败，错误为“达到拆分深度上限：源码分片摘要为空或超长”。原来每批最多 8 项、18,000 字符，单片摘要硬限 600 字，实际项目会反复递归拆分并仍可能被摘要长度门禁拒绝。这是动态用例和部署计划被跳过的直接原因。
2. 同一任务的 PHP 文档根已正确解析为 `bWAPP-master/app`，但程序根路径 `/` 返回 404；源码扫描没有找到候选路径，旧逻辑只探测 `/`，最终 `route_origin=none`、HTTP 状态码 0。Worker 正常启动并回收容器；因此这是独立于 AI 压缩的 PHP 入口探测缺口。
3. 候选修复按模型配置的上下文窗口计算有上限的批次预算，将最大字符数限制在 120,000、来源项数限制在 32、摘要上限调整为 1,200；不截断源码或摘要。PHP runner 增加固定 GET 白名单入口探测，只检查存在的 `index.php`、`login.php`、`home.php`、`dashboard.php` 和 `admin/index.php`，不探测任意 PHP 文件。
4. 测试以 481 个源码片段和超过旧摘要上限的摘要验证来源覆盖、批量压缩及不静默截断；这不是“超过 100 万 token”的真实模型容量证明。生产是否修复仍以 v4.0.89 发布后的 Safari 真实任务回执为准。

## 生产发布入口核查

- Worker systemd 当前运行树为 `/opt/prism-releases/f2a8fd91101abe414e2bec04fd9c99b89c0a23bb`；生产主机磁盘使用率 91%，可用 17 GiB。发布检查仍要求至少 12 GiB 可用且使用率低于 95%；不自动执行 Docker 或系统磁盘清理。
- 本轮只从该活动 release 树延续，发布脚本重新校验活动 SHA、候选 bundle 摘要/大小、备份恢复及运行健康，不使用旧 `/opt/code-review` 源码状态作为基线。

## 任务范围

- 修复 PHP 黑盒入口根目录发现，覆盖嵌套项目入口，并保持多候选时的确定性与失败诊断。
- 一个沙箱任务内只压缩一次完整源码上下文；部署规划与动态用例复用同一任务作用域的压缩结果、来源 ID 和受保护事实。来源校验、覆盖校验、时间/调用上限保持 fail-closed。
- 在失败回执中明确区分上下文准备、应用启动和路由探测，补齐共享压缩调用数/耗时证据。
- 在本地以原始 bWAPP 回执结构和等价 PHP 多层目录夹具复现，修复后重复原场景并增加正反样本。
- 为大文件片段显式提供路径、片段偏移和原文件总长度，提示压缩模型只归纳片段可见内容；仍保留 SHA、来源 ID、逐字引文、覆盖率和 fail-closed 校验，不把缺片段当作完整上下文。
- 通过代码、测试、发布门禁后，按照 Prism 正式发布流程部署并在生产普通 Safari / Worker 上复测。

## 不在范围内

- 不修改用户旧主工作区的 55 项未提交改动。
- 不改变测试权限、Worker 沙箱隔离、数据库或外部远程目标策略。
- 不删除生产任务、审计记录或证据制品；此次测试记录按用户既往授权保留。
- 不把假模型或本地夹具描述成真实模型的百万 token 理解证明。

## 需求理解与验收

“黑盒/白盒可正常使用”须以具体样本、模式、运行环境、执行回执和清理回执分别记录。压缩不完整时不得继续声称 AI 已完整审查；入口返回 404 也不得伪装通过。部署只从与当前生产代码 SHA 对齐的干净候选工作树进行。
