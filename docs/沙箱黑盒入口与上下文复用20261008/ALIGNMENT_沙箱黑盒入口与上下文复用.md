# 沙箱黑盒入口与上下文复用对齐

## 原始需求

用户要求继续完成 Prism 黑盒、白盒测试验收，复现实际失败、修复后重跑并完成部署；本轮最新请求为“帮我部署，你看看什么原因”。

## 当前确认的项目与生产基线

- 本轮复测开始时生产应用为 v4.0.87，代码 SHA `9ee56b8d9a0cdfb1393df5275814c551bbd48c69`；本次修复候选版本为 v4.0.88。
- 候选工作树基于上述生产 SHA 创建。旧主工作区有未提交修改，不纳入本候选。
- 普通 Safari 真实生产任务 `sbx_149fd2ec2fe447b593d9671e` 对 bWAPP 项目执行了本机隔离 PHP 黑盒测试，任务失败；结果回执保留且 Worker 回执确认容器和 job 目录已清理。
- v4.0.87 部署后又通过普通 Safari 创建了 bWAPP PHP 黑盒任务 `sbx_324746c18daf43ae80e82013`。源码压缩报告“输入 text 为不完整 JSON 数组，末尾 size 值处被截断”，导致动态用例跳过且黑盒路由 `route_origin=none`、`status_code=0`；本轮不把此失败算成通过。

## 已复现问题与证据边界

1. 黑盒 PHP runner 只检查当前目录、`public/` 和单层子目录。bWAPP 入口为 `bWAPP-master/app/index.php`，实际启动根目录落在源码根，`GET /` 返回 404。生产结果日志明确记录 readiness status 404、候选路由数 0；使用同样的两层目录结构及隔离 runner 夹具，本地复现得到相同结果。应用入口识别缺陷已被复现。
2. 部署规划和动态用例生成共享 300 秒 deadline，却各自重新压缩同一份完整源码。生产事件确认部署计划与动态用例都因源码上下文压缩超时而未完成。重复压缩是代码已证实的调用路径；生产具体消耗的模型调用数尚未记录，不能据此声称它是 404 的唯一原因。
3. 生产回执不包含压缩叶子调用数，也不完整呈现压缩失败的阶段计时；本次会补充可审计计数并复用经过哈希、来源覆盖核验的压缩结果。
4. v4.0.87 新失败的直接原因是：归档内单个大文件按偏移切成多个无损源码片段，片段边界不保证保留 JSON 语法；模型把这种边界误判为输入被截断并返回 `error`。应用端随后依来源完整性策略拒绝不完整摘要，因此动态测试被正确跳过。此路径与 PHP 入口 404 是两个独立问题。

## 生产发布入口核查

- `/opt/code-review` 是旧的 v4.0.72 发布上下文，`ops-check` 因账本与当前容器不一致而阻断；它不是当前活动发布目录。
- 当前活动目录 `/opt/prism-releases/22206a5d7b91cc9ae994ced115c350be85ad58a4` 的发布账本与运行镜像一致，`ops-check` 为 `degraded/can_continue=true`，唯一降级项是磁盘 89%（21 GiB 可用）。
- 因此候选发布必须从活动 release 树延续，不得使用旧 `/opt/code-review` 的状态文件；不自动执行磁盘清理。

## 任务范围

- 修复 PHP 黑盒入口根目录发现，覆盖嵌套项目入口，并保持多候选时的确定性与失败诊断。
- 一个沙箱任务内只压缩一次完整源码上下文；部署规划与动态用例复用同一任务作用域的压缩结果、来源 ID 和受保护事实。来源校验、覆盖校验、时间/调用上限保持 fail-closed。
- 在失败回执中明确区分上下文准备、应用启动和路由探测，补齐共享压缩调用数/耗时证据。
- 在本地以原始 bWAPP 回执结构和等价 PHP 多层目录夹具复现，修复后重复原场景并增加正反样本。
- 为大文件片段显式提供路径、片段偏移和原文件总长度，提示压缩模型只归纳片段可见内容；仍保留 SHA、来源 ID、逐字引文、覆盖率和 fail-closed 校验，不把缺片段当作完整上下文。
- 通过代码、测试、发布门禁后，按照 Prism 正式发布流程部署并在生产普通 Safari / Worker 上复测。

## 不在范围内

- 不修改用户旧主工作区的 55 项未提交改动。
- 不改变测试权限、Worker 沙箱隔离、数据库或外部远程目标策略。
- 不删除生产任务、审计记录或证据制品；此次测试记录按用户既往授权保留。
- 不把假模型或本地夹具描述成真实模型的百万 token 理解证明。

## 需求理解与验收

“黑盒/白盒可正常使用”须以具体样本、模式、运行环境、执行回执和清理回执分别记录。压缩不完整时不得继续声称 AI 已完整审查；入口返回 404 也不得伪装通过。部署只从与当前生产代码 SHA 对齐的干净候选工作树进行。
