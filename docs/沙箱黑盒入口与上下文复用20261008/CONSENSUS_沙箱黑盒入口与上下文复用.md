# 沙箱黑盒入口与上下文复用共识

## 需求与实现决策

- 本轮 v4.0.89 候选以已核对的生产 SHA `f2a8fd91101abe414e2bec04fd9c99b89c0a23bb` 为唯一代码基线；旧主工作区不作为发布候选。
- PHP 入口发现采用受限递归扫描：跳过隐藏、依赖、缓存和测试目录；先剔除已被更浅文档根覆盖的嵌套入口；只在剩余结果唯一或有唯一约定目录可判定时选择。多候选歧义不得任意选择。
- 支持深度内找不到 PHP 入口时明确失败；不得静默把无入口的归档根目录当成 Web 根。
- 沙箱服务在一次任务开始时解析并校验源码摘要，部署规划与测试用例生成共用同一个 summary 对象。经过 `compact_source_context` 的结果在任务内绑定原始源码摘要、分片 ID、来源覆盖和受保护事实；后续 Agent 只能复用同一对象，不建立跨账号/跨任务缓存。
- 上下文压缩失败仍 fail-closed：动态 AI 用例与部署规划标记未完成，确定性 runner 可提供独立证据，但不得把总体状态报成 AI 测试通过。
- 压缩调用数与耗时写入进度事件，以便区分模型慢、预算耗尽、覆盖验证失败和应用运行失败。
- v4.0.89 生产复测确认 PHP 路由已通过，但 481 片源码压缩耗尽 300 秒共享预算；v4.0.90 将同一层级的独立来源批次改为有界并行，最大并发 4，并通过进程级信号量限制总模型调用并发。保留批次结果顺序、调用数上限、共享 deadline 与 fail-closed 来源校验，不通过放宽预算掩盖耗时。
- 并发压缩必须通过 `contextvars.copy_context()` 为每个批次建立独立上下文，带入用量归因和记账 Session 工厂；每个工作线程不得共享同一个 `Context`，模型调用日志也不得因线程切换漏记。
- v4.0.90 的真实 481 片 bWAPP 复测仍未完成 AI 动态覆盖：138 次压缩调用中 55 次输出截断、4 次读超时，最终触发 300 秒共享截止时间；另有 19 条逐字有效引文超过旧 80 字校验上限。
- v4.0.91 生产复测（`sbx_b0e1448463804dcea6a696f3`）再次确认 481 片压缩耗尽 300 秒：153 次调用、1,269,580 tokens，51 次长度截断、4 次读超时；确定性黑盒 `/login.php` 通过，AI 动态用例为 0，不能认定黑盒 AI 审查通过。
- v4.0.92 候选根据线上调用预算证据，将压缩首轮输出预算从 2,048 提至 4,096（仍受配置上限与 4,096 硬帽约束），保留输入递归拆分和所有来源校验；目标是消除生产中已证实的低预算首轮重试延迟。
- v4.0.91 将每批最大来源数从 32 降为 8、字符数上限从 120,000 降为 40,000，模型摘要提示目标设为 600 字，逐字可核验引文上限设为 160 字。来源 ID、SHA、原文子串、受保护事实、共享截止时间和 fail-closed 规则继续保留。

## 技术约束

- 不放宽来源 ID、SHA-256、引用逐字校验、受保护事实账本、`MAX_SOURCE_CHUNKS`、`MAX_COMPACTION_CALLS` 或共享 deadline。
- 不靠单纯提高 timeout 掩盖重复工作；不丢弃头部、中部、尾部或清单项来获得表面成功。
- 生产验收使用普通 Safari 和专用 Worker；不创建远程目标探测，不运行真实外部攻击。
- 只有在发布 SHA、备份/恢复门禁、迁移、运行 SHA、健康检查、Worker profile 与结果回执全部一致时，才宣称部署完成。

## 验收标准

1. 修复前 bWAPP 等价目录夹具复现 `/` 返回 404、路由候选 0；修复后相同样本能从 `bWAPP-master/app` 启动并探测到 HTTP 2xx。
2. 两个 Agent 阶段共享一次完整源码压缩；自动化用例证明成功时只压缩一次、共享 deadline 耗尽时不重复发起压缩、来源覆盖不完整时不生成用例。
3. 增加 PHP 多根歧义、无入口、超深入口、简单根入口、`public/` 入口和嵌套管理入口回归。
4. 相关后端/runner 测试、部署脚本门禁、构建上下文摘要核验、全量 CI 通过。
5. v4.0.92 部署后实际验证黑盒 bWAPP 入口、至少一个 PHP 白盒样本、Worker ready、模型用量记账、481 片共享压缩与动态用例数量、cleanup receipt。生产结果必须如实记载为当前样本证据，不推断所有项目通过，也不将 481 源码片段等同于 100 万 token 证明。部署前须满足 12 GiB 容量门槛；若需要清理旧镜像，按既有保留策略保留 current/previous 和最近两版，并保留回滚状态。
