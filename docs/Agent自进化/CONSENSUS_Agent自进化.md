# CONSENSUS_Agent自进化

> 在 ALIGNMENT 基础上锁定范围、分层取舍与验收口径。

## 1. 一句话范围

把「审查 → 用户处理 issue（fixed/ignored）→ 聚合反馈 → 反思蒸馏候选规则/经验 → 评估闸门 → 人工审批 → 启用后自动流回下次审查」这条闭环工程化，并保证全程**可解释、可评估、可回滚**。

## 2. 进化分层与本期取舍

按「可解释性 / 可回滚性」从高到低排，优先做上层、低风险、高 ROI 的：

| 层 | 进化对象 | 本期 | 说明 |
|---|---|---|---|
| **L0 遥测** | 调用与结果数据 | ✅ 做 | 扩展 `ai_call_log` 关联 issue 结果，建反馈聚合 |
| **L1 经验记忆** | 检索过往案例 | ✅ 做 | 新增 `review_experience`，审查时检索相似案例注入 Prompt；带时间衰减 |
| **L2 规则蒸馏** | 人类可读规则库 | ✅ 做（核心） | `EvolutionAgent` 从反馈产出候选 `review_rule`（默认禁用，待审批） |
| **L3 Prompt/few-shot 优化** | system prompt、示例 | 🟡 部分 | 先做 few-shot 样本库（采纳案例入库注入），prompt 自动优化列为增强 |
| **L4 工具/技能合成** | Agent 自写检查器 | ⏳ 远期 | 反复命中的模式自动生成静态规则，本期不做 |
| **L5 权重级** | 模型参数 | ❌ 非目标 | DPO/RFT 风险高、难回滚，信任敏感场景不做 |

**取舍原则：能用「可读规则 + few-shot」进化，就不用「改权重」进化。**

## 3. 反馈信号语义共识

| 信号 | 来源 | 学习含义 |
|---|---|---|
| `status = fixed` | `review_issue` | 真阳性：意见被采纳并修复 → 强化 |
| `status = ignored` | `review_issue` | 疑似假阳性/噪声 → 弱化（需防偷懒，见闸门） |
| `status = pending_review` | `review_issue` | 待定，不计入信号 |
| `handled_by / handled_at` | `review_issue` | 处理人与时点，用于去偏、时间衰减 |
| 静态规则命中 vs LLM 命中 | `security_static_rules` | 交叉验证，提高置信 |
| 圆桌讨论共识 | `discussion_bus` | 多 Agent 一致性参考 |

## 4. 验收口径

| 编号 | 验收项 | 口径 |
|---|---|---|
| A1 | 反馈聚合 | 能算出每条规则/每类 issue_type 的采纳率、假阳性率、样本量 |
| A2 | 经验记忆 | 审查时能检索相似历史案例并注入 Prompt，命中可在调用日志体现 |
| A3 | 规则蒸馏 | `EvolutionAgent` 能产出候选提案（新增/降权/禁用/收窄语言），带证据 |
| A4 | 评估闸门 | 提案 promote 前必须在 `eval_case` 黄金集上跑分，不退化才放行 |
| A5 | 人工闸门 | 提案默认禁用，admin 审批后才写入生效；每次变更入 `audit_log` |
| A6 | 可回滚 | 任一已 promote 的提案可一键回滚，规则恢复原状 |
| A7 | 闭环验证 | 审批启用的规则在下一次审查 Prompt 中可见（经 `_format_rules`） |
| A8 | 防翻车 | 满足最小样本量 + 跨任务双门槛才提案；纯单用户忽略不触发删规则 |

## 5. 关键指标（Metrics）

- **审查质量**：findings 采纳率（fixed / 总数）、假阳性率（ignored / 总数）。
- **噪声**：人均/单任务被 ignored 的 issue 数趋势（应随进化下降）。
- **进化健康**：提案通过率、回滚率、黄金集 precision/recall 趋势。
- **成本**：`ai_call_log` 的 token 与耗时（经验注入不应显著抬高成本）。

## 6. 风险与红线

- **Goodhart / 奖励黑客**：信号选错方向就反了。红线——`ignored` 不直接自动删规则，必须双信号 + 人工闸门。
- **回声室**：进化产物若直接当训练数据会自我强化。红线——`eval_case` 黄金集为人工锚点，进化产物必须过它。
- **漂移**：旧经验会过期。措施——`review_experience` 带时间衰减。
- **信任**：审查是信任敏感场景。红线——优先可读产物，全程留痕、可回滚、可审批。
