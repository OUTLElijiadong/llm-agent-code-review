# Redis 容器路径夹具复现与修复

- 日期：2026-10-07。
- 关联 CI：[`37574657795`](https://github.com/OUTLElijiadong/llm-agent-code-review/actions/runs/37574657795)，head `c5e3301244ab703e31975465a23e4a8885bd2be1`。
- 复现：GitHub Linux 后端 job 收集 6501 项，结束为 6495 passed、0 failed、6 errors、5 warnings，耗时 857.83 秒；覆盖率 83%。六个 errors 都发生在 `backend/tests/unit/core/test_login_rate_limit_real_redis.py` 的 Redis fixture setup：客户端已通过 Unix socket ping、socket/父目录权限、TCP=0 和 TLS TCP=0 校验；之后测试读取容器内 `CONFIG GET unixsocket` 值 `/tmp/redis.sock`，误与宿主机 bind mount 路径 `/tmp/prism-login-redis-37574657795-1/redis.sock` 直接比较。六个 Lua 限流行为测试没有运行到业务断言。此前 `sh`/Bash runner 和容器名/socket fixture 冲突已不再出现。
- 同次 CI 其余 job：前端 142 个测试文件、1850 tests 通过，ESLint、类型检查与生产构建成功；部署 job 137 passed、2 skipped，33 项发布绑定通过，ShellCheck、`bash -n`、Compose 配置检查及 `test_scripts.sh` 成功。整体 CI 因后端六个 fixture errors 标记失败。
- 修复：测试现在单独识别宿主机 socket 与 Redis server namespace socket；CI 显式设置 `PRISM_LOGIN_TEST_REDIS_SERVER_SOCKET=/tmp/redis.sock`，本机启动的 Redis 默认仍使用同一路径。新增同命名空间、容器挂载命名空间及错误路径拒绝三项单元测试。
- 本机复测：`backend/.venv311/bin/python -m pytest -q -rs tests/unit/core/test_login_rate_limit_real_redis.py` 为 3 passed、6 skipped；六项需真实 Redis 服务，本机未安装 Redis server。`ruff check` 通过。真实 Redis 行为与全量后端门禁须在修复提交推送后重新跑 GitHub Actions。
- 边界：本次发现的是 Redis 测试夹具的路径断言缺陷，不是已证实的登录限流业务漏洞。此前 6495 项后端用例通过，但在 Redis 六项未执行前，不能声称 Redis Lua 行为完整验收。CI 通过也不能替代生产 Worker/Safari 黑白盒业务验收。
