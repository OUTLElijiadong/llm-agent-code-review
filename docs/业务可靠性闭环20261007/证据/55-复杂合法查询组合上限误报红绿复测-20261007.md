# 复杂合法查询组合上限误报红绿复测

## 复现

在 Python 黑盒测试契约中构造 11 个返回稳定字符串的 helper，将其组合后通过 `urlencode` 编码为查询参数，同时从 `PRISM_PREVIEW_PORT` 读取可信 loopback 端口并请求 `127.0.0.1`。原逻辑将任何静态字符串解析溢出都映射为整个环境来源不可信，导致该合法请求被报为动态 URL/端口错误。

## 修复与复测

- 将复杂度溢出标记限定到导入、反射、动态方法/部分函数等安全敏感调用；普通 URL 参数拼接不再触发环境变量来源失效。
- 保留动态模块名组合的恶意负例：方法名隐藏在超过上限的字符串组合中时仍必须 fail-closed，并受 `<2s` 边界断言保护。
- 修复后的两个最小回归：`test_blackbox_contract_keeps_encoded_high_complexity_query_with_trusted_port` 与 `test_blackbox_contract_bounds_static_string_products_and_fails_closed` 均通过（2 passed）。
- 最终 4 个相关模块回归 244 passed，证据/56；全后端回归 6495 passed、6 skipped，证据/57。

本证据记录该问题修复时的测试快照；后续新增 SIGINT/SIGTERM 回归后的最终定向和全后端结果以证据/56、证据/57为准。本修复只覆盖已复现的静态解析误报/动态导入边界，不等于生产 Worker 或所有外部项目与模型已验收。
