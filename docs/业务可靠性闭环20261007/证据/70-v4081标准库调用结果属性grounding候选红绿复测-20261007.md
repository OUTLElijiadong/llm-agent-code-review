# v4.0.81 标准库调用结果 grounding 修复与候选验收

## 观察到的问题与复现边界

- 普通 Safari 中的历史生产任务 `sbx_65b29eecb2754ab5a856a023`（项目 `V4验收样本20260920`，Python 白盒）记录为 v4.0.79；三轮 AI 动态用例因 grounding 拒绝而跳过，后回退到确定性检查。原始模型脚本未保存，因此本地回归复现的是同一 AST 调用结果属性误判机制，不能称为原始模型输出的逐字重放。生产记录详见证据/64。
- 复现输入包括 `inspect.signature(...).parameters`、调用结果参数 `.annotation` 和 `importlib.util` spec/loader 链。旧逻辑漏掉调用节点返回类型，既误拒合法反射链，也因导入、赋值、动态命名空间及模块写操作的绑定变化而存在误信任边界。

## 修复内容

- 用 AST 表达式树追踪受限调用结果及其返回类型；仅接受实际导入绑定、项目同名模块优先、未被遮蔽或改写的精确 `inspect`/`importlib` 链。没有把 `parameters`、`annotation`、`loader` 等名称加入通用白名单。
- 对赋值/删除、星号解包、`setattr`/`delattr` 及简单别名、`globals`/`locals`/`vars`/`__builtins__`、`exec`/`eval`、`getattr` 模块字典访问、直接传入 helper 的标准库名称/属性/星号解包/字面量容器撤销相关绑定信任。项目函数/类遮蔽 `print`、`list`、`repr` 等内置名时，不享受只读内置例外。
- 保留合法的内联反射、`importlib.util` 赋值别名与 spec loader、可信参数映射的 `list(...)`，以及未遮蔽的只读内置观察样本；生成器入口回归确认合法用例不触发 grounding 二次反馈重试。
- 检查范围是静态可识别的绑定、直接属性表达式、星号解包和字面量容器；它不等同于任意 Python 程序的全语义解释器，也不证明经过多层变量容器、任意动态执行或外部模型/依赖/网络后的所有路径安全。
