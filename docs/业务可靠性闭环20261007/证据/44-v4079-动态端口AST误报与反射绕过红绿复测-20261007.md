# v4.0.79 动态端口 AST 误报与反射绕过红绿复测

测试范围：`backend/app/services/sandbox_service.py::_generated_test_contract_issues` 的 Python 生成测试契约检查。验证攻击者通过 `operator.methodcaller` 改写 `os.environ['PRISM_PREVIEW_PORT']` 后，不能把任意端口伪装成受信任的动态端口；同时验证无关只读 `methodcaller` 与环境变量读取不会误拦。

## 修复前复现

1. 独立复核在 13 个常规别名用例已通过的候选中，复现 2 个误拦：无害 `methodcaller('upper')` 与 `json.dumps(os.environ)` 或只读 `read_port(os.environ)` 同文件时，合法 loopback URL 被当作端口污染。
2. 同一复核复现 2 个漏拦：`getattr(__import__('operator'), 'methodcaller')(...)(os.environ)` 和 `__import__('operator').__dict__['methodcaller'](...)(os.environ)` 可以改写动态端口但未产生 contract issue。
3. 新增上述 4 个回归参数后，修复前执行：

   ```text
   .venv311/bin/python -m pytest -q -o addopts= tests/unit/services/test_agent_test_cases.py -k nested_call_ast_contract
   13 passed, 4 failed, 46 deselected
   ```

   失败正好对应 2 个误拦期望和 2 个反射绕过期望。

4. 独立复核再补入 builtins/importlib 导入别名、从 `os.__dict__` 获取环境映射，以及只改 `OTHER_FLAG` 的 9 个变体后，修复前结果为：

   ```text
   17 passed, 9 failed, 46 deselected
   ```

   其中 7 个是新的反射漏拦，2 个是对无关环境变量的误拦。

5. 再补 operator 字典 `.get`、`vars(operator).get`、`sys.modules.get('operator')` 和 `functools.partial` 的 5 个可执行 payload 后，修复前结果为：

   ```text
   26 passed, 5 failed, 46 deselected
   ```

   独立 Python 片段验证这 5 种写法能把 `PRISM_PREVIEW_PORT` 改成测试端口；契约检查当时均返回空 issues。

## 修复后复测

删除文件级“能力、环境变量和端口字符串共现即拒绝”的启发式，改为识别调用链中的 methodcaller 工厂、只读/变更方法、operator 模块别名、解包别名、`getattr`、模块 `__dict__` 与简单 helper 返回值；只有变更 methodcaller 实际接收 `os.environ` 时才污染受信任端口来源。

同一测试命令修复后结果：

```text
31 passed, 46 deselected
```

覆盖 13 个直接/赋值/解包/函数返回别名、2 个只读无害组合、14 个动态导入/环境映射反射与 partial 变体，以及 2 个仅修改 `OTHER_FLAG` 的正常场景。修复后的关键行为是只改其他环境变量时保留动态预览端口的可信来源；目标端口被直接或间接改写时拒绝该测试。真实 ZIP 多文件源码经递归切分后逐字引文 grounding 的集成回归复测：
