# v4.0.83

修复代码沙箱黑盒执行在业务路由失败后缺少明确阶段终态、最终等待到 profile 硬超时才被容器强杀的问题类别。runner 为依赖准备、应用启动、就绪探测、动态断言和全任务增加有界时间，并输出结构化超时或启动失败回执；退出时回收应用进程组。路由候选提取改为词法扫描，注释和普通/多行字符串中的路由示例不会被当成可执行路由。

历史 v4.0.81 任务 `sbx_3b317e05c0fa45128c20e31d` 的直接结束原因已确认是 Python profile 120 秒上限触发并返回 `exit_code=124`。它使用的唯一项目没有 Web 入口，所测健康与常见入口返回 404，路由失败符合样本事实。旧日志没有完整阶段尾迹或停止前进程树，不能确认那次任务具体卡在哪个阶段；v4.0.83 是对这类无界等待的有界化和可诊断修复，不伪称已经证明历史卡点。

当前状态：本地候选已完成全量后端与部署回归，仍需精确 SHA 的 GitHub CI、生产容量复查、生产备份/隔离恢复门禁和主站/Worker 发布后核验。候选未发布前，生产仍以健康接口实际回报的 v4.0.82 为准。
