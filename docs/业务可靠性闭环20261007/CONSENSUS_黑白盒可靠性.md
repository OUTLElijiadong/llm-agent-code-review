# 黑白盒业务可靠性共识

1. Worker 状态、退出码、必需子回执和黑盒动态断言证据必须一致；缺失、矛盾、重复或伪造证据不得汇总为通过。
2. 白盒确定性检查、AI 动态用例、黑盒路由烟测、动态断言分开报告；未执行的 AI 用例不能显示 AI 通过。
3. 黑盒 2xx 仅证明该路由可达；3xx/401/403 为部分或认证边界；404/5xx、启动错误和断言失败为失败。
4. Python 导入/属性调用按对应源码模块核验。动态端口只接受可信 Worker 环境来源；os.environ/getenv 与 operator/methodcaller 别名改写均 fail closed。
5. 大源码压缩保留来源 ID、顺序、哈希及可核引文。模型请求不得重复附带完整文件元数据；截断可无损拆分并逐片核验，预算耗尽或引文不匹配明确失败。
6. Worker 模型请求只投影来源 ID 和本次正文；完整文件元数据只用于后端 grounding。
7. 生产验证使用普通 Safari、白盒先行、黑盒串行、仅 loopback 目标；逐项核对任务事件、Worker 回执、报告、持久化和清理。
8. 语言矩阵、真实模型语义和外部依赖环境缺少实测时明确记作未覆盖。
