# 黑白盒业务可靠性对齐

## 原始需求

确保正常业务路径可落实；补充完整正常、边界和异常测试；重点修复反复失败的黑盒、白盒测试，使真实业务测试具有可靠执行和准确结果。

## 已核实项目现状

- 生产基线在本轮 Safari/HTTPS 核验时为 v4.0.77，release SHA `083c64a9af018c00339d7288b196dee4650b17c4`；工作区正在制作 v4.0.78 候选。
- 生产历史白盒失败任务 `sbx_5c65ce4e3d2e447d9e856338` 及 v4.0.77 新观察到的 Python 白盒/黑盒 AI 用例生成失败均保留原始记录。后者出现三轮不受支持符号拒绝、随后确定性回退；AI 动态生成状态为 skipped，不能称作 AI 测试成功。
- 本次 Safari 复核生产黑盒任务 `sbx_0bb11491c12a402d9b0fda43`，发现动态用例 skipped/0 个，但 Worker JSON 仍报 `agent_assertions_passed=true` 和 `route_and_agent_assertions`。200 状态只证明 `/health` 路由冒烟；AI 断言字段与注入/执行证据矛盾，详细记录见 [`生产黑盒回执复核`](证据/26-生产黑盒回执标真复核-v4077-20261007.md)。
- v4.0.77 黑盒回执在动态用例未执行时仍可能报告 `agent_assertions_passed=true`。已增加先失败再修复的 runner 回归，要求未生成动态脚本时该值为 null。
- 候选源码独立复核还发现 Python 模块属性访问可借另一个源码文件中的同名符号蒙混过关，`operator.delitem`/`methodcaller` 可改写预览端口来源，且无动态断言时回执仍写“路由与断言”。修复前 7 项复现测试失败、22 项通过；修复后定向 200 项通过。端口变更拒绝用例现在覆盖原有 20 种与新增 4 种路径，模块属性覆盖有效导出、伪导出及多种导入方式。
- 后端与 Worker 执行请求字段不一致的问题已通过 Backend 白名单投影解决；来源修订与修复轮信息保留在后端执行账本，首轮和 PHP 修复轮都用实际 Backend 组装请求对 Worker 校验器做契约回归。
- 更早的总状态假通过、302/根路由回执及启动异常诊断问题，已有历史证据和回归，见本目录 `证据/01` 至 `证据/11`。
- 非 Python（Node/PHP/Go/Java）避免错误套用 Python AST/token 规则；本轮仅核实生成输出及执行契约，没有实现各语言等价的源码模块导出 grounding。五种语言的隔离运行时状态不等于语义覆盖证明。

## 本轮范围

在既有沙箱修复基础上，修复 Python 测试生成的源码符号 grounding、白盒/黑盒提示约束、生成失败分类、动态端口校验及 AI 动态断言回执语义；补充 Node ESM/CJS、Java classpath、依赖准备顺序与源码压缩失败拆分回归；运行后端全套与前端测试、静态检查和构建。部署恢复后按白盒先行、黑盒 loopback-only 的顺序在 Safari 复测。

## 边界

- 不删除或重写生产历史失败任务，不并发叠加同项目测试。
- 代码测试、真实 Worker 任务和生产供应商模型评估分别记证据；模拟 Agent/百万分词代理不能证明真实模型处理百万 token。
- 目标是通过门禁拒绝假通过并提高任务成功率；不承诺任何软件在任意输入、供应商或网络故障下绝不失败。
- 若生产实际白盒仍失败，保留事件、响应与清理状态，先复现再修复，不以健康检查或本地单测替代。

## 验收口径

候选全量后端/前端回归、类型检查、ESLint、构建、Ruff/compileall、Shell、发布故障注入均通过；修复前红测确实失败、修复后同场景通过；官方精确 SHA 发布门禁通过；生产真实白盒任务结果、来源哈希、Worker 回执、工件和清理闭环核实；白盒结束并确认清理后，再做串行 loopback-only 黑盒任务；失败、部分和未知状态展示与底层证据一致。
