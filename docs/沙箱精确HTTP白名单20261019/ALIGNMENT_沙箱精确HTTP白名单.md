# 沙箱精确 HTTP 白名单需求对齐

## 原始需求

用户选择“先改产品，加可强制执行的路径白名单”。背景是需要让本地 PHP 靶场在 Prism 隔离沙箱内完成一次可展示的黑盒运行；范围此前已限定为本地请求、禁止系统文件访问、不访问外部目标、不使用浏览器。

## 项目理解

沙箱执行由 FastAPI 后端创建不可变源码快照，Sandbox Worker 校验固定协议并创建隔离容器，容器内固定 `runner.sh` 启动应用、探活、发现路由并可能执行注入的 PoC 与 AI 测试脚本。仅增加页面输入或提示词无法约束运行器的实际请求，因此范围必须经后端、Worker 和 runner 三层校验并落实。

## 范围边界

- 本任务实现本地黑盒测试的精确 HTTP 请求白名单。组合测试会运行项目测试脚本，因此不开放此模式，避免脚本绕过 runner 请求计划。
- 只允许 GET；只访问沙箱容器自身固定 loopback 端口。
- 每个条目由精确路径、精确查询参数及可选预期状态码组成；查询键值只接受未编码 ASCII 安全字符并限制长度；不支持通配符、重定向跟随、外部地址或请求体。
- 限制最多 20 个请求条目，至少一条；`GET /` 只有在它确实属于应用入口时才配置，不作为固定探活要求。
- 白名单模式不得执行 AI 生成的部署补丁、PoC、动态测试脚本或 PHP 语法修复副本。
- 回执和报告列出实际请求目标、状态码、耗时、响应字节数、断言情况及未覆盖范围；不保存或展示响应正文。
- 远程授权黑盒、白盒测试、部署流程保持现有语义。
- 初始实现阶段原计划先完成代码验收，再安排一次受限演示。之后用户授权在 4.1.11 生产产品页运行固定 PHP LFI 提交一次；该任务已执行且失败，触发了本次“根路径可选”修订。该次授权已使用，不据此重复运行同一靶场。

## 已解决的不确定性

- 约束必须由服务端强制执行，不依赖用户遵守提示。
- 白名单条目采用只读 GET 和精确 path/query 匹配。
- 未配置预期状态码时只记录 HTTP 回包事实，不声称业务断言通过；报告明确覆盖不足。
- 原始请求响应体可能包含敏感文件内容，因此仅保留状态和有上限的字节计数。

## 验收标准

1. 本地黑盒请求缺少白名单、使用非 GET、重复目标、非法路径/参数或超过上限时，后端与 Worker 均失败关闭；不含根路径的合法应用入口可提交；组合测试不得提交白名单字段。
2. Worker 将规范化白名单纳入执行请求摘要，并只向 runner 提供受控编码后的请求计划。
3. 限定 runner 仅发送列出的 loopback GET；跳过路由发现、注入 PoC、AI 测试脚本及 AI 生成的启动/修复代码。

## 生产证据后的需求修订

生产 UI 运行发现被测应用的三个显式 PHP 路由都返回 HTTP 200，而强制 `GET /` 未返回 HTTP 状态行，导致任务整体失败。应用就绪检查本身已经是 TCP-only，因此根路径不是安全探活的必要条件。修订为：白名单仍至少包含一条、最多 20 条精确 GET；每条仍被服务端和 runner 强制执行；根路径可选。回执摘要优先沿用已配置的无查询根路径，否则以第一条实际白名单请求作为摘要路由与状态码。该修订目前仍在源码工作区，尚未部署和功能验证。
4. runner 返回唯一可信结构化回执；后端核对回执请求与已保存白名单逐项一致，否则任务失败；日志被截断时不采信回执并失败关闭。
5. 结构化结果和 Markdown 报告包含真实 HTTP 证据与动态覆盖缺口，不含响应正文。
6. 前端仅在本地黑盒模式提供精确请求条目并显示结果，不把白名单限制伪装成完整漏洞测试结论。
7. 相关 Python、前端、runner 测试及 runner 镜像摘要校验通过。
