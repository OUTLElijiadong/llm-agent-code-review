# 测试契约同步复核

父代理全后端首轮报告中两个失败由测试契约滞后造成，本轮修改仅涉及测试：

1. 用量归因 fixture 的可恢复运行原来写入 `{}`；当前 A05 检查点完整性正确拒绝缺失 transcript。fixture 改为完整 `RunCheckpoint` 序列化，明确 `transcript=[]`、`tools=[]` 与运行标识、模型、完成状态。没有放宽损坏、缺失或摘要不符的检查点拒绝。
2. Nginx 模板 HEAD 已限定部署域名 `APP_DOMAIN` 和 `APP_DOMAIN_ALIASES` 的 WebSocket 源；旧测试仍期待请求 `$host`。同步为现有固定域名契约，并要求三份 enforce CSP 相同、script-src/connect-src 精确匹配。没有修改实际 Nginx 配置。

独立运行用量归因、Nginx 安全头、Responses 集成三个文件，共 122 项通过，2.82 秒；既有 passlib crypt 弃用警告 1 条。修改测试的 Ruff 与 diff whitespace 检查通过。日志见同目录。全套后端是否通过由父代理后续全量运行另行判定。

前端最终 6 个沙箱 API 失败后重试样本亦只读复核，并独立重跑 8 文件 113 项通过（一次，1.92 秒）。五处 catch 保留统一 HTTP 提示、配置与当前任务，finally 仅在目标仍有效时恢复 busy 状态。该证据补充此前 107 项独立日志，不代表生产、真实手机或当前最终 bundle 的浏览器验收。
