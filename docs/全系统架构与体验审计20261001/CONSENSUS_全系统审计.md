# 全系统审计交付约定

1. 不把另一个 AI 的报告直接认定为漏洞；回到当前源码和实际复现。
2. 每项分开标记：已复现缺陷、静态优化建议、生产观察、待验证风险。
3. 对已复现缺陷记录触发条件、影响边界、源码位置、复现结果、推荐修法及扩展样本。
4. 三个子 Agent 并行只读检查；主 Agent 独立重跑核心样本并核对结论。
5. 页面审计使用当前生产截图，不把历史消息展示当成新模型调用验收。
6. 验收通过只表示本轮报告和证据完成，不表示全部功能、全部账号或生产安全通过。

## 继续修复的确认合同

- 用户已授权修复、重复原场景并扩充样本、发布后复测；无需重新确认例行修复与发布。
- 新发现先保存旧行为失败证据，再最小修改并重复三轮；子Agent独立复核源码、测试和证据数据。
- 安全发现默认待核实；精确片段匹配、置信度或多来源一致不自动变成已确认漏洞。非安全问题的确切源码匹配保留既有正向处理。
- 输入预算明确区分保守估计、本地官方tokenizer计数与供应商账单usage；原文账本、压缩事实来源和超预算拒绝不得为测试通过而放宽。
- 圆桌异步详情只允许当前账号与当前选择的最后一次请求更新界面；关闭窗口、切换选择、切换账号及卸载后迟到响应不得重新打开或污染界面。
- 分数保持原算法，报告说明候选/已驳回仍参与原始扣分、来源一致不等于验证；官方门户和参考标准不得被写成平台已同步最新库或官方认证。
