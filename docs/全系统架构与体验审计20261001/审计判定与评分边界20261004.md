# 审计判定与评分边界

用户要求在审计中明确何时能认定漏洞，并按规范流程适配。本页是本轮实现和验收合同，不是对整站无漏洞、官方认证或完整语义理解的保证。候选修复在正式发布核验之前不计为生产通过。

## 漏洞成立的证据要求

| 判断阶段 | 必须记录 | 能得出的结论 |
|---|---|---|
| 模型或静态规则发现 | 来源Agent/规则、文件与版本、主张、原始引用 | 候选，不能仅以置信度认定漏洞 |
| 源码定位 | 完整源码中精确引用、真实坐标、来源哈希 | 引用已匹配；不等于条件和影响已验证 |
| 条件核实 | 真实入口、受影响版本、权限及配置前提、已有防护是否覆盖 | 条件成立或不成立；未知项单列 |
| 影响核实 | 能从源码和实际环境证据支持的影响范围、验证方式与实际结果 | 已核实影响；不能外推全量用户或未测试数据 |
| 人工裁决 | 有权限的审核人、接受/驳回/补证意见和时间 | 人工结论；不是自动复测证明 |
| 修复复测 | 原版本失败、修复提交、同场景复测和新增样本、未覆盖范围 | 仅所测场景修复成立 |

多个Agent一致只增加独立来源信息，不能把同一未经核实的观点变成事实。外部报告先作为线索，未测试风险不能写成已确认漏洞。存在争议、源码引用不匹配或缺少条件/影响证据时保持待核实；未知的CWE、CVSS或环境指标不得补造。静态源码可以提供充分证据的缺陷也应写明静态证据范围，不强行声称已经运行验证。

## 当前代码的实际适配

- 保留既有证据枚举，`verified`只表示源码引用匹配。旧相似匹配会忽略大小写和字符串内部空白，本轮改为精确子串，不再把不同内容标成匹配。
- 任何合并来源引用未匹配时进入待人工核实；安全类别主张即使引用匹配也待核实，因为当前聚合器没有环境条件/影响验证工件。非安全问题的真实源码匹配保留既有正向流程。
- 人工“接受”“驳回”“需补证”和问题“已修复”是各自状态；当前人工接口只有文字意见和裁决历史，没有结构化验证工件。因此不能将其展示成“已复测验证”。本轮不批量改写旧裁决。
- 详情区说明引用匹配、置信度、多来源和人工裁决的区别；报告各格式补充同一证据与计分范围说明。

## 评分与官方资料

当前质量分是平台内部按问题严重度计数的扣分口径。待核实和人工驳回的问题仍在既有计分集合内；本轮保持算法和历史分数，仅增加可审计说明。`confirmation_count`表示保留的来源数。它不是漏洞成立验证数，风险分也不是官方机构评级。空问题报告保留旧显式分数时，不能称已验证无漏洞。

2026-10-04核对全国标准信息公共服务平台：

- [GB/T 39412-2020《信息安全技术 代码安全审计规范》](https://std.samr.gov.cn/gb/search/gbDetailed?id=B4C25880C2F31CB3E05397BE0A0A92D0)为现行标准；引用其名称不等于产品已按全部条款实现或通过认证。
- [GB/T 30279-2020《信息安全技术 网络安全漏洞分类分级指南》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=458BACCE700CA8E0B728CFB5F762DE7A)为现行标准；[修订计划20260806-T-469](https://std.samr.gov.cn/gb/search/gbDetailed?id=4C30E22D8B94BBB9E06397BE0A0A52F3)仍在征求意见，不能把草案当现行规则。
- [GB/T 34943-2017](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=00AD3629A2AEC567B8242A234539226D)的官方名称是“C/C++语言源代码漏洞测试规范”；本轮纠正页面原错误标题并显示为参考规范。

CNVD/CNNVD门户、静态参考资料和模型提示不能代替有授权的数据查询与同步。本轮没有核验官方记录版本/更新时间或建立最新库同步能力，报告明确保留该限制。后续数据适配必须能提供记录编号、适用版本、发布时间/最近同步时间、来源和刷新失败状态；未知时不能声称“最新”“权威已确认”。

## 本页验收边界

关联证据见同目录ACCEPTANCE、发布与验收及evidence。隔离SQLite与API函数序列化不等于生产HTTP权限验收；本地官方tokenizer统计不等于供应商usage；真实桌面点击不等于真实手机；已发布也不等于全部功能通过。各项按实际证据单独关闭。
