# 报告全链路质量修复共识

## 需求描述

修复报告发现、可见性、终态生成、内容完整性和格式呈现。对无权查看的账号，列表、工作台、项目近期任务均不返回私有报告任务元数据；对有权账号，终态任务报告应可读取，明确成功/失败/取消/授权过期和覆盖不足。已支持的 HTML、PDF、Word 导出按语义呈现 Markdown；领域报告继续使用原生详情页与 JSON 导出。

## 验收标准

1. 报告任务账号隔离在 API 列表、工作台汇总、近期任务卡片、详情、问题及导出入口一致；无权账号不能获得任务名、编号、状态、报告卡片或正文。
2. 代码审查、审计、黑盒、白盒及黑白盒任务正常/失败/取消/过期时，状态、报告生成与覆盖披露一致；远程评估即使执行器无法启动也留下账号可读的失败报告，且明确没有发出网络请求。
3. 报告正文完整解释发现、证据、影响、复现/验证、修复建议和未覆盖范围；不得静默省略发现。存储容量限制必须显式披露，结构化记录仍可追溯。
4. 标准报告 HTML、PDF、Word 对标题、强调、段落、列表和代码块进行可读排版；语法性 Markdown `##`/`**`/列表标记不作为视觉正文显示，代码内容保持原样。
5. 领域报告不显示不可用导出按钮；其原生详情和 JSON 导出不被破坏。
6. 相关后端/前端回归、格式检查、构建和部署健康验证通过；生产中不造数据。

## 技术方案与约束

- 复用 `task_metadata_access_filter`，使工作台计数和近期任务的 SQL 条件与任务列表一致。
- 复用现有报告所有者/管理员校验与领域导出限制；前端展示真实任务终态、错误和覆盖信息。
- 使用项目依赖实现共享 Markdown 解析；HTML 关闭原始 HTML 并经现有净化器清洗，PDF/Word映射到标题、段落、列表和代码样式。
- 移除渗透报告发现数与字段的静默截断；在有限存储下生成明确标记的紧凑报告，并保留结构化发现表中的完整字段。
- 远程后台启动失败时调用既有终态报告持久化流程，并把未运行阶段写成跳过/未执行。
- 不新增 API、数据库迁移、角色或能力；本次报告修复正式发布版本为 4.1.0。

## 边界与风险

远程网站评估现有授权范围为单 HTTPS 根路径的有限只读 GET 检查，不等价于完整网站渗透测试。测试报告可以准确展示已观察信号，但不能把未执行范围写成已验证。生产浏览器只读验收覆盖当前账号抽样；未进行生产双账号浏览器实测，隔离结论应限定为后端权限测试覆盖。

对当前账号在 4.1.0 部署前的两条终态远程评估失败记录，允许基于已持久化阶段证据补写部分报告记录；不得重放目标请求、触发模型或改写任务结论。该历史回填与其他生产数据隔离，完成后必须读回核对所有者、失败阶段和报告完整性。
