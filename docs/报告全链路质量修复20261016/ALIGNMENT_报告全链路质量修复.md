# 报告全链路质量修复对齐

## 原始需求

正式部署后核对代码审查、审计、黑白盒测试及远程网站评估的报告链路。账号无权访问的报告不得出现在该账号的报告卡片或近期任务入口；可访问的任务应有可读报告，内容准确并交代覆盖范围、失败或未完成原因；HTML、PDF、Word 等已支持的导出排版应清晰，不应把 Markdown 强调或列表标记当作正文显示。

## 项目与任务特性

- 当前项目为 Prism 代码审查平台；本任务在 v4.0.109 基础上修复和验收，当前工作树为 `codex/prism-v4-0-109-release`。
- 报告来源包含标准代码审查、审计/领域报告、本地沙箱黑白盒、授权渗透测试及远程网站安全评估。
- 现有权限模型以任务所有者/管理员及项目权限为边界；领域报告已有原生详情页面，标准格式导出能力因报告来源而异。
- 报告数据与生产用户数据敏感。生产阶段只做备份、发布和只读验证，不创建合成任务或报告。

## 当前核实的问题

1. 工作台近期任务与累计成功任务未完全沿用报告任务所有者过滤，可能向同项目的其他账号暴露黑白盒或渗透任务卡片。
2. 报告导出模板将 AI Markdown 摘要按纯文本输出，HTML、PDF、Word 会显示 `##`、`**` 等语法符号。
3. 渗透测试报告只详细列出前 30 条发现，并截短证据、描述、复现步骤与修复建议；精简回退没有充分提示详情位置。
4. 远程网站评估的后台执行线程启动失败时，任务虽已失败但没有持久化报告。
5. 报告列表/详情对失败、取消、过期或覆盖不完整的状态说明不足，容易把完成状态、测试结果和覆盖程度混为一谈。

## 任务边界

- 修复已有报告列表、工作台、详情、导出和终态报告生成流程；不新增报告 API 或权限角色。
- 不将领域 JSON 专属报告伪装成标准 HTML/PDF/Word；继续使用其原生详情页和现有 JSON 导出能力。
- 远程评估报告必须明确单根路径、有限 GET 请求、未跟随重定向等真实检查范围，不宣称完整网站渗透覆盖。
- 不改变生产业务数据；不以自动化合成数据代替生产账号验证。

## 疑问与决策

| 问题 | 决策 | 依据 |
| --- | --- | --- |
| 是否为领域报告补造 HTML/PDF/Word？ | 否，保持现有原生详情和 JSON 导出契约，避免字段语义丢失。 | 已有接口明确拒绝不适用格式，前端也隐藏这些选项。 |
| 无权限但有近期任务卡片怎么办？ | 在数据库分页/计数前过滤，列表与仪表盘都不返回不可见报告任务。 | 只在卡片点击后拒绝会泄露任务元数据。 |
| 报告内容太长时如何处理？ | 优先完整报告；确有存储上限时显式标注摘要/索引边界，并保留结构化发现详情。 | 不得静默删减或暗示覆盖完整。 |
| 部署验收如何覆盖真实账号？ | 使用只读生产健康/版本/权限范围检查；浏览器若被站点策略阻止则明确记录限制，不伪称完成 UI 验收。 | 当前 Safari 对该域的自动化访问存在限制。 |
