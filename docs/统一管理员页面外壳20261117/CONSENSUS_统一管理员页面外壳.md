# 统一管理员页面外壳：最终共识

## 明确需求

管理员从 `/admin/operations` 前往 `/forum`、论坛帖子详情、发帖或编辑时，继续显示管理员外壳。用户和审查员仍使用原页面外壳。论坛所有现有功能、路径、接口和权限限制保持可用。

## 技术方案

- 复用 `AppLayout` 中现有的管理员共享页面机制。
- 将 `/forum` 与 `/forum/*` 纳入 `isAdminSharedRoute` 判定，使管理员路由渲染现有 `AdminLayout`。
- 保留 `/forum*` 路由记录和 `personalAccountOnly` / workspace 守卫；不通过布局分支绕过授权。
- `AdminLayout` 已有论坛导航、活动路径识别、帖子路由内容容器；不新增 API 或后端迁移。
- 为共享路由匹配和角色分流增加回归测试，并运行前端定向测试、lint、构建；随后用普通 Safari 核验生产页面。

## 发布约束

- 当前生产基线：`34f9fb71f9aa0c0d56f4fdbc805471b98959b3d3` / `4.1.55`。
- 已核对现有引用中的最高候选版本为 `4.1.56`；本次版本使用 `4.1.57`，避免复用候选版本号。
- 发布必须绑定干净、精确的提交 SHA。生产脚本仅支持 `./deploy.sh all --revision <SHA>`；前后端同提交发布。
- 发布前需满足 CI、备份、隔离恢复验证和部署门禁；发布后核对健康、就绪、release SHA、首页资源和两条目标路由。

## 验收标准

1. 管理员访问 `/admin/operations?section=overview` 使用 `AdminLayout`。
2. 管理员访问 `/forum`、`/forum/new`、`/forum/:id`、`/forum/:id/edit` 均使用同一 `AdminLayout`。
3. 普通用户或审查员访问论坛仍使用 `AppLayout`。
4. 论坛列表、搜索、分类、排序、发帖、详情、编辑和回复入口仍存在；企业成员访问限制保持有效。
5. 管理页与论坛之间导航后左侧分组、账号入口、小菱入口和当前页面状态不丢失。
6. 定向测试、前端 lint 和构建通过；生产版本及 SHA 与健康端点一致。

## 边界

不删除论坛，不合并或重写业务页面，不改变 API/数据库，不扩大到普通用户页面布局改造，不发布旧工作区的其他改动。
