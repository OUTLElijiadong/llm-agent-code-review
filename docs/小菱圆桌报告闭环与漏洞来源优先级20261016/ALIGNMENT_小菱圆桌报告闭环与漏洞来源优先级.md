# 对齐：小菱圆桌、报告闭环与漏洞来源优先级

## 原始需求

- 小菱无法可靠停止，停止后任务仍可能继续或再次启动并消耗 Token。
- 圆桌讨论应由小菱主持，固定专家参与，并能按任务需要使用当前任务范围内的临时专家；用户插话后应尽快由小菱接管。
- 圆桌前台进度要随执行更新，重连后不能回退到空状态；未打开前台时应明确当前执行方式和状态。
- 代码审查以及黑盒、白盒测试即使失败、取消或只覆盖部分范围，也必须有可读报告，并如实列出未检查范围。
- 漏洞展示以 CNVD、CNNVD 为主并分别注明来源；没有可核实的两库官方记录时再标注 OWASP。
- 用户喜欢参考视频中“每日 Token 用量”可视化的感受，希望优化管理员页面。
- 用户补充全局动效方向：登录成功后按钮收束成光球、节点拼出对勾；指标数字如里程表滚动；真实多节点关系画成逐步生长的星图并支持根节点溯源；每日 Token 热力图波浪铺开；详情卡片原地展开、邻居随布局变化让位。

## 已核实的项目现状

- 管理员总览已经包含每日 Token 趋势，支持 7/30/90 天、刷新状态、缺失用量提示和图表明细。本次保留并核验现有实现，不重复创建用量接口或第二张图。
- 项目已有 `useCountUp`、全局 `prefers-reduced-motion` 规则和 Agent 团队真实依赖追踪组件；动效应先复用已有能力，不造演示关系。
- 用户提供的短视频链接无法由当前网页读取工具打开；不能声称看过其中未能访问的视觉细节。当前仅依据用户明确提到的每日 Token 可视化效果和现有管理员总览改动。
- 圆桌普通 REST 启动依赖后续 WebSocket 首连，小菱工具启动则直接启动后台任务；主持总结不是小菱 Agent，用户插话不会立即交接，模型调用期间没有进度心跳，断线重连不恢复活动状态快照。
- 圆桌完成后的 `user_input` 路径允许创建续会；取消状态和结果回投未形成稳定的停止屏障。
- 代码审查、沙箱黑白盒、渗透测试的部分失败/停止路径没有报告记录或完整覆盖说明；成功路径也存在覆盖数据未进入报告的问题。
- OWASP Top 10:2025 快照仍是 OWASP 当前版本。CNVD、CNNVD 目前没有接入并存档官方记录的完整数据链；平台手工映射不能表示为官方分类或认证。

## 已澄清的口径

- CNVD 与 CNNVD 都纳入，报告/界面应各自标注来源。
- 分类主次：先使用带官方记录证据的 CNVD 或 CNNVD 标签；两库均无可核实匹配时才标 OWASP。不得根据关键词猜测来源，不得伪造编号或官方映射。
- 失败、取消和部分覆盖报告必须标出真实状态；部分报告不得显示为成功或完整。
- 用户随后明确授权完整部署；范围已扩展为基于当前生产精确 SHA 的 v4.0.109 全量发布与发布后核验，不做无关业务数据修改。

## 待实施边界

- 修复本地仓库中的小菱停止/圆桌续会、主持与进度闭环、报告生成/读取/导出及安全分类展示。
- 管理员 Token 趋势以现有代码为基线核验；除非验证发现明确缺陷，不重复实现。
- 不宣称 CNVD/CNNVD 已实现实时同步，除非仓库中存在并经验证的官方数据接口与许可依据。
- 完成本地测试、项目文档和已授权的正式发布门禁；分别记录候选代码与生产环境证据。
- 动效应轻量、可中断、可访问，服从系统减少动态效果偏好；新增图形只展示真实依赖、运行或用量数据。
