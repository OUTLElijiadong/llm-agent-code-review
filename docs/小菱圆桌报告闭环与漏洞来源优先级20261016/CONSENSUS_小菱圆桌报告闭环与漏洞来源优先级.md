# 共识：小菱圆桌、报告闭环与漏洞来源优先级

## 需求与验收标准

1. 用户停止小菱后，关联的圆桌/团队任务进入真实取消终态；取消的会话不得被 task.result、自动评估或失败回投重新启动。只有用户在后续对话中明确要求继续，才可创建独立续会。
2. 圆桌主持职责明确属于小菱；固定专家按既有项目配置参与，任务相关临时专家必须限定在当前账号与任务范围内，不进入永久 Agent 库。用户插话需在当前不可中断的模型调用返回后优先交主持处理并调整后续讨论。
3. 执行中可见当前阶段/轮次/发言人和心跳时间；WebSocket 重连先恢复真实活动快照。成功、部分完成、失败、取消应有不同终态呈现。
4. 代码审查、沙箱黑盒/白盒、授权渗透测试的所有可达终态均有可读的报告中心记录和详情；失败、取消、超时或部分覆盖不得被表述为成功。
5. 报告包含输入范围、完成范围、排除/失败/跳过项、错误、证据索引及完整/部分/未执行状态；前端详情和支持的导出使用同一覆盖口径。报告发布失败须可见，不得静默当作成功。
6. 漏洞来源显示顺序为 CNVD、CNNVD、OWASP fallback。只有存在 CNVD/CNNVD 官方记录标识或官方来源证据才可使用相应分类；未匹配项标为 OWASP，并保留 OWASP 版本/引用，不伪造 CNVD/CNNVD 对照或编号。
7. 保留并回归管理员总览现有每日 Token 图表、7/30/90 天切换、未知用量标识、刷新/失败状态与明细表。
8. 动效复用全局运动令牌与 `useCountUp`：登录成功按钮收成光球并由节点拼出对勾；指标按里程表方式变化；用量热力格按波浪次序显现；真实任务依赖展示为可逐步生长、可从根节点溯源的星图；详情支持原地展开、周边内容平滑让位。
9. 新增动效尊重 `prefers-reduced-motion`、键盘与读屏语义；响应式重排依靠文档流，不用绝对定位遮挡或模拟布局。
10. 相关后端/前端测试、构建与生产检查通过后，按用户随后明确的“部署啊，请你完整做完”执行完整 v4.0.109 发布；分别记录本地验证和生产验收证据，不将二者混为一谈。

## 技术约束

- 先复用现有 DiscussionBus、ReviewTask/ReviewReport、报告 API/导出器、CNVD/CNNVD 来源注册与 ECharts，不平行造第二套业务接口。
- 任何取消/续会逻辑须绑定真实 owner、surface、session 和父运行，保持幂等并阻断迟到回执。
- CNVD、CNNVD 与 OWASP 是不同来源/分类体系；仅根据可追溯的官方条目直接标注，未知映射显式保留未知，不推断来源。
- 星图只根据真实 `depends_on`、团队、任务和事件关系绘制；无可验证边的 Agent 状态不可被虚构成任务依赖。
- 保留原工作树和服务器上与构建无关的既有未提交修改；候选基于当前生产精确 SHA 构建，并使用支持的完整发布事务。发布前创建新备份并在隔离数据库验证恢复；发布脚本不得自动降级数据库。

## 范围修订

- 初始本地验收边界为“不部署”；用户随后明确要求部署，因此范围已扩展为包含 v4.0.109 全量部署和发布后核验。

## 不在本次范围

- 不宣称或实现没有官方数据契约支撑的 CNVD/CNNVD 实时同步。
- 不将 OWASP Top 10 作为完整扫描能力承诺。
- 不对所有后台作业建立通用停止策略；停止边界限于用户要求的 XiaoLing/圆桌及其可追溯子任务。
- 不复刻无法访问的视频未观察到的样式细节。
- 不将旧同步模型调用包装成供应商端可即时取消；如需保证停止计费，仍需真实供应商取消契约与账单验收。
