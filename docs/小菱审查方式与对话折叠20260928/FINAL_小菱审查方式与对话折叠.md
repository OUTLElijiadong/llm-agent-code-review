# 小菱审查方式与对话折叠交付结论

## 本次完成

- 将小菱 Responses 工作步骤改为 Codex 式紧凑折叠摘要：默认只展示状态/计数、当前审计阶段和失败项名称，展开后保留原始完整步骤、错误与结果；独立结果仍可单独展开。
- AgentTeam 聊天卡片默认折叠，折叠态显示真实完成比例和失败/阻塞计数；总任务为 0 时不生成百分比。稳定 `aria-controls` 目标始终存在，折叠时完整团队树不挂载。屏幕阅读器按钮名称包含团队名与团队编号，工具步骤名称包含当前状态摘要。
- 在用户没有指定审查方式时，新增复用现有 `ask_user` 询问方式的策略约束，并按既有工具枚举分别给选项；不声称真实模型一定遵循提示，也不把异步 GitHub 导入后恢复原模式的行为写成已证明。
- 将候选 `VERSION` 从生产 4.0.21 提升为 4.0.22。

## 验证结果

- 前端全套：122 个测试文件、1375 项通过。
- 后端全套：5143 通过、5 跳过、2 个 xfail；方式选择/runtime 定向用例 7 通过。
- 全前端 ESLint、backend `ruff check app`、Python `compileall`、`git diff --check` 通过。
- 前端 `npm run build` 成功，构建 3716 个模块。
- 独立复核检查了折叠面板关联、隐藏时懒挂载、不同及同名团队的辅助名称、状态摘要和恢复测试；最新定向测试 65 项通过。
- 生产部署前只读 `ops-check` 为 `status=ok`，生产仍运行 4.0.21 / SHA `f5f8855b0d54ba28ded201055078713aa9df8c24`。候选 4.0.22 尚未发布，未取得生产浏览器截图。

## 已知边界

- `ask_user` 模式选择仍是模型提示策略，并非后端确定性派发门禁；GitHub 队列导入跨恢复的精确 `scan_mode` 传递没有行为级闭环证明。
- 真实 390px Safari/手机视口、软键盘、屏幕阅读器和多失败大调用量未实测；组件单测不能代替这些验收。
- 本次折叠只改展示，不改任何 AI/Agent 的模型上下文压缩、超长响应恢复或上游 token 输出边界。
- 生产部署还需生成干净提交并通过发布清单。部署主目录已有未跟踪 `.env.before-*` 文件，必须用隔离发布 checkout，不得清理或覆盖。
