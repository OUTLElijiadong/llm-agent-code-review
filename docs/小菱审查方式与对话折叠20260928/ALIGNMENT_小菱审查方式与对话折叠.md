# 小菱审查方式与对话折叠对齐

## 原始需求

用户要求：所有经小菱发起的代码审查和安全审计，都能在执行前询问审查方式；聊天框内展示审查/审计进度；小菱对话过程折叠交互参考 Codex，帮助快速浏览并在需要时展开细节。

## 项目现状

- 成员端小菱当前活跃聊天走 Responses runtime；动态 `ask_user` 已支持问题、选项、禁用自由输入和暂停/回答后续跑，前端由 `ResponseInputCard` 展示。
- 正式代码审查模式与 AgentTeam 成员模式使用不同枚举：直接审查支持 `quick|standard|security|performance|full`；团队正式审查目前只接受 `full|security`。
- 安全审计模式也按范围区分：单文件 `scan_depth` 为 `quick|standard|deep`；项目 `scan_mode` 为 `full|static_full|triage`；任务审计复用既有任务结果，没有独立模式参数。
- 聊天内 `AgentTeamTrace` 已可折叠，成员、任务、事件和协作消息均可展开查看；进度百分比目前只在团队详情窗可见。`ResponseToolTimeline` 尚无整体折叠。
- `ResponseToolTimeline` 当前逐项显示工作步骤，工具成功结果可单独展开；错误和审计阶段即时可见。
- 本地已有长上下文压缩、团队持久账本、会话恢复和账号隔离实现；本任务不重做这些机制。

## 范围

1. 方式缺省时，小菱通过现有 `ask_user` 在发起有副作用的审查/审计调用前询问；用户已经明确指定兼容模式时不重复追问。
2. 模式候选只能映射到当前工具支持的参数。项目全量静态加有界语义扫描（`static_full`）要明确说明语义范围有限，不能标成完整语义审计。
3. 聊天里的工具步骤与 AgentTeam 过程默认显示紧凑摘要，可展开查看原有完整步骤、成员、错误和证据；团队卡片折叠时也显示真实完成比例和状态。
4. 保留完整消息和账本数据；折叠只改变呈现，不删除、截断或改写结果。
5. 响应式支持桌面与窄屏键盘/触屏交互，使用原生可访问状态。

## 边界与假设

- “像 Codex”在本任务中解释为：默认紧凑的执行摘要、清晰状态/进度、按需展开完整过程；不复制 Codex 品牌或内部视觉资产。
- 正式团队审查仍复用现有 `review_orchestrator` 与安全审计 Agent；不新增 Agent、API、表结构或权限。
- 用户明确说“审查一下”但未给模式时才需要提问；对代码解释、历史报告查询等非执行请求不弹方式选择。
- 正式审查模式、项目安全扫描、单文件扫描及历史任务审计维持各自已支持语义，不强行统一成一个不存在的后端枚举。

## 观察证据与限制

用户提供的生产截图显示单次 AgentTeam 为 33%、完成 1/3、失败/阻塞 2；其中一条代码质量 Agent 错误说明模型输出被长度上限截断。截图不证明重复执行的根因，也不证明所有生产审查都失败。本功能不把该样本写成普遍故障。
