# 小菱审查方式与对话折叠执行共识

1. 审查/审计请求缺少方式时，必须先用现有 `ask_user` 收集明确选项，再派发审查工具或团队；若用户已明确给出可执行方式，直接沿用，不重复询问。查询历史、解释报告、只读咨询不触发方式询问。
2. 每个候选使用具体已支持模式和说明；不得把 `static_full` 描述成完整语义覆盖，不得把团队审查只接受的 `full|security` 当作所有 ReviewTask 类型。
3. 团队卡片在聊天消息流内显示真实完成百分比、完成/总数、活动状态及失败/阻塞计数；详细成员树和账本可折叠查看。只有账本计数有真实总数时显示百分比。
4. 工具活动区默认折叠为一行摘要；失败、等待输入、审批和取消仍需在摘要中可见。展开可检查逐步工具结果、审计阶段和完整错误。
5. 所有折叠内容仍保留完整源文本和证据，不因 UX 优化而丢失聊天、工具或 AgentTeam 账本数据。
6. 复用现有会话/团队数据源和权限校验，不增 API、数据库迁移、永久 Agent 定义或跨账号状态。
7. 验收分自动化、本地浏览器和生产浏览器三类记录；没有部署到生产的功能只能写候选通过，不能声称生产通过。
