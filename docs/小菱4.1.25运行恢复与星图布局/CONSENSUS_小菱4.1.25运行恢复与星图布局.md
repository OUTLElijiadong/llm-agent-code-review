# 共识：小菱运行恢复与星图布局

## 验收标准

1. 新运行先提交检查点再发布 `response.created`；兼容旧客户端在提交前进行 `pending` 探测时，服务端可在有界窗口内重读并仅返回同账号、同会话、同 surface 的真实动作；令牌版本变化、权限撤销及错误归属仍拒绝。
2. 未知 run 最终仍返回明确 404；停止/终态运行仍返回冲突，不得转成空成功。
3. 圆桌列表保持活跃/暂停优先、更新时间和会话 ID 倒序、offset/limit 语义、账号隔离及活跃会话刷新；排序查询只投影会话 ID。
4. 星图位于聊天消息区上方；不会强制聊天滚动到底；悬浮窗及星图在桌面、窄屏、低视口下均可滚动、无文字/控件重叠。
5. 必要定向检查、前端类型检查、lint 和构建通过；正式发布后核对 SHA 与健康。业务点击验收交由用户。

## 技术约束

- 复用现有 SQLAlchemy ORM、AgentResponseRun 所有权检查、团队授权和 AgentChatDrawer 结构。
- 查询重试必须在只读场景重置事务快照，并保存请求开始时的 `token_version`。
- 生产发布仅使用 `deploy/deploy.sh all --revision <完整 SHA>`，遵守当前发布清单的资源、备份和恢复门禁；不绕过失败门禁。
- 自动执行只适用于用户已明确授权且应用权限允许的操作；不得把便利性等同于提权。


6. 两端禁止把成员结果、finding、验证、错误或协作正文拼成 assistant 消息；星图上方固定可见，小菱真实汇总位于星图下方聊天区。

## 自动维护补充约定

应用每5分钟回收过期仪表盘统计、沙箱测试文件缓存及已结束且无订阅/执行任务的圆桌内存副本；持久讨论记录不因缓存回收而删除。报告按终态时间及可配置保留期有界清理，先复用现有类型专属生命周期，避免子报告被后台自动重建。
