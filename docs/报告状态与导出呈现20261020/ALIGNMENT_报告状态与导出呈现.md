# 报告状态与导出呈现需求对齐

## 原始需求

用户要求真实验证黑盒测试能否运行、报告能否准确说明执行情况，并指出报告状态和格式需要清楚可信。当前生产报告已由授权的固定白名单黑盒任务生成；本次只修复检查中实际发现的状态展示和长任务编号排版问题。

## 项目理解

沙箱报告数据由 `sandbox_service` 持久化为确定性 Markdown 与结构化 `ai_review` 元数据；`report_service.load_task_issue_stats` 将其投影到报告列表与详情；前端列表和详情分别提供状态说明。领域报告 PDF/Word 复用 Markdown 转换器，导出标题由任务名和公开任务编号构成。

## 已复现问题

已授权运行的生产报告明确记录多 Agent AI 审查“按策略跳过”，但后端列表/详情数据投影只透传 `complete` 和 `incomplete`，前端因此显示“状态未知”。Word/PDF 导出将长任务编号放进标题并手工切段，造成标题换行割裂。真实 Word 在 WPS 中可以显示中文，字体不是此次缺陷。

## 范围边界

- 透传并展示 AI 审查的 `skipped` 状态及可用原因；真正没有状态证据的旧报告仍显示“状态未知”。
- 修复长公开任务编号在 PDF/Word 中的标题层级与断行，不改报告正文或事实。
- 不重跑靶场，不调用模型，不改写任务结论，不做批量历史报告迁移。
- 生产回归只复用既有任务记录和授权账号；不触发新的黑盒或远程目标请求。

## 疑问澄清

无。缺陷已在真实生产报告及导出文件中复现，状态来源与修复边界明确。
