# 报告状态与导出呈现需求对齐

## 原始需求

用户要求真实验证黑盒测试能否运行、报告能否准确说明执行情况，并指出报告状态和格式需要清楚可信。当前生产报告由已授权的固定 HTTP 白名单任务生成；本轮复用该报告，只修复实际发现的状态展示与 PDF 断行问题。

## 项目理解

沙箱报告数据由 `sandbox_service` 持久化为确定性 Markdown 与结构化 `ai_review` 元数据；`report_service.load_task_issue_stats` 将其投影到报告列表与详情；前端列表和详情分别提供状态说明。领域报告 PDF/Word 复用 Markdown 转换器，导出标题由任务名和公开任务编号构成。

## 已复现问题

已授权运行的生产报告明确记录多 Agent AI 审查“按策略跳过”，但后端列表/详情数据投影只透传 `complete` 和 `incomplete`，前端因此显示“状态未知”。PDF 通用断行器把超过 24 字符的英文片段强行切段，实际把项目名切成 `Dem` / `o`，并切开沙箱编号。WPS 实际打开 Word 后确认中文、正文和编号均正常；先前 LibreOffice 的方框显示是本地字体环境造成的误判，不属于 Word 导出缺陷。

## 范围边界

- 透传并展示 AI 审查的 `skipped` 状态及可用原因；真正没有状态证据的旧报告仍显示“状态未知”。
- 保留 PDF/Word 的标题编号分层，并修复 PDF 断行：不拆开项目名与 40 字符以内标识；更长的连续 ASCII 标识最多每 40 字符换行。
- 不重跑靶场，不调用模型，不改写任务结论，不做批量历史报告迁移。
- 生产回归只复用既有任务记录和授权账号；不触发新的黑盒或远程目标请求。

## 疑问澄清

无。状态投影缺陷及 PDF 断行已在真实生产报告中复现，修复边界明确。
