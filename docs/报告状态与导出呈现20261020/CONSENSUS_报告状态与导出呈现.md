# 报告状态与导出呈现需求共识

## 需求与验收标准

1. `ai_review.status=skipped` 必须从持久化来源投影到报告列表和详情，显示“已跳过/按任务策略跳过”，不得写成“未知”或“失败”。
2. 已知跳过原因独立保存并展示；原因缺失时仍可依状态说明“按任务策略跳过”，但不编造原因。真正缺少状态字段的历史记录继续显示未知。
3. PDF/Word 的主标题只显示报告类型，长任务编号作为独立次级信息显示，编号必须完整可读；PDF 不得把项目名或 40 字符以内标识硬切成残片。
4. 不改动 HTTP 实际执行记录、覆盖状态、评分或报告发现，不重跑靶场，不批量更新历史记录。
5. 部署后用现有任务的报告页面与 PDF/Word 导出进行生产核验，确认原执行证据仍一致、AI 跳过状态准确、编号不被标题切断。

## 技术实现

- `sandbox_service` 保存与合并 `skip_reason`，并在恢复既有终态时保留该元数据。
- `report_service` 对列表和详情统一透传 `skipped`、失败原因和跳过原因。
- 报告详情和列表按 complete/incomplete/skipped/unknown 分别呈现。
- `domain_report_exporter` 为长任务编号建立独立元信息行；其余报告导出内容保持原样。
- PDF 只对超过 40 字符的连续 ASCII 标识加人工换行，保留短项目名、沙箱编号和常见提交摘要的完整连续显示。
- 不新增 API、数据表、数据库迁移或外部依赖。

## 质量门控

- 新增后端投影与元数据合并回归用例、前端列表/详情状态用例、Word/PDF 长标题用例。
- 静态审查确认 unknown 仅用于无状态证据，skipped 不落入告警通用文案。
- 正式发布按仓库 release checklist 执行；部署后只读回查现有真实报告，不重复运行安全靶场。
