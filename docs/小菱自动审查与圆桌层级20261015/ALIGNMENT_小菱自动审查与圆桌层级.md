# 小菱自动审查与圆桌层级对齐

## 原始需求

- 网页各页面保持一致的视觉层级；圆桌讨论作为小菱的次级操作，不应与全站主导航或主行动并列。
- 用户提交代码给小菱后，应自动调度适配的审查 Agent 并在当前会话收到结果，无需手动选择模式、刷新或点击“继续”。
- 真实复测已观察到临时 Agent 证据契约失败和最终 Responses 请求 HTTP 402；保留失败原因，不把部分结果包装成完整成功。
- v4.0.104 普通 Safari 刷新复测进一步确认：终态团队结果仍在服务端账本，但失败会话只恢复错误卡；恢复逻辑只覆盖实时回执，没有覆盖已确认回执的历史恢复。

## 范围与边界

- 对齐用户端与管理员小菱面板中的圆桌入口；通过真实页面复核桌面和手机层级、定位与遮挡。
- 未指定方式的普通代码审查默认使用标准代码审查；代码片段与项目正式审查按输入范围分别路由。
- 临时 Agent 只在当前账号、当前团队执行；不扩大工具权限、不绕过审批、不写项目文件。
- 失败时从同一 run 的精确 Mesh 回执 ID，或该 run 持久化的 `create_agent_team` 完成事件所指团队，回收已保存子 Agent 结果；标明未完成核验项和模型服务错误，不重跑模型、不重复确认、不编造成功结论。
- 安全审计模式选择、高风险操作审批及真实渗透授权规则不在本次放宽。

## 当前项目理解

- 技术栈为 Vue 3/Vite、FastAPI、SQLAlchemy、Pydantic；团队任务由持久化团队账本与 Mesh 终态回执驱动。
- 圆桌入口由全局 `GlobalDiscussionHost` 挂载并传送到活动小菱抽屉标题栏，菜单脱离标题栏 stacking context；其视觉仍需压低为次级入口。
- 临时分析器以真实来源 ID 和逐字证据校验输出；代码片段属于 `task_input`，没有数据库文件坐标。
- 会话消息由服务端 Responses transcript、Mesh 团队账本和账号隔离的本地快照共同恢复；任何降级答复都必须与团队 ID 和当前账号绑定。

## 歧义处理

- 未指定代码审查方式时固定默认为“标准审查”，不询问模式；只有缺少目标、输入或权限等会改变执行对象/安全边界的信息时才澄清。
- 子 Agent 或模型失败不阻塞已持久化的可用发现；结果必须标明“部分结果/未完成核验”，失败原因与剩余风险并列展示。

## 验收标准

1. 临时片段审查仅引用 `task_input` 和原文引文，不伪造文件 ID 或行号；数据库源码文件仍要求真实文件及行号证据。
2. 自动重试将可信、服务端生成的纠偏提示送入有效模型上下文；调用方不能伪造内部重试元数据。
3. 团队终态后模型总结失败时，页面自动显示已保存的部分结果，团队回执幂等收敛，刷新/切换会话后可恢复。
4. 代码提交无需选模式、手动续跑或刷新；普通代码审查按标准模式并自动调度团队。
5. 圆桌按钮只在小菱面板内以次级控件显示，桌面与手机均不遮挡主内容、标题或关闭操作。
6. 相关后端/前端测试通过；真实 Safari 标准浏览器复测成功与失败恢复路径。上游额度不足时只验收确定性部分结果闭环，不宣称模型审查全通过。
