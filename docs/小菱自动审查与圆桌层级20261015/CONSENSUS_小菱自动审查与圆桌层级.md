# 小菱自动审查与圆桌层级共识

## 需求描述

提交代码给小菱后，系统自动以标准代码审查为默认方式，调度当前账号可用的审查团队，等待终态并在同一聊天会话给出结果。用户不需要先选择模式、手动重试、刷新或点击继续。圆桌讨论入口属于小菱会话的次级操作。

## 实现方案

1. 在 Responses 小菱行为规范中将普通代码审查默认模式改为 `standard`；审计扫描模式仍遵守原有选择和授权规则。
2. 临时 Agent 提示词根据来源类型约束证据坐标；片段/用户输入不带虚构 `file_id` 或行号，真实源码文件仍校验实际文件及行号。
3. 自动重试只接收团队服务写入的内部策略，校验租约与 attempt 后把固定、安全的纠偏提示注入第二次有效分析提示词。
4. 结构化校验失败保留不含原文/密钥的错误类别，便于确认失败环节。
5. 若终态团队已有结果而 Responses 汇总因上游失败，展示清楚标记的确定性部分答复；刷新恢复按失败 run 的 Mesh 消息 ID 或同一 run 的团队创建完成事件精确关联团队账本。已完成回执不再无限触发同一失败模型调用。
6. 统一圆桌控件的标题栏次级样式、桌面/移动断点和 popover 层级，继续复用现有 GlobalDiscussionHost 和 design tokens。

## 安全及数据边界

- 不改变会话账号隔离、页面角色权限、原工具白名单、租约校验、风险审批或安全审计授权。
- 降级答复只读取当前账号/当前 surface/当前 session 的终态团队数据，清楚区分已完成、失败、阻塞与未核验。
- 只有完整验证节点成功后才能报告团队整体通过；402 只说明上游计费/额度拒绝，不代表代码检查通过或失败。

## 验收

- 后端片段证据契约和自动重试上下文有回归测试；调用方注入内部标记被清除/拒绝。
- 前端失败回执能自动整理并持久恢复结果，消息仅一次且顺序正确；用户端和管理员端均纳入。错误 run 不得关联其他会话回执，也不得因刷新再次请求模型。
- 代码模式默认标准且不调用 ask_user；明确安全审计模式仍遵守原确认规则。
- 圆桌入口与小菱标题栏同层、低于主会话动作；桌面及 390px 视口可见、可点击、无溢出/遮挡。
- 生产 Safari 测试记录实际版本、账号角色、触发输入、结果、刷新恢复和上游状态；有限条件单独标明。
