# 通用 AI 接口配置与双栏滚动隔离：对齐

## 原始需求

1. 完整完成后续待办，并优化管理端通用 AI 接口配置。
2. 配置页应具备截图中的接口类型、Base URL、API Key、当前模型、超时时间、最大重试次数、温度系数、保存配置、测试连接，并能拉取模型。
3. 拉取模型、测试连接或保存失败时，页面不能被错误堵死，应保留输入、显示原因并提供可继续的操作。
4. 管理后台左侧侧边栏与右侧内容区域隔离滚动；从长页面切换到“大模型配置”时无需先手动向上滚动。

## 项目理解

- 后端是 FastAPI + SQLAlchemy，系统级配置保存在 `system_config` 键值表，API Key 使用现有 Fernet 密钥环加密。
- 用户个人 API 配置和管理员全局配置共用 OpenAI-compatible Chat Completions 传输，但当前全局路由没有 `/models` 能力，测试逻辑没有统一的重试和错误映射。
- `ApiConfig` 是运行时解析结果，优先级为用户配置 > 全局配置 > 环境变量默认；不能破坏此优先级和现有 SSRF 校验。
- 普通用户布局已具备部分高度约束，管理布局缺少固定外壳高度与路由切换复位，需要在管理布局边界修复。
- FlyTrap 已退役，现有退役审计和受控清理产物不得删除；备份验证不得再次把大备份恢复到生产 MySQL。

## 本次边界

### 纳入

- 管理员全局 LLM 配置的字段、持久化、脱敏输出、模型列表拉取、连接测试、有限重试、错误分类和系统默认回退。
- 运行时将全局超时、重试和温度配置传递到通用 Chat Completions Agent；保持用户个人配置优先。
- 管理后台桌面端和移动端的左右/上下区域滚动隔离，以及路由切换后的内容滚动位置复位。
- 后端单元测试、前端组件/API 测试、构建与可用的浏览器/API 验收。
- 更新本次任务的 6A 文档，并修正与 FlyTrap 退役状态冲突的待办表述。

### 不纳入

- 不恢复 FlyTrap，不删除退役备份，不改动生产数据库数据。
- 不在没有专用实例和资源门禁的情况下执行大备份恢复验证。
- 不把用户个人 Agent 专属温度策略、Responses 原生协议改造成另一套接口；只让通用配置作为兼容默认值并保持已有专属覆盖规则。

## 默认决策

- 接口协议采用公网 OpenAI-compatible `/models` 与 `/chat/completions`；Base URL 可带 `/v1`，也可误填末端路径，服务端统一归一化。
- `/models` 不支持或返回 404/405/501 时，不把页面锁死：若已有模型名则保留该模型并返回“手工模型回退”警告；没有模型名则明确要求人工输入。
- 仅对超时、传输异常、429 和 5xx 做有上限的指数退避；401/403/4xx 参数错误不重试。
- 保存配置不因上游暂时不可用而丢失用户输入；激活状态仍由管理员明确选择，运行时解析异常继续回退系统默认并记录机器可读原因。
- 已停用或凭据不可用的历史全局覆盖不得遮住真正生效的系统默认配置；系统默认 Key 仅可在端点身份完全一致时用于拉取模型和测试，不能作为自定义全局覆盖的可复用 Key。
- timeout 范围为 5-600 秒，max retries 为 0-5，temperature 为 0-2；非法持久化值按安全默认值修正，不使服务启动失败。

## 验收问题清单

| 优先级 | 问题 | 当前决策 |
| --- | --- | --- |
| P0 | 未提供模型列表时是否完全阻断保存 | 否，保留手工模型并给出可见警告 |
| P0 | API Key 是否回显或进入日志 | 否，始终脱敏，异常只返回安全摘要 |
| P0 | 单次上游失败是否阻断整个页面 | 否，表单级错误 + 重试/手工继续 |
| P1 | 全局配置异常如何影响业务 | 解析失败回退系统默认，健康来源明确标记 |
| P1 | 侧栏与内容如何滚动 | 管理外壳固定 `100dvh`，两列各自滚动，路由切换内容回顶 |
| P2 | 备份验证是否在本任务中重复恢复 | 否，继续保持生产主库保护，另以护栏文档记录 |

## 对齐结论

本任务以“配置可用、失败可继续、回退可解释、页面可操作”为完成定义。所有新增接口保持向后兼容，已有请求省略新增字段时使用现有环境默认值。
