# 通用 AI 接口配置与双栏滚动隔离：共识

## 需求与验收标准

1. 管理员页面可以查看并编辑 provider、Base URL、API Key、当前模型、timeout、max retries、temperature 和 active 状态。
2. 页面点击“拉取模型”后调用受保护的管理员接口；成功展示去重模型列表，失败保留已有/手工模型并显示可读原因。
3. “测试连接”先使用选择的模型进行最小 Chat Completions 请求；对瞬时故障有限重试，认证、参数和地址错误快速返回，不循环等待。
4. API Key 仅在服务端短暂使用并加密保存，响应、日志和审计摘要不得包含明文。
5. Base URL 继续执行协议、凭据、query/fragment、DNS/公网地址校验；末端 `/models` 或 `/chat/completions` 可被规范化。
6. 全局配置异常、密钥解密失败或上游不可用时，运行时回退系统默认 DeepSeek；页面明确显示来源和下一步动作。
7. 管理后台桌面端侧栏和内容区可分别滚动，页面主体不发生第三个滚动条；移动端菜单横向滚动、内容纵向滚动，切换路由后内容滚动到顶部。
8. 新增后端/前端测试覆盖成功、空列表、404 回退、401、429/5xx、超时、非法参数、加载失败、保存失败和滚动契约；原有测试和构建不回归。

## 技术方案

- 后端在现有 `api_config_service` 中抽取统一的 URL 规范化、模型列表解析、瞬时错误重试和连接测试逻辑；管理员路由增加 `POST /api/admin/llm/models`。
- `system_config_service` 在原 `llm_provider` JSON 中增量保存运行参数，读取时进行类型钳制和默认补齐；不新增数据库迁移。
- `ApiConfig` 增加带默认值的运行参数字段，追加在现有字段之后以保持位置参数兼容；通用 Agent 使用解析出的值，专属 Agent 显式参数仍可覆盖。
- 前端管理页改为完整表单，保留输入状态，分别维护加载、拉取、测试、保存状态和局部错误；Key 输入留空表示保留，提供恢复系统默认动作。
- `AdminLayout` 固定外壳高度并隐藏外层溢出；`.admin-nav` 与 `.admin-content` 设置 `min-height:0`、独立 overflow 和 overscroll 隔离；监听路由并将内容容器滚动位置复位。

## 运行与回退约束

- 模型发现接口失败不改变已保存配置；测试失败不自动激活新配置。
- 历史覆盖不可用时，配置页展示当前真正生效的系统默认端点、模型和脱敏 Key 状态；仅同端点测试可复用系统 Key，切换端点必须重新填写 Key。
- 保存提交异常必须回滚数据库会话，前端不清空表单并允许再次提交。
- 上游错误消息截断并清理控制字符，不反射 Authorization、API Key、内部堆栈或 SQL。
- 备份验证脚本继续禁止生产主库恢复；在专用验证数据库未就绪前不执行破坏性验证。

## 共识状态

关键歧义已按上述默认决策闭合，无需额外人工选择即可实现和验证。
