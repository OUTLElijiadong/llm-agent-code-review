# 沙箱测试阶段标识对齐

## 原始需求

部署并查明 Prism 黑盒、白盒测试失败的原因；修复经复现确认的问题，发布后复测并记录证据。

## 现状和证据边界

- 生产历史任务 `sbx_3b317e05c0fa45128c20e31d` 请求的是黑盒测试；路由探测在约 5 秒处已明确失败，但容器约 120 秒后才以退出码 124 终止。
- 该任务的代码扫描没有发现可验证的服务路由。测试失败是样本路由断言失败，不是 Prism 公网 `/healthz` 或 `/readyz` 故障。
- 历史执行器只按 PID 结束进程；事件时间线和 4.0.78 runner 代码支持后代进程未及时退出的解释，但没有退出前进程快照，具体遗留进程不能断言。
- 生产 4.0.83 runner 已加入进程组回收，修复了上述清理缺口；生产 Worker 的重复复测仍需本任务完成。
- 4.0.83 仍将所有测试模式的启动阶段记录为 `running_whitebox`，导致黑盒和组合模式被显示成“白盒测试”。

## 范围

只修正沙箱测试启动阶段的模式标识及显示兼容，不改变执行器内部活动状态、停止协议、测试判定、权限、数据库结构或沙箱资源限制。

## 验收标准

白盒、黑盒、组合模式产生正确事件阶段；旧黑盒/组合历史事件按环境保存的测试模式正确显示；相关后端单测、前端单测、Lint 和构建通过；生产发布后复测黑盒正常与无路由异常样本、白盒样本，并核对真实 Safari 页面。
