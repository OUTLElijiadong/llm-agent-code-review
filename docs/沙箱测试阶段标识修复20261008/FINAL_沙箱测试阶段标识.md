# 沙箱黑盒与白盒失败原因、修复和生产验收

## 交付结论

v4.0.85 已于 2026-10-08 00:21 UTC 正式部署，生产应用与独立 Sandbox Worker 使用同一提交 `727d636c22e5ff7e8d7fe887f934867ce591e1f3`。本次复测确认 Worker 的有效黑盒、白盒和组合执行均通过；负例按预期失败。验收覆盖生产 Worker 的直接执行接口和 Safari 页面版本/历史列表读取，不等同于通过真实账号从 UI 新建任务的完整业务端到端验收。

## 查明的原因

- 历史黑盒任务 `sbx_3b317e05c0fa45128c20e31d` 所用样本没有可用 Web 路由，配置的 8 个候选路径返回 404。这解释该样本的业务探测失败，不能据此判断 Prism 公网服务故障。
- v4.0.83 曾把黑盒和组合任务的启动事件记录成 `running_whitebox`，导致进度显示错误；v4.0.84 修正事件阶段与前端映射。
- v4.0.84 的生产复测又暴露了 Worker 同进程竞态：每 30 秒运行的 janitor 把仍由 `submit_job()` 处理、处于 `validating`/`preparing` 阶段的任务误认为重启遗留任务并终止。systemd `NRestarts=0`，因此这次失败不是进程重启。
- v4.0.85 在回收逻辑中跳过仍有进行中/待处理提交预约的任务；真实 Worker 重启后进程内预约会消失，遗留任务继续按失败关闭策略处理。
