# 沙箱黑盒与白盒任务阶段及回收竞态修复

## 交付状态

本次根因已定位，4.0.85 候选已在本地通过目标回归与相关测试，但尚未完成候选 CI、生产发布和发布后复测。本文件当前记录的是阶段性结论，不表示交付完成。

## 已确认原因

1. 历史任务 `sbx_3b317e05c0fa45128c20e31d` 使用的项目样本没有可用 Web 路由，配置的 8 个路径返回 404；这是样本路由断言不匹配，不能据此认定 Prism 公网服务故障。
2. 4.0.83 将黑盒、组合任务的 Worker 事件阶段统一记成 `running_whitebox`，造成前端进度标签错误。4.0.84 已修正事件阶段并部署主站和独立 Worker。
3. 4.0.84 发布后的 12 轮生产 Worker 复测中，第一轮无路由负例被误终止。审计事件为 `validating → preparing → stopping → cleanup_retry → failed`，错误提示称执行器重启时任务停留在 `preparing`；同时 systemd `NRestarts=0`。因此问题不是服务重启，而是同进程 30 秒 janitor 与 `submit_job()` 发生竞态：janitor 将活跃提交误认为重启遗留任务。其余 11 轮符合预期，不能把 12/12 记为场景通过。

## 已实现的 4.0.85 候选修复

`_recover_jobs()` 在处理 active 状态前检查 `SUBMISSIONS_INFLIGHT` 和 `PENDING_SUBMISSIONS`；若同一进程仍在提交任务，本轮跳过回收。真正进程重启会清空进程内预约，遗留的 `validating`/`preparing` 仍按原有失败关闭策略处理。

修复前新增的进行中状态回归稳定复现错误；修复后用真实 `submit_job()` 线程分别在 validating/preparing 阶段并发触发恢复器，任务均继续到 running。还验证了两种预约集合、以及模拟重启后预约集合为空时失败关闭并完成清理。当前本地候选通过 executor 测试文件 86 项、前端标签测试 6 项、Ruff 和 Python 编译。
