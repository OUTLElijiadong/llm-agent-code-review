## 执行约束

1. 每项已声明为缺陷的问题必须先由失败回归或生产只读复现证明，再实施修复并重复原场景。
2. 只有有源码/数据/测试证据的结论进入“确认”；其余明确记为未验证，不升级为漏洞。
3. 生产用户、权限、审批、Agent、报告及项目数据保持只读；不能通过点击任何会保存或改变状态的控件来制造验证数据。
4. 完整测试、构建和发布按同一候选 commit 记录；外部 Redis/供应商模型/移动真机未运行时逐项说明。
