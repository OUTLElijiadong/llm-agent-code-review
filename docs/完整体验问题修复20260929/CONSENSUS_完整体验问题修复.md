# 完整体验问题修复：验收共识

## 需求描述

以生产 v4.0.30 为基线，针对当前可复现的授权、异步状态、账号隔离和运维界面可理解性问题实施最小修复。安全和业务权限以服务端为准，前端隐藏入口只改善可用性，不能替代授权校验。完成候选验证后按既有发布流程部署，并在普通 Safari 对本轮改动关联页面进行只读真实点击验收。

## 验收标准

1. 新旧报告导出接口在对象查询和渲染之前同时检查 `report:view`、目标格式权限及报告 owner/admin 与项目当前访问范围；不满足对象范围时不泄漏内容。
2. `review_report` 沙箱 Markdown 元数据和下载均要求报告查看权限及 owner/admin 范围；普通测试证据继续按原项目访问规则返回。沙箱/渗透报告在任务列表和详情中的条目数、严重度、评分、评分明细及摘要使用相同的报告访问判定；无权限时字段返回 `null`，前端清楚标出受限，不把隐藏值呈现为零。普通代码审查结果继续按既有项目成员范围读取。
3. 审批、操作审计、AI 调用日志、用户列表只在成功空结果时显示空态；失败有错误与重试；pending 时不误报空态；旧筛选或旧账号请求不能覆盖新数据或清理新请求状态。
4. 移动端审批列表区域具备可访问名称、焦点与真实横向滚动能力；至少通过 320/375/390px 的布局/滚动回归。此自动化结果不等于移动设备真机验收。
5. reviewer 在界面、拒绝消息和 Agent 提示中统一称“审查员”，不改数据库角色名、编码、权限或生产数据。
6. 已知计划 `daily@HH:MM`、`hourly@*:MM` / `hourly@MM`、`interval@Ns` / `interval@Nm` 显示中文解释；Cron 校验接受 APScheduler 的月份与星期英文缩写及数字表达式，范围、大小写与后端规则一致；无效和未知计划继续显示原文；编辑、保存值始终保留机器原值。
7. 监控明确说明工具调用/调度执行/奖惩为累计记录、审批按事项当前状态分组、开放告警为当前未关闭；审批表列为“状态 / 事项数”，工具执行仍称“结果 / 次数”；告警空态不暗示历史失败不存在。
8. 圆桌同账号刷新时丢弃过期分页数据并释放加载状态；账号切换时清空旧账号页面数据，更晚返回的旧账号请求不能污染或清除新账号状态。追问窗口和入口徽标按结束后 5 分钟状态更新。
9. 管理工作台切换模式时旧请求不能覆盖新模式数据或提前清除新模式加载状态；知识页详情响应还须对应当前模式和 Agent。
10. 针对性回归、完整前端测试、完整后端测试、类型检查、前端构建、相关 lint 与差异格式检查通过。被环境跳过的 Redis/外部服务检查要明确标记。
11. 发布后记录完整 SHA、版本、健康/就绪及 release 身份；普通 Safari 验证登录态下相关管理页、角色术语、监控说明与调度说明均已上线。不得在生产触发审批、保存、删除、权限调整等写操作。

## 技术约束

- 使用 FastAPI/SQLAlchemy 现有 RBAC、报告对象访问函数与 Vue 页面状态；无 schema 迁移时不新增迁移。
- `can_view_report` 是只读布尔能力字段，不暴露报告正文或其他账号身份。
- 报告访问以报告可用、具备 `report:view` 且为任务发起人或管理员为准；无权时不读取沙箱 Markdown 以生成列表摘要，列表和详情均遮蔽领域报告派生统计与评分。
- 报告拒绝采取权限拒绝或统一隐藏对象的既有语义，不得影响普通沙箱证据下载。
- 用户与角色目录应并行加载；授权对话框要在角色目录可用后再开启，目录失败必须明确提示。
- 圆桌分页结果按列表代次校验，身份代次单独保护 loading；同账号刷新能释放过期 loading，旧账号 finally 不得清除新账号状态。
- 运维计划的本地化只作用展示层；前端语法/范围校验与后端一致，未知编码/计划保持原值，便于诊断和编辑。
- 数据库、审批和 Agent 治理生产页只读；发布操作按项目生产发布清单先备份、验证、部署、观测。
