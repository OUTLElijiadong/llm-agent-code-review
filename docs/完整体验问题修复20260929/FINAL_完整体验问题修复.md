# 完整体检与告警分页：交付总结

## 当前生产版本

截至 2026-09-30，生产运行 Prism **v4.0.32**，发布 SHA 为 `910af80fc93a41c65314c5cd59589e3518085adf`。`/healthz` 与 `/readyz` 均返回该版本和完整 SHA。v4.0.31 是本轮体验与治理修复的前一生产基线；v4.0.32 在其上补上管理告警分页及未知总数状态修复。

最终 SHA 已从 Git bundle 部署到生产独立 release worktree；GitHub 分支的 push 因 HTTPS 443 连接超时未确认成功。因此，“生产运行该 SHA”有健康接口和发布账本证据，“GitHub 远端已包含该 SHA”没有证据，不能视为已推送。

## 已完成并有证据的范围

- v4.0.31：报告访问权限闭环、角色称谓、治理列表加载竞态、圆桌分页/账号竞态、调度表达式释义、监控统计口径、审批统计命名、日志空态和管理工作台异步响应保护。对应生产只读验收见 [ACCEPTANCE](./ACCEPTANCE_完整体验问题修复.md)。
- v4.0.32：新增管理告警分页 API，保留旧数组接口兼容；管理页显示分页及总数；请求总数未知或失败时隐藏分页控件，避免误报“共 0 条”。105 条隔离数据按 50/50/5 分页，三个 ID 集合与数据库降序查询完整一致，无遗漏、无重复。
- v4.0.32 定向检查：后端 API 集成测试 9 项、前端治理工作台测试 37 项、移动视口 Playwright 40 项通过；Ruff、ESLint、`vue-tsc` 和前端生产构建通过。移动视口测试使用本地模拟 API 和 Chromium，不是真机或生产移动验收。
- 生产发布：备份校验通过；临时隔离库恢复 103 张表并清理；Alembic 保持 `058_roundtable_sessions`。MySQL、Redis、ClamAV、Backend、Frontend 均 healthy。发布后普通 Safari 登录会话真实点击第 2 页、末页、50 条/页并在末页刷新三次；总数、页数、卡片和列表一致，末页 1 条且下一页禁用。生产告警自然从 100 增至 101，测试没有新增、编辑或关闭告警。

## 运维状态与风险

生产 `ops-check` 为 `degraded`，`can_continue=true` 且没有阻断项；磁盘使用率 85% 达普通告警线，critical 阈值为 95%。只运行了清理 dry-run，没有删镜像、缓存、备份或数据。生产主机检查发现 BT-Panel 进程监听 `*:8888`，公网对该端口根路径的 HEAD 返回 Nginx 404；这尚不能证明面板管理路径可访问或可利用，也未确认云安全组和运维依赖。需要运维负责人确认允许来源和依赖后，才能决定限制该端口。
