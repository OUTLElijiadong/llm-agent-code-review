# 完整体验问题修复：对齐

## 原始需求

用户要求对 Prism 做完整检查，结合生产真实点击继续寻找可确认的逻辑和前端问题；修复后按原场景复测并扩充样本。另要求处理《棱镜安全审计报告-2026-09-29.md》所列风险，最终发布并验证，不能把未测风险写成漏洞，也不能把局部验证写成全量通过。浏览器验收使用已登录的普通 Safari，不开无痕窗口。生产审批、权限变更和业务数据写入不属于只读验收动作。

## 基线与证据边界

- 生产基线为 v4.0.30，代码来源提交为 `fc0042149061bfabf870a9597cc1ea4ab8d9da6d`；候选分支起点为 `a957a5db2cd86dc4b8da2dfe26036248cec705e3`。候选改动在发布前不得描述为生产已修复。
- 生产普通 Safari 只读核验已覆盖管理权限、用户、角色、计划调度、监控指标、调用日志和操作审计页面；当前数据与 2026-09-29 旧 UX 报告有差异，历史数字不作为当前生产结论。
- 生产角色/权限页实际存在 61 个权限项，用户列表会自动加载；reviewer 的角色名显示“评审员”，其他页面称“审查员”，属于术语不一致，不代表角色编码或权限不同。
- 生产计划字段有实际值而非空白；运维任务原始英文标识和计划语法可读性弱，是 UX 改进项。调度输入仍需保留原始可编辑值，中文仅为辅助释义。
- APScheduler 的生产调度入口还接受月份和星期英文缩写；前端 Cron 校验必须兼容对应名称、大小写与字段范围，不能仅接受数字表达式。
- 管理审批请求 pending 时切换治理工作台模式，旧响应可能回写隐藏审批数据并提前清除新页面共享加载态；需按当前模式和请求代次丢弃过期结果。
- 监控接口按不同统计粒度返回数据：工具调用、调度执行和奖惩事件是累计记录；审批按事项当前状态分组；开放告警只统计当前未关闭项。数字不同本身不是数据矛盾，页面未标示统计口径才是确认的解释性缺陷。
- 旧报告中的“管理员没有审计数据”“权限点为 0”“调度计划列全空”“顶栏账号裸文本”“审查员任务/报告为空”等均不直接作为当前漏洞；需结合当前页面、数据粒度或权限范围判断。本轮只记录有当前证据的事项。
- 安全审查对验证码强度、限流、路径边界、沙箱及权限行为采用源码和隔离测试验证；未在生产攻击、绕过或写入，不把剩余未知配置声明为漏洞。

## 本轮范围

1. 报告及导出接口统一执行查看权限、格式导出权限和报告对象范围；修复沙箱报告 Markdown 制品下载出口的权限缺口，同时保留非报告测试制品的原授权方式。
2. 报告详情入口与服务端 `can_view_report` 能力一致；任务摘要不得把仅报告可见的沙箱内容泄漏给无权限项目成员。
3. 审批、系统审计、AI 调用日志、用户列表的加载/错误/空态分离，加入重试与乱序/账号切换保护；移动端审批列表能通过键盘或触屏横向查看。
4. 圆桌账号切换时隔离旧请求的分页数据与 loading 状态；结束后 5 分钟追问期继续可用，到期后禁言并按时更新入口状态。
5. 管理端计划显示可读中文释义但保留原始计划；监控明确标注累计、当前开放和审批当前状态的统计粒度；统一 reviewer 显示名“审查员”。
6. 更新任务文档，记录生产只读核验范围、候选测试证据、发布身份和实际未覆盖范围。

## 不在本轮范围

不在生产创建测试账号、发起审查、创建/删除 Agent、审批/驳回事项、改角色或权限；不为排版建议改动业务模型；不把推测的 404、超长上下文或其他未复现风险记为已确认缺陷；不以自动化、源码、部署成功替代真实生产浏览器验收。
