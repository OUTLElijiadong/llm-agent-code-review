# 账号角色与审计权限生产验收对齐

## 原始需求

验证生产管理员、审查员（审计员并入审查员）和普通账号；确认审查员具备审计能力、普通账号不能越权，并验证各账号的 Agent 团队数据互相隔离。

## 边界

- 只使用用户明确提供的三个生产账号执行登录和只读 API 验收；不修改账号、角色、密码或业务数据。
- 允许为修复审计权限缺口发布 v4.0.2；发布事务通过受控迁移 057 调整审计菜单路由。
- 密码、JWT、审计正文和团队 ID 不进入报告。
- 生产磁盘达到 85% 告警线时记录降级，不自动清理镜像、备份或数据。

## 需求理解

代码已有 053 迁移将 auditor 权限并入 reviewer 并停用 auditor。生产账号 18878489000 有 `audit:view`，但审计 API 先前仍只接受管理员；原菜单路径也落在管理员路由下，因此权限声明与实际访问不一致。

## 已确认

- 审查员必须只有一个有效的 `reviewer` 角色，同时具有 `audit:view`。
- 管理员保留审计访问和管理接口；普通账号访问审计与管理接口必须收到 403。
- 临时团队及历史私聊数据按账号隔离，跨账号读取必须被拒绝。
