# 账号角色与审计权限验收共识

## 验收标准

1. 三账号均可登录且身份、状态与预期一致。
2. 管理员、审查员、普通用户分别只有一个有效角色：`super_admin`、`reviewer`、`user`。
3. reviewer 同时有 `audit:view`、`review:view`、`agent:chat`，可见 `/audit` 并能读取审计 API。
4. 普通用户没有 `/audit` 菜单；审计 API、用户管理、RBAC 管理返回 403。
5. 管理员审计和管理 API 可用；非管理员不能查询他人角色权限。
6. 三账号团队列表互不相交；每个账号读取其他两账号的团队详情均被 403/404 拒绝。
7. 发布版本、代码 SHA、迁移、健康检查和备份恢复证据相互一致。

## 技术方案

审计 API 使用既有 `audit:view` 权限门禁并把当前查看者传给审计服务；迁移 057 将带 `audit:view` 的菜单从 `/admin/audit` 移到 `/audit`，降级可精确还原原路径。前端路由和侧边栏以 reviewer 角色及 `audit:view` 双重约束。

## 限制

生产验收使用 HTTPS API 和权限菜单数据，不等同于浏览器人工逐按钮点击或视觉验收。磁盘治理只记录状态，不在发布时清理。
