# CONSENSUS_文档项目对齐

## 1. 需求描述

让项目文档能够准确反映当前代码、配置、部署方式和验证状态,避免后续开发、部署、答辩或交接时被旧文档误导。

## 2. 验收标准

- README 和 `说明文档.md` 中的技术栈、目录、模块数量、表数量、Agent 数量与当前项目一致。
- `docs/01-11` 核心文档不再把当前已实现能力写成未实现或预留。
- API 文档覆盖当前正式路由分组,包含安全审计、自进化、文件夹上传、任务取消和任务删除。
- 部署文档只引用仓库真实存在的部署文件和 nginx 配置。
- 测试文档明确当前自动化验证结果和覆盖率差距。
- 新增本任务 6A 文档和验收记录。

## 3. 技术约束

- 不修改业务实现。
- 不提交 `.env`、密钥或运行时日志。
- 保留历史专项文档的阶段语境;对旧数字添加当前状态说明,不把历史记录伪造成新结果。

## 4. 集成方案

直接更新 Markdown 文档,并用命令复查路由、Agent、文件数量、测试和构建结果。
