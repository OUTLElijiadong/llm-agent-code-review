# 01 · 对齐文档

> 用途:在开发开始之前,把"做什么、不做什么、谁来用、做到什么程度"写清楚,作为与导师、答辩组沟通的基线文档。每次范围或决策有变化,直接更新本文。

## 1. 项目背景

随着大语言模型(LLM)能力的成熟,代码审查正从"基于规则的静态分析"向"基于语义的智能审查"演进。传统工具(如 SonarQube、ESLint、PyLint)依赖预设规则,虽然查得准但缺乏 **语义理解** 和 **修复建议**;商业 AI 工具(如 GitHub Copilot Review)又依赖外部平台和付费订阅,不适合教学场景。

本系统作为本科毕业设计,目标是 **以最小工程代价,构建一个可演示、可解释、可闭环的智能代码审查平台**,验证大模型在代码质量管理中的落地价值。

## 2. 项目目标

### 2.1 业务目标

- 让用户(学生、教师、小团队开发者)能够在本地系统中管理代码项目和文件;
- 借助 DeepSeek 大模型,自动发现代码中的质量问题并给出修复建议;
- 生成结构化审查报告,支撑代码质量分析与教学反馈。

### 2.2 技术目标

- 验证 **数据库直存代码 + LLM 审查** 的工程可行性;
- 沉淀一套可复用的 Prompt 模板、结果解析与问题闭环机制;
- 实现一个具备完整前后端、可容器化部署的工程化系统,而非脚本式 Demo。

### 2.3 毕设目标(答辩视角)

- 系统功能完整、演示稳定、可现场操作;
- 文档体系齐全(需求/设计/数据库/接口/部署/测试);
- 有可量化的指标:审查耗时、问题数量、评分变化等;
- 有可讲清楚的技术亮点:Prompt 工程、分片策略、结果解析、闭环管理。

## 5. 关键决策

> 每条决策标明 **决策 / 备选 / 选定理由**。所有备选都被排除,这里只保留最终结论与原因。

### D-01 · 不接入第三方代码托管平台

- **决策**:不集成 GitHub / GitLab / Gitee。
- **备选**:OAuth 登录 + webhook 拉取 PR;Git 仓库本地克隆。
- **理由**:接入第三方平台对答辩演示几乎无加分,但带来 OAuth 流程、网络依赖、webhook 调试等额外复杂度。数据库直存代码更稳定,演示一次过。

### D-02 · 后端选用 FastAPI

- **决策**:FastAPI 3.11 + SQLAlchemy 2.x + Pydantic v2 + Alembic。
- **备选**:Django、Spring Boot、Flask。
- **理由**:Python 生态调用 DeepSeek 最顺手;FastAPI 自动生成 Swagger;异步原生支持,后续可平滑接 Celery。

### D-03 · 前端选用 Vue 3 + Element Plus

- **决策**:Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts + Monaco Editor。
- **备选**:React + Ant Design;原生 HTML。
- **理由**:Element Plus 表单/表格/对话框开箱即用,极大节省时间;Monaco Editor 是 VS Code 同款,体验加分。

### D-04 · 代码存数据库 LONGTEXT

- **决策**:`code_file.content` 字段使用 `LONGTEXT`,直接存源代码。
- **备选**:对象存储(MinIO/OSS)、本地文件系统。
- **理由**:LONGTEXT 上限 4GB,远超单文件需求;事务一致;部署简单不依赖外部存储。

### D-05 · 单文件审查为主,长文件分片

- **决策**:以单个文件为审查单元;文件 > 配置阈值(默认 6000 字符)时按函数/逻辑块分片调用。
- **备选**:全项目一次性送入。
- **理由**:DeepSeek 上下文有限,单文件粒度匹配开发者直觉,问题定位到行更精准。

### D-06 · DeepSeek 输出强制 JSON

- **决策**:Prompt 中明确要求返回 JSON,使用 `response_format={"type":"json_object"}` 约束;后端做容错解析。
- **备选**:自由文本 + 正则解析。
- **理由**:结构化结果便于入库、统计和前端渲染。

### D-07 · 审查规则用数据表 + 用户级配置

- **决策**:`review_rule` 表存预置规则,用户可启用/禁用;Prompt 动态拼装启用的规则。
- **备选**:硬编码 Prompt。
- **理由**:展示"可配置性"亮点;答辩时方便讲故事。

### D-08 · JWT 鉴权 + Bearer Token

- **决策**:登录返回 access_token(JWT),前端存 localStorage,Axios 拦截器自动带上。
- **备选**:Session + Cookie。
- **理由**:前后端分离场景下 JWT 更轻量。

### D-09 · 审查任务同步执行(一期)

- **决策**:一期审查任务同步执行,前端显示 Loading;二期再考虑 Celery 异步。
- **备选**:一上来就接 Celery + Redis。
- **理由**:同步逻辑简单、调试容易;DeepSeek 单文件耗时 5-30 秒,前端可接受。

### D-10 · 报告导出后端生成

- **决策**:Word/PDF 在后端用 python-docx / ReportLab 生成,流式下载。
- **备选**:前端 jsPDF。
- **理由**:后端生成可控样式,版本一致。

### D-11 · 多 Agent 采用轻量编排而非新任务系统

- **决策**:在现有同步审查链路中增加多 Agent Prompt 编排,不新增数据库表和异步队列。
- **备选**:独立 Agent 任务表、消息队列、跨模型投票。
- **理由**:当前项目以毕设演示稳定为优先,轻量编排能体现多 Agent 概念,同时复用 `ai_call_log`、`review_task` 和 `review_issue`。

### D-12 · 前端导航采用 9 大功能模块分类

- **决策**:把前端侧边栏主导航固定为 9 项功能(F-01 ~ F-09),管理员补 3 项(F-A1 ~ F-A3),与 3.3 节的功能模块分类一一对应;新增 Agent 中心、问题追踪、代码中心、个人中心四个一级入口。
- **备选**:沿用现有 5 个主导航 + 2 个管理项,把 Agent、问题、代码、个人入口都藏到二级菜单或下拉。
- **理由**:9 大模块对应业务认知里"项目-代码-审查-问题-报告-Agent-规则-看板-个人"完整闭环,导航一屏可见即可触达;Agent 中心是多 Agent 编排能力的可视化窗口,作为一级入口能在答辩时直观展示系统亮点;问题追踪和代码中心则解决跨项目场景下的"找不到、跳不到"痛点。

## 6. 关键假设

| 编号 | 假设 | 验证方式 |
| --- | --- | --- |
| A-01 | DeepSeek API 可稳定访问且响应在 30 秒内 | 接入前用 curl 测延迟与限流 |
| A-02 | 单文件代码量 ≤ 50KB,绝大多数 < 10KB | 上传时硬限制 200KB |
| A-03 | 用户数 < 100,并发审查 < 5 | 本地系统,无需高可用 |
| A-04 | 用户浏览器为 Chrome/Edge 最新版 | 不做 IE / 旧版兼容 |
| A-05 | 用户具备基本编程能力,能看懂代码与建议 | 不做新手引导 |
| A-06 | 多 Agent 审查会增加 LLM 调用次数 | 演示前验证 DeepSeek 余额和耗时 |

- [ ] docker-compose 一键启动,从空环境到能用 ≤ 5 分钟

### 7.3 演示验收

## 8. 风险清单

| 编号 | 风险 | 等级 | 缓解措施 |
| --- | --- | --- | --- |
| R-01 | DeepSeek 限流或返回不稳定 | 高 | 接入重试 + 本地缓存最近一次结果;答辩用截图兜底 |
| R-02 | LLM 返回非 JSON | 中 | 强制 JSON 模式 + 二次清洗 + 失败重试 |
| R-03 | 长文件超出上下文 | 中 | 分片策略 + 按函数切分 + 限制文件 200KB |
| R-04 | 前后端联调延期 | 中 | 提前定 API 契约(本文档 + Swagger),后端 mock 数据 |
| R-05 | Monaco Editor 加载体积大 | 低 | Vite 按需引入语言包 |
| R-06 | 数据库代码字段过大影响性能 | 低 | LONGTEXT 字段不索引,查询不 SELECT * |
| R-07 | 审查耗时长导致前端超时 | 中 | Axios 超时设 60s;后续接异步队列 |
| R-08 | 演示环境 DeepSeek 余额耗尽 | 中 | 提前充值;预录演示视频兜底 |
| R-09 | 多 Agent 模式调用次数增加 | 中 | `standard` 保持单代理;答辩现场优先选小文件 |
| R-10 | 9 大功能模块扩展带来的工程量 | 中 | F-03/F-05/F-07/F-09 与 F-A3 为新增页面,优先做 UI 骨架与最小可演示数据;F-A3 系统审计可暂用 `ai_call_log` + 关键服务日志拼接,不新增独立表 |
