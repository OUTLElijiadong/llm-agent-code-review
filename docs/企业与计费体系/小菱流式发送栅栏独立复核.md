# 小菱流式发送栅栏独立复核

## 范围与当前状态

本记录针对本地开发中的企业小菱计费归属发送栅栏，不代表生产代码已部署或真实供应商验收。公司群与私聊新付费入口的验证门禁尚未开放；企业、小组、成员权限、计费预占、外部请求和未知账单须分别验证。

本地检查使用 `httpx 0.28.1`、`httpcore 1.0.9`。目前 `NativeResponsesTransport` 创建的异步客户端关闭了环境代理，默认不跟随重定向，也未启用 HTTP/2；直接模型调用、Search/Fetch、团队任务和其他网关是不同路径，不能仅凭一条主模型测试推断全部路径安全。

## 已验证的发送边界

当前依赖 `http11.send_request_body.complete` 等事件，尝试在请求体写入本地网络传输后释放归属锁。独立运行仓库现有本地 HTTP 测试 `tests/unit/services/test_enterprise_assistant_stream_fence.py` 为 **1 项通过**：测试服务器读到请求体、尚未完成流式响应时，模拟授权栅栏已释放。该测试使用本地 HTTP/1.1、模拟上下文管理器，不验证真实数据库行锁、真实供应商、HTTP/2、代理、网络中断或计费结果。

本地 `httpcore` 源码中，HTTP/1.1 和 HTTP/2 的该事件分别位于请求体发送协程完成后。它至多说明该版本的本地传输写入步骤已结束，**不证明供应商已接收、处理、计费或持久化请求**。发送后的断线、超时、取消和提交不明确仍须按未知账单处理，不能自动重发或当作未发送释放。

官方 [HTTPCore 扩展说明](https://www.encode.io/httpcore/extensions/)说明异步 trace 回调必须为异步函数，事件集合可能跨版本变化；依赖特定事件时建议固定版本。仓库 `backend/requirements.txt` 和 `requirements-dev.txt` 目前使用 `httpx>=0.27.0,<1.0.0`，未直接固定 `httpcore`；发布前须核对实际锁文件、构建依赖及镜像版本，并对升级重新测试。事件未出现时，当前实现会退至响应头或异常边界，授权锁可能持有至网络超时，需验证实际等待与容量，不能解释成精确的已发送证明。

## 代理 CONNECT 的提前事件

仅用于隔离复现的 `/tmp/prism_proxy_trace_probe.py` 启动本机 HTTP 代理，让代理对 CONNECT 返回 502；未访问真实模型服务。目标 POST 完全未发时，实测仍收到：

```text
http11.send_request_body.started   request.method = CONNECT
http11.send_request_body.complete  info 中无 request
```

本机 `httpcore/_async/http_proxy.py` 将原请求的 `extensions` 传给 CONNECT，因此仅凭事件名释放锁，若将来显式启用 HTTPS 代理，会在真正模型请求前释放。当前代码未设置显式代理且 `trust_env=False`，不能据此说当前直连发生了该问题。必须将禁用代理、重定向及未验证的自定义传输作为可验证约束，或可靠关联 `started` 事件中的真实目标方法、URL 与对应 `complete`；`complete` 的 `info` 只有返回值，不能直接取请求身份。代理、重试或重定向策略改变时须重跑真实协议测试。

## 同一事件循环的同步锁等待

隔离模拟 `/tmp/prism_transport_eventloop_probe.py` 使用当前 `_stream_without_billing`：任务 A 同步进入模拟锁栅栏后 `await` 模拟网络（计划 0.05 秒）；同一 asyncio 事件循环中的任务 B 同步等待同一锁、0.4 秒后超时。实际记录为 A 在 0 秒持锁、B 在 0.41 秒超时、A 的网络回调也直到 0.41 秒才运行。

这证明当前控制流在同步锁竞争时会阻塞同一事件循环，使本应释放锁的异步网络/trace 难以运行；模拟用的是 Python 锁与模拟网络，不是 MySQL 实测。一次为独立验证启动的临时 MySQL 容器在 readiness 前退出并自动删除，无法确定退出原因；该次环境失败**未计作通过**。须用隔离 MySQL、真实 SQLAlchemy 锁、同一个事件循环和真实本地 HTTP 分别验证同成员两任务、不同成员、取消、超时与资源释放，再决定是否需要异步数据库/线程隔离或其他防线。不能用不同线程各自运行事件循环的正向测试代替此项。

## 尚需验证

- 主模型、Search/Fetch、已发布资产及团队子调用逐条覆盖预占、发送、结算和未知账单；禁止遗漏异步、同步、重试及恢复入口。
- 归属变更、退出重加、账号状态与凭据版本、订阅冻结、会话资格和各自授权独立校验；A→B→A 或无组→入组→退出不能复用旧授权。
- 完整请求体、部分写入、断开、提前返回错误响应、trace 回调异常、HTTP/1.1 与如启用的 HTTP/2、取消与超时；明确没有 trace 时的最长持锁时间。
- 不同成员及不同企业在真实 MySQL 下的锁序、吞吐和死锁；不能为降低等待而取消当前权限读取或提前释放未验证的授权栅栏。
- 真实服务提供商的账单和普通浏览器多账号场景另行验收；模拟本地结果不构成支付、生产或利润证明。
