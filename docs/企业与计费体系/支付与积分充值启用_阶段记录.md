## 接入与验收

1. 获取至少一个用户已签约渠道的接入条件；敏感材料通过安全的服务器配置方式提供，不写入仓库或会话。支付宝和微信分别核对应用、商户、证书和 HTTPS 回调。微信 Native 还需核对已认证 AppID 与商户号绑定及产品权限。参考[微信支付 Native 接入要点](https://pay.wechatpay.cn/doc/v3/merchant/4054257695)与[支付宝开发与沙箱](https://open.alipay.com/paymentServicer/paymentProvider.htm)。
2. 对充值包和会员/企业套餐分别验证服务端报价、订单创建、二维码、商户签名、重复/乱序通知、查单、关单、金额和商户身份一致性；仅经可信支付确认后入账或开通权益。失败、超时和结果未知不得伪造成成功。
3. 验证充值后的余额扣减、并发预占/释放/结算、企业与个人隔离、已使用余额退款限制、渠道退款结果和幂等对账。对真实资金使用受控小额验收并记录实际结果；没有商户或测试条件时不能将 mock 当成真实通过。
4. 先核实平台所有实际模型与工具调用的计费归属、价格目录和上界，补齐搜索/抓取等能力的计价及不可计价时的处理；账单、商户手续费、税费、退款和基础设施成本需单独核对。不得通过关闭计量或绕过现有代码门制造“可收款”状态。
5. 依照独立验证结果逐渠道、逐商品上线，记录上线人、版本、配置状态与回滚方式；未完成部分保留关闭状态。开关检查、配置存在与沙箱通过都不能替代真实渠道收款、退款和对账。

## 沙箱联调前置条件与发现

- 支付宝开发者需登录官方平台并取得独立沙箱应用及其测试配置；官方示例列出的材料包括沙箱 AppID、沙箱网关、沙箱应用私钥和支付宝沙箱公钥。扫码支付还需核对沙箱买家账号和沙箱钱包是否属于同一测试环境。参考[支付宝沙箱开发说明](https://open.alipay.com/paymentServicer/paymentProvider.htm)和[沙箱扫码排查说明](https://aipay.alipay.com/article/3691)。测试密钥仅存放在隔离环境，不能提交源码或贴入会话。
