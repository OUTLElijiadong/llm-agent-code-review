# 目录上传取消与权限边界

## 实现范围

目录上传沿用逐文件提交和逐文件结果，不是批量原子操作。解析完成后，请求将整份 Form 的临时文件所有权交给有界后台任务；后台使用自己的数据库会话及不可变令牌版本、过期时间快照，不借用请求的 Session 或 ORM 用户对象。每处理一个文件前重验账号和文件上传权限，并继续调用已有项目权限与扫描服务。请求取消会阻止后续文件开始；已经提交的文件保留，正在处理的文件可能完成并提交。客户端必须刷新项目核对结果，不得自动重试或将取消解释为整批回滚。

当前每个进程最多运行或接收四个目录上传，未启动的 Future 取消、提交失败、解析错误、后台结束均释放容量和临时文件。该限制不是跨进程全局容量限制；已有的请求总量和文件数量上限继续有效。授权/角色和审查员权益锁可能覆盖单个文件扫描到提交的时间，慢扫描下对登出或退款等并发操作的实际等待及生产容量尚未验收。

## 复现与本地验证

- 原缺陷使用真实 multipart、真实工作线程和请求取消复现：请求先关闭 Form 后，后台线程继续读取触发 `ValueError: I/O operation on closed file`。该测试随后验证后台仍能读取自己的文件。
- SQLite/服务及接口组合 **121 项通过**：包括真实 JWT 成功上传、首文件提交后取消不启动下一个、取消未开始的 Future、包装 future 取消、验证失败时重复取消仍关闭全部临时文件、1000 小文件、容量回收、账号禁用/角色变更/令牌版本改变后的后续文件拒绝、解析失败与原上传契约。恶意文件扫描本专项部分测试使用替身，不等于实际扫描器验收。
- 一次性 MySQL 8.0.45 从空库迁移至本地 head 后，首文件提交后的取消和登出竞争 **2 项通过**。另复现 1 项已有项目授权问题：先建立 RR 快照，再转移项目所有者，`_check_project_access` 的当前锁读可被 `require_project_access` 随后的普通快照读取覆盖，旧所有者仍能写入首文件。已保留仅匹配专用异常的 **strict xfail**；不表示目录上传已解决项目所有者、企业授予或所有撤权竞争。此缺陷须单独修复并验证当前读及锁序。

## 尚未完成

- 新目录工作线程持有账号、角色及可能的订阅证据锁跨单次文件扫描；须针对真实扫描器超时、慢请求、多账号和退款竞争验证锁顺序与负载。
- 令牌和审查员权益在扫描前获取并锁定原事务证据，现于普通文件、解压归档与隔离归档的持久化前再次按当前时间检查；若扫描触发回滚，隔离归档会在新事务重获授权及证据，不复用原锁。当前检查发生在数据库提交调用之前，二者并非同一时钟原子操作，不宣称覆盖检查到实际提交之间的任意暂停。
- 项目权限的现有 RR 旧快照缺陷、企业项目 grant 变更和同项目并发锁序由独立专项处理。不得只根据本次 JWT/RBAC 测试宣称项目撤权安全。
- 没有持久任务回执、批次幂等键或自动恢复；请求中断后的具体完成文件须刷新项目核对。
- 跨进程总资源配额、1000 个大文件、慢盘、真实浏览器、多账号和生产环境未验收；本地合成数据不等于生产验证。

## 扫描期间自然到期验证

- 独立复现：使用真实 JWT、角色和 SQLite 权益账本，令牌或审查员七天宽限期在扫描替身执行期间到期时，旧实现仍提交文件。修复为同一事务保留已锁证据，并在文件、解压包或隔离包写入提交前复核原 JWT 和已锁权益的当前时间；扫描导致事务已提交或重置时，不允许复用原证据。
- 恶意归档路径先回滚释放原有锁，再按原有顺序重新验证和锁定账号、角色与权益，最终归档及审计写入提交前复核；申请线程或目录解析不获取额外的反向账本锁。已提交的先前文件不被回滚，也不会自动重试。
- SQLite 目录取消、文件服务与归档组合 **90 项通过**；一次性 MySQL 8.0.45 空库迁移至当前 head 后 **14 项通过**，覆盖原 JWT 到期前/恰好到期/到期后 × 普通/解压/隔离三种分支、审查员宽限期前/恰好/后、扫描持锁期间登出及隔离回滚后先登出再重授权。测试使用扫描替身控制时间，非真实扫描器或生产验收。
- 检查与数据库实际提交之间仍存在非零时间窗口；慢扫描持锁、真实扫描器/浏览器、跨进程容量以及项目授权边界必须单独验证。该节点只覆盖目录上传，不改变单文件、其他源码入口或历史数据。

## 隔离归档的当前写授权（本地验证）

- 独立 MySQL 8.0.45 红测确认：在可重复读事务建立旧快照后，若项目所有者发生变更、项目被隔离、企业编辑授权被撤销或组长降级，隔离归档的原写入服务仍可凭旧快照提交；四类负例均复现。测试使用合成数据和扫描替身，不说明生产已发生。
- 归档入口现在先以 `NOWAIT` 当前读锁定项目，再复用 `require_project_access(lock=True, nowait=True)` 重验项目及成员权限；源码文件、既有隔离归档和活动部署检查也使用当前读。MySQL 锁等待或死锁映射为可重试的冲突，读取接口和历史记录不变。该处理同时覆盖目录恶意扫描回滚后的隔离入口与独立隔离归档入口。
- 一次性 MySQL 全迁移链上，隔离归档旧快照四类撤权、真实 JWT 目录上传回滚后授权、已提交源码/归档互斥，以及授权先持锁后所有权变更的真实等待共 **8 项通过**；与目录令牌/会员到期专题合计 **22 项通过**。SQLite 目录、文件与隔离归档组合 **69 项通过**。测试中恶意扫描使用替身；未执行生产数据库或真实扫描器验收。
- 当前读缺失键仍可能产生跨项目索引间隙等待，`NOWAIT` 只在本事务取锁受阻时快速返回，并不证明其他事务不会等待本事务。授权检查与最终提交之间仍有非零时间窗口；真实多账号浏览器、混合版本部署和容量尚未验收。

## 直接上传的提交前授权（本地阶段）

- 独立复核发现，单文件上传及直接隔离归档上传原先不使用目录上传的提交前检查；真实 JWT 在扫描期间到期后仍可能提交。隔离 SQLite 红测分别复现普通文件、解压归档、恶意文件转隔离和直接隔离归档的路径。
- 两个 HTTP 入口现在复用目录上传的同事务上传授权及提交前时间检查；扫描后隔离路径回滚时重获授权。隔离过程中身份或权限错误不再被包装为恶意文件扫描错误，正常恶意文件拒绝语义保持。原令牌和真实审查员权益到期的正反用例合计 **20 项通过**，SQLite 目录、上传、隔离等组合 **373 项通过**；一次性 MySQL 8.0.45 空库迁移至当前 head 后，直接上传与回滚后注销竞争 **17 项通过**，目录及隔离归档原有专项另外 **22 项通过**。测试扫描为替身；检查与实际提交之间仍有非零时间窗口。
- 此更改没有给内部项目导入任务伪造 HTTP 令牌，也不证明后台导入、其他写接口、真实扫描器或生产环境的授权已经闭环。真实多账号及混合版本发布须单独验证；用户失去权益时，已提交的早前文件不会被本次检查追溯撤销。

## 直接上传的独立复核与冲突语义

- 真实 JWT、SQLite 和上传服务组合先红测：恶意归档进入自动隔离后，项目授权当前读产生 `40901` 时，原异常被通用异常分支吞掉，HTTP 调用收到恶意扫描拒绝而不是可重试冲突。权限没有因此放宽，但错误语义不正确。现将 `ConflictError` 与身份/权限异常一样回滚并透传；其他未知内部异常仍按原恶意扫描拒绝处理。真实 JWT 的 HTTP 层测试确认响应为 409/40901，失败路径不写源码或隔离归档；另有扫描拒绝及回滚正反例。
- SQLite 上传、文件服务、直接归档和到期组合 **102 项通过**；独立 MySQL 8.0.45 空库迁移至当前 head 后，直接上传 JWT/会员、隔离回滚与项目锁竞争 **25 项通过**。MySQL 第一次测试因容器未开启 `performance_schema`，锁观察用例未能观测而失败；第二次容器在建库期间退出导致连接失败，均属于测试环境失败，未算产品通过或缺陷；第三次开启 `performance_schema` 且使用独立磁盘写层的容器后通过，容器已停止。扫描和部分渠道均用替身，未验生产。
- 旧同步 HTTP `/api/projects/import-remote` 虽标记弃用但仍可调用，原先的 `import_remote_project → _upload_archive` 没有传入提交前 guard。独立 SQLite 使用真实 JWT 和下载/扫描替身，在扫描时推进至原令牌到期，仍成功写入 1 个源码文件；该路径原先还提前提交新项目。

## 旧同步远程导入的授权与事务（本地阶段）

- HTTP 入口在下载完成后重新锁定原 JWT、`project:import` 权限和适用的审查员权益，普通源码与隔离归档各在提交前按当前时间复核；新项目、owner 成员与源码或归档处于同一事务，授权失效或冲突回滚这些本次写入。权限依据原接口的 `project:import`，没有额外要求 `file:upload`；下载阶段不持这些写入锁。
- SQLite 新专项和相关项目导入、上传、归档组合 **140 项通过**；隔离 MySQL 8.0.45 空库迁移至当前 head 后 **11 项通过**，覆盖真实 JWT 普通/隔离导入到期、审查员宽限期、旧 RR 快照下权限撤销、禁用与令牌版本变化、权限撤销和注销先后竞争，以及扫描期间新项目未对其他事务可见。真实 HTTP 正例确认仅有 `project:import` 的普通用户仍可导入；下载、扫描为替身，未调用真实外部服务或生产。
- 该检查与数据库 commit 之间仍有非零时间窗口。扫描期间持有账号/角色及可能的会员证据锁，慢扫描等待和大并发容量未验；已提交后响应丢失时结果需刷新核对，不能自动假定未写入。无 guard 的内部服务调用保留既有事务语义；后台异步项目导入没有被本次修改，也未被本次测试证明安全。实现及测试仍需另一代理独立复核，生产数据、真实浏览器和供应商验收未完成。

## 旧同步导入的锁冲突语义

- 独立 MySQL 8.0.45 上使用真实 HTTP、JWT 和另一事务锁住账号行：修复前授权重验实际发生 1205 锁超时，HTTP 返回 500；新项目、成员、源码和归档均未提交。修复后，仅旧同步导入的授权重验使用 `NOWAIT`，实测数据库返回 3572，HTTP 返回可重试的 409/40901，相关写入仍为零。其他上传路径及内部调用保留原等待行为。
- 授权重验中仅将 MySQL 的 1205、1213 和 3572 映射为冲突；其他数据库错误继续传播。真实 HTTP 和 MySQL 连接下额外注入这些错误码及无关错误，检查错误映射和回滚：其中 1205、1213 的映射测试为注入，不能当作实际死锁或锁超时正测。完整 MySQL 专项 **17 项通过**，含旧快照撤权、双方持锁先后次序和到期边界；下载和扫描仍为替身。
- 本次验证不覆盖异步导入、生产、真实下载或真实扫描。扫描阶段继续持有授权锁，检查到实际提交仍有非零时间窗口；无法仅凭本次结果断言慢扫描并发容量或全平台权限闭环。
