# 平台管理员模型成本中心：对齐、设计与任务

## 目标与边界

生产管理员小菱在平台托管 Key 下因缺少可信计费作用域而被拒绝。本阶段只构建默认关闭、未接模型发送路径的可验证基础，独立记录平台承担的模型成本；不使用员工/企业钱包，不创建或赠送隐含余额，不打开全局未计量或销售开关，不修改模型白名单。任何结果不得称为已恢复生产功能。

当前可信账本仅支持 `user`/`enterprise` 钱包和 `member`/`enterprise_auto` 用量。平台真实成本采用人民币微元，不把客户积分售价冒充供应商成本；仅使用已生效、经核验的现有目录中供应商成本，冻结版本与提供方身份。实际供应商、平台预算来源、限额和启用时间均不得凭空设定；尚未建立独立主体和受审预算时一律拒绝。

现有目录的审批状态、来源时间及程序下限只验证系统记录符合既有规则，**不能单独证明实际账户供应商最高价、币种、峰谷、缓存或账单相符**。包括当前白名单 Flash 在内，所有拟启用模型都必须先独立核验实际供应商路由、最高价格、官方依据与真实账单，再审计录入目录；缺证据时保持关闭。

## 安全契约

1. 平台预算按显式受审周期定义硬上限，0 不表示无限；用原子条件更新预占上限，`已用 + 已冻结 <= 预算`；无有效预算、超额、并发争抢失败均不得获得许可。预算仅测试数据或未来独立受权流程创建，业务请求不能修改预算。
2. 每次模型尝试绑定真实服务端认证的当前平台管理员、不可变 attempt 标识、平台预算周期、已验证 system/global 提供方及模型、已核验目录版本、输入/输出 Token 上界和 CNY 成本快照；唯一性和锁竞争不得依赖客户端指定 surface 或钱包。参数、身份、价格或预算不一致的重放拒绝，密钥及模型请求内容不写预算记录。
3. 报价使用供应商输入/输出人民币微元每百万 Token，按上界向上取整；禁止用客户积分费率替代成本。已发结果的结算只能按冻结费率和可验证的用量，实际超过预占、缺失/不确定用量均冻结。网络请求是否已经发出由未来发送接线和围栏解决，本阶段没有联网能力。
4. 预占后任何未明确证实的发送结果不得自动释放或重发。未来账本状态机需支持 reserved/unknown/settled；unknown 保留冻结，不提供自动释放。当前基础只定义 reserved/unknown，unknown 写入口已关闭，settled 尚未实现。提交或发送结果不确定时保持冻结并交人工审核；不得因超时或 lease 到期推断未发送。
5. 每次业务授权由服务端重新核验；平台主体与员工账户不互相混用。BYOK 必须按最终解析的 `billing_credential_source=user` 单独处理，fallback/system/global 不得伪装 BYOK；本阶段不接入或改变 BYOK 路径。

## 阶段和依赖

- **A 基础/红测**：在隔离数据库测试受限主体、预算、幂等、原子预占与未知冻结；调用由内部测试显式打开，默认关闭，无 API、生产调用方或自动补充余额。
- **B 持久迁移**：现工作树唯一 head 为 121；并行 owner 分支正设计 122，顺序尚未定。本阶段不创建 Alembic 新版本，待统一最终唯一 head 后创建下游迁移并重测 MySQL 真实迁移/备份恢复及旧 worker 兼容；ORM 测试表不等于已迁移数据库。
- **C 安全接线**：生产路径之前，先确定取消方处置、attempt 身份绑定、旧 worker 隔离、异常恢复、受审费率与 budget 配置。完成真实 MySQL 并发/崩溃/对账及浏览器验收后才可考虑单独开启平台能力；不改变其他计费门。

## 验收红测

未启用、无效/非管理员、缺失预算或费率、未批准模型/供应商/BYOK/fallback、无足够预算、同键不同绑定、两个请求竞争最后余额、预占回滚、unknown 后重试、缺失及超额 usage、状态重复与异常均须拒绝或保持冻结；验证同事务回滚不提交调用方数据。MySQL 必须测试独立连接并发、锁序与应用异常，SQLite 不代表 MySQL 证据。真实供应商结果、后台恢复、生产 DB、支付和角色浏览器均为未验收。

## 当前 WIP 与验证边界

当前实现仅在独立 metadata 和显式测试开关下提供单例中心、周期硬预算及 CNY 微元上界预占；没有生产模型注册、Alembic 迁移、预算管理入口、发送、结算或释放。两连接红测复现仅凭同账号和 attempt key 即可改写 `unknown`，因此已暂时禁止该写入口：任何调用都拒绝，原有 `reserved` 继续冻结；这不是已完成的未知结果处置，待同事务 owner 和取消围栏完成后才能重新设计。`AttemptKey` 由内部工厂生成随机字节，拒绝普通字符串；它只是进程内接口约束，不是可防止任意 Python 内部调用的安全边界，也不是认证、重放防护或持久 owner。生产调用方将来必须将经验证身份、最终解析的提供方、实际发送 payload、持久运行及独立 attempt owner 绑定并重新校验；详见[平台模型调用所有权设计](平台模型调用所有权_设计与红测.md)。

预占和未来所有预算创建/启停写入必须先锁同一平台中心行，再按已审核锁序进行费率、预算和尝试操作；当前没有生产预算写入口，这只是未来接线的强制契约。外部 SQL 或不遵守锁序的写入仍可破坏该假设，旧 worker、直接 DB 写入和最终部署必须单独隔离验收。锁等待后会重新检查预算周期和费率；调用方可能延迟提交或之后停用中心，故真实发送前仍需独立的授权、预算与发送标记围栏。调用者会话有未 flush 的 ORM 新增、变更或删除时，基础服务拒绝操作而不自行提交或回滚；已 flush 的外层事务与全系统锁序仍须在实际接线时复核。

本地回归：SQLite **33 项通过**，包括角色/配置待写状态不被覆盖、供应商与多输出参数拒绝、预算过期、余额不足、重复标识和独立连接竞争；一次性 MySQL 8.0.45 **1 组通过**，覆盖中心停用先后、预算锁等待跨期、遵循中心锁的重叠预算及双管理员竞争最后额度，另由独立代理在另一个随机标记空库复跑通过。测试不涉及真实供应商、MySQL 完整迁移、生产角色、生产预算或账单，不证明服务可启用。隔离测试容器及本次创建的受限凭据文件已核验后清理。
