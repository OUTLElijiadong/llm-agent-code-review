# 项目成员管理当前授权验证

## 范围与复现

个人项目旧成员接口包括添加、移除和调整角色；企业项目成员授权继续通过企业授权接口处理。隔离 MySQL 8.0.45 的可重复读事务先建立旧快照，再由另一事务提交项目或账号变化，旧实现仍可执行成员写入：

- 项目所有者变更、项目进入隔离、原操作者被禁用或令牌版本变化后，添加、移除、调整角色均可能继续成功。
- 项目绑定企业后，旧快照仍可能调用个人成员接口；内部调用即使未传操作者，也不得绕过企业绑定限制。
- 目标成员已被提升为项目 owner 后，旧快照仍可能移除或降级；目标账号已禁用后仍可能被加入。
- 已认证操作者的 `project:member:manage` 权限已撤销后，旧快照仍可能执行上述三项操作。

这些均在一次性隔离数据库和合成账号上复现，不代表线上已发生。修复前前四类及企业绑定矩阵 **18 项失败**，目标账号/成员状态 **3 项失败**，单项权限撤销 **3 项失败**。

## 本地实现

成员写入在同一事务中使用项目、企业绑定、账号及目标成员的当前锁读；企业项目不退回个人成员接口。已认证请求重新检查真实令牌版本、有效角色、`project:member:manage` 授权以及适用的审查员权益；原本由内部可信调用方传入 `operator=None` 的语义保持，但仍执行项目范围和企业绑定检查。MySQL 锁等待、死锁或 NOWAIT 冲突映射为可重试 409，不降低授权要求。现有成员保存方式及权限角色含义未改变。

## 验证与限制

- 一次性 MySQL 8.0.45 自空库走完迁移链，成员写授权、当前目标状态、企业绑定、权限撤销、真实 JWT API 正反向及逆序目标用户锁竞争合计 **27 项通过**；迁移和业务数据均为合成，临时容器随后关闭。
- SQLite 项目成员、只读成员、企业项目、隔离与 API 组合 **387 项通过**。本地 Ruff 检查通过。
- 空企业绑定记录的当前锁读在 MySQL 可重复读下可能产生已知索引间隙等待；本节点的跨用户逆序锁竞争只证明指定 NOWAIT 路径。生产数据分布、所有跨项目并发和容量均未验收。
- 此处不声称其他项目写入口、用户真实浏览器、现有生产库或多 worker 混合部署已经验收。认证及权益的时间检查与数据库提交之间仍有非零时间窗口；最终全量及独立代理复核仍需完成。

## 独立复核：成员授权锁等待

已用一次性 MySQL 8.0.45 完整迁移链和真实 JWT 在原实现复现：账号行或成员管理授权行被另一事务锁定时，添加成员等待约 3 秒至数据库锁超时才得到 409；原生意图是及时提示可重试冲突。现仅对成员写入口的权益与 RBAC 当前读传入 `nowait=True`，共享栅栏的其他调用仍保留原默认行为。

隔离 MySQL 综合 **35 项通过**，其中新增 8 项覆盖添加、移除、角色调整分别遭遇账号行和权限行竞争，真实 JWT HTTP 409，以及审查员订阅订单权益行竞争；每种冲突锁释放后均验证允许的操作可正常提交。SQLite 相关服务与 API **43 项通过**，Ruff 和 `git diff --check` 通过。测试为合成账号和隔离数据库；绑定缺失的索引间隙锁、生产容量、多 worker 和真实浏览器仍未验收。

### 拒绝访问时的事务与审计

独立 MySQL 红测发现，失败审计原本直接提交调用方的 Session，可能把同一事务里此前暂存的其他变更一并提交；后续“先回滚再审计”的临时修复又会关闭调用方 `begin()` 上下文或回滚整个外层事务，嵌套 savepoint 中的失败审计也可能丢失。复现使用直接服务调用和合成数据，未证明实际 HTTP 路径发生。

当前实现不再接管调用方事务：授权拒绝只登记用户 ID、用户名快照、项目 ID、角色类别和时间，并立即记录不含用户名、源码或异常正文的最小拒绝事件；每个 Session 的待处理记录最多 128 条，超额记录脱敏告警。在该 Session 自有的最外层事务结束后，最多 128 条全局等待记录进入单后台线程，由独立 Session 逐条写入失败审计。成功审计仍属于调用方事务。正常停机最多等待 2 秒排空；队列满、数据库写入失败和停机未排空时记录脱敏告警。若 Session 绑定外部 `Connection`，其会话事务结束不代表连接所有者的外层事务结束，故不自动写数据库审计，只记脱敏告警；内存 SQLite（包括内存 URI）仅记脱敏告警，避免回调获取连接时阻塞或跨线程连接到不同的数据库。

审计数据库记录为**最终一致、内存队列不具备崩溃持久性**：外层事务未结束前、进程崩溃、队列满或数据库不可用时，不能保证 `audit_log` 绝对不丢；告警是否可靠保留取决于部署日志配置。隔离 MySQL 成员三模块组合 **44 项通过**，包含真实 JWT 的添加/移除/角色调整拒绝后业务回滚与审计、外层 `begin`/嵌套 savepoint、单连接池和池被占用时调用方不等待；SQLite、队列及生命周期定向 **60 项通过**，覆盖队列满、写入失败、限定时间停机和恢复、被阻塞后台线程不会阻止进程退出、外部 Connection 的提交/回滚。该机制仍需独立代码复核、最终全量、生产数据库与日志持久性验收，不能把本地结果视为生产保证。

补充独立复现：内存 SQLite 单连接池被占满时，旧的同线程审计会使调用方事务结束等待约 0.5 秒并超时；现改为只记脱敏告警。回归使用真实连接池验证 `rollback`、`commit`、`close` 均在 0.2 秒内返回，并验证 SQLite 内存 URI、每 Session 128 条上限与超额告警。SQLite 相关组合 **70 项通过**，独立 MySQL 成员专项再次 **44 项通过**。上述耗时阈值仅为本地测试结果，不代表生产响应时限。
