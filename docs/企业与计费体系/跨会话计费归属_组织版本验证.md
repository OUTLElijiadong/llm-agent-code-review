# 跨会话计费归属：组织版本验证

## 范围

本节点只实现成员计费小组归属版本和运行表所需字段。116 迁移在 `enterprise_member` 加非空 `billing_group_version`，历史成员初始为 0；在 `enterprise_assistant_run` 加独立的 `billing_group_id`、`billing_attribution_version`、`billing_membership_version` 和 `billing_user_token_version`。历史运行的计费组及成员/账号版本为 NULL、口径版本为 0，不按当前组织成员关系推断或回填历史账单。原会话 `group_id` 和权限关系不改变。

## 成员版本

企业成员有效小组的新增、退出、重新加入，默认组的实际变化，以及企业成员移出和重加均在原事务持成员行锁后递增版本。重复设置同一默认组、仅变更有效小组角色不会递增。移出默认组时清空默认组和成员退出是同一归属变更，只递增一次。版本异常或达到有符号 64 位上限时拒绝变更，先检查版本再改变成员状态，不能留下部分内存修改。事务回滚会还原版本与组织状态。

接受邀请时对原成员使用当前锁读，避免 MySQL RR 旧快照将已移出的成员误判仍为 active；新成员初始版本为 0。

## 阶段验证与限制

- SQLite：组织服务及 116 迁移共 16 项通过，其中覆盖 A→B→A、同值设置、小组加入/移出/重加、企业移出/重加、无权限设置、事务回滚和版本上限异常。
- 一次性 MySQL 8.0.45：初始化库迁移至 116 后 5 项通过，覆盖临时旧数据表执行 116 时默认值、RR 旧快照下 A→B→A、旧快照下移出再重加、两次小组恢复竞争时 `performance_schema` 实测等待企业行及回滚。两个各已有 owner 和一名成员的企业同时接受不同新成员时，第一事务持锁期间第二事务正常提交且未观察到等待；这只覆盖本测试键分布，不保证所有企业规模或索引间隙不存在等待。临时数据库与测试容器已移除；不是生产数据副本验证。
- 本版本由当前已盘点的组织服务维护，不能证明外部直接 SQL、数据库外维护或未来新增写入口自动更新；小组状态、账号、会话、订阅和资源权限仍须各自当前校验。精确不存在成员记录的当前锁读在 MySQL RR 下仍需更多键分布和容量验证。
- 计费归属创建、模型外发、Search/Fetch、资产与团队子调用及前端显示尚需其他节点完成，不能因组织版本通过就开放收费或宣称完整防绕过。多组预算同时约束、真实浏览器/供应商/生产验收仍未完成。
