# 企业用量与额度认证快照

## 问题与修复

额度保存原先没有绑定发起时的登录令牌。若发起请求后、Axios 请求拦截器执行前切换账号，请求可能以新账号身份发送；服务端仍会检查新账号权限。用真实 Axios 拦截器和隔离适配器复现了这一时序。

企业用量、月度额度和小组成员查询，以及额度保存，现在传递发起时的认证快照。请求发送前若登录状态变化则取消；请求完成后组件还会核对当前令牌与请求代次，丢弃旧账号的迟到结果。原有企业、小组切换时的结果隔离和保存结果未知提示保留。

独立复核还复现：管理员选择小组并输入额度后，父页面刷新等价的小组列表会把范围重置为整个企业，却保留原输入；组长的所选小组也会被重置。现在等价列表刷新保留有效选择和输入；切换企业、角色或所选小组失效时清除可能被误用于新范围的输入。保存过程中切换小组、范围、成员或月份，旧请求成功或结果未知均标明原目标和月份，避免用户误判；账号切换后不显示旧账号结果。额度查询失败时只展示错误，不再同时误报该月没有额度。

后续独立复核发现页面跨上海时间月初保持打开时，原月份选项不会更新；保存成功后若在额度刷新期间切换范围，原目标的成功提示也可能丢失。现在页面恢复、刷新和保存前都会核对月份：已过期的选中月份更新为当月，清除原输入并要求重新输入；原选择仍有效时保留输入。保存确认后的刷新期间切换范围也会标明原目标和月份，账号变化后不显示旧结果。

再次独立复核发现额度查询失败后，顶部刷新只重试用量，不能重试额度。现在刷新同时更新用量、额度和相关小组成员；跨月导致额度月份改变时复用已有监听器，避免重复额度请求。刷新只发读取请求，不重复提交额度保存。

## 验证

- 真实 Axios 拦截器测试覆盖四类请求在发送前切换账号时均取消，以及账号未变化时按原账号提交。
- 用量组件测试覆盖旧账号保存、用量、额度及成员请求的迟到成功和失败；原有企业、小组切换和权限撤销测试保留。
- 独立复核先复现了 6 项范围重置/错误空态问题及保存中切换小组、范围、成员或月份时的结果提示问题；修复后相关三个前端测试文件共 88 项通过，覆盖管理员、小组长、范围失效、角色与企业切换、保存中刷新、账号切换和迟到结果。目标 ESLint 和 `vue-tsc --noEmit` 通过。
- 跨月和保存后刷新竞争均先经隔离测试复现，新增组件测试覆盖焦点/可见恢复、显式刷新、保存前跨月、仍有效的下月输入、企业/账号切换与刷新期间切组；用量组件现 34 项通过，目标 ESLint、`vue-tsc --noEmit` 和 `git diff --check` 通过。
- 额度刷新缺口先由隔离组件测试复现，再增加失败重试、跨月单次请求、部分失败和账号/企业切换迟到结果测试；用量组件更新后 38 项通过，目标 ESLint 和 `vue-tsc --noEmit` 通过。

上述为本地模拟；真实浏览器多账号和生产环境尚未验收。
