# 个人基础 Agent 待实施方案

> 状态：**部分实现，完整功能尚未验收**。记录时间：2026-11-08。个人私有配置的创建、读取、编辑、停用、版本查询和界面已实现；模型计费执行及全局发布审核仍未实现。本文件衔接现有 ALIGNMENT、CONSENSUS、DESIGN 和 TASK，不改变已确认的企业知识共享范围、权限边界或销售锁。继续实施前须再次核对工作树、迁移 head、现有接口和最新验收结果。

## 需求与已核对现状

- 用户要求企业和非企业普通用户均可创建 Agent；普通个人用户能够自己使用，审查员也可以自定义使用，并可申请全局发布，须经平台管理员确认。`ALIGNMENT_企业与计费体系.md` 第 12 条记录普通个人用户可创建基础 Agent。企业 Agent 的企业内及全局发布规则沿用现有共识。
- 当前个人 Agent Studio 的路由 `backend/app/api/v1/agent_studio.py` 整体依赖 `require_studio_role`；`agent_studio_service.create_agent` 再次要求审查员或管理员。现有服务级测试 `test_owner_and_protected_code_boundaries` 覆盖普通用户创建被拒绝。前端 Agent 工作台也依据 `agent_asset:create` 显示创建入口。
- 企业成员可以通过企业资产 API 或小菱 `create_private_agent_skill_draft` 创建作者私有企业草稿。该草稿依赖企业身份，工具明确返回 `executable=false`，并不等于非企业个人用户可运行的 Agent。`test_draft_versions_are_private_and_do_not_enter_global_assets` 覆盖私有草稿及不进入旧全局资产目录。
- 旧 `CustomAgent` 的 code 全局唯一；`DeclarativeReviewAgentFactory.resolve_published` 只解析启用且存在已发布 release 的 Agent。不能仅把普通账号加入工坊角色、把未审批资产注册为全局 Agent，或将企业草稿当作个人可执行 Agent。
- 2026-11-08 定向复跑上述两项现有测试为 **2 passed、6 条警告**，这是服务级证据；尚无个人普通账号浏览器创建/使用验收。

## 建议交付边界与依赖

第一步做可创建、可使用的**个人私有基础 Agent**纵切。支持登录用户创建自己可见的 Prompt Agent，用普通文本发起单模型请求并取得结果；普通用户和审查员均可使用。以此闭环私有创建与使用，但不把它称作个人 Agent 的全部产品能力：原始需求还包括可控的全局发布及管理员审核，需完成后续阶段和整体验收。

仅服务端选择已批准计价模型、平台托管凭据和可信输入/输出上限。首个纵切不接入任意 Skill、工具、代码执行、网络、可配置 endpoint、BYOK、客户端指定计费主体或供应商服务端工具。个人创建的私有 Agent 不加入 AgentRegistry、不创建全局可见 `CustomAgentRelease`，也不自动进入企业目录或旧全局审查团队。

依赖现有用户认证、个人钱包、已审批费率目录、可信模型上界、`billing_scope`、模型调用及现有账本；所有发送前权限和余额校验由服务端完成。商业计量关闭、钱包/费率/平台托管凭据不符合条件时，调用须在上游请求前失败关闭；不能复用关闭计量后直接走无 scope 的兼容路径。本方案不打开 `BILLING_SALES_CODE_GATE_OPEN`。

## 数据与接口草案

以下是方案提出时的接口草案；当前已有的 103 个人配置接口以源码为准，计费运行和个人发布接口尚未实现。迁移号以实施前实际 head 为准。

1. 个人 Agent：归属 `owner_user_id`，保存名称、状态、当前版本、创建时间及客户端创建幂等信息。普通读取、修改、停用、删除及运行均以当前账号为所有者，跨账号猜 ID 一律返回无资源结果；平台身份不自动赋予读取他人私有正文权限。
2. 个人 Agent 版本：保存受限 schema、提示词、版本号与内容摘要；运行固定所选不可变版本。编辑创建新版本，不能改变已有调用或日后审批快照。字段、约束和最大长度在实现前与现有输入验证和数据库方言对齐。
3. 调用记录：保存 owner、Agent/版本、客户端幂等键、输入和版本的指纹、运行状态、关联 reservation、受限结果和时间。以数据库唯一约束处理同一用户同键并发；同键不同输入或版本返回冲突，不得重新请求上游。确认隐私留存与删除规则后确定结果正文保留期限；账本与审计按既有规则保留。
4. 候选路由：`GET/POST /api/me/agents`、`GET/PUT/DELETE /api/me/agents/{agent_id}`、`POST /api/me/agents/{agent_id}/invocations`、`GET /api/me/agent-invocations/{invocation_id}`。所有路由由当前登录账号推导 owner 和个人钱包，不接受请求体指定其他账户；最终路径和错误结构复用项目 API 约定。
5. 个人空间加入“我的基础 Agent”入口，支持创建、编辑、停用和运行，展示加载、余额不足、结果和待核对状态；企业空间的现有 Agent/Skill 功能及审批边界继续独立。后续按实际代码审查需求设计 Agent 与个人单 Agent 审查入口的集成，不能把文本问答误称完成全部审查能力。

## 调用与计费契约

1. 创建调用时校验账号、Agent 所有权、Agent/版本状态和有限输入，按 owner 与客户端幂等键原子认领。相同请求正在执行时返回已有状态，终态结果可在重新授权后读取。
2. 从服务端确定个人钱包和付款主体，在受控 `billing_scope` 内对每一次 provider 请求按费率快照预占。利用 attempt guard 与调用记录代际在事务中复核账号、版本和授权；发送前再按现有机制复核。余额不足、撤权或关闭时不得发送请求。
3. 使用可信 provider usage 和原始预占费率结算；缺失用量、超出上界或传输中断保持未知/冻结。账户被禁用或 Agent 被停用时，不把这些变化解释成上游未收费；结算与结果展示按实际发生的状态分别处理。
4. 同一调用键至多发起一次不确定的上游请求。已有已结算账单但结果缺失时明确显示结果不可恢复，不自动重发；响应或用量未知时进入待核对。账单结算和结果持久化若跨事务，必须如实暴露两者之间的崩溃窗口，不声称原子性。
5. 现有模型 reservation 不具有 Search/Fetch 的同款 provider attempt 标记。进程在预占后中断时，不能仅凭 `reserved` 推断请求未发送并释放；实施前须设计和验证明确的陈旧调用恢复、状态流转与锁顺序，避免重复收费。不得为让测试通过而将未知费用计零。
6. 记录调用次数和 Token 到现有个人用量视图；不能把工具费用、基础设施或税费混同模型直接成本。不得据此声称产品整体不会亏损。

## 全局发布：尚未完成

个人普通用户和个人审查员提交全局发布申请属于原始需求，**当前个人基础 Agent 尚无该闭环**。后续需定义独立的申请、撤回、拒绝、审批和撤销流程，固定不可变版本、作者、摘要与申请内容；由符合现有平台审批规则的管理员审核，通过前不向其他账号展示或执行。审批人与申请人、自批、账号停用、并发撤销、版本变化、授权和计费均须按现有共识复核。个人来源发布不能依赖虚构企业成员关系；与已有企业发布和旧 Agent Studio 的目录/审批如何合并，应先对齐数据来源和权限，再实施。不得将本文件的候选接口视为该功能已经交付。

## 验收与测试

- 基础功能：非企业普通用户、个人审查员各自创建、编辑、停用及运行自己的 Agent；其他用户、平台管理员猜 ID 不能读取或运行；同一账号多个企业空间切换不会改写个人所有权。
- 边界：受限 schema 拒绝未知字段、客户端模型/工具/URL/密钥和越界输入；普通用户不能借基础入口调用高级工坊、Skill、企业资产或绕过全局审批；现有审查员功能回归。
- 计费：余额不足、授权撤销或计量门关闭时无 provider POST；有效 usage 按原费率快照扣取个人钱包并显示在个人用量；超时、缺 usage、结果保存失败及进程中断不自动重发或虚构零费用。
- 并发：隔离 MySQL RR 同键双请求最多一次上游请求/一次预占，不同用户不同键可并行；状态变更、停用、退款/撤权与发送竞争，验证锁顺序、账单状态和结果可见性。分别覆盖 SQLite 及 MySQL 迁移与旧数据保留。
- 前端与浏览器：普通用户和审查员用隔离账号在真实浏览器走创建、使用、刷新、停用与跨账号拒绝；验证键盘、窄屏、错误和待核对提示。自动化、真实 provider/账单和生产验收分别记录。
- 全局发布另需覆盖待审不可见、非授权审核者拒绝、自批边界、快照不可变、通过后可见、撤回/拒绝/撤销及调用端授权；**在这些完成前不得将全局发布标记为完成**。
