# 企业项目绑定与个人渗透授权

## 问题和约束

在 MySQL 可重复读事务中，个人渗透审批可能先读取旧快照，随后项目所有者把项目绑定企业并提交；旧审批仍可能把该项目的个人委托标为已授权。隔离测试使用真实权限依赖、真实绑定和审批服务复现了该状态；没有执行真实目标探测。

个人委托不属于企业审批域。绑定项目与批准个人委托必须通过同一项目行串行；如果个人委托已经处于已授权或执行中，绑定操作提示项目所有者先取消或等待执行结束。待审批、取消及其他历史终态不因此自动删除或修改。

## 实现和锁序

个人审批在账号/RBAC 权限栅栏后，以当前锁定读取得项目、当前读取企业项目绑定，再锁定并重验委托后提交。企业绑定沿现有企业、成员、项目顺序取得项目锁，再以当前锁定读检查该项目是否存在已授权或执行中的个人委托。绑定先提交时，旧快照审批拒绝；审批先持项目锁时，绑定等待审批提交并拒绝把有效个人授权带入企业。明确要求调用方处理冲突，不静默撤销授权或更改历史数据。

## 本地验证和边界

一次性空 MySQL 8.0.45 从项目基线建链至当前迁移头，测试绑定先提交和审批先持锁两种顺序，后者由 performance_schema 观察到绑定事务实际等待；与审查员退款审批竞争组合共 9 项通过。相关 SQLite 项目权限及个人渗透服务组合 151 项通过；绑定对已授权、执行中拒绝且取消后可绑定的 2 项补充测试通过。

本验证不代表真实浏览器、生产数据或实际探测验收；项目绑定和其他个人委托写入口仍应按各自业务边界审查。SQLite 不提供 MySQL 行锁证明。
