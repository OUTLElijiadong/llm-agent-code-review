# 项目与审查写入当前授权验证

## 范围与复现

本次仅检查和修复项目元数据更新/删除、审查问题状态与人工裁决、审查任务取消/删除的项目写授权；不代表所有项目、成员、知识或远测入口均已覆盖。验证在隔离的 MySQL 8.0.45 上使用合成用户和项目，不涉及生产数据。

先建立可重复读旧快照，再由另一事务把项目所有者转给其他用户并提交。修复前，以真实 JWT 身份调用项目更新、项目删除、问题状态修改、问题人工裁决、审查任务取消、审查任务删除，均未拒绝旧所有者；另一条企业 editor 项目授权撤销后修改元数据也未拒绝。为复现五条关联入口，初次临时测试因缺少 ORM 元数据而失败；加载真实全部模型重跑后，问题状态、人工裁决、审查任务取消、审查任务删除和项目添加成员五项均实际发生 `DID NOT RAISE`。项目成员变更由另一专项处理。

## 本次修复

- 项目更新/删除使用 `require_project_access(..., lock=True, nowait=True)`，在同事务中持有当前账号、项目及授权相关行至提交。企业项目生命周期变更和删除继续要求企业项目 `manage`，普通元数据编辑仍遵循原有 `write` 权限。
- 问题状态/裁决和审查任务取消/删除共用当前写授权检查，并在项目授权之后锁定当前任务和问题，核对任务项目及问题任务归属没有改变。真实权限撤销或资源范围变化时失败关闭。
- MySQL 对上述锁获取返回 1205、1213 或 3572 时回滚事务并转可重试的 409；不把其他数据库错误当权限冲突。个人项目缺失企业绑定的索引范围锁可能导致无关项目等待，相关缺口和严格预期失败见《项目源码写入当前授权验证》。

## 验证及限制

- 临时 MySQL 从初始化脚本和迁移链建库后，项目生命周期和问题/任务写授权组合 **50 项通过**：包括旧 owner、真实 JWT 注销、企业授权撤销、组长降级、组禁用、成员移除、任务与问题换归属、锁竞争及项目授权先于所有者变更；个人 owner、企业 editor 元数据编辑和组长生命周期操作有正例。
- SQLite 既有项目生命周期、审查任务权限、问题聚合、审查服务、企业项目策略等组合 **126 项通过**；另先前项目/隔离/企业政策组合 **349 项通过**，两组有重叠，不能相加当成不重复数量。修改文件的 Ruff 通过。
- 企业授权、组状态和范围变更用合成数据库记录直接更改来检验服务是否读取已提交新值；并非所有情况都通过真实组织变更 API。隔离 MySQL/SQLite 不代替真实浏览器、生产数据或所有运行中任务竞争验收。
- 项目成员添加/移除/角色修改由独立专项处理；`project_source_revision_service.delete_revision`、项目成员 API、企业项目 grant 管理、远测审批/执行、其他 Agent/知识和报告关联写路径仍须逐入口核对，不能据此宣称全站授权完成。审查写入与项目变更的完整锁顺序、缺键 gap 和生产并发容量仍需单独验证。

## 操作级权限撤销与项目删除锁冲突（本地修复）

- 独立 MySQL 实测：真实 JWT 经入口权限依赖后，如果管理员在写入前撤销 `project:update` 或 `issue:handle`，原实现仍可执行写入；项目删除若等待其他事务锁定的活动审查任务，MySQL 1205 也未转换为 409。原测试的初次建模错误是 ORM 元数据未加载，加载后才取得真实失败证据。
- 针对持有真实 JWT 快照的调用，在当前事务内按路由原权限码重新锁定校验：项目更新/删除分别使用 `project:update`/`project:delete`，单条问题和裁决使用 `issue:handle`，批量逐条使用 `issue:batch`，审查取消/删除使用 `review:cancel`。审查员继续先锁现有订阅/退款证据，再锁账号与权限；直接可信服务调用不凭虚构 JWT 添加新的权限要求。MySQL 锁竞争按既有约定失败关闭并转为可重试 409。
- 批量问题状态仍采用原有逐条提交：中途权限撤销后，前面已提交的结果保留、后续停止，不代表整批原子。令牌自然到期检查与实际 commit 之间仍有非零时间间隔。
- 隔离 MySQL 的新旧项目/审查/审查员令牌竞争组合 **83 项通过**；新增专项在此后增加审查员权益行锁竞争用例并单独重跑为 **25 项通过**，覆盖 7 种操作的撤权/正例、真实 JWT HTTP、批量不同权限与中途撤销、权限和审查员权益锁 NOWAIT、先持授权时撤权等待、审查员退款和永久权益。SQLite 相关回归 **230 项通过**，Ruff 通过。这些数字是阶段性结果，不代表真实浏览器、生产或全站操作权限验收。项目删除、源码修改等仍有缺键范围锁导致跨项目等待的容量风险，现有严格 xfail 继续保留。
