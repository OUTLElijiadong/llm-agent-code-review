# 企业全局资产个人运行：对齐、设计和任务

## 对齐与边界

用户要求企业创建的 Agent 经批准后可发布给所有人使用。现有企业全局目录允许登录账号查看已批准资产，但执行仅接入企业小菱，非企业账号无法运行。补齐个人账号使用已批准全局资产的路径，并沿用原目录配置可见性合同；企业私有资产及待审批资产不因此开放。现有兼容类型为 schema v1 的 Prompt Agent 和 `llm_transform` Skill，其他类型保持只读并明确不可运行。

个人调用使用发起人的个人钱包、固定版本和单次模型请求；不改变企业群聊以企业钱包计费的规则，不自动重发未知结果。用户、发布范围/状态、摘要、配额与费率均在服务端校验。当前部署和商户状态不因本任务改变。

## 设计

```mermaid
flowchart LR
    U[登录账号] --> C[已批准企业全局目录]
    C --> R[固定发布版本的个人运行]
    R --> V[权限和摘要校验]
    V --> W[个人钱包预占]
    W --> P[一次模型请求]
    P --> S[已知用量结算或未知冻结]
    S --> H[本人运行结果和历史]
```

迁移 110 在 `personal_agent_run` 增加企业发布 ID 外键，允许该来源不引用个人 Agent，使用约束将个人私有、个人发布与企业全局发布三种来源互斥。所有运行继续共享账号幂等键和账单唯一约束。下架与发起按发布行锁串行；已发请求按实际用量结算，下架先完成时抑制未提交结果；历史已完成结果只允许发起人读取。不得因资源来源相同或整数 ID 相同而混淆不同目录。

新接口在 `/enterprise-asset-catalog/{publication_id}/runs` 下提供创建、按 ID 查询和按请求标识查询；历史通过 `/me/agent-runs?source=enterprise_public` 提供，摘要和结果不增加配置、作者或企业私有信息。原目录响应不删除既有字段。

## 任务与验收

1. 先写服务、API、迁移、前端测试，验证个人账号调用两种兼容资产、个人钱包预占与结算、未知结果冻结和幂等。
2. 新增迁移与来源约束，复用单次执行/计费链；覆盖错误来源、企业私有范围、下架、失效账号和不同账号隔离。
3. 提供可用性状态、输入、结果和本人历史；跨账号、页面切换和迟到响应安全，未兼容版本不显示运行按钮。
4. 通过隔离 MySQL 完整迁移及下架/运行竞争、已有个人 Agent 回归、接口合同、权限清单和前端组件测试。与生产发布、真实模型和多账号浏览器验收分开记录。

## 状态

个人钱包运行服务、三种运行来源互斥迁移、真实 JWT 接口、本人历史和全局目录入口已实现；原全局定义可见性合同保持不变。兼容的 Agent 与 Skill 均使用单次请求和原账本，未知结果冻结，下架后不发送新请求、在途调用按已知用量结算但不展示结果。

定向后端及原个人运行/发布、历史和前后端合同组合 **42 项通过**；共享目录与运行组件 **10 项通过**（另有前端相关 24 项阶段回归）。隔离 MySQL 复现撤销与运行中的外键父行锁死锁后，改为共享当前读；重跑历史升级及来源约束、Agent/Skill 撤销先行和运行先行、同键和跨账号并发、作者编辑/重发先后共 **11 项通过**，竞争场景通过 performance_schema 观察到真实锁等待。测试使用合成数据及模拟供应商，未验证真实浏览器、模型或生产环境，不代表发布完成。
