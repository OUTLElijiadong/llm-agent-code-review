# 个人渗透撤权后的安全取消

## 复现与边界

独立真实 JWT/FastAPI 测试中，项目创建者移除原项目成员后再修改项目名称，原成员的个人渗透委托列表、详情和取消响应仍返回撤权后的新项目名称；报告正文接口返回 404，个人委托重新启动被拒绝。该证据来自隔离数据库，不表示生产已复现。原成员的运行中委托仍需要保留安全取消入口。

## 处理

- 对本人已有委托，若当前已无项目查看权，响应保留委托公开 ID、状态和取消所需的基本信息，隐藏项目 ID、当前名称、目标类型、scope、备注、URL、授权范围、阶段、发现及报告信息；取消仍按既有状态机执行，不把取消当作 worker 已退出。
- 有当前项目查看权的账号维持既有内容；持当前有效 `pentest:authorize` 的审查员可以查看他人申请的必要审批信息，但审批权不授予报告或项目正文权限。审查员不能凭自己的审批权绕过其本人项目的撤权。
- 客户端在脱敏时显示“项目不可用”，隐藏重启入口与空阶段，运行中仍保留取消。真实浏览器多账号尚未验收。
- 序列化前以同一事务的当前锁定读复核账号、JWT token 版本、审批角色、项目、企业绑定和成员关系；企业绑定提交后个人入口不暴露该项目。付费审批角色的退款/撤权沿既有权限服务，不把降级为仍有基础权限的普通用户误判成完全失权。

## 测试与未解决项

隔离 SQLite 的真实 JWT/FastAPI 测试覆盖成员移除、本人取消、已有成员正向、审查员审批、账号停用、企业绑定和终态脱敏；隔离 MySQL 8.0.45 RR 覆盖旧事务读取、账号角色和 token 版本变化、绑定先提交及同项目绑定未提交时的实际行锁等待。前端列表/详情组件测试覆盖撤权状态与取消入口。详细数量以独立测试结果为准。

**仍有已复现的并发性能风险：** 在 MySQL RR 下，对不存在的企业绑定使用当前锁定读会在唯一索引 supremum 产生 gap 锁；一个事务读取未绑定项目时，另一个无关项目绑定可能等待。`FOR SHARE SKIP LOCKED` 已在隔离测试中证明不能消除此等待。当前保留安全读取，不回退到已复现会泄露的旧快照；对应测试保留为严格预期失败，不能宣称无阻塞。

后续候选是在项目行维护经迁移回填并与企业绑定同事务更新的归属标记，或为完整请求链设计不丢失认证/待写数据的 READ COMMITTED 事务。前者需覆盖历史数据、所有绑定写入口、异常回滚和一致性核验；后者需覆盖现有依赖、连接池饱和与角色/成员并发。两种方案均未实施，需先用真实 MySQL 和生产脱敏数据副本验证，再进入发布验收。
