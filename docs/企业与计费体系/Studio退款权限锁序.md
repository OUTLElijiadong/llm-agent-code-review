# Agent Studio 写入与审查员退款权限

## 已复现问题

审查员通过 Studio 的角色与权限依赖后，同一 MySQL REPEATABLE READ 事务可以保留旧快照。如果另一事务先批准该审查员订阅退款并提交降级，旧事务仍能执行 `create_agent` 并提交草稿。隔离 MySQL 8.0.45、完整迁移链至 110 的测试先验证此行为，旧实现的拒绝断言失败；这不是生产环境复现。

## 本地修复

创建及修改 Agent、创建及修改 Skill、绑定及解绑 Skill、测试、提交和撤回共九类 Studio 写入，在读取或锁定资产之前，按对应权限码调用 `check_paid_permission_fenced`。该检查在同一写事务内锁定账号和 RBAC 授权，并在 MySQL 下从短只读事务读取当前付费权益；角色与权限锁一直保留到原 Studio 提交。HTTP 认证时的 Token 版本快照传入 fence，与锁定后的当前账号版本比对；可信内部调用没有认证快照时沿原内部调用规则处理。Studio 的 reviewer/admin 身份检查和资产归属检查继续保留，普通账号即使被误授某个工坊权限也不能因此写入。

退款事务先锁订单等计费记录再同步账号角色；Studio 在账号锁之后不获取计费写锁。该锁序仅针对这些 Studio 写方法，不代表审查员其他写入口已被覆盖。

## 本地验证

- 在一次性 MySQL 8.0.45 中验证退款先提交时旧快照写入被拒绝；Studio 写入先持有账号锁时，使用 `performance_schema.data_lock_waits` 观察到退款事务真实等待，随后按顺序提交；永久审查员退款后仍可写入。共 3 项通过，容器已停止并移除。
- 九个写入口逐项验证服务端调用精确权限码，并覆盖普通用户误授权拒绝；Studio 状态机、发布审批、已发布依赖和管理工具相关组合 79 项通过。测试夹具显式建立角色、权限和账号绑定，没有绕过权限 fence。
- 真实多账号浏览器、真实商户退款及生产数据库尚未验证；其他 reviewer 写入口仍需另行盘点和逐项验证。
