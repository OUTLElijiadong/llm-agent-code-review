# 沙箱停止与请求登记并发验证

## 范围

在独占、空白的一次性 MySQL 8.0.45 中，从项目初始化数据库及迁移链建库到测试运行时唯一 head。测试使用合成用户、项目、环境和模拟 Worker；没有连接生产数据库或调用真实沙箱。

## 验证结果

`backend/tests/test_mysql_sandbox_stop_fence.py` 的 API、工作线程停止及回执组合共 **15 项通过**：

- 登记事务先持行锁时，停止事务在 `performance_schema.data_lock_waits` 中可观察到等待；登记提交后停止能读取新登记的请求并持久保存对应回执。
- 停止事务先写 `stopping` 且尚未提交时，旧可重复读快照中的登记事务实际等待；停止提交后登记被拒绝。
- 已停止环境不会被旧事务的重复停止恢复为 `stopping`。
- 两个停止请求重叠时，迟到失败只有在当前环境的 Worker、执行令牌摘要和全部登记请求的清理回执匹配时，才能接受另一请求已完成的结果。
- 缺少回执、错误令牌或漏掉已登记请求均不能将迟到失败误判为成功；缺少、额外、错误请求号、非终态及未确认清理的 Worker 响应不会被接受为完整清理。

其中 **2 项**覆盖真实 `_execute_environment` 内部停止路径：模拟 Worker 返回或抛出传输异常期间由另一事务提交 `stopping`，工作线程读取当前状态、调用模拟 `/stop`，随后持久化 `stopped` 及匹配 Worker、执行令牌摘要和请求号的回执。此前正常返回路径的 SQLite 红测曾停留在 `stopping`，修复后通过。首次 MySQL 尝试因测试账号没有绑定实际 RBAC 角色而未进入目标外呼，补齐真实角色绑定后才通过。

临时数据库容器已删除；测试中的 Worker 调用由隔离桩返回。执行器真实网络响应、进程与子任务终止、生产角色浏览器交互及生产数据库行为均未在本次验证，不能据此视为生产验收通过。
