# 退款执行列表分页

平台退款执行页原来只能显示某一状态最新 100 条，较早退款无法在该页面执行或查单。现在列表以退款 ID 倒序使用游标加载更多，切换状态清空旧筛选，账号切换或新请求会丢弃迟到结果。正在加载下一页时保留已展示记录；首屏加载失败不会显示“暂无记录”。

`GET /api/billing/admin/refunds` 继续返回原数组格式，新增可选 `before_id`，并为数组元素补充 `id`。不传游标时保留原有顺序、筛选与条数规则。新增退款位于较新一侧，翻页不会重复；刷新首屏才能看到翻页期间新增的记录。

分页不是状态快照：翻页期间，已跨过游标的退款若变为当前筛选状态，需要刷新首屏才能看到。历史 `approved`/`failed` 且渠道为 `NOT_FOUND`、已有发送尝试的退款只能查单；`manual_review` 的 `SUCCESS`、`PROCESSING`、`UNKNOWN`、`NOT_FOUND` 均提供查单入口，是否允许最终记账由服务端核验。

隔离后端测试覆盖超过 100 条、翻页期间新增退款、状态筛选和非法游标；前端组件测试覆盖加载更多、切换筛选与账号时的迟到响应。未进行真实浏览器或商户环境验收。
