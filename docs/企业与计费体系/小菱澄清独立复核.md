# 小菱澄清基础独立复核

## 范围

本记录检查本地工作树的 115 澄清记录、内部服务和 `waiting_clarification` 运行内核。它们尚未连接澄清接口、用户决议界面、真实工具授权、初次及后续模型发送门禁或后台子 Agent；`recorded` 只是记录状态，不是执行、付款或外发授权。不得将此节点视为自然语言冲突治理完成或用于开放销售。

## 复现和验证

- 隔离 SQLite 先复现：澄清记录完成后更改发起消息正文，状态仍不失效；实现加入来源正文摘要后，独立测试通过。当前未发现真实用户可编辑该消息的入口；此测试构造的是数据变化。
- 内存运行时先复现：已审批工具执行期间取消运行，工具随后返回需澄清时，持久检查点为已取消但调用结果返回失败。实现补持久取消检查后独立测试通过；该实验没有让后续工具或模型执行。
- 对历史高权限消息正文更改、合成删除及作者降权各做一次独立 SQLite 测试，均返回 `stale`。合成删除测试的 SQLite 未启用外键，不表示产品有消息删除入口。上述五项独立定向通过，不等于真实浏览器、供应商或生产验证。
- 实现代理在隔离 MySQL 的可重复读旧快照中复现已提交决议仍显示等待，补充有序当前锁读后进行阶段验证；其两种消息与检查的持锁顺序使用合成数据，不能替代真实执行、发送链路及生产容量验收。最终结果以实现代理最新记录为准。

## 明确未完成

- 作者从管理员降为普通成员后又恢复管理员时，仅比较角色当前值会使旧决定恢复有效。应引入覆盖成员、组权限和账号等相关写入路径的可信单调权限版本，并验证竞争和恢复；不能以状态名称代替授权保证。
- 管理员对某来源拒绝后，当前记录不允许企业所有者在同一运行中复核并形成新的有效决定；需要保留原拒绝证据的高权限复核和版本化流程，不能直接覆盖审计记录。
- 对应两项合成回归保存在 `backend/tests/unit/services/test_enterprise_assistant_clarification_open_gaps.py`，当前为 **2 项 strict xfail**，限定专用异常；它们代表未实现契约，不是通过项。修复后应重新定义或转正对应测试，并验证审计历史、角色变化与并发。
- 当前实现锁读全部会话人类历史消息，并可能对发起人以外每条同级或更高权限消息生成待澄清项。未验证大群性能，也没有证明能识别无关事项的范围规则；不能简单截断历史或依赖模型判断来声称消除风险。
- 还须完成模型发送和每个副作用事务中的身份、租约、精确参数、权限版本、支付额度与决议核验，独立公告审批与恢复，真实 MySQL 旧快照/竞争、多账号浏览器及供应商账单验证。
