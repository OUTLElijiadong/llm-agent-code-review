# 需求对齐：企业与计费体系

## 2026-11-08 用户补充的设计与实现要求

- 目标、架构、设计和实现保持简单；视觉方向参考 Linear 官网和苹果备忘录的干净感。删除不帮助操作的标语、重复提示和次要标签，以布局与清晰控件表达层次。
- 每项决定同时检查用户体验（UX）、开发者体验（DX）和智能体体验（AX）：用户能理解和完成任务，维护者能定位和验证行为，智能体能通过稳定且有权限约束的接口理解状态并操作。
- 不删减原始业务需求或破坏既有功能；必要的操作状态、不可用原因、错误与账单风险不能为了视觉简洁而隐藏。新增的占位式、不可执行运行记录已撤回，真实个人 Agent 运行和发布审核仍需完整实施。

## 依据与范围
- 基线：生产 4.1.42，发布提交 a165f94ed4c208fb05251e4c7d12accb427c8ba3；生产 Alembic 065_review_rule_lang_severity。
- 个人空间与多企业空间分离；企业组织、席位、项目授权、知识和 Agent、群聊、小菱、会员、积分与支付按已确认任务书实施。
- 个人审查员基础/高级能力区别、旧共享项目和永久审查员迁移以既有用户确认的规则为准。
- 生产数据不作为开发或测试数据，旧主工作树及现有的其他工作树保持原状。

## 已确认的关键边界
- 企业管理员不是平台管理员；企业成员只访问明确授权的项目。旧个人项目只有项目创建者本人可绑定进企业；移除企业成员时停用其企业内显式项目授权，日后重新加入不自动恢复旧项目权限。
- 个人远测保留普通审查员对普通用户申请的既有审批能力。企业远测由所属企业 owner/admin 审批，owner/admin 可审批自己的企业申请；企业小组长可审批自己负责小组内其他成员的申请，但不可自批。审批权本身不授予项目、报告或其他企业资源正文的访问权。
- 企业成员具备审查员能力，个人普通用户可单 Agent 审查并创建基础 Agent。
- 小菱群内主动讨论，业务写入须经有权用户明确发起；群内权限、结果可见性和费用归属独立检查。
- 企业 Agent/Skill 先以作者私有的版本化草稿保存；企业内发布只对该企业成员可见，由另一名有效企业 owner/admin 审批；提交前必须有其他审批人，否则不创建会悬挂的申请。全局发布由平台唯一最高管理员审批；最高管理员不能批准自己提交的全局申请，也不能提交会导致自批死锁的全局申请。
- 发布申请绑定不可变版本快照、范围、企业、申请人和 SHA-256；审批前使用当前锁定读复核申请人及源版本，企业成员变更与审批共享企业锁。待审申请阻止删除源草稿，离职申请可拒绝但不可批准。审批只开放目录可见性；兼容的 schema v1 Prompt Agent 与 `llm_transform` Skill 另由企业小菱专用工具按企业额度运行，不接入旧 Agent Profile、Agent Studio 或任意工具执行。企业发布范围为全企业，不做小组范围；企业成员可读企业目录，登录用户可读平台批准的全局目录。
- 企业资产草稿和审批页嵌入企业空间；全局目录对登录用户开放，全局审批页仅平台最高管理员可访问。审批、撤回、拒绝和下架均保留记录。
- 付费和真实收款上线依赖商户资质及签约，不得以模拟回调声称支付成功。

## 现存约束
- 企业租户授权、计费覆盖和真实外部支付需要完整实现与验收；未完成之前相关入口不作为可收费功能开放。
- 生产发布和生产浏览器验收应另核对版本、备份、迁移和真实账号，不能用本地测试代替。

## 后续阶段：模型账本人工对账工作台
- 原始缺口：旧预占缺少不可变费率/供应商身份快照；`reserved/unknown` 状态因证据不足保持冻结，当前没有面向平台最高管理员的检索、证据记录和双人复核入口。渠道支付宝/微信账单工作台只处理支付订单，不涵盖模型调用账本。
- 本阶段范围：新增平台最高管理员专用的未结预占队列、详情和审阅历史；`unknown` 可提交结算提案或“经外部证据确认未发送”的释放提案，并由不同的第二名平台最高管理员审批或拒绝；`reserved` 仅显示，不允许人工变更，因为它仍可能对应活动中的 provider 请求。审计事件追加写入，钱包/额度/预占变更与批准事件同事务提交。
- 财务规则：结算只能使用原预占费率和供应商身份快照，以输入/输出 Token 重算应扣积分，禁止管理员手填收费金额或修改历史费率。缺少费率/身份快照、Search/Fetch 计数缺失或出现未计价正数时不得结算；只有明确的 Search/Fetch `0/0` 可证明没有该类费用。继续冻结并展示阻断原因。已发送与未发送只按提交的外部证据作双人判断；平台不自动查询上游账单。
- 证据规则：仅记录外部证据来源标识、SHA-256、必要的供应商请求 ID 和不含密钥/提示词/个人支付信息的说明；不上传、保留或向工作台展示原始聊天、提示词或外部原始账单。哈希格式可校验但来源真实性由两名审核者在平台外核验。
- 事件规则：提案、批准、拒绝及已知预占上的业务策略阻断均形成追加事件；阻断事件只保存操作者、预占、处理方式和服务端原因，不写入失败请求正文/证据值，也不改变账本或原提案状态。无效身份/格式请求和不能关联到已存在预占的请求不记入这张财务事件表。
- 权限与并发：所有读取/提案/复核 API 仅 `require_super_admin`；提案人与审批人必须是不同账号。审核动作在数据库事务中锁定付款钱包和预占，重新核验预占状态、快照、证据和幂等状态；并发审批仅能有一个成功。普通管理员、企业管理员和企业成员均无此工作台权限。
- 硬边界：工作台不开放销售、不调用支付渠道或模型、不修正渠道订单、不创建费率快照、不凭当前费率结算历史项。无法由可信证据与已存在快照算出的账目必须留在人工冻结队列。

## 2026-11-09 补充：小菱历史指令的发送与工具门禁

- 原始要求：企业群、小组群、私聊中发生指令冲突时，按当前有效权限等级处理；不改变发起人的账号权限、企业范围、额度或审批规则。
- 已核实：请求上下文已向模型展示最近消息的服务端角色与优先级；后端显式澄清仅接入注册 Agent 团队创建。模型发送、收费工具、其他持久化工具和发布前内容仍缺历史指令硬门禁。
- 本次精确范围：冻结快照内最近 30 条、来源消息之前、其他当前有效且等级不低于发起人的显式 `@小菱` 消息。每次模型运行先审核是否可将该请求及上下文发给模型；每次工具调用再审核精确工具名、目标和参数摘要。取消保持可用。无候选时记录上下文与所有快照作者权限版本证据；任何证据变化均停止继续。
- 边界：不声称模型能可靠识别无 `@小菱` 的自然语言矛盾；此类语义由模型依据角色提示处理，若无法判断必须询问，不把模型判断当作权限授权。真实模型、支付和生产不在本地实现验收中。
- UX/DX/AX：继续使用企业微信式悬浮聊天中的单张澄清卡；把“本次回复发送”与具体工具动作分开显示。后端使用稳定、可测的模型发送/工具两类 pending 状态；恢复接口按类型分派，不伪造工具调用，Agent 获得明确状态、动作摘要和失败关闭结果。
