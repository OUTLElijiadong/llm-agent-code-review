# 费率独立复核：任务与验收

```mermaid
flowchart LR
  A[真实依赖链复现] --> B[迁移与权限]
  B --> C[草稿独立审核]
  C --> D[两人取消]
  D --> E[前端管理与复核入口]
  E --> F[真实 MySQL 与多账号验收]
```

| 任务 | 输入与依赖 | 输出及约束 | 验收 |
|---|---|---|---|
| A 已复现 | 唯一超管、不同平台管理员 | 草稿自批 409，另一管理员 403；取消无合法第三角色 | 真实认证依赖链测试；服务层构造批准只用于复现取消前提 |
| B 授权与迁移 | 当前唯一 head、C4 和 105 | 独立费率 grant，默认无；记录授予撤销并随身份变动失效 | SQLite/MySQL 旧数据不变；权限交叉矩阵、禁用恢复不自动重新授权 |
| C 草稿审核 | B、有效 105 双币目录 | 最小列表/详情、第二人批准或拒绝；审批时重新核价与时效 | 真实账号角色、伪造 actor、跨权限、过期来源、自审、重复/并发复核 |
| D 取消申请 | B、已批准未来目录 | 独立取消申请表；两人申请/决定及审计，原子防重 | 同一申请自批拒绝、两个互不相同账号成功、重复与过期、与生效并发 |
| E 界面 | B–D 的实际 API | 超管委任界面、独立审核待办、取消申请/复核及结果未知提示 | 前端状态、权限变化、窄屏/键盘、迟到响应与多账号隔离 |
| F 验收 | B–E | 完整自动化与 MySQL 并发，更新主任务验收和待办 | 不同事务锁竞争、真实多账号浏览器；沙箱、真实费用、生产分别列未验证 |

每项先复现/测试，后实现并验证；不打开销售锁，不自动部署或更改生产。105 未补证据的历史目录保持不可新预占，已有账单不改变。
