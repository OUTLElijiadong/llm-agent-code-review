## A2：按次账本、C4 与用量拆分（2026-11-07）

- 新迁移 `100_billing_tool_reservations` 在 migration 099 后增加 `model/search/fetch` 类型、工具价格快照、成功次数、attempt marker 和 C4 0/1 证据。SQLite 使用 `batch_alter_table` 替换模型费率对约束；检查发现工具费率字段必须显式拒绝 NULL 后，ORM 与迁移约束已补 `IS NOT NULL`。`reservation_part` 和 `reservation_limit` 在真实 migration/ORM 中不是 `billing_reservation` 外键，SQLite 回归按仓库真实 schema 验证历史关联行保留。
- `reserve_tool` 只允许企业钱包，无个人回退；锁企业钱包与适用月额度，按单次客户价格全额预占；写入 provider attempt 后必须先提交才允许发送。同一 key 永不重发；只有无 attempt marker 才能按未发送释放。未知状态不能自动结算或重试。
- C4 对未知工具账单须记录来源证据、供应商请求 ID 和 0/1 成功次数，由另一位最高管理员复核后按原快照结算。审计发现 C4 核实 0 次会从不计费数统计中遗漏，已让 personal/enterprise 用量查询把已核实的零成功也纳入明确不计费计数；企业用量页补上模型扣费列。
- 用量图的 Token 和已计量模型金额只统计 `billable_kind=model`；Search/Fetch 单独显示成功次数、客户扣费、unknown/held、pending/held 和不计费调用。C4 展示逐 reservation 供应商成本与客户价；用量页面没有聚合供应商成本或 margin，费率目录的直采毛利也不代表产品整体盈利。
- 定向后端验证：A2 reservation/C4/API/migration 与 usage 组合 **28 项通过**（含工具计费服务、SQLite 迁移回归、0 次 C4 用量核验）；既有警告为 pytest/依赖弃用。
- 本阶段没有调用真实 DeepSeek，没有查真实供应商账单，没有运行商户沙箱、生产数据库迁移或部署。

## A3：DeepSeek Search/Fetch 适配器（2026-11-07）

- 本次核对 [DeepSeek 官方 Search & Fetch 指南](https://api-docs.deepseek.com/zh-cn/guides/search/)和[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)：固定 POST `/v1/tools/search` 与 `/v1/tools/fetch`，Bearer Key；单价按成功请求次数。HTTP 200 且 Search results 非空/Fetch 返回非空正文才收费；无结果、失败响应、超时不计费；对响应不确定时不推断供应商是否收费。
- 新增独立计量 service：只放行 `system/global` DeepSeek 平台凭据和固定官方 HTTPS 主机；HTTPX `trust_env=False`、不跟随重定向、不自动重试，拒绝自定义 host 与 BYOK。输入验证后预占并再次权限校验，持久化 attempt marker 并提交，之后才执行单次 HTTP 请求。
- Search 固定 5 条、关闭正文内嵌，query 1–128 字符；Fetch URL 不超过 2,048 字符、无凭据，并拒绝非公网 IP 字面量。上游响应读取最大 256 KiB；下游最多 12,000 Unicode 字符。错误只返回状态摘要，不保存原始请求、Key、上游原始响应或供应商错误详情；A4 为崩溃恢复持久化规范化的有界结果，其中可能包含结果标题、链接或 Fetch 正文，尚未实现保留期清理。A3 阶段当时尚未注册为小菱函数工具；A4 已完成条件式工具注册与运行时接线，实际请求仍受商业计量门禁和费率目录控制。
- mock 测试覆盖 Search 成功/空结果/429、Fetch 成功与截断、timeout、malformed 200、固定 endpoint、请求字段、Key header/代理环境/重定向选项、无公网 URL、请求参数注入、平台凭据门和预占后撤权；对应后端 A3/A2 定向组合 **28 项通过**。不代表真实 DeepSeek HTTP 或真实费用验收。

## A4：企业小菱运行时与崩溃恢复（2026-11-07）

- 运行时仅在活动费率与商业计量配置 ready 时注册本地 Search/Fetch schema；执行端限制来源于当前企业小菱 run，并复核企业/成员/会话/小组/租约；单 run 最多启动 3 次外部调用，禁止供应商内置 `web_search` 绕过账本。
- 收到 `usage_unknown` 或缺失工具结果时，Responses 立即终止本轮剩余工具，不把未知错误重新交给模型继续触发费用。已发现的同 key 已保存结果在重新授权后回放；不得再次请求供应商。
- 新增迁移 101 持久化有界工具结果，并与确定的账务结算/释放放在同一事务；迁移 102 给陈旧预占恢复增加受约束的 `recovered` 审计事件。仅当外呼 marker 已写、结果与 usage 均缺失、预占仍完整、企业运行租约过期且超过 30 分钟，平台最高管理员才可将 `reserved` 转为 `unknown` 交给 C4；恢复不扣费、不释放、不重新外呼。
- 后端运行时、迁移、对账、checkpoint 与权限定向组合 **146 项通过**；revision 长度修正后迁移约束专项另 **4 项通过**。前端 C4 工作台 **6 项通过**，ESLint 和 `vue-tsc`/Vite 生产构建通过。该结果尚不包含 MySQL 001→102 全链和完整前后端 suite。未调用真实 DeepSeek。
