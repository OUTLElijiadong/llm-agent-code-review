# 项目源码写入当前授权验证

## 范围和问题

个人和企业项目的源码创建、单文件/目录上传会先锁项目，再调用原统一权限函数。MySQL `REPEATABLE READ` 下，原函数随后用普通快照查询并 `populate_existing`，可能用旧 owner 覆盖刚锁定的当前 owner；企业项目绑定、显式编辑授权和小组长角色也可能被旧快照保留。先独立建立旧快照，再提交真实变更的测试中，owner 变更、项目隔离、企业授权撤销和组长降级四项均复现为仍允许写入。

## 本地修复

- 仅源码写入路径对项目、企业绑定、账号及角色、企业、组、成员关系和显式项目授权使用事务内当前锁读，锁保留至写入提交；常规只读调用保持原行为。隔离整包归档的互斥判断也使用当前读。
- 源码写入可能在已有账号/项目锁后遇到企业组织锁；这些锁定读使用 `NOWAIT`，冲突时返回 409 并要求刷新重试，避免以相反顺序等待形成死锁。只读取的企业和组采用共享锁，不将不同成员在不同项目上的写入一律串行。
- 现有企业订阅权限与项目权限仍分别校验；不能将当前项目授权视为覆盖整个付费、JWT 或跨进程工作流的保证。直接数据库写入或未遵循项目绑定写入约定的外部进程不在本次证明范围内。

## 本地证据与限制

- 一次性 MySQL 8.0.45 从空库完整迁移至本地 head：**15 项通过、1 项严格预期失败**。覆盖旧快照后的 owner、隔离状态、活动归档、企业绑定、成员与小组状态、授权撤销及组长降级；还覆盖真实项目绑定后撤销初始授权、个人管理员降级、授权先持锁与授权撤销/移组先后、持企业锁时立即返回冲突、同企业不同成员项目并发。真实 JWT 目录上传的取消、注销和 owner 变更另 **3 项通过**。
- SQLite 现有个人/企业项目授权、源码和隔离组合 **402 项通过**；Ruff 通过。这些是自动化测试，不等于真实生产数据和浏览器验收。
- **待解决容量门禁**：MySQL RR 下个人项目不存在企业绑定时的当前锁读可能锁住唯一索引间隙，使无关项目的绑定插入等待；独立 `--runxfail` 已复现 MySQL 1205，严格 xfail 限定专用异常。当前竞争插入为合成数据，并非真实绑定 API 或生产负载；不要为了消除此等待退回普通旧快照读。需设计无需缺键范围锁的可验证项目归属序列化机制，并做生产规模容量测试。
- `NOWAIT` 是用户可见行为变化：项目授权或所属企业正被修改时请求可能返回 409，应刷新后重试；不保证在所有历史客户端中的交互已验收。应独立审查锁顺序、同一企业读写与失败审计；必须对最终代码重新运行完整后端回归。

## 已有源码文件与当前账号补充验证

- 独立 MySQL 红测确认：原修复覆盖新建和上传，但已有文件的编辑、重命名、删除和版本恢复仍在项目行锁后使用旧权限快照。所有者变更、项目隔离、企业编辑授权撤销和组长降级四种变更下，四种写操作共 **16 项**原先错误成功。现在这些操作在保持项目→文件锁后，以 `NOWAIT` 当前读复核完整项目授权；发生锁冲突时返回可重试的 409。
- 另以真实 JWT 复现个人项目所有者被禁用或注销后，原逻辑仍可能通过 owner 关系写入。当前锁定写授权入口在信任项目关系前先锁定并核验账号状态、有效角色及 JWT 原始版本/过期时间；内部服务调用无 JWT 时仍校验当前账号和角色。隔离 MySQL 覆盖禁用、注销、禁用后恢复、授权先持锁及授权撤销竞争，新建与上传均走真实服务入口。
- 修改后独占 MySQL 组合 **54 项通过、1 项严格预期失败**；其中本补充用例 **39 项通过**，含 JWT 到期前、到期时及到期后三个授权边界；剩余预期失败为前述无关项目绑定间隙等待。SQLite 源码及项目权限组合 **104 项通过**，Ruff 和 `git diff --check` 通过。上述测试使用合成数据库，不能替代实际生产、真实浏览器或完整后端全量。
- JWT 与角色只是在项目写授权时复核；本节点不单独证明所有 `FILE_EDIT`/`FILE_DELETE` 权限绑定在入口验证之后被撤销的竞争，也不声称消除了授权检查与数据库提交之间自然到期的时间间隙。其他源码写入或归档接口须分别检查是否使用当前锁定读，不能由本节点外推。
