# 微信资金账单基础切片

## 共享 multipart 独立复核（本地）

- 对重复 `boundary` 参数（包括相同值和大小写混写）及重复 `Content-Type` 原始头，在读取请求正文前拒绝，避免不同组件各取首值或末值；已覆盖的独立 quoted 参数中的分号、转义和扩展参数不按字面误判为重复。目录上传、资金上传、共享 parser、取消、大小限制及代码文件服务组合 **143 项通过**，Ruff 通过。
- 边界值采用 RFC 2046 的 1–70 个允许 ASCII 字符；原解析器可能接受的 71–256 字节非标准 boundary 现在拒绝，重复的 `boundary` 或 `Content-Type` 即使取值相同也拒绝，不能声称所有历史非标准客户端完全兼容。随机兼容探针还发现：无关 quoted 参数以转义反斜杠结束时，底层 `python-multipart` 有时会吞掉后续 boundary；当前因无法确定而失败关闭，原底层同样无法正确解析，不能声称支持所有合法 quoted 参数形式。另一次独立 5000 组合成 quoted 参数测试中，底层可识别的 4708 组均正常通过，其余 292 组由当前门禁拒绝；这个随机样本不能代表真实客户端比例。
- 独立真实 ASGI 红测复现：目录上传缺少 Content-Type、错误边界时返回 500，未捕获异常的服务端堆栈可能包含请求片段。共享解析器现将缺失/非 multipart 类型及 `python-multipart` 明确的解析错误转为不回显正文的客户端错误，关闭已创建的临时文件；未预见的服务异常仍原样抛出，不冒充用户输入错误。
- 目录上传和资金上传的异常输入、日志不含合成正文、有效单文件/目录上传、截断不部分提交、上限、断流/取消及代码文件服务组合 **101 项通过**，Ruff 与 `git diff --check` 通过；测试使用合成输入或依赖替身，不能替代真实浏览器验收。
- 一次性 MySQL 8.0.45 空库迁移至 117 后，资金上传真实 JWT、原令牌失效、旧快照与跨连接锁组合 **6 项通过**。独立 Linux 容器验证重复文件描述符在原临时文件关闭后仍可读取，仅覆盖操作系统所有权基本行为。已认证请求的跨 worker 预解析并发、慢上传和真实商户容量仍未验收。
- 同轮另复现原有目录上传取消后线程继续运行而文件已关闭；该问题与本次解析异常映射不同，已交由独立专项处理，不能将上述通过结果视为目录上传取消安全验收。

## 后台独立复核：上传鉴权与取消（本地）

- 后续独立复核先复现了服务关闭同时取消父、子 task 时，工作线程仍在运行但请求会话和表单已经关闭。现在线程持有独立 Session 与不可变的账号/JWT 快照；内存 spool（至多 64 KiB）复制为 bytes，落盘 spool 通过复制的独立文件描述符读取，future 在取消前未启动及线程执行后均释放描述符和容量槽。请求方取消后线程仍可能提交，必须刷新确认，不能将取消当作撤销或未提交。
- 测试覆盖重复取消父 task、单独取消子 task 后关闭请求会话与表单再继续处理、内存/落盘 spool、排队未开始时取消回收资源，以及本机 12 MiB 落盘文件读取时事件循环心跳；隔离 Linux 容器验证复制描述符在原临时文件关闭后可继续读取。该心跳测试不代表慢磁盘、生产负载、进程被强制终止或真实渠道可用性。
- 认证后上传若 Content-Type 不存在、为 JSON/text 或伪 multipart，现返回 415；缺失 multipart boundary 返回客户端错误。先前无 Content-Type 会触发 500，该现象已用真实 ASGI 模拟复现并回归。
- 合法 multipart 媒体类型但正文边界损坏时，python-multipart 可能抛 `MultipartParseError`；资金路由将其映射为固定的 400，不回显正文或异常栈。共享有限 multipart 解析器现要求收到完整结束事件；发现未结束边界或未附着到返回表单的临时文件时，关闭本请求全部临时文件并拒绝。真实目录上传回归覆盖第一个文件完整而第二个截断时不执行任何上传，以及合法双文件正常处理。
- 共享 multipart 入口还在读正文之前按 [RFC 2046 §5.1.1](https://www.rfc-editor.org/rfc/rfc2046.html#section-5.1.1) 检验 boundary：解析引号后须为 1–70 个允许的 ASCII 字符，允许中间空格但不得以空格结尾；非法或过长 boundary 安全返回客户端错误，不广泛捕获文件 I/O 和其他程序异常。独立生成的 300 组合法及 300 组非法样本全部通过；资金/目录 API、共享解析、限额及相关代码服务阶段组合 **129 项通过**。以前 Python 解析器可能接受 71–256 字节的非标准 boundary，现会拒绝；不能宣称这类历史非标准客户端完全不受影响。
- 真实 ASGI 红测复现：使用 FastAPI `File/Form` 声明时，2 MiB 的匿名请求先进入 multipart 解析，再由鉴权拒绝；全局总请求大小限制虽然已经在解析前生效，但不等于认证前零解析。
- 资金上传改为先执行现有唯一最高管理员认证，再复用有界 multipart 解析器；每个文件最多 12 MiB，原总请求限制继续生效。处理文件与数据库仍在线程池中，异步接收期间不持数据库锁；手动保留原 OpenAPI multipart 合同。解析过程断线或取消关闭临时文件；正常父任务取消会等待线程退出，若服务关闭使子 task 也被取消，线程仍拥有独立文件和会话，可在请求资源关闭后继续结束。已发起的操作结果仍应以刷新为准，不能以客户端取消推定事务未提交。
- 真实 JWT 验证普通账号在解析前被拒绝、最高管理员可导入；活动 RBAC 多角色漂移和停用的超管角色均拒绝，与平台单有效角色规则一致。SQLite、资金服务、网关和大小限制组合 **88 项通过**；一次性 MySQL 8.0.45 空库迁移至 117 后 **5 项通过**，包括真实 JWT 上传、下载期间注销、旧快照幂等和跨连接 NOWAIT 锁。Ruff 通过，临时容器已停止。
- **剩余容量边界**：多个已认证请求可以在取得跨 worker 数据库单例锁之前并行接收并解析各自的限额内 multipart；DB 锁只串行后续账单处理，并非上传前的全局并发门禁。慢上传、临时磁盘及多 worker 容量尚未经过生产规模验收。资金账单、原交易账单和导入接口的真实商户、渠道和银行余额对账仍未完成。
- 文件独立所有权和共享解析器修改后，资金 API、解析、限额、目录上传与代码文件服务组合 **101 项通过**；一次性 MySQL 8.0.45 空库迁移及真实 JWT、并发和旧快照组合 **6 项通过**。MySQL 的渠道请求仍为替身。

## 官方契约与设计

- [申请资金账单](https://pay.wechatpay.cn/doc/v3/merchant/4012791867)：`GET /v3/bill/fundflowbill`，账单日期限最近三个月内，账户为 `BASIC`、`OPERATION` 或 `FEES`。申请响应按现有微信 API v3 机制验证平台签名与证书身份；下载请求使用商户签名，下载地址限定既有 HTTPS 微信主机和已核实路径、禁止跳转。
- [下载指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071218)要求比对文件 SHA1；本切片请求未压缩数据，对下载原始字节核验 SHA1，不推断 GZIP 摘要针对哪一层。文件大小使用已有上限，摘要不匹配时不提供内容。
- [资金明细字段](https://pay.wechatpay.cn/doc/v3/merchant/4013071249)：资金账单按账户余额实际变动时间记账，金额单位元、精确到分；逐笔交易流水、手续费支出及退还手续费为不同业务记录。解析保留业务标识、收支和余额，不保存申请人或备注。`扣除交易手续费`支出、`退还交易手续费`收入分别统计；未知业务类型保留且不得自动归类为手续费。官方公开示例中，同一资金流水号可分别关联交易收入和手续费支出；重复本身不代表差错，记录重复号但保留所有行，不据此修改账务。
- 明细必须存在匹配所请求日期的记账时间及合法金额，汇总表头和唯一汇总行必须完整，笔数及收入/支出金额分别等于明细汇总。校验仅证明文件内部一致，不代表与本地订单、退款、银行余额或其他资金账户对上。账单未提供期初余额，因此不推断期初/期末或跨日连续性。

## 独立复核与本地修正

- 复核发现原 CSV 读取在检查行数之前先把所有记录构造成列表。短小 GZIP 可展开大量空行，超过行数限制却在拒绝前消耗过多内存。现改为逐行读取并及时限制行数、单行字符数、列数和字段长度；解压和文本本身仍有既有大小上限，不代表已完成并发容量测试。
- 构造的未引用额外逗号会令明细字段错位，原解析器可能将错误字段作为业务凭证号且汇总仍一致。现拒绝超出明细表头宽度的非空字段，允许合法引号内逗号和尾随空列。该检查只能拦截可见的额外字段，不证明任意人工编辑或字段置换均可被检测；文件内部汇总通过不能作为业务字段或商户余额可信的充分证明。
- 复核发现若已验签响应中的 URL 查询含未编码的空格或非 ASCII 字符，原来签名路径与 httpx 实际规范化发送路径可能不同，导致下载失败；尚无证据表明真实微信响应会出现此类 URL。现对 httpx 实际规范化的请求路径签名，同时重新对规范化 URL 校验允许的 HTTPS 主机、路径、端口及其他边界；测试保留原有对危险主机、用户信息、端口、重定向、空查询等的拒绝。
- 申请应答的验签依赖管理员事先配置并信任的平台公钥或证书和对应序列号；现有代码从证书提取公钥，不独立验证 X.509 证书链或证书有效期，也没有证明自动轮换可用。配置、更新和停用信任材料需要后续单独验收。
- 修改后资金解析、网关及现有交易账单服务/API 组合 **80 项通过**，Ruff 通过；历史展示样例 CSV 再次得到 53 条、收入 47 分、支出 22 分、手续费支出 8 分。测试使用公开样例或合成数据，未接真实商户。

### 资源边界复核与补充（本地）

- 再次复现时，约 1 MiB 的一百万逗号会使 `csv.reader` 先构造 1,000,001 列后才拒绝。现按引号和双引号转义规则在 `csv.reader` 前检查列数及字段长度，限制单次物理行读取，先红后绿；同一探针现未构造任何 CSV 行，`tracemalloc` 跟踪峰值约 7 MB。合法引号内逗号、转义双引号、CRLF 和尾空列保留；3000 组不含换行的随机合法 CSV 与标准库结果一致。
- **资源限制仍有边界**：原始下载、最多 48 MiB 的解压结果、解码文本及 `StringIO` 仍会整体驻留或复制；上述峰值不是服务器总内存或并发容量证明。实现按官方说明拒绝含真实跨行换行的引号字段，跨行 CSV 不支持；与本地订单或渠道余额的对账仍未实现。
- 尾空列与错误 CSV 存在无法仅凭字段数消除的歧义：当备注含未引用逗号且末尾业务凭证号原为空，错误的备注片段仍可能落入业务凭证号而汇总一致。此切片不把该字段自动关联本地订单；今后接入须依赖可信原始来源及人工复核，不能将文件内汇总当作字段真实性的证明。
- 独立复核对 29,524 组短输入逐项与标准库严格 CSV 解析比较，在临时缩小的列数和字段上限下未发现合法字段误拒或超限漏拦；跨行及未闭合引号仍拒绝。另先红测后加入 C0/C1 控制字符拒绝，保留普通 CRLF 行结束；微信官方明示 SOH 应在渠道侧替换，但其他控制字符在真实商户文件中的出现情况仍未验证。
- 隔离内存探针使用 16,329 字节 GZIP 展开 16 MiB 空行，到行数限制时 `tracemalloc` 峰值约 83,953,774 字节。这是本地 Python 分配观测而非进程 RSS 或并发承载上限；不应把 CSV 行迭代称为整文件流式解压。增加控制字符测试后，资金解析、网关与旧交易账单服务/API 的组合回归 **91 项通过**，公开样例仍为 53 条；真实商户、并发容量和字段歧义依然未验收。
