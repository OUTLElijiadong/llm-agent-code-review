# 个人渗透成员撤权后访问审计

## 验证范围

在隔离的测试数据上验证个人渗透任务的列表、详情、报告与本人取消；不连接生产数据库。真实 JWT 接口用例覆盖项目成员撤销后的脱敏和本人取消、现有成员正常访问、审查员审批他人申请、自身审查员身份不能绕过撤权、停用和外部账号、企业项目隔离及终态脱敏。报告正文和项目更新后的名称、目标及范围不得向已撤权成员泄露。

MySQL 8.0.45 使用独占空容器和 REPEATABLE READ 事务，覆盖旧快照建立后成员撤权、审查权限降级、企业项目绑定、JWT 版本撤销，以及同一项目并发绑定时等待后拒绝读取。测试通过真实服务层执行；其中绑定先提交的部分场景使用合成绑定记录。同项目等待通过 `performance_schema.data_lock_waits` 观察。SQLite 的 JWT 用例不能替代 MySQL 并发验证，服务层测试也不能替代真实浏览器及生产验收。

## 已确认的跨项目锁等待

`backend/tests/test_mysql_pentest_revoked_project_access.py` 保留了独立的反例：读取一个尚未绑定企业的个人项目后事务尚未结束，另一用户绑定无关项目时，InnoDB 会等待 `enterprise_project.uk_enterprise_project_project` 的 `supremum pseudo-record` 间隙锁。该用例通过性能模式观察等待，已实际复现；它证明跨项目阻塞，并未证明发生死锁或生产故障。

独立实验将绑定检查的 `FOR SHARE` 改为 `FOR SHARE SKIP LOCKED`，同样重现该间隙等待，因此不能把 `SKIP LOCKED` 当作已验证的解决方案。恢复普通快照读取会重新引入企业绑定已提交但旧事务看不到绑定的权限风险。当前保留安全的当前读，跨项目等待用例以 `strict xfail` 记录已知缺陷；修复后应取消标记并重新验证安全、同项目竞争和无关项目并发，不能把预期失败计为通过。

## 证据和限制

- JWT 接口回归：`backend/tests/test_pentest_revoked_project_access.py`。
- MySQL 旧快照、认证版本、同项目等待与跨项目间隙锁回归：`backend/tests/test_mysql_pentest_revoked_project_access.py`。
- 临时 MySQL 仅用于隔离测试，容器自动删除；未验证生产数据库、真实浏览器或线上行为。
