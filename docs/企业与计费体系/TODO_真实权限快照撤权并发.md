# 待办：真实权限快照下的撤权并发

## 已复现现象

在隔离 MySQL 8 中，注册 Agent 团队使用真实 `_live_role_snapshot` 时，第一团队进入模型请求后持有企业行共享锁。此时执行 `enterprise_org_service.remove_group_member` 会先请求企业行排他锁并等待；另一个独立团队随后请求企业行共享锁，也可能排在该排他锁之后，直到第一团队的上游请求返回。SQL 追踪分别记录撤员的 `enterprise ... FOR UPDATE` 和其他团队的 `enterprise ... FOR SHARE` 在同一时段等待约 15 秒。

这与本次修复的账单 `SELECT ... LIKE ... FOR UPDATE` 范围锁跨团队串行是两个不同的等待点。后者已将最终发送事务限制为 READ COMMITTED 并保留当前读及团队锁；前者涉及组织权限写者和发送者之间的锁序，尚未重构。上述为隔离测试证据，不代表已经在线上复现。
