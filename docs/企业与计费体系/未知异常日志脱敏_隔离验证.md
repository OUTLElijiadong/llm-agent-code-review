# 未知异常日志脱敏：隔离验证

该记录仅覆盖隔离环境中的未知 HTTP 异常及 ASGI 服务器边界，不表示生产已发生凭据泄露，也不表示其他业务日志均已脱敏。

已用合成密钥和离线数据库故障复现：通用异常处理器及 Loguru 默认诊断栈可记录请求对象的敏感字段；即使通用处理器不再输出敏感值，Starlette 仍会将原异常重新抛给 Uvicorn，后者的错误日志可能包含异常文本。

候选修改关闭控制台和文件 sink 的局部变量诊断；通用 HTTP 未知异常只记录请求 ID、异常类型和最多五个受限应用代码帧。在每个应用进程初始化时，为 Uvicorn 的 `uvicorn.error` 安装针对其固定 ASGI 错误记录的过滤器，移除该日志记录的异常详情，仅记录受限类型与应用代码帧；原异常对象及 ASGI 控制流不变。

在本机回环的真实 Uvicorn 中，以合成值分别检查普通 500、已完成响应后的后台异常、部分流中断、客户端断连、WebSocket、带消息取消、自定义 `BaseException` 和异常组；核对应用与服务器日志不含合成敏感值。另对真实配置路由、控制台和文件 sink 进行隔离测试，同时保留可检索的非敏感诊断信息。具体测试结果和独立复核以最终发布记录为准。

全取消异常组不得直接变成单个 `CancelledError`：真实 `asyncio.TaskGroup` 中，两者对兄弟任务取消和异常组传播的行为不同。候选不修改异常对象；隔离回归确认原取消组对象上抛、兄弟任务按原语义取消，并核对 `KeyboardInterrupt`、`SystemExit` 和 `GeneratorExit` 原样传播。

边界：过滤器只针对当前锁定 Uvicorn 版本及其固定 ASGI 错误记录；其他 ASGI 服务器、覆盖或主动移除过滤器的自定义日志配置、导入和 lifespan 异常以及其他 `logger.exception` 消息不在该证明范围内。测试无真实用户、供应商或生产数据库，候选未经生产验收。

## HTTP 与 WebSocket 查询凭据

隔离红测复现了实际 `/api/agents/events` 与 `/api/ws/discuss/1` 的未认证请求可将查询令牌写入 Uvicorn 访问或握手日志。候选在应用进程初始化时，为固定的 Uvicorn HTTP 访问记录和 WebSocket 接受、拒绝记录增加过滤，仅替换已识别凭据查询字段的值，保留路径、非凭据字段、HTTP 方法、状态和 WebSocket 接受状态；请求本身不做修改。覆盖查询键大小写、编码以及重复字段。

使用真实 Uvicorn 和默认 CLI 日志，在回环环境检查 HTTP 流和 WebSocket 本地模拟路由的成功交互；真实业务路由只验证未认证拒绝路径，未验证真实账号登录后的业务流。该过滤仅覆盖锁定 Uvicorn 固定格式、已列出的查询字段，以及应用初始化完成后的日志；代理日志、其他字段名和其他日志源不在覆盖范围。

项目两个后端 Dockerfile 均以单 worker 启动 Uvicorn，未传 `--log-level`，使用该版本默认 INFO；这是代码中的启动配置，不能证明线上没有额外覆盖。单独对两 worker 的 DEBUG/TRACE 运行方式进行隔离红测，发现 WebSocket 协议级调试日志可暴露请求行、认证头与消息内容，ASGI TRACE 可暴露 scope。候选丢弃 websockets 包发出的协议 DEBUG 记录和 `uvicorn.asgi` 的 TRACE 记录，保留 Uvicorn 通常的握手与状态日志；因此这两类低层调试信息将不可用。该处理不保证其他库或 logger、HTTP 代理、自定义 handler、其他服务器版本的日志安全。

## 当前范围与待验证项

- 本分支是待集成候选，独立复核包含 22 项自动化测试和额外真实 Uvicorn 隔离测试；结果只说明所测路径，不代表所有日志均已保护。
- 反向代理、网关、其他应用或库的 logger，以及已生成的历史日志未纳入本次验证。
- 真实 `/api/agents/events` 和 `/api/ws/discuss/{id}` 仅验证未认证拒绝；真实账号认证成功后的 SSE 与 WebSocket 业务流程尚未验收。
- `wsproto` 未纳入隔离测试，不能推断其调试输出受到当前过滤器保护。
- 查询过滤器仅识别代码中列出的敏感字段名；未知字段名、任意字段值中的凭据和其他格式的日志记录不在覆盖范围。
- 候选尚未合并、部署或进行生产环境验收。

## 121 部署兼容门

发布测试在 `121_billing_model_evidence` 的 reader 入口指纹检查处失败：原先 29 个固定模块中只有 `app/main.py` 与原指纹不同。与已核对的生产 4.1.53 提交 `38f181c86c3f74f40ce73c43ce73ff23b0f6a292` 对照，删除新增的日志过滤器导入和初始化调用后，入口的其余 AST 完全一致；其余 28 个固定模块的 AST 指纹未变。独立日志回归已检查过滤器的异常和连接行为，但指纹检查仍不能替代计费业务验收。

探针现在把 `main.py`、`core/error_handlers.py` 和新依赖 `core/uvicorn_log_filter.py` 作为完整版本组合校验，其他 28 个模块保持原精确指纹。允许的组合仅为已审计的生产 4.1.53 入口及旧异常处理器、且新过滤器文件不存在；或者当前候选的三个精确文件。新增测试拒绝缺失或修改依赖、混搭旧新文件、移除 API 路由及覆盖路由注册。旧组合获准仅表示通过 121 reader 兼容门，并不表示它包含本分支的日志修复；实际回滚及部署后的业务仍需另行核验。
