# 09 · 网络安全内容扩展

> 版本：v2.1.1 · 状态：设计中 · 起始日期：2026-05-28
> 衔接 [08-SecuritySentinelAgent设计.md](./08-SecuritySentinelAgent设计.md),
> 在 SecuritySentinel 已经能"扫"的基础上,补足"知识 + 态势 + 规则覆盖"。

## 一、立项动机

v2.1 SecuritySentinel 上线后,实际使用暴露出三个缺口:

| 缺口 | 现象 | 影响 |
|---|---|---|
| **规则覆盖不足** | 只有 12 类敏感信息正则,缺乏弱加密/HTTP 头/更多平台 token 识别 | 中等项目漏报严重 |
| **知识缺位** | 用户拿到 finding 上面写 `OWASP A03 / CWE-89` 但不知道什么意思 | 修复决策没依据 |
| **态势不可见** | 工作台没有"我的项目当前安全状况"的入口 | 用户需要逐项目点开才能看 |

v2.1.1 围绕**让 Prism 不光会扫,还会讲;不光给单点结果,还给全局态势**做能力补全。

## 二、目标与边界

## 三、扩展一:扫描规则扩充

### 3.1 新增敏感信息正则(12 → 20)

新增 8 类,集中在"主流 SaaS API token"和"OAuth 凭据":

| 名称 | 正则匹配 | CWE | OWASP |
|---|---|---|---|
| GitLab Personal Token | `glpat-[A-Za-z0-9_\-]{20,}` | CWE-798 | A07 |
| Heroku API Key | `[hH]eroku.{0,30}[\"'][0-9a-f]{32}[\"']` | CWE-798 | A07 |
| Discord Bot Token | `[MN][A-Za-z0-9_-]{23}\.[A-Za-z0-9_-]{6}\.[A-Za-z0-9_-]{27}` | CWE-798 | A02 |
| Telegram Bot Token | `\d{8,10}:[A-Za-z0-9_-]{35}` | CWE-798 | A02 |
| SendGrid API Key | `SG\.[A-Za-z0-9_-]{22}\.[A-Za-z0-9_-]{43}` | CWE-798 | A07 |
| Twilio API Key | `SK[a-z0-9]{32}` | CWE-798 | A07 |
| Mailgun API Key | `key-[a-z0-9]{32}` | CWE-798 | A07 |
| Square OAuth | `sq0(?:at|cs)p-[A-Za-z0-9_\-]{22,43}` | CWE-798 | A07 |

实现位置:`backend/app/ai/security_patterns.py`,沿用既有 `SecretPattern` 数据类。

### 3.2 静态语义规则:弱加密 + HTTP 安全头

正则只能识别字面 secret,**弱加密 API 调用** 和 **配置文件中缺失的 HTTP 安全头** 需要"形态识别"。新建 `backend/app/ai/security_static_rules.py`,定义:

```python
@dataclass(frozen=True)
class StaticRule:
    code: str          # 'weak_md5' / 'missing_hsts' 等
    name: str          # 中文名
    cwe: str
    owasp: str
    severity: str      # 默认严重度
    description: str
    fix_suggestion: str
    file_filter: tuple[str, ...]  # 仅在这些扩展名上跑
    pattern: re.Pattern
```

#### 3.2.1 弱加密规则(8 条)

| code | 命中 | severity | 适用扩展名 |
|---|---|---|---|
| `weak_md5` | `hashlib.md5(`, `MessageDigest.getInstance("MD5")`, `CryptoJS.MD5(` | 高 | py/java/js/ts |
| `weak_sha1` | `hashlib.sha1(`, `sha1sum`, `SHA-1` 标识符 | 中 | py/java/js |
| `weak_des` | `from Crypto.Cipher import DES`, `Cipher.getInstance("DES")` | 严重 | py/java |
| `aes_ecb_mode` | `AES.new(... AES.MODE_ECB)`, `"AES/ECB/"` | 严重 | py/java/go |
| `insecure_random` | `random.random` / `Math.random` 用于 token/password/key 上下文 | 高 | py/js/ts |
| `ssl_verify_disabled` | `verify=False`(requests), `rejectUnauthorized: false`(node) | 严重 | py/js/ts |
| `pickle_load` | `pickle.loads(`, `cPickle.loads(` | 严重 | py |
| `eval_user_input` | `eval(` 紧跟 `request.` / `input(` 的上下文 | 严重 | py/js |

#### 3.2.2 HTTP 安全头规则(5 条)

仅扫描 `.conf` / `.yml` / `.yaml` / `.toml` / `.nginx` / `nginx.conf` / `apache2.conf` 等:

| code | 缺失项 | severity |
|---|---|---|
| `missing_hsts` | `Strict-Transport-Security` | 高 |
| `missing_csp` | `Content-Security-Policy` | 高 |
| `missing_x_frame_options` | `X-Frame-Options` | 中 |
| `missing_x_content_type_options` | `X-Content-Type-Options` | 中 |
| `cors_wildcard` | `Access-Control-Allow-Origin: *` 同时 `Allow-Credentials: true` | 严重 |

规则触发逻辑:文件**必须是配置文件类**(file_filter 命中)**且至少出现 1 处 HTTP 头声明**(说明这是个 web 配置),才检查"是否缺失"——避免对普通 yaml 误报。

### 3.3 集成方式

SecuritySentinelAgent 新增 `_static_findings(file)` 内部方法,在 `scan_file` 流程的"正则后、LLM 前"插入:

```
file.content
  └─ scan_secrets()          # 正则秘钥
  └─ apply_static_rules()    # 弱加密/HTTP 头(新增)
  └─ _llm_findings_for_file  # LLM 语义审查(可被 quick 模式跳过)
```

三类来源在最终 finding 列表里通过 `source` 字段区分:`regex` / `static` / `llm`。

## 四、扩展二:Dashboard 安全态势 API

### 4.1 端点

```
GET /api/security/dashboard-summary?days=30
```

### 4.2 入参

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `days` | int | 30 | 统计窗口,1-365 |

### 4.3 出参

```json
{
  "user_scope": "self",            // self / global(admin)
  "project_count": 8,              // 用户范围内项目总数
  "scanned_project_count": 5,      // 近 days 天有过安全 finding 的项目数
  "avg_risk_score": 72,            // 平均风险评分(取最近一次审查得分)
  "severe_issues_total": 3,
  "high_issues_total": 9,
  "medium_issues_total": 12,
  "low_issues_total": 4,
  "owasp_hotspots": [              // OWASP 热点 Top5
    {"owasp": "A03:2021-Injection", "count": 12},
    {"owasp": "A02:2021-Cryptographic Failures", "count": 5}
  ],
  "top_risky_projects": [          // 风险评分最低的前 3 个项目
    {"project_id": 12, "project_name": "demo-api", "risk_score": 35, "severe_issues": 3}
  ],
  "trend": [                       // 按天/桶的严重问题数曲线(days 长度)
    {"date": "2026-05-01", "severe": 1, "high": 2},
    {"date": "2026-05-02", "severe": 0, "high": 0}
  ]
}
```

### 4.4 数据源

- 项目总数:`project` 表(过滤当前用户)
- finding 聚合:`review_issue.issue_type='安全漏洞' AND task_id IN (项目下所有任务)`
- OWASP 热点:从 finding 的 `description` 末尾 `<!-- meta: {owasp,cwe} -->` 注释中正则提取(本期保留 SecuritySentinel 写库时的兼容方案)。若注释缺失,降级用关键词推断(复用 `_infer_owasp_cwe`)
- 风险评分:沿用 `review_task.score`,无安全审查记录时显示 `null`

### 4.5 性能保护

- 同步执行 SQL,**只查不算**(不调用 LLM)
- 限制 `days ≤ 365`,数据库索引:`task_id` + `issue_type`(已有)
- 单次响应 < 500ms,超过 1s 在 loguru 中 warning

  name_en: string
  name_zh: string

  harm: string          // 30-100 字
  bad_example: { language: string; code: string }
