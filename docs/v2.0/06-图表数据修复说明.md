# 06 · 图表数据修复说明

## 一、问题清单（v1.0 → v2.0）

### F1 维度键值不一致

Dashboard 的 `dimMeta` 用 `maintain`，但后端可能返回 `maintainability`（AI 自由发挥）。`issueTypeLabels` 表已经做了一次映射，但 `dimSummary` 计算 `find((x) => x.key === d.key)` 时不会匹配上。

**修复**：在 `loadIssueTypeStatistics` 阶段做一次归一化：

```ts
const KEY_ALIAS: Record<string, string> = {
  maintainability: 'maintain',
  bug: 'logic',
  // 兼容旧/新两套
}

issueTypeData.value = data.map((item) => {
  const normalized = KEY_ALIAS[item.issue_type] ?? item.issue_type
  return { key: normalized, name: issueTypeLabels[normalized] ?? normalized, value: item.count }
})
```

### F2 dim_scores 兜底

`ReportDetail.vue`：当 `stats.dim_scores` 缺失时，所有维度被填成整体 score，雷达图变成一个正六边形假象。

**修复**：缺失时显示"暂无该维度数据"占位条，而不是回填同一个值。

```ts
const dimScores = computed(() => {
  const dim = (stats.value.dim_scores as Record<string, number>) ?? {}
  return dimKeys.map((k) => {
    const v = dim[k]
    return typeof v === 'number' ? Math.round(v) : null   // null 在 ECharts 中显示为缺口
  })
})

const hasDimData = computed(() => dimScores.value.some((v) => v !== null && v > 0))
```

### F3 review-frequency 边界日期

`dashboard_service.get_review_frequency` 把 0 计入返回，但 cutoff 是当前 UTC 减天数，前端 dayjs 用本地时区，跨天会丢一条。

**修复**：后端按用户时区裁剪，或前端 `format('YYYY-MM-DD')` 与后端 ISO 字符串严格比对（不要再用 `M/D`）。v2.0 选前端兼容方案：

```ts
frequencyData.value = data.map((item) => ({
  name: dayjs(item.date).format('M/D'),     // 显示用
  value: item.count,
}))
// 保留原始 date 用于 x 轴对齐
```

### F4 风险等级颜色映射不一致

`riskData.value` 的 `severity` 字段拿到的是中文严重度（"严重"/"高"...），而 `severityClass(item.severity)` 需要英文枚举 → key 映射。当 v1.0 部分历史数据用英文枚举存储时会失配。

**修复**：`severityClass` 已经在 v1.0 兼容了中英两套，但 `PRISM_SEVERITY_COLORS` 的 key 全是英文 → 加保护：

```ts
const colorOf = (sev: string) => {
  const key = severityClass(sev) as keyof typeof PRISM_SEVERITY_COLORS
  return PRISM_SEVERITY_COLORS[key] ?? '#9BA3B0'
}
```

### F5 仪表盘 stat-card 空数据时 delta 文案

`累计审查任务` 在 0 次时显示"▲ 较上月"，明显是假数据；`代码文件` 永远显示 `deltaDir: 'up'`。

**修复**：当对应值为 0 时，delta 改为 `—`，deltaDir 改为 `'flat'`：

```ts
delta: summary.value.review_count > 0 ? `▲ 较上月` : '—',
deltaDir: summary.value.review_count > 0 ? 'up' : 'flat',
```

### F6 Score Trend 评分轴反向

`getScoreTrend(6)` 返回的是按 create_time desc 后取 6 条再 reverse，但 `scoreTrendData` 名称用 `#${task_id}`，新审查的 id 大但显示在最右，符合预期。**这条已正确**，不需修复，仅在 v2.0 文档中标记为已审。

### F7 Agent 中心 usage 与运行时不同步

usage 表只统计 multi_agent 的 5 个 code（general/security/...），但 v2.0 真实 Agent 是 12 个。

**修复**：v2.0 中 usage API 改为按 `model_name` 解析后缀（沿用现有逻辑），但**新增**按 EventBus 实时统计（Redis 或内存计数器）的"近 1 小时"维度，独立于 AiCallLog。

## 三、归一化常量集中维护

新建 `frontend/src/constants/dim.ts`：

```ts
export const DIM_KEYS = ['style','naming','comment','maintain','performance','exception','logic','security'] as const
export type DimKey = typeof DIM_KEYS[number]

export const DIM_ALIAS: Record<string, DimKey> = {
  maintainability: 'maintain',
  bug: 'logic',
}

export const DIM_LABELS: Record<DimKey, string> = {
  style:'代码规范', naming:'命名规范', comment:'注释完整性', maintain:'可维护性',
  performance:'性能问题', exception:'异常处理', logic:'潜在 Bug', security:'安全漏洞',
}

export function normalizeDimKey(raw: string): DimKey | null {
  if ((DIM_KEYS as readonly string[]).includes(raw)) return raw as DimKey
  return DIM_ALIAS[raw] ?? null
}
```

各页面统一从这里 import，避免散落定义。
