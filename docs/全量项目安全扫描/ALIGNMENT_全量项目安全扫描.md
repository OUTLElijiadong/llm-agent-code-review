# ALIGNMENT_全量项目安全扫描

## 原始需求

用户希望安全扫描支持“整个项目一起扫码”，同时保留现有单个项目扫描能力。进一步补充：全量扫描需要包含接口扫描、项目代码联动性分析，并以多 Agent 讨论方式给出审查结论。

## 项目上下文

- 当前安全审计能力由 `SecuritySentinelAgent` 提供，已有 `scan_file`、`scan_task`、`scan_project` 三种粒度。
- 后端 API 位于 `backend/app/api/v1/security.py`，前端封装位于 `frontend/src/api/security.ts`。
- 前端扫描弹窗 `SecurityScanModal.vue` 已支持文件、任务、单项目三种来源。
- 安全中心 `SecurityCenter.vue` 目前主要展示规则、态势和跳转项目列表，未提供直接扫描所有项目的入口。

## 需求边界

### 本次实现

- 新增“全量项目安全扫描”能力：扫描当前用户可见的全部活跃项目。
- 保留单项目扫描：`scan-project` API 和项目详情页安全审计按钮继续可用。
- 全量扫描结果复用现有 `SecurityScanOut` 结构，聚合所有项目的 findings、风险评分、文件数、威胁模型摘要。
- 威胁模型需要包含接口清单 `api_endpoints`、代码联动关系 `code_links`、跨文件攻击路径 `data_flows`。
- 扫描结果需要输出非实时的多 Agent 讨论摘要 `discussion`，包含安全、可靠性、性能、可维护性和主持 Agent 的发言、共识与行动项。
- 普通用户仅扫描自己的活跃项目；管理员扫描全部活跃项目。
- 前端安全中心增加直接启动全量扫描的入口。

### 不做范围

- 不新增数据库表。
- 不把安全扫描结果强制落入 `review_issue` 表，沿用现有安全扫描即时返回模式。
- 不移除或替换单文件、任务复审、单项目扫描。
- 不改变 DeepSeek API Key 配置方式。

## 疑问澄清与决策

| 问题 | 决策 |
| --- | --- |
| “整个项目”是否指当前用户所有项目？ | 按产品语义解释为“当前账号可见的全部活跃项目”，不是单个项目。 |
| 是否还需要单项目扫描？ | 保留现有项目详情页入口和 `scan-project` API。 |
| 空项目如何处理？ | 全量扫描跳过无活跃代码文件的项目，在摘要中体现跳过数量。 |
| 输出结构是否新增专用结果类型？ | 复用 `SecurityScanOut`，降低前端改造和报告下载成本。 |
| 多 Agent 讨论是否复用实时圆桌 WebSocket？ | 本次在安全扫描结果中生成同步讨论摘要，不强耦合实时会话，避免全量扫描被长连接状态阻塞。 |

## 验收标准

- 后端提供全量扫描 API，可扫描当前用户可见项目。
- 普通用户不会扫描他人项目。
- 全量扫描可识别常见接口定义和前端 HTTP client 调用。
- 全量扫描可输出接口到危险接收点、跨文件数据流的代码联动关系。
- 全量扫描可输出多 Agent 讨论摘要、共识和行动项。
- 安全中心可直接启动全量项目扫描。
- 项目详情页单项目扫描仍可用。
- 后端测试、前端类型检查和构建通过。
