## 复现与修复证据

1. 候选去重曾把围栏内的 `###` 误识别成问题标题，删除重复块后会留下不闭合代码围栏并吞掉后续报告章节。加入重复问题章节、围栏伪标题回归；修复后保留七个必需章节。独立复核另以三反引号、四反引号及 `~~~` 围栏检查，均保持闭合；错误长度的围栏关闭会被完整性门禁拒绝。
2. 不同候选各自含相同的 `### 证据` 字段时，旧去重逻辑会删除后一候选的证据。先运行新回归确认失败，再令去重仅以真实、非字段 H3 作为发现边界；修复后两个发现和两份证据均保留。
3. 报告总结合并曾以正则定位下一个 `##`，会把总体结论代码块中的伪 H2 当作真实章节边界。先运行回归确认伪章节泄漏，再以围栏感知的 Markdown H2 偏移定位并替换真实总体结论；修复后真实白盒/黑盒章节保留，伪章节不泄漏。
4. 多 Agent 黑白盒报告必须具备七个非空章节和完整成功角色清单。模型输出不完整、不可用或出现报告阶段异常时，生成确定性执行报告并保存 `ai_review.status=incomplete` 与原因；报告持久化失败明确返回失败回执，不伪造已保存。
5. AI 报告中的发现统一作为“未核实候选”，不进入已确认问题计数。报告的执行覆盖与 AI 生成状态分别呈现；历史缺少状态时显示“未知”。报告读取权限不放宽。
6. 新增占位内容门禁：已复现仅有 `x`、空标点、空复选框、`TODO/N/A` 扩展占位语句、`待复核/生成中/模型未给出` 等内容会被误判为完整。修复后这些样本全部拒绝；真实说明及“问题清单：无问题”仍接受。
7. 标准审查与圆桌共用的发现合并器曾允许模型提交无效行号/伪造锚点；新增源代码证据校验，唯一精确原文可重定位，重复原文标为位置歧义，越界且无可核验证据的条目标记待复核。安全声明即使被模型标成“其他”也强制待人工复核。独立复核先复现 IDOR/跨租户与动态 SQL 用户输入拼接两类漏判，随后补入英文词形和中文拼接线索回归；旧逻辑未标待复核，修复后全部进入待复核。性能风险对照样本仍不被误归为安全漏洞。
8. 源码缺失时，模型原始高置信度曾与“证据不足、待复核”并存。0.99 置信度回归先失败，再按证据等级限制置信度，并同步限制 Agent 来源明细中的置信度；修复后来源不可用的安全问题最多显示 0.45，只有直接证据未核验的声明最多显示 0.80。NaN/Inf、负值与超上限值也经有限数值校验，不能绕过证据等级封顶。
9. 圆桌最终落库曾把待复核问题保存成普通“未修复”，且遗漏证据质量、冲突状态和聚合依据。新增真实内存 SQLite 落库回归，旧逻辑实得 `unfixed`、新逻辑保存为 `pending_review` 并保留复核元数据。
10. Worker 执行异常及受授权远程探测超时曾只留下沙箱失败状态、没有审查报告记录。分别以 Worker 超时和远程探测超时复现；旧 Worker 场景找不到报告任务，新逻辑生成明确“验证未完成”的失败报告并记录失败阶段。取消任务仍遵循取消语义，不伪称生成完整报告。
11. 报告明细接口加载失败曾可能被页面当成空问题列表；现在区分无权限、加载失败与成功加载，失败时显示重试提示而不把统计显示成零。分页统计必须读完接口宣告的总数，否则展示加载失败。
12. 独立复核发现模型可在 `source_details` 中提交伪造 `source_anchor`，即使主锚点已重建，该伪值仍会进入 API 元数据。删除模型来源明细中的锚点后，仅由合并器补入已核验主锚点；新增伪锚点回归验证了输出来源明细与主锚点一致。
