# 共识：审查与黑白盒报告可信度

## 需求与验收

- 普通代码审查的 Agent 覆盖或证据聚合不完整时，任务不能被记作完整成功；保留失败原因与覆盖信息。
- 沙箱报告只在执行回执和报告结构完整时显示对应完成状态。模型候选与已确认问题分区，未复现候选不进入已确认问题统计。
- Markdown 章节解析忽略围栏代码中的伪标题；支持编号标题、重复标题、混合列表/标题、空清单和已有候选段；重复候选合并后数量与页面显示一致。
- AI 模型不可用或输出不完整时生成确定性报告，并同时保存 AI 审查未完成状态和可理解原因；报告持久化失败明确返回失败状态，不伪造成功。
- 报告详情和列表分别展示执行验证覆盖与多 Agent AI 报告生成状态。历史未记录状态显示未知。
- 报告读取继续执行现有所有者/管理员与项目权限校验；不以“可查看”为由放宽权限。

## 技术约束

不改数据库结构；复用现有 `ReviewTask.coverage`、`ReviewReport.content_json`、报告来源字段与 sandbox artifact。发布必须来自干净精确 SHA，通过现有 `deploy/deploy.sh all` 完成。
