# 对齐：审查与黑白盒报告可信度

## 原始需求

“确保所有代码审查报告正确，黑白盒报告正确，不要出现任何做不了的情况出现。”

## 范围与边界

本次核查普通代码审查的证据聚合与失败状态路径，以及沙箱白盒、黑盒、黑白盒组合报告的生成、统计、持久化、权限读取和前端状态提示。AI/供应商或数据库不可用时，报告应尽量回退为确定性执行报告并标明 AI 审查未完成；不得把模型候选写成已确认漏洞，不得把局部或未知覆盖标成完整通过。

第三方模型、网络、数据库、存储或权限被撤销时不能承诺“永不失败”。验收目标是已执行范围有可读结果、失败原因可追踪、报告统计不把未知算作零、没有证据时不冒称通过；持久化基础设施完全不可用仍可能无法生成可访问报告。

## 项目理解

标准代码审查由 `review_service` 编排静态规则与 Agent 结果，再通过确定性证据聚合及覆盖门禁落库。沙箱报告由 `sandbox_service` 汇总执行回执与模型报告，`sandbox_report_summary` 解析报告条目，`report_service` 提供列表/详情，Vue 报告页呈现验证覆盖与报告状态。

## 尚未确认项

无。生产发布仍需精确提交、备份/恢复、镜像构建、迁移与健康门禁；本机测试不等于生产验收。
