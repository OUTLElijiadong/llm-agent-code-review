# CONSENSUS_v3.9.6安全规则与全项目闭环20260918

## 需求共识

v3.9.6 不再继续堆叠相似页面或平行规则表，而是建立一个用户可理解、系统可核对的安全审查入口。合并的是展示、导航和事实目录，不是把不同执行机制强行改成同一张数据库表。

## 实现合同

### 统一页面

- 新页面标题为“安全与审查规则”。
- 标签页至少包含“安全态势”“审查规则”“规则基座”。
- `/security` 按 query 恢复标签；`/rules` 仅做兼容重定向。
- 菜单、全局搜索、页面引导、角色首页白名单和能力注册统一更新。

### 统一规则目录

- 目录项包含：稳定标识、名称、类别、语言、严重度、来源、执行器、是否可执行、可用状态、CWE/OWASP 映射和权威来源 URL。
- DB 审查规则仍由 `/api/rules` 管理；平台静态规则继续由代码实现；CodeQL 由 GitHub Actions 扫描本仓库。统一 API 只做查询聚合，不制造双写。
- CodeQL 工作流固定官方 Action 提交版本、语言与 `security-extended` 套件；平台目录不得把仓库 CI 或本机 CLI 探测冒充用户上传项目的执行结果。

### 输入安全矩阵

- 从 OpenAPI、Pydantic Schema、文件上传和外部 URL 输入生成清单。
- 测试分类：SQL 参数化、HTML/Markdown 输出净化、模板边界、命令参数、路径归一化、SSRF 允许范围、文件类型/大小、长度、控制字符与 Unicode。
- 不能安全自动执行的用例标明原因，不用“覆盖完整”掩盖缺口。

### DeepSeek 全项目闭环

- 每次运行先冻结文件清单和内容摘要。
- 普通审查在任务 `coverage.files` 中记录每个文件的总分片、成功分片索引、失败分片和错误；完整项目安全扫描继续使用既有自适应拆分与字符核账。
- `finish_reason=length`、无效条目和解析不完整先按更高输出预算重试；仍失败则继续后续分片/文件并把任务标成覆盖不完整。进程恢复仅保留状态为 `complete` 的文件，其余文件重跑。
- 总结只消费成功分片，并显式携带覆盖比例与未完成项；预算不足时停止新分片但保留已完成结果。

### 数据治理与重复功能

- QA 数据通过可识别前缀、创建批次、关联审计和所有者证据确定；删除优先软删除，执行前后重算。
- 演示账号和历史业务数据没有充分证据时不删除。
- 重复功能按数据源、写权限、业务目标、受众和审计要求五项判断；五项一致才合并，否则改名或建立统一入口。

## 质量门禁

- 先测试后实现；每个修复有回归用例。
- 变更文件 Ruff/ESLint，后端/前端全量测试，`vue-tsc`、Vite 构建和 `git diff --check` 全绿。
- 实际外部引擎/模型验收必须保存脱敏机器证据；模拟测试不能替代生产实跑。
- 发布过程保持前后端同一不可变 SHA，备份可恢复，公网 health/ready 与浏览器验收一致。
