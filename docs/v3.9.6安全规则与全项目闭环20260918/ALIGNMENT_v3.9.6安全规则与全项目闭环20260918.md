## 原始需求

在 v3.9.5 已完成角色收敛、双人渗透授权和小菱账号隔离的生产基线上，继续关闭以下遗留项：

1. 合并“安全中心”和“审查规则”，保留旧链接兼容。
2. 引入有权威出处且能够实际执行的代码审查规则基座；CNVD/CNNVD 作为漏洞情报与中文分类来源，不冒充静态分析引擎。
3. 对全站输入建立可重复执行的防御性测试矩阵，覆盖参数化查询、上下文输出编码、文件与 URL 边界、长度和 Unicode。
4. 完成 DeepSeek 全项目审查的覆盖账本、截断续跑和真实有预算回归。
5. 治理生产测试/演示数据，不把无法确认归属的数据直接删除。
6. 普查用户端与管理端重复页面、路由、API 和权限语义，能合并的合并，语义不同的保留并说明。

## 范围与边界

### 本轮实现

- 新建统一“安全与审查规则”页面，以标签页区分安全态势、规则管理、规则基座/来源；旧 `/rules` 兼容跳转到统一页面。
- 后端提供统一规则目录，把可编辑审查提示规则、平台静态规则、敏感信息规则和外部引擎能力放在同一事实模型中，但保留各自执行语义。
- 以 GitHub CodeQL `security-extended` 套件作为本仓库 CI 的权威可执行规则基座；平台目录只展示实际 CI/CLI 能力状态，不把“发现 CLI”标成产品扫描可执行。平台上传项目的 CodeQL CLI/SARIF 接入不在本轮伪造完成。
- 新增面向 API Schema 和高风险接收点的输入安全合同测试与覆盖清单；特殊字符按业务允许列表、参数化查询和输出编码处理，不做破坏业务数据的全局过滤。
- 为全项目审查增加确定性文件清单、每文件/分片状态、重试次数、完成原因和缺口清单；截断不能标记成功。
- 对明确命名、明确来源的 QA 临时数据执行可回滚治理；存疑演示账号只标记、隔离或列待确认，不直接删除。
- 生成重复功能矩阵，优先完成无歧义的路由收敛；涉及不同数据域或审批职责的页面不因标题相似而强行合并。

### 明确不做

- 不对未获授权的第三方网站发起主动探测。
- 不把 CNVD/CNNVD 编号虚构到代码弱点规则；没有官方接口/数据授权时不抓取或伪造漏洞实例。
- 不以“加大到 1M 上下文”代替分片、续跑、覆盖核对和费用门禁。
- 不删除归属不明的生产账号、项目、审查记录或 Agent 数据。

## 已解决的关键决策

| 决策点 | 结论 |
| --- | --- |
| 版本 | 采用 `v3.9.6`，作为 v3.9.5 的兼容性收敛版本。 |
| 单页结构 | `/security` 为唯一导航入口；`/rules` 兼容跳到 `/security?tab=rules`。 |
| 规则事实源 | 统一目录，不混淆三类执行器：提示规则、平台静态规则、CodeQL 外部规则。 |
| 权威执行基座 | CodeQL；默认高精度套件可用，扩展套件由用户选择并明确误报权衡。 |
| 中国漏洞库 | 作为来源、分类和情报映射层；以 CWE/CVE 为桥，不当作源码扫描器。 |
| 特殊字符 | 不做全局删除；在服务端按字段限制、危险接收点安全 API 和输出上下文处理。 |
| 生产数据 | 证据充分才清理；其余只隔离、标记或进入待确认清单。 |

## 当前阻断事实

Codex Security 深度扫描插件返回：`Deep Scan cannot safely start a read-only worker: the parent must provide a managed filesystem permission profile.` 本轮不把该插件结果声明为已完成；使用项目测试、CodeQL/本地静态执行和独立子代理复核补足可执行验证，并在最终验收中保留这一工具环境边界。

## 验收标准

- 统一页面只有一个主导航入口，旧路由可达正确标签页，权限与浏览器前进/后退行为正确。
- 统一规则目录的数量、来源、执行器、版本和可用状态均可核对；CodeQL 仅显示实际 CI 配置/CLI 探测结果，不显示假产品执行能力。
- 输入安全矩阵覆盖本轮识别的高风险接收点，自动化用例能证明服务端长度约束、ORM 参数化、输出净化和文件/URL 边界；未逐项动态攻击的普通字段保留为明确测试缺口。
- 全项目回归能给出文件总数、已完成数、失败数、重试数和缺口，任何截断不会被计为成功。
- 数据治理有清单、来源、动作、恢复办法和操作后重算。
- 后端全量、前端全量、静态检查、类型检查、构建、迁移与发布门禁全部通过。
- 生产发布前有数据库备份和恢复校验；发布后以公网 API 和真实浏览器截图验收。
