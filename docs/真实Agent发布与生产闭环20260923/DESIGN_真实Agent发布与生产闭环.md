# 真实 Agent 发布与生产闭环设计

```mermaid
flowchart LR
  S[审查员 工坊] --> D[(草稿与版本)]
  D --> T[静态契约校验]
  T --> A[(审批单)]
  A --> M[管理员 审阅与发布]
  M --> C[(发布快照与目录)]
  C --> I[真实源码模型调用]
  C --> X[小菱团队编排]
  I --> R[问题与用量证据]
  X --> E[成员事件与会话历史]
  R --> V[三账号及界面验收]
  E --> V
```

## 接口与权限

- 创建、测试、提交：现有 Agent 工坊接口，草稿按所有者隔离；测试为静态检查。
- 发布：仅有 `agent_asset:publish` 的管理员处理精确的 Agent 发布审批单；审批动作必须验证审批单类型、资源和目标版本。
- 调用：已发布目录及 `invoke_published_agent` 复用相同运行服务，服务层再次检查 `custom_agent:invoke`。
- 团队：小菱 `create_agent_team` 以精确的 `custom:<code>` 和已发布快照创建可追踪成员；成员失败应显式记录，不以最终摘要代替运行轨迹。
- 已发布审查成员的输入：建队时必须提供非空 `code`，或同时提供当前账号可见的 `project_id`、`file_id`。文件模式在创建、模型调用前及结果回传前复核项目归属、文本类型、权限、团队租约、源码哈希及文件名/语言/状态；源码仅在执行时读取，不复制进团队持久化输入。
- 临时成员：输出截断时在同一任务内复核权限，使用精简输出契约最多补调用一次；两次请求分别记用量。仍截断则明确失败，不在团队外层原样重试，也不将部分文本冒充完整结论。
- 文件定位：`list_code_files.keyword` 使用已有文件名查询，仍由现有项目访问校验限制范围。
- 报告手机布局：封面区分项目主语言和实际审查文件语言；窄屏封面改为单列，表格放在可聚焦的横向滚动容器内，打印时恢复完整展示。

## 异常与证据

归档会话的心跳 409 应收敛该会话而继续其他收件箱；首次恢复的浮动窗口应定位在视口内。异常退出后按服务器会话与消息重建，不凭本地旧索引推断持久化成功。UI 截图、可核对的对象 ID、运行提交与实际模型响应分开保留。
