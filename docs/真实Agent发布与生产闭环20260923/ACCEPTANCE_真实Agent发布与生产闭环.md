## 已复现或确认的缺陷与边界

- 生产 v4.0.2 的专用发布、通用审批、管理员工具和修订入口缺少一致的目标校验；本地在共享服务层与入口处封堵，篡改时返回 409 且不改变数据，生产仍待发布后验证。
- 归档会话心跳 409 可中断其他会话同步，恢复归档与旧目录并发时可丢失目标会话；登录恢复时小菱浮窗可能首次未定位。本地已修复并加入并发回归，生产仍待发布后验证。
- 已发布 Agent 的修订草稿与待审状态曾使旧版无法加入团队；发布新版又使旧团队固定旧快照返回 404。本地已按真实 v1→v2 服务流程修复与回归，生产仍待发布后验证。
- 管理员“发布审批”页签误走旧 `/admin/agents` 路由，重定向到 Agent 目录；本地已修复并加入导航回归。
- 旧登录型 E2E 把实际账号口令写在已跟踪文件，并使用固定项目编号；本地已移除明文默认值，且只允许显式配置、本机隔离、后端 `/healthz` 标记为 `dev` 时运行。既有 Git 历史可能保留旧口令，需在完成验收后由账号持有人轮换。
- `agent_delegate` Skill 不启动独立成员；本轮团队验收必须检查独立运行事件。
