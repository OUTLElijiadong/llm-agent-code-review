# v4.0.107

## 报告可信度与失败兜底

- 普通审查和圆桌统一校验模型发现的源码行号、原文证据及安全声明；IDOR/BOLA、跨租户、动态 SQL 与用户输入拼接等安全线索不会因被标成“其他”而绕过人工复核。模型提交的来源锚点会丢弃，只保留源码核验后重建的锚点；定位不明的发现进入待复核，证据不足或置信度非有限时按证据等级封顶。
- 黑白盒报告会将重复问题清单、编号标题和混合列表/标题统一解析；围栏代码中的伪标题不参与发现统计。
- 未经执行回执或人工复现确认的模型发现只保留在“AI 候选发现（未核实）”区；精确重复候选只显示一次，已确认问题统计不受候选污染。
- 多 Agent 报告章节或角色执行清单不完整、模型不可用时，发布确定性执行报告并保存 AI 审查未完成状态和原因。
- 报告详情 API、列表和详情页分开呈现执行覆盖与 AI 报告生成状态；旧报告状态未记录时显示“未知”。
- 保持既有报告所有者、管理员与项目访问权限；不因修复报告可见性而放宽授权。

## 验证

候选与标准代码审查回归、前端组件测试、Lint、Python 编译及生产构建结果记录在本版本任务验收文档。生产健康与实际报告页面验收仅在发布后填写；本文件本身不代表生产已经部署。
