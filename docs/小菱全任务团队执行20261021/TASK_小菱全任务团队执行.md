# 小菱全任务团队执行任务拆分

## T1：生产基线和历史问题复现

- 输入：生产 4.1.15、公开健康信息、只读 SSH。
- 工作：对账源码 SHA、镜像 tag、容器健康、发布容量与迁移/备份信息；复核已有历史复现记录。需要用户登录态的行为单独标为待验证。
- 输出：生产基线证据和问题范围；不读取密钥，不清理服务器数据。
- 门槛：SSH 可读但用户页面未登录时，只完成只读基线；不得把登录态 UI 标成已验收。

## T2：全任务协调器执行门

- 依赖：T1 的精确 4.1.15 SHA。
- 工作：协调器工具白名单、直接业务工具拒绝、单根团队归因、团队终态证据门禁；确定性派发回执避免无意义模型重试。
- 输出：普通请求和 task.result 后续汇总的正反向回归用例。

## T3：团队成员合同

- 依赖：T2。
- 工作：补齐有界普通文字 worker、注册页面只读 worker 路径；确认领域 Agent contracts 与权限；缺失合同返回明确 blocked，不提供通用网络/命令执行。
- 输出：固定输入/输出合同、权限及租约检查和审计证据。

## T4：团队 UI 与临时成员保留治理

- 依赖：T3。
- 工作：新团队自动展示真实成员和派发 instructions；实现临时成员合同指纹/复用记录，复用达到审慎门槛时生成治理候选，保留需通过既有 Agent Release 链。
- 输出：运行中/完成/阻塞/停止状态可区分，候选保留理由可追溯。

## T5：评分、报告、圆桌问题修复

- 依赖：T1 的逐项复现。
- 工作：基于既有评分来源和报告账号归属修复显示；不删业务历史。圆桌修复需区分显式用户停止和系统中断。移除用户指定的 OWASP 热点说明句。
- 输出：分别绑定真实任务/报告 ID 的验收结果；权限不匹配项目默认隐藏。

## T6：发布与生产验收

- 依赖：T2–T5。
- 工作：通过正式部署脚本创建并验证生产备份/回滚点，发布后检查镜像/版本/迁移/健康/台账；待用户登录后，再验收报告页、Agent 团队行为、圆桌行为和逐页布局。
- 输出：分别记录服务器发布验收与未完成的登录态 UI 验收。GitHub 推送失败不作为验收终止条件。
