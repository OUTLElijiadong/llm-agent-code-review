# 共识：Responses 审批闭环

## 验收标准

1. 对明确修改平台共享/默认模型配置的请求，允许进入现有高风险审批流程；仅选择当前任务模型或讨论模型名称，不得被解释成全局配置修改意图。不清楚时先澄清。
2. 审批关联 payload 或 resource 任一指向持久化 Responses run 时，通用批准和驳回均返回拒绝，且审批状态与 run 状态不变。
3. 审批列表用批量查询识别会话关联项，避免逐条 N+1 查询；界面引导回到原小菱会话处理。
4. 没有关联持久化 run 的旧式审批继续兼容现有通用流程。
5. #234 只读复核，不将生产事项当测试夹具，不批准、不驳回、不触发配置变更。
6. 定向和全量测试、前端 lint/build、后端 Ruff 通过；精确 SHA 发布后核对健康、版本和审批状态。

## 技术约束

复用既有审批 API、`AgentResponseRun`、治理列表 schema 和小菱对话路由，不创建并行审批接口或新的数据库结构。发布沿用 `deploy/RELEASE_CHECKLIST.md` 的精确 SHA、备份/恢复和同版本前后端流程。

## 明确保留

测试通过不代表模型理解零幻觉，也不代表生产审批已被处置。其他待验范围按主审计 TODO 保留。
