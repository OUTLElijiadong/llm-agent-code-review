# 需求对齐：Responses 审批闭环

## 原始需求

外部检查报告指出，审批中心有一项危急的“更新并应用全局 LLM 配置”审批，用户表示不是自己触发，要求查明并避免其被误处理；并指出审批与小菱会话的执行闭环需要可靠。

## 项目理解

Responses 高风险工具审批可关联持久化 `AgentResponseRun`。若管理后台的通用审批接口只修改审批行状态而未恢复对应会话，审批会显示已处理而工具调用仍停在等待状态，形成状态分裂。运行关联可能分别记录在 `request_json.run_id` 和 `resource=response_run:<id>`。

## 范围和边界

- 修复模型意图提示、后端通用审批决策、审批列表标记和管理界面动作。
- 对已关联持久化 Responses run 的审批，必须回到原小菱会话续跑；通用批准/驳回接口不得单独改变其状态。
- 同时检查 payload 与 resource 两个关联字段，任一字段命中持久化 run 即按会话审批处理。
- 保留没有持久化会话的历史审批兼容行为。
- 对生产审批 #234 只读追踪；本任务不批准、不驳回、不执行全局配置修改。
- 其他审批治理、完整模型幻觉保证和全部生产业务流程不在本次交付范围。

## 已知限制

提示词不能证明模型永不误判；后端审批门和原会话续跑路径才是执行约束。需分别记录隔离测试与生产只读证据。
