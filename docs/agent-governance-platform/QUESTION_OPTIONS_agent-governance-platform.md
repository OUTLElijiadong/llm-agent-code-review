# QUESTION_OPTIONS_agent-governance-platform

> 用途：确认进入 Consensus 前必须明确的关键边界。  
> 请直接回复一串编号，例如：`Q1-B Q2-B Q3-B Q4-A Q5-B Q6-B Q7-B Q8-A Q9-B Q10-B`。

## 推荐组合

`Q1-B Q2-B Q3-B Q4-A Q5-B Q6-B Q7-B Q8-B Q9-B Q10-B`

说明：保持你选择的高自动化方向，但把策略引擎失败、生产代码修改、外部凭证、跨 Agent 知识读取这几类高风险点收住。

## Q1. 高风险系统操作定义

- `Q1-A` 仅权限变更、删除数据、生产配置变更算高风险。
- `Q1-B` 权限变更、删除数据、生产配置、业务代码修改、prompt/skill/策略修改、shell、外部 API、批量知识入库都算高风险。推荐
- `Q1-C` 所有影响其他用户、其他 Agent 或生产数据的动作都算高风险。

## Q2. E4 全自动自我进化是否立即生效

- `Q2-A` 全部立即生效，仅保留审计和回滚。
- `Q2-B` 知识和个人记忆可立即生效；prompt/skill/策略自动生成新版本，灰度生效并可回滚。推荐
- `Q2-C` 所有进化先进入沙箱试运行，通过评估后自动生效。

## Q3. Agent 修改业务代码

- `Q3-A` 默认允许直接修改业务代码。
- `Q3-B` 允许生成补丁和 PR/变更提案，真正写入业务代码需策略允许或管理员确认。推荐
- `Q3-C` 禁止 Agent 修改业务代码，只能给建议。

## Q4. shell / 本地命令执行

- `Q4-A` 默认经过策略引擎；读命令自动放行，写命令/危险命令阻断或升级。推荐
- `Q4-B` 默认允许执行，执行后审计。
- `Q4-C` 默认禁止，只有管理员手动授权。

## Q5. 策略引擎不可用或判断失败时

- `Q5-A` 执行优先，记录策略失败。
- `Q5-B` 阻断优先，进入审批或告警。推荐
- `Q5-C` 根据动作风险：低风险执行，高风险阻断。

## Q6. 每日抓取来源配置

- `Q6-A` 仅抓项目代码、项目文档、现有 docs。
- `Q6-B` 抓项目代码、项目文档、官方文档、指定 URL、GitHub issue/PR；外部来源由管理员配置白名单。推荐
- `Q6-C` Agent 可自行发现和扩展抓取来源。

## Q7. 抓取内容入库策略

- `Q7-A` 全部自动入库。
- `Q7-B` 低风险自动入库，高风险/低置信/外部未知来源进入审批。推荐
- `Q7-C` 全部先进入暂存库，自动蒸馏但不进入正式知识库。

## Q8. Agent 知识库隔离

- `Q8-A` 完全隔离，Agent 不能读取其他 Agent 知识库。
- `Q8-B` 默认隔离；允许通过策略引擎授予只读共享知识域。推荐
- `Q8-C` 所有 Agent 可共享全局知识库。

## Q9. 奖励/惩罚影响范围

- `Q9-A` 只记录分数，不影响行为。
- `Q9-B` 影响调度优先级、预算、自动审批阈值、是否降权，但不直接封禁。推荐
- `Q9-C` 可自动封禁工具、停用 Agent、回滚版本。

## Q10. 告警通知方式

- `Q10-A` 只在管理后台显示。
- `Q10-B` 管理后台 + 系统审计 + 可扩展 Webhook 配置。推荐
- `Q10-C` 管理后台 + 邮件 + Webhook + 短信/企业微信等外部通知。

## Q11. 知识库表设计

- `Q11-A` 复用现有 `knowledge_doc/knowledge_chunk`，增加 `owner_type/owner_id`。
- `Q11-B` 新增 Agent 专用知识库表，避免破坏个人知识库。推荐
- `Q11-C` 两者并存，并增加统一检索视图。

## Q12. 调度实现

- `Q12-A` 项目内轻量调度表 + 后端启动时周期扫描。
- `Q12-B` 先做任务表和手动触发，定时由系统 cron / Docker cron 配置。推荐
- `Q12-C` 引入 Celery/Redis 或 APScheduler。

## Q13. 真实 OpenClaw / Hermes 依赖

- `Q13-A` 本期只做项目内概念抽象，不接外部依赖。推荐
- `Q13-B` 预留接口，后续你提供链接后再接。
- `Q13-C` 本期必须接入真实项目，需要提供仓库或文档。

## Q14. 管理端入口与用户端隔离方式

- `Q14-A` 同一个前端应用内做独立 AdminLayout：管理员登录后进入 `/admin/overview`，左侧只显示管理后台菜单；普通用户仍走 `/dashboard` 和用户端菜单。推荐
- `Q14-B` 共用现有 AppLayout 和 `/dashboard`：管理员仍能看到普通业务菜单，只是多显示管理菜单。
- `Q14-C` 完全独立管理应用：新增单独 admin 前端入口/构建/部署，例如 `/admin-app` 或独立子域，和用户端运行时隔离。
- `Q14-D` 严格后台模式：管理员账号只能访问 `/admin/**`，不能访问项目、代码、报告、论坛等普通用户页面。
