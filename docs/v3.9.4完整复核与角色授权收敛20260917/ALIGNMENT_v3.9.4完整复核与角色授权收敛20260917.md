# v3.9.4 完整复核与角色授权收敛对齐文档

## 原始需求

复核 v3.9.4 相对 v3.9.2 是否完整修复生产问题；以生产页面、数据库、版本和测试证据核实。角色仅保留普通用户、评审员、管理员以及不可分配的唯一超级管理员；审计员并入评审员，评审员负责自定义 Agent 和独立审批渗透授权。将证据截图和未完成事项置顶写入个人知识库，并在范围内修复确定的高优先级缺口。

## 边界

- 基线：`c03ef264cba831af0e7bbd9a4e96f47158fa6f4e`（本地 v3.9.2 基线）。
- 被审版本：`2b26fbc30d701ff72cdf9bb04b501ecf22121c33`（生产 v3.9.4）。
- 当前修复：在 v3.9.4 工作树上实现，发布前必须另行形成新版本号和不可变提交。
- 公网远程目标仍只登记授权范围，不在本轮开放主动探测。
- 不把“页面出现”或“单元测试通过”表述为生产端到端通过。

## 已确认业务规则

1. 角色集合为 `user/reviewer/admin/super_admin`；`auditor` 合并到 `reviewer`，不再独立展示或分配。
2. 普通用户可创建渗透委托和确认自身资产/规则声明，但不能自我批准。
3. 评审员及以上可查看待授权委托并批准；申请人获批后才能启动。
4. 小菱会话以服务端当前账号发现结果为事实源；无法证明归属的旧浏览器缓存不得迁入任意账号。
5. 生产修改前备份，发布后用真实角色、负向 403、重登恢复和数据库状态共同验收。

## 当前事实

- 生产版本、镜像、健康接口与 Alembic 均为 v3.9.4 / `052_user_password_len`。
- 生产仍有 5 个内置角色，安全中心与审查规则仍为两个页面，且仍有 `qa_*` 账号数据。
- v3.9.4 新增的裸会话迁移会把无法证明归属的旧缓存复制到当前账号，构成跨账号泄露窗口。
- v3.9.4 的 legacy `set_role` 会保留审计员/自定义附加角色，降级不完整。
- v3.9.4 仍由申请者自签并启动渗透测试，没有独立审批人字段和权限。
