# 圆桌讨论持续会话与压缩：需求对齐

## 原始要求与证据

用户要求继续完善生产圆桌：多 Agent 圆桌共同分析优化；展示真实进度；后台运行时从页面任意位置再次唤起并可随时发送消息；规定结束后的五分钟对话窗口；大量内容应压缩处理而非直接截断。2026-09-24 的 390×844 Safari 截图显示：标题和轮次被头部按钮挤成竖排，讨论显示“已结束”，输入被禁用，`dashboard_routes.py` 的报告整理因 `finish_reason=length` 失败。

用户随后进一步明确：小菱本身也必须压缩过长对话上下文，不能只因输入历史或模型输出过长就静默截断。这个要求覆盖小菱工具循环、读取圆桌历史、持久化回答和再次打开会话的完整链路。

当前生产发行代码为 v4.0.6 `c86a7483aec160b2aa55c8e3195a3ad26d813387`。本任务以包含该代码的独立工作树为基线，不修改旧的默认脏工作树。截图和历史文档用于定位，不能单独证明修复后的行为。

## 项目现状

- 前端圆桌面板挂在 `AgentCenter.vue`；路由查询参数清除后，换页或关闭面板缺少稳定的重开入口。
- `AgentDiscussionPanel.vue` 的头部在 390px 仍为单行 flex，操作按钮挤压标题；目前只有轮次文字，没有汇总、抽取及报告落库进度。
- `DiscussionBus` 将会话、消息和控制回调放在进程内存；当前 WS 用户输入在确认会话可接收前先广播，结束后可能出现看似已接受、实际未处理的消息。
- `_extract_issues` 把完整源码和全部讨论一次交给结构化 JSON 抽取；当前调用未设置阶段专属输出预算，默认 4096 token，`finish_reason=length` 使整份报告整理失败。
- 当前已有圆桌续会服务，但返回的部分 `open_path` 缺少前端要求的 `discuss_agents` 参数；上一轮结论/纠正还存在固定字符截取。
- 小菱的旧上下文投影使用静态条目预览，长用户约束及工具结果末尾可能被裁掉；模型 `incomplete/length` 的处理、持久化工具结果与公开响应也需分别核查，不能把“原始历史存着”误称为“模型看到了完整语义”。

## 边界与验收方向

1. 布局：320/390/768/桌面均不得出现标题、轮次、状态和操作按钮互相挤压或遮挡；参会者、消息和输入可滚动且可点击。
2. 进度：只能展示服务端真实阶段及已完成数量；中断、失败和部分报告必须与成功明确区分，不以定时器伪造百分比。
3. 生命周期：换页、收起、刷新及短时断线后可重开当前账号有权访问的圆桌，输入由服务端状态和权限校验，不能因客户端伪造状态写入历史。
4. 压缩：保留原始源码、发言及证据锚点；按预算分批提炼或压缩供模型处理，输出不完整时不得把部分 JSON 当完整问题清单。需要可复核的批次覆盖与失败记录。
5. 验证：先复现截图中的移动错位与报告抽取失败，再做单元/集成/浏览器回归；发布后用真实生产圆桌、手机视口和多次重复样本复验，并记录模型用量与失败反馈。
6. 小菱对话：原始消息与工具结果完整保留；省略历史需要经语义压缩并带来源锚点，长消息的尾部和后来的用户更正必须进入压缩输入。模型输出达到上限时安全增加预算或续写，仍不完整则显式标记，绝不执行半截工具调用或保存貌似完整的半截答案。

## 待用户确认的唯一业务歧义

“结束后五分钟才能结束不允许对话”可能指：最终报告后仍可追问五分钟，超时才锁定；也可能指报告后立即禁言，五分钟后关闭。已提出聚焦问题。在收到回答前，五分钟追问/禁言的实现契约暂不定稿，其余布局、进度、后台入口和压缩工作可独立推进。
