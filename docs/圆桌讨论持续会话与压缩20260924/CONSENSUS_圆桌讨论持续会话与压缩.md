# 圆桌讨论持续会话与压缩：已确认需求

## 目标

圆桌讨论在手机与桌面上清晰显示标题、参与者、进度与操作；讨论在后台运行时，当前账号可从其他页面重新打开并继续发送消息。大量源码和讨论记录进入模型前按预算分批压缩和抽取，保留原始内容与来源锚点；模型输出不足时明确报告未完成范围，不产生看似完整的报告。

小菱的普通聊天、工具调用和圆桌读取同样遵守这一原则：对话原文与可审计工具结果不因预览长度被改写；运行时对省略历史做可追溯语义压缩；过长的模型完成响应必须经过有界、安全的预算重试或明确失败，不能把 `length` 响应当成完成结果。

## 已确定边界

- 本次以 v4.0.6 生产运行提交 `c86a7483aec160b2aa55c8e3195a3ad26d813387` 为基线。旧讨论记录保留，不能覆盖原始发言和生产审计。
- 圆桌会话由服务端按账号授权；无权账号即使知道会话编号，也不能取得会话或发言内容。重开入口展示当前账号有权访问的会话。
- 进度依据服务端的真实轮次、成员发言、总结、问题抽取和报告保存阶段；失败、取消、部分完成各有明确状态。100% 仅表示最终报告已成功保存。
- 移动端 320/390px 与 768px、桌面宽度都应完整显示标题、状态、操作、消息与输入。中文文本不得被单行头部挤成逐字竖排。
- 用户插话必须先由服务端验证账号和会话可接收，再按序保存并广播；被拒绝的消息不能出现在历史中。
- 真实生产验证使用可访问的正式源码与圆桌，区分测试环境、生产只读证据、生产实际操作。重复运行多个样本，记录成功、部分、失败与模型用量。

## 五分钟追问规则（用户已确认）

用户确认：圆桌正式结束后保留固定五分钟可继续追问，之后禁言。截止时间以服务端记录的结束时间加 300 秒计算，追问不续时；已接受的提问即使答复跨过截止时间，也必须继续完成并保存。仅正常生成报告的圆桌开放此窗口；失败、取消、中断的圆桌保留历史，但无完整报告依据可追问。主持人以同账号的完整原始发言账本为依据，按来源压缩历史回答；模型长度失败需重试或清楚显示失败，不能展示半截回答为成功。关闭面板只断开当前连接，后台任务和固定截止时间不变。

## 验收准则

1. 真实 390×844 Safari 与 320px 窄屏不再出现截图中的标题/轮次竖排、按钮遮挡或输入裁切；所有控件能实际点击。
2. 主持总结成功、结构化抽取耗尽输出预算时，报告状态准确显示抽取失败或部分完成；分批/压缩重试成功后可生成可复核的报告。
3. 圆桌在其他路由、刷新及重连后能由当前账号重新打开；按编号请求其他账号的圆桌受拒，消息顺序保持稳定。
4. 进行中可发送并收到接收反馈；正式成功结束后至第 300 秒前可追问，第 300 秒起禁言。被拒消息不写入历史，已接受问题和主持回答按序持久化。
5. 进度每一阶段与后端事件及报告事务一致，不用虚假的计时百分比。
6. 输入历史超过阈值后，小菱对第 13 条及之后的用户约束、单条长消息尾部和多个工具结果均能保留来源并用于后续决策；审计仍可读取原始内容。
7. 工具读取大量圆桌发言以分页/游标返回，明确剩余数据和下一页；模型或页面出现长度上限时不静默裁掉尾部。失败的半截工具调用不执行、不对用户冒称完成。
