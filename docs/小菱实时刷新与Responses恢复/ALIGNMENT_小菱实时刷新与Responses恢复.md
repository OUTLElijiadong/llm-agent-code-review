# 小菱实时刷新与 Responses 恢复 - 对齐文档

## 原始需求

1. 小菱状态必须实时刷新。
2. 小菱与子 Agent 的交流过程必须显示在悬浮窗内，并默认折叠。
3. 修复 `No tool output found for tool call` Responses HTTP 400。
4. 修复后必须复现原故障路径，并以真实重试不再报错作为成功标准。

## 现状与根因

- 管理端和用户端悬浮窗只在运行态每秒读取会话；进入等待态、完成态或失败态后停止轮询，跨会话消息与状态无法继续进入当前视图。
- 会话接口已经返回 `mesh_messages`，现有时间线也已经把 `send_message` / `receive_message` 默认折叠展示，缺口是终态停止刷新。
- Responses 运行时先持久化模型的 `function_call`，再执行工具并持久化 `function_call_output`。两次写入之间若进程中断，重试会把孤立调用原样发送给上游，触发 HTTP 400。

## 边界

- 同时修复管理端小菱和用户端小菱。
- 不伪造工具输出，不跳过真实工具执行。
- 只恢复最近一次 `completed` Responses 输出中尚无终态证据的调用；失败或不完整响应中的工具调用仍禁止执行。
- 活跃会话保持 1 秒轮询，非活跃会话采用较低频率轮询，避免无界请求压力。

## 已确认事项

用户已要求直接完成设计、开发、测试、服务器部署与真实验收，并在本轮明确要求修复后复现验证；不再新增业务决策问题。
