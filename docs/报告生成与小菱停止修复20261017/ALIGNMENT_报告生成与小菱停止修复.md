# 报告生成与小菱停止行为对齐

## 原始需求

用户反馈小菱点停止后仍可能再次启动并继续消耗 Token；要求代码审查、安全审计、沙箱黑白盒、渗透及远程网站评估的报告能按当前账号权限正确显示，报告内容、覆盖范围、评分和版式准确清晰，不显示无权限的报告卡片，也不显示 Markdown 星号等格式标记。用户提出 `4.1.0` 作为可接受的三段式版本示例，并要求后续版本各段不超过三位数。本轮发布前从生产健康接口实测版本为 `4.1.1`，因此本次单调递增发布候选为 `4.1.2`，不回退到 `4.1.0`。

## 项目现状与边界

- 生产基线由本轮发布前的健康接口重新确认；候选版本须从线上版本向前递增。
- 报告工作流包括普通代码审查、安全扫描/全链路审计、沙箱黑白盒、渗透及远程网站评估。远程网站评估使用独立领域任务和报告数据，不可伪装成标准代码审查报告。
- 成功响应但没有正向覆盖证据时，必须显示“覆盖未知”；失败或取消的渗透任务不得因没有已确认发现而显示满分/低风险；远程评估在启动前取消也要留下可读取的部分报告。
- 漏洞来源只显示 CNVD 与 CNNVD 两个独立来源；只有精确官方编号或官方详情链接命中时才标记对应来源，其余以带版本的 OWASP 分类兜底。未获准的数据接入未完成前，不虚构国内库匹配结果。
- 现有管理员总览已经提供每日 Token 用量热力图、数字滚动及波纹进场；登录成功光球、团队依赖图和根节点溯源由现有组件提供。本次保留这些交互并通过构建与代码回归检查，不重复造组件。
- 不更改真实审计结论，不把未验证范围描述为通过；无真实评分时须显示“未评估”。

## 验收范围

1. 停止响应后，取消回执和迟到的后台团队消息不得触发同一父运行自动续跑。
2. 报告型任务只能在所有者/管理员和现有 `report:view` 许可范围内显示；越权列表不泄露卡片，越权详情统一隐藏。
3. 安全审计结果持久化为账号归属报告，保留发现、证据、修复建议、覆盖情况和失败原因；部分/失败结果如实标记。
4. 报告展示与导出使用清晰的中文标题、分段和纯文本摘要；不把模型 Markdown 装饰符当正文输出，代码/证据内容保持原样。
5. 产品版本候选为 `4.1.2`；后续版本继续采用三段式格式，任一段超过三位数或带前导零时拒绝发布。正式生产版本以部署后的健康接口和账本为准。
6. 小菱工具发起的圆桌在没有打开圆桌面板/WebSocket 时也必须启动后台执行；已经发出的同步供应商请求不能保证即时中断，停止语义须如实描述为阻止后续调用。

## 非目标

- 不清理或改写历史报告和真实业务数据。
- 不合并独立远程网站评估报告为普通代码审查导出，也不新增未注册的外部情报接口。
- 不在无授权账号间复用报告内容。
