# 报告生成与小菱停止修复共识

## 需求与验收标准

1. 点击停止后，前端把当前响应标记为用户取消；迟到回执只能完成该运行的收尾，不能启动新模型请求。后端取消该父运行下的活动团队，并抑制会被前端解释为继续执行的待投递终态通知，同时保留审计记录。
2. 黑白盒、渗透、安全扫描与全链路审计等报告任务按所有者/管理员隔离；其他账号在列表、项目动态、详情和报告统计里均看不到越权数据。
3. `security_scan` 与 `fullchain_audit` 的执行结果保存为当前账号的可读报告，持久化问题、文件快照、评分可用性、执行状态和覆盖范围。
4. 部分或失败扫描不得宣称完整成功；无可用评分时显示“未评估”，不以 100 分占位。报告摘要、问题说明和建议不暴露 AI Markdown 装饰符。
5. 标准审查保留现有 JSON/HTML/PDF/Word；领域报告遵循已注册来源导出器的支持格式，远程网站评估仍使用其真实领域报告，不以空标准报告替代。
6. 发布版本 `4.1.2`。每个语义版本段限定为 0–999 的无前导零整数，版本来源统一为仓库根目录 `VERSION`。
7. 成功状态本身不证明扫描完整；没有覆盖凭证时报告为“未知”，已知计数冲突/跳过时报告为“部分”。失败、取消或过期的渗透任务评分不可用，列表、详情与报告正文显示“未评估”。远程网站评估在 worker 启动前取消时也要生成范围受限的部分报告。
8. 中国漏洞来源只展示 CNVD 与 CNNVD；精确官方编号/详情链接才算命中，未匹配时按 OWASP 版本兜底。没有获准数据源前只标“未匹配/未同步”，不虚构国内库编号。
9. 小菱工具启动圆桌不依赖面板 WebSocket；停止可以立即确认并拦住后续专家调用，但正在进行的同步供应商 HTTP 请求无法保证撤回。

## 实现约束

- 沿用现有 ReviewTask/ReviewIssue/ReviewReport、RBAC、项目访问校验和报告导出路由；不新增与现有能力重复的 API。
- 账号过滤必须在分页总数和分页前执行；详情的越权响应采用现有统一 404。
- 评分不可用与真实 0 分分开表达；报告记录的旧非空整数列仅用中性值保存，并以 `score_available` 控制展示。
- 保留管理员总览、登录成功和团队依赖图已有动效，并尊重减少动态效果设置。

## 风险边界

- 发布必须使用干净、已提交的精确 SHA，执行现有备份、隔离恢复验证、健康检查、运维巡检和回滚兼容性门禁。
- 自动化测试不替代线上真实登录账号的报告与权限验收；未完成的生产检查须明确记录。
