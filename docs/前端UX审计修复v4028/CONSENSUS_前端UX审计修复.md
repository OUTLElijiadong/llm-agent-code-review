# CONSENSUS 前端 UX 审计修复

## 需求与边界

- 以 v4.0.28 UX 审计报告为待核清单，在候选工作树内修复有代码或测试证据支持的问题。
- 生产发布不在本轮直接执行：现有生产会话目录账号隔离异常仍是独立发布阻断；本轮不能将其描述为已关闭。
- 保留后端 API、数据、角色权限、审批副作用、Agent 配置和审计范围。安全审计、审批类型或角色工作台仅在共享权限约束已证实的前提下整合导航/呈现。
- 真实生产数据的数值矛盾须通过接口、统计 SQL/service 和账号权限交叉核对；没有证据的只记录待核，不构造数据或通过静态文案掩盖。

## 验收标准

1. 逐条响应报告中的入口重复、职责混淆、术语、列表默认加载、数字口径、标题/账号、引导状态、工作台文案、窄屏布局和加载状态。
2. 审批中心让发布审批、规则提案及其他待审批流程可区分且仍走各自已有受权操作；空分类解释无待办，不伪造统一数据源。
3. 日志与审计只在数据模型和 RBAC 允许时共用导航；各日志类型明示范围、角色可见性和时间窗口。
4. 375px、390px、桌面视口下抽屉、遮罩、页头、卡片操作列和加载状态不遮挡可操作内容。
5. 变更对应自动化用例及 `git diff --check`、前端 lint/typecheck/build；检查结果与生产验收结果分开记账。
6. 更新 `ACCEPTANCE`、`FINAL` 与 `TODO`，逐项记录证据及未闭环风险；不得以本地构建通过宣称生产 UI 全面通过。

## 设计约束

- 复用现有路由、统一管理中心和服务，不额外造重复 API。
- 页面卡片和表格显示固定统计口径；数字无法比较时显示各自范围/时间窗，而非静默换算。
- 临时或兼容 Agent 仅改变面向用户目录的标签/过滤呈现时，也须保留已有可调用性和审计记录。
- 所有可折叠或关闭提示需有明确可发现的重新打开路径；偏好在当前登录账号本地保存。
