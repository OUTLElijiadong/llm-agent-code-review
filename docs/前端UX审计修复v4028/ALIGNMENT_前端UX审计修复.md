# ALIGNMENT 前端 UX 审计修复

## 原始需求

依据用户提交的《Prism · 棱镜 前端 UX 审计报告（v4.0.28）》，修复或补充审批/日志入口、代码中心区分度、审查方式说明、Agent 入口和术语、数据统计矛盾、管理台重复标题、账号展示、引导提示持久化、专业术语、移动端抽屉和加载状态等问题。

## 项目和任务理解

- 当前候选工作树为本任务的代码基线；生产环境仍有独立的账号会话目录元数据异常，不能以本轮 UX 修改替代或掩盖该发布阻断。
- 前端使用 Vue 3、Vue Router、Element Plus；多个管理页面已由 `/admin/{governance,operations,access,platform}` 的统一中心承载，不能仅按菜单文字判断真实重复。
- 页面数字来自不同角色范围、接口和时间窗口。实现前须追踪 UI → API → service/query；无证据的矛盾记录为待核，不得为了数字一致而硬改后端口径。

## 边界

- 本轮在候选工作树内修复前端呈现、导航、响应式、说明文案和有证据支持的前端数据口径缺陷，并补有针对性的回归测试与验收记录。
- 保留既有 API、角色权限、审计可见范围、审批语义和业务数据；不删除或重配 Agent，不合并不同审批后端流程，不放宽权限。
- 真实生产验收与发布仍须通过既有生产门禁；已知会话目录元数据异常未关闭前，不声称全站生产验收通过。

## 需求理解

1. 把同属一个管理工作流的审批入口收敛到可识别的“审批中心”，必要时以类型分区；对发布、规则提案、工具执行等后端语义不同的流程保留原有处理器和授权校验。
2. 让调用日志、系统审计、角色可见的操作记录具有一致的命名/导航线索；不把不同数据源伪装成同一数据集，也不扩大管理员或审查员的数据访问权限。
3. 让“项目管理”与“代码中心”以主要动作和页面定位清楚区分；发起审查各模式增加场景说明；收敛任务、新建审查、严重度、版本恢复及账号术语。
4. 逐项核对审查员计数、失败告警、权限点、用户首屏、圆桌运行数、待继续任务、严重度分布和计划展示。只有查明实际口径或复现前端问题后才修复。
5. 统一管理后台标题层级与账户入口，保存用户关闭小菱提示的偏好；为工作台文案去除普通用户不需要的框架术语。
6. 在 375px 等窄屏验证侧栏抽屉遮罩、顶栏和内容滚动；统一仪表盘加载占位，避免并行动画造成重复提示。

## 待核问题

- 审批类型是否共用同一后端队列；等待代码核实后决定是一个中心中的独立子页，还是同页筛选。
- 审计页空/有记录是否源于请求权限、过滤条件或数据范围；不得凭截图推断数据泄露或遗漏。
- 不同角色首页卡片是否使用相同统计窗口和严重度映射；按实际服务契约确定统一展示口径。

## 验收边界

- 所有确认为缺陷的 UI 行为都有修复前复现记录、回归用例或明确截图/DOM 证据。
- 修复后重跑原场景并增加宽度/角色/统计样本；前端单测、类型检查、lint、生产构建通过。
- 每条原始审计项标为“已修复并验证 / 已核对非缺陷 / 未复现或待生产证据 / 被生产门禁阻断”，不得用整体通过替代逐项状态。
