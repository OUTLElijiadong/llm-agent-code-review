# 共识与验收标准

## 需求

合法源码 `tar.gz` 启动白盒测试不再因 ZIP 误判返回 500；团队卡片在团队被服务端账本发现后挂在对应调用时间线；关闭/重开、新建后切回历史仍可恢复卡片及详情入口。

## 技术方案

- `plan_decompilation_archive` 调用 `read_archive_members`，统一处理 ZIP/TAR 系列并保持路径、链接、压缩倍率约束。
- `ChatMessage.teamIds` 保存消息与 Agent Team 的关联；快照保留含团队 ID 的空时间线消息。
- 恢复时从本地快照恢复锚点，再用服务端团队详情补齐卡片；短暂空列表不清空已有卡片。
- 未找到锚点时只创建一个时间线占位消息，团队卡片仍按调用顺序展示。

## 验收标准

- tar.gz 普通源码规划返回 `skipped`，内嵌有效 APK 仍返回 `planned`，损坏归档失败闭环。
- 后端反编译单元测试通过；前端类型检查、团队卡片/快照测试通过。
- 公网 `/api/readyz`、登录页和白盒启动链路无 500；恶意文件策略仍给出结构化业务结果。
- 团队卡片出现在对应调用时间线，不再固定出现在最终结论之后；关闭重开和历史切换后仍可见。
