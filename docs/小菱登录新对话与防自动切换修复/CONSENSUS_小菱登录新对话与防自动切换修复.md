# 共识：小菱登录新对话与防自动切换修复

## 行为契约

1. `login()` 成功后为 `user`、`admin` 两个小菱入口分别写入一次性“待新建”标记；Token 恢复 `fetchProfile()` 不视为再次登录。
2. 会话切换器挂载时消费当前入口标记，创建并选中一个新会话；历史索引与服务端会话均保留。
3. 标记消费后，同一登录周期重挂载或关闭再打开只恢复最后显式选中的当前会话。
4. 服务端发现只合并列表和运行状态，不根据 `last_seen_at`、后台忙碌状态或消息完成状态改变当前会话。
5. 后台 Mesh 消息仍在目标会话执行并更新状态，但完成后不抢占用户当前上下文。
6. 当前会话被用户显式归档时，允许按既有规则选择合法后继会话。

## 技术约束

- 登录周期标记使用 `sessionStorage`，不写数据库，不改变历史会话数据。
- 标记按 `user` / `admin` 分开消费；重复调用必须幂等。
- 会话 ID 继续使用 `crypto.randomUUID()`，标题继续使用“新对话”。
- 不以清空 `localStorage` 伪造修复，不删除“默认对话”。

## 验收标准

- 公网重新登录后，首次打开普通端小菱显示“新对话”，历史仍可从菜单找到。
- 管理端共享组件测试证明同一契约适用。
- 点击“新建对话”后等待至少两个目录刷新周期，标题与会话 ID 不变。
- 历史会话处于 running/waiting 或后台完成时，当前新会话仍不变。
- 关闭再打开继续当前会话；再次成功登录才再次新建一次。
- 前端定向测试、扩大回归、类型检查、Lint 与生产构建通过。
