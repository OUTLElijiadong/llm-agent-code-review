# 对齐：小菱登录新对话与防自动切换修复

## 原始问题

- 每次成功登录后第一次打开小菱，当前会话仍是历史“默认对话”，而不是全新的空白对话。
- 用户点击“新建对话”后，约一个目录刷新周期会自动跳回历史或“默认对话”。

## 用户确认的行为边界

1. 每次成功登录后，普通端和管理端第一次使用小菱时各创建并选中一个全新空白会话。
2. 同一次登录中关闭再打开悬浮窗，继续当前会话，不重复创建。
3. 新建或手动选择会话后，只有用户再次点击会话条目、新建或归档当前会话等明确动作才能改变当前会话。
4. 轮询、后台任务完成、历史同步、组件重挂载和恢复运行状态不得自动切换。
5. 保留“默认对话”和全部历史，不删除、不迁移、不改写后端数据。

## 已复现事实

- 2026-08-24 公网登录后首次打开小菱，显示历史会话“请组建一个只读子 Agent 团队核…”。
- 点击“新建对话”后先显示“新对话”，约 10 秒后自动变为历史会话“帮我全面审计皮卡丘漏洞平台…”。
- 后端只按 `user_id + surface + session_id` 恢复会话，不存在默认会话选择指令。
- 前端目录每 10 秒刷新；当前为空时会选取最近心跳的历史会话。
- Mesh 每 5 秒给全部历史会话发心跳，`last_seen_at` 不能代表用户主动选择。
- 打开策略会追逐忙碌历史会话，后台 Mesh 完成后也会调用强制聚焦。
- 登录状态没有“小菱本次登录尚未初始化”的生命周期标记。

## 范围

- `AgentSessionSwitcher` 的登录首次初始化和选择权约束。
- 用户 Store 成功登录时设置一次性初始化标记。
- 普通端与管理端后台 Mesh 完成路径取消自动聚焦。
- 单元测试、类型检查、Lint、生产构建和公网真实登录验收。

## 不改变

- 后台任务、审批等待、输入等待、轮询、心跳、Agent 团队、团队卡片、历史恢复和服务端归档。
- 用户显式停止、显式新建、显式选择、显式归档的既有业务语义。
- 后端 API、数据库结构、RBAC、普通端与管理端 `surface` 隔离。
