# 共识：渗透报告修复复测

## 需求与验收标准

- SEC-01：确认验证码接口是否把答案返回客户端；不将算术题自动化弱点误报成答案泄漏。
- SEC-02：审查启动应有可解释的账号级 HTTP 限流；超过阈值必须在入队和模型调用前拒绝；账号之间额度隔离，重新登录不能重置额度。
- SEC-03：区分四个点号的普通目录名与真正的 `..` 路径穿越；保留合法文件路径，拒绝越界路径。
- SEC-04：只记录 8888 监听的实际归属，不改变任务外的宿主机面板。
- SEC-05：通过本地隔离数据库测试草稿的创建、取消、删除与删除后 404；生产不删除原有 `#7/#8`。
- UX-07：列表加载中不显示错误的空数据；请求失败时显示重试态并阻止旧请求覆盖新筛选结果；维持报告属主隔离。
- 审批计数必须遵循当前管理员可见权限和执行审批口径；入口显式进入执行类型，发布与规则提案继续使用原有审批流程。
- 生产发布只允许干净、精确 SHA；备份、迁移、健康/就绪、ops-check 和普通 Safari 实际页面复测均需留证。

## 技术约束

- 生产数据不做清理、删除或创建测试实体。
- 生产每日 Token 预算未有已确认策略；本次只实施 5 次/分钟账号级 HTTP 限流，不将其宣传为每日额度。
- 生产 8888 属于非项目服务；未经本任务范围确认不得停止或改防火墙。
- 生产报告列表/权限继续遵循现有数据归属，不通过放宽授权来掩盖差异。

## 已解决的不确定性

- `....//....//x.py` 按 POSIX 分段是 `..../..../x.py`，不是父目录穿越。
- “审批待办”首页指标明确改为“执行审批待办”；发布审批与进化提案各有独立工作流与闸门。
