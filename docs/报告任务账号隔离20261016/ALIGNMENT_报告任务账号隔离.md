# 报告任务账号隔离对齐

## 原始需求

用户指出普通账号打开 `/reviews/215` 时看到“沙箱黑白盒测试”任务、项目名、状态、任务号和耗时，但正文与统计提示无权查看，并询问任务不属于当前账号为何仍展示。用户期待账号不拥有的黑白盒/渗透报告任务不出现在该账号页面。

## 已核对的项目行为

- README 规定报告保留发起人/管理员范围，并受项目当前可见性约束。
- `review_service.list_tasks` 目前先按项目可见性分页，再把无报告权限任务作为脱敏行返回。
- `get_task_detail` 目前允许同项目成员读取此类任务的元数据，只隐藏正文、分数和发现统计。
- `project_service` 的近期任务也保留了无权查看的任务 ID、状态和时间，只对部分字段置空。
- 这造成“无权查看报告却能看见报告任务”的 UX 矛盾；这是可复现的授权可见性缺口，不能只归为旧浏览器显示问题。

## 范围与边界

- 只调整 `sandbox_test` 与 `pentest` 报告型任务的发现/读取范围；普通代码审查继续遵循项目成员可见规则。
- 报告型任务的任务号、标题、项目关联、状态、耗时、覆盖、评分、统计和报告正文都只向发起账号及管理员开放；仍须通过现有项目访问校验。
- 报告查看权限不足但本人发起的任务仍可查看任务状态；报告正文/评分仍依现有 `report:view` 权限隐藏。
- 不改写历史数据、不删除任务、不改变管理员范围。
