# 报告任务账号隔离共识

## 需求

修正报告型任务跨账号可见性：发起人和管理员能发现并读取黑白盒/渗透任务；其他账号在任务列表、直接详情及项目近期任务中看不到该任务记录。非报告型代码审查继续按项目成员权限显示。

## 验收标准

1. 普通项目成员的 `/api/review/tasks` 不返回他人 `sandbox_test`/`pentest` 任务，分页总数也不计入这些任务。
2. 同项目成员直接读取他人报告任务详情或问题明细时，返回与缺失/无项目权限一致的 404，不含任务名、项目 ID、状态等元数据。
3. 项目近期任务不显示不可见报告型任务；项目卡最近审查时间/分数不会由不可见报告型任务泄漏。
4. 发起人和管理员可继续访问；发起人缺少 `report:view` 时，任务状态可见但报告正文、评分、统计仍隐藏。
5. 普通代码审查任务的项目成员可见性保持不变。

## 技术约束

- FastAPI/SQLAlchemy 服务层集中定义报告型任务元数据可见策略，列表过滤必须在计数和分页之前完成。
- 使用现有统一 404 防枚举响应；不新增 API、数据库迁移或权限角色。
- 保留现有 report:view 与对象所有者双重校验。
