# 共识：部署诊断与历史终态兼容

## 需求与验收标准

1. 生产当前版本、release SHA、健康/就绪响应相互核对。
2. 发布源必须是精确完整 SHA，构建目录 clean，精确 SHA CI 通过；不把 v4.0.2 脏工作区发布到生产。
3. 仅在事件类型为 `result`、终态为 `succeeded/failed`、任务模式为 `blackbox/combined` 且正文与旧 Worker 已证实的固定白盒终态文案完全相等时，按任务模式投影文案。
4. 白盒事件、非终态事件、非精确或未知正文逐字保持不变；API、数据库和审计记录不被回写。
5. 定向前端测试、lint、类型检查、生产构建和精确 SHA CI 通过；若发布通道不可用，明确标出已完成代码修复与发布阻断证据，不声称已部署。
6. 若完成发布，核对备份/恢复、迁移、前后端 SHA、健康/就绪、HTTPS 和实际旧任务刷新后的页面显示。

## 实现方案与约束

- 在现有沙箱展示工具中增加纯函数兼容投影，避免后端数据迁移和历史审计改写。
- 页面事件正文统一调用该函数；终态标题仍使用现有 `stageLabel`。
- 版本按仓库规则升至 v4.0.86；不混入其他 Agent、沙箱执行或用户业务代码变更。
- 上线前先检查活动发布树、磁盘、备份和当前/上一镜像；触发门禁时先诊断，不绕过脚本。
