# 小菱评分与报告终审知识库

> 适用：用户端小菱（chat_assistant）与管理小菱/贾维斯（manager）。本库存放在生产服务器 Agent 知识库，不依赖任何本地笔记。小菱只负责规划、组队、派发、跟踪、核验和汇总；评分由规则计算，小菱做最终可信度终审。

## 一、六类评估任务与对应团队

| 任务 | 入口 | 评分规则 | 建议团队成员 |
|---|---|---|---|
| 代码审查（快速/标准/全面/安全） | /reviews/start | severity-deduction-v1：100 − 15×严重 − 8×高 − 3×中 − 1×低 | 静态规则 + 审查 Agent（多代理时含安全、性能、规范） |
| 安全审计（安全扫描/全链路审计） | /security | 同上，按已核验发现计数 | Recon、Analysis、Verification、Report 四角色 |
| 圆桌讨论 | 审查详情或文件页“圆桌讨论” | 同上，按讨论抽取的结构化问题计数 | 各专家 Agent + 主持人 |
| 沙箱白盒/黑盒/组合测试 | /sandboxes | sandbox-check-pass-rate-v1：100 × 已执行检查项得分之和 ÷ 已执行检查项数（通过 1、部分 0.5、失败 0） | 确定性 runner、AI 动态用例生成、黑盒入口探测 |
| 授权渗透委托 | /pentests | pentest-confirmed-deduction-v1：100 − 40×严重 − 25×高 − 12×中 − 5×低（只计已确认发现） | 侦察、检测、受控利用、后渗透推演、报告 |
| 远程网站测试 | /remote-pentests | 同渗透已测范围分；主动探测受授权与 fail-closed 约束 | 授权核验、被动探测、报告 |

## 二、评分范围（必须随分数一起说明）

- 完整覆盖：执行成功且覆盖账本完整，分数代表整份提交。
- 仅覆盖已审范围：部分文件、发言轮次或测试阶段未完成。分数照常按规则给出，只代表已完成的部分；未覆盖的文件、轮次、阶段写在报告“覆盖记录”。
- 历史任务按已保存问题集复算：早期任务没有覆盖账本，按已保存的问题严重度计数重新计算。
- 不出分：只有“没有任何已审文件 / 有效发言 / 已执行检查项 / 已完成检测阶段”时才不出分，必须写明原因。任何情况都不得用 0 分占位。

## 三、执行中的自动兜底

- 代码审查：单个文件失败会自动重试一次；重试后仍失败但其他文件已完成时，任务以“仅覆盖已审范围”完成并出分，失败文件列入覆盖缺口。
- 圆桌讨论：部分轮次失败但已有有效发言并完成问题抽取时，按已完成发言出分；主持人接管且未抽取问题时不出分。
- 渗透/远程测试：远程目标未执行主动探测属于覆盖缺口，不再导致不出分；检测阶段已完成即按已确认发现给出已测范围分。
- 沙箱：失败的测试同样按已执行检查项给出真实低分；没有任何已执行检查项（停止、过期、未进入测试）时不出分。

## 四、小菱终审（score_audit）

1. 报告展示前，按上表规则从原始输入独立复算：问题严重度计数、沙箱检查项回执或渗透已确认发现计数。
2. 复算值与记录分一致 → “可信”，生成报告。
3. 不一致 → “已打回重判”，报告改用规则重算分，并保留被否决的原值。
4. 规则输入缺失 → “不出分”，说明缺少什么。
5. 旧版失败任务记录的 0 分没有评分版本，属于占位值，不参与比对，直接按问题集复算。

## 五、回复模板

- 已出分：“本次{任务}按{规则}得分 {分数}（{评分范围}），小菱终审：{可信/已打回重判}。{未覆盖范围一句话}”
- 不出分：“本次{任务}没有可计分的已审内容（{原因}），因此不出分；建议{重新发起/补充授权/检查沙箱}。”
- 不要只报分数而不报评分范围，也不要把“仅覆盖已审范围”的分数说成整体结论。

## 六、常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 报告页提示“报告不存在” | 不是报告丢失，而是权限或可见性：账号缺 issue:view（代码审查类）或 pentest:view（渗透类）、任务不是本人发起且非管理员、项目已删除或隔离、任务已被删除 | 让管理员在 /admin/access 补权限点，或确认项目状态 |
| 报告列表看不到某任务 | 默认列表只显示已出分的终态报告；没有任何已审内容的任务需打开“含历史” | 指导用户勾选“含历史”查看原因 |
| 安全审计/沙箱报告提示“快照缺失” | 领域报告正文未生成 | 引导到报告页重新生成 |
| 分数显示“已打回重判” | 记录分与规则复算不一致 | 属于正常终审结果，报告已用规则分 |
