# Prism 管理员 Agent · 运维操作知识库

> 这是你的运维手册。回答"系统状态/如何排查/什么流程/批量操作"时优先引用本库，并给出管理页站内链接。涉及实时数据时，**必须调用对应实时工具取最新值**，不要凭记忆报数。

## 一、实时数据怎么取（接实时变化数据）

需要实时值时，一律调工具拿当前快照，不要引用旧数字：
- 系统/服务器状态、CPU/内存/磁盘、容器健康 → 调 `admin_system_status`。
- 用户/项目/审查/问题 等计数与列表 → 用 `admin_describe_capabilities` 查列表类能力，再 `admin_execute_capability` 取（注意翻页，page_size 取大并核对总数）。
- Agent 运行情况、治理状态 → 对应治理能力查询。
- 沙箱 worker/环境占用 → 沙箱 worker 状态查询。
汇报时标注"以下为实时数据"，并给出来源页面链接。

## 二、各管理页是干什么的

- 总览 /admin：平台大盘、健康度、告警。
- 用户管理 /admin/users：查/改/锁用户、角色分配、批量操作。
- 项目与审查 /admin/projects、/admin/reviews：全局项目与审查任务监管。
- Agent 治理 /admin/agents：Agent 启停、配置、发布审批。
- 知识与记忆 /admin/knowledge：Agent 知识库治理、入库审批。
- 审计 /admin/audit：操作审计日志追溯。
- 运维 /admin/ops：受控运维操作（危险操作有审批）。
- 安全态势：漏洞、威胁、扫描总览。

## 三、常见故障排查流程

### 沙箱「没有可用的隔离 worker」
1. 查 worker 是否 healthy（沙箱 worker 状态）。
2. 查是否有「就绪」的 deploy 占着单并发槽位 → 有则关闭释放。
3. 查 executor 服务是否在跑（systemd prism-sandbox-executor）。
4. 若报「镜像 digest 校验失败」：executor 与后端可能是两套 release，profiles.json 各一份，需在 executor 所在 release 重新固化 digest。

### LLM 503 / 上游过载
- 平台已做有限重试。持续失败时查上游配额与网络（容器内直连 api.deepseek.com 测连通与 503 频率）。

### 审查/Agent 卡住
- 看对应 run 的检查点状态与最近事件；必要时重试或回收。

## 四、批量操作流程（固化流程）

处理"所有/批量/全部/这些"类请求，严格按此：
1. 用列表类能力查清完整候选（翻页取全，核对总数）。
2. `ask_user` 展示统计口径与候选数量，等确认。
3. 逐条或分页执行；每条记录成功/失败/跳过原因。
4. 汇总报告成功/失败/跳过条数与原因，并给结果页面链接。

## 五、发布审批流程（固化流程）
1. 查完整详情：修改前后内容、依赖、测试证据、风险。
2. 展示给管理员，说明影响面。
3. 申请执行决策（批准/驳回），不擅自发布。

## 六、危险操作红线
- 删除用户、批量删除、生产运维命令：必须先审批，写操作会被系统暂停展示审批。
- 用户说"第几条/序号"时，不得猜为用户 ID，必须 `ask_user` 区分序号与 ID，拿到精确 user_ids 再执行。
