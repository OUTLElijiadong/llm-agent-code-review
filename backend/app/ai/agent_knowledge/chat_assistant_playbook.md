## 一、各页面是干什么的、怎么操作

### 工作台 /dashboard
- 看板：项目数、待办问题、最近审查、Agent 动态。
- 操作：点卡片可跳到对应页面。新用户先看这里了解全貌。

### 项目 /projects
- 管理你的代码项目。
- 操作：新建项目（填名称、语言）→ 进入项目 → 上传源码。
- 上传源码两种方式：
  - 「上传代码文件」：走普通源码链路，可用于部署（deploy）。
  - 「隔离审计归档」：把源码当可疑证据审计，**此方式的项目永远不能部署**，只能审计/测试。

### 审查 /reviews
- 发起代码审查（快速/完整/安全等类型），看审查任务与结果。
- 流程：选项目 → 选审查类型 → 发起 → 在 [审查记录](/reviews) 看进度和结果。
- 审查出的问题进 [问题](/issues)。

### 问题 /issues
- 审查发现的漏洞/缺陷列表。
- 操作：按严重度筛选，点进看详情、定位代码行、标记处理状态。

### 报告 /reports
- 由审查结果生成报告。
- 操作：选审查任务 → 生成报告 → 下载（JSON/HTML/PDF/Word）。下载用 download_report。

### 沙箱 /sandboxes
- 隔离环境里测试和部署你的项目。三种测试 + 部署：
  - 白盒：静态检查 + 跑你的单元测试。
  - 黑盒：起服务后从外部发真实 HTTP 探测。
  - 组合：先白盒再黑盒。
  - 部署(deploy)：把项目跑起来给你预览链接。**部署成功后会自动跑白盒+黑盒+冒烟测试链**。
- 流程：选项目 → 选「测试」或「部署」→ 选语言/模式 → 提交 → 右侧看 Agent 实时进度。

### 个人知识库 /knowledge
- 你的私人知识，按你的账号隔离，别人看不到。
- 你审查过的问题、报告、论坛/反馈历史会沉淀在这里；我回答时会检索它，越用越贴合你的风格。
- 操作：可手动补充知识；也可让我"记住这个"，我帮你沉淀。

### 其他
- 圆桌 /roundtable：多 Agent 对某问题辩论出结论，用 start_roundtable_discussion。
- 论坛 /forum、反馈、工单：交流与求助。
- 个人中心 /profile：改资料、密码、个性化偏好。

## 二、常见报错怎么解决

### 「没有可用的隔离 worker，任务未运行」(50301)
- 原因：沙箱是**单并发**。有一个处于「就绪」状态的部署(deploy)一直占着 worker。
- 解决：去 [沙箱](/sandboxes)，把状态是「就绪」的旧部署「关闭」，再重新发起测试/部署。

### 白盒/黑盒「测试未通过」
- 多半不是平台坏了，是你的项目自身问题被如实测出来：
  - Python 报 `No module named 'tests'`：你的测试代码 `from tests.xxx import`，但 `tests` 包没一起上传。把依赖包一并上传。
  - Python 部署报 `no supported Python deployment entry`：部署要求项目**根目录**有 `app.py` 或 `main.py` 作为入口。
  - PHP 项目用内建 `php -S` 起服务，无需入口文件。

### 部署报「隔离源码归档只能审计或测试，不得部署」(40341)
- 原因：你是通过「隔离审计归档」上传的源码，该方式按安全设计**永不部署**。
- 解决：想部署，请改用「上传代码文件」方式重新上传源码，再走部署。

### LLM 报「503 Service is too busy」
- 这是大模型上游临时过载，平台已自动重试。稍等几秒重发即可；持续不行再反馈。

### 部署后想再测试，却提示 worker 不可用
- 部署(deploy)会一直占着 worker 直到到期。想再测试，先关闭该部署。

## 三、标准操作流程（固化流程，按此执行）

### 流程A：从零审查一个项目
1. [项目](/projects) 新建项目，填对主语言（部署要靠它选运行时）。
2. 用「上传代码文件」传源码（要部署就别用隔离归档）。
3. [审查](/reviews) 发起审查。
4. [问题](/issues) 看漏洞，[报告](/reports) 导出报告。

### 流程B：部署并自动验证
1. 确认项目是「上传代码文件」方式上传的，且根目录有入口（Python 要 app.py/main.py）。
2. [沙箱](/sandboxes) 选「部署」，提交。
3. 等右侧进度：会自动 白盒→部署→黑盒/冒烟，结论显示"自动测试链 白盒✓/黑盒✓/预览冒烟✓"。
4. 点「打开预览」看真实运行的应用。
5. 用完记得「关闭」释放 worker（单并发）。

### 流程C：让我帮你沉淀个人知识
1. 你说"记住这个 / 沉淀一下"。
2. 我把它整理进你的 [个人知识库](/knowledge)。
3. 以后你问相关问题，我会优先引用你自己的沉淀和你的习惯。
