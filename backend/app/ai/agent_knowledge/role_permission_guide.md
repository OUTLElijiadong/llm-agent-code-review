# 棱镜 Prism 角色权限说明书

> 这是整个系统的角色与权限边界。判断"这个用户能不能做这件事"时，先按本说明书判定；用户请求超出权限时，直接说明"你没有 XX 权限，无法执行"，不要调用工具，也不要把工具权限错误当成执行结果。

## 一、三个内置角色

### 1. 普通用户(user)
- **能做什么**：项目管理(创建/编辑/删除自己的项目)、代码浏览与编辑、发起代码审查、处理审查问题、查看/导出报告、自定义审查规则、安全中心、Agent 中心(调用已发布的自定义 Agent)、代码沙箱(白盒/黑盒/组合测试)、开发者论坛、个人 API 配置。
- **不能做什么**：看不到任何管理端页面(/admin/*)；不能管理用户/角色；不能配置系统；不能执行服务器运维；不能审批。
- **权限边界**：只能访问自己创建或被添加为成员的项目；只能下载自己有权限的文件/报告；沙箱测试在自己有权限的项目内执行。
- **Agent 工具**：user_describe_capabilities/user_execute_capability(按页面能力过滤)、固定项目工具(update_project/import_remote_project/download_*)、沙箱工具(run_project_tests/deploy_project_sandbox/close_sandbox/extend_sandbox)、圆桌讨论工具、知识笔记本(recall_knowledge/save_knowledge_note)。

### 2. 管理员(admin)
- **能做什么**：除"服务器运维/全局基础设施"外的全部管理功能——Agent 治理、审批中心(仅程序类审批)、策略中心、工具权限、知识与记忆、任务调度、监控告警、用户管理、RBAC 角色与权限分配、报告模板、审计日志、自进化、Skill 管理、奖惩趋势、回滚中心。
- **不能做什么**：不能执行服务器运维动作(admin_execute_operation)；看不到唯一超管专属工具(admin_system_status)；不能修改/抓取外部知识来源(需唯一超管)；不能查看/审批服务器级敏感审批(operations.*、production:*、server_ops:*、mcp:* 资源)；受限调度任务(crawl/ops_health_check/security_monitor/db_backup)对其隐藏且不可启停。
- **权限边界**：审批列表只显示其有权处理的事项；管理能力按权限点过滤(如 overview.system、llm.config.*、embedding.config.* 对普通管理员不可见)。

### 3. 超级管理员(super_admin, 唯一账号 admin)
- **能做什么**：以上全部 + 服务器运维(admin_execute_operation 全部动作)、服务器实时状态(admin_system_status)、外部 MCP 工具、知识源写/抓取、受限调度任务、服务器级敏感审批、MCP 与沙箱节点治理(/admin/mcp-workers)、大模型配置(/admin/llm)、RAG 嵌入配置(/admin/embedding)。
- **运维教程**：见「运维教程」文档(仅超级管理员可检索)。
- **权限边界**：服务器运维动作分只读/写/高危，写与高危自动等待用户批准。

## 二、判断规则(小菱执行前先判断)
1. 先看当前登录用户角色：user → 用户权限；admin → 管理权限(不含服务器)；super_admin → 全权限。
2. 用户请求超出当前角色权限 → 直接拒绝并解释，不调用工具。
3. 服务器运维/删除/改角色/批量删除等敏感操作 → 先复述当前身份并请用户确认。
4. 工具列表是后端按权限过滤后的结果：没有提供的工具一定不可用，不要尝试调用。

## 三、常见权限错误与正确回应
- 用户要求"开放端口/重启服务器/看服务器日志"而当前不是 admin 或不是唯一超管 → "你没有服务器运维权限，仅超级管理员 admin 可执行；如需请找管理员处理。"
- 普通管理员要求"查看 llm 配置/embedding 配置/MCP 节点" → "这些页面仅超级管理员可用。"
- 普通用户要求"管理用户/审批/看管理后台" → "管理后台仅管理员可用。"
- 用户要求删除项目/用户等高危操作 → 先说明影响并等待批准，不直接执行。
